# Samila 原版时间线验证

2026-10-21，2.0 的 M3 实现阶段。新导入 Samila 的等待、相机动作和参数动画改用独立的源队列规则。已有本地作品保持原行为；没有打包或替换现有 1.0 Apple Silicon 应用。原版 JVM／JOGL 整图一致性仍为 **0/11**。

## 实际变化

重新导入原版 Samila JSON 会使用 `samila-scene-sequence-v1`。编辑器只提供等待与动作组，支持直接修改参数上下界和步长；预览、采样与导出共用文档帧率。旧的“持续采样帧率”在此模式下隐藏，其保存值仍保留。开发接口 `parseLegacyScene(text, {samilaTimeline:'legacy-v1'})` 可以仅保留旧时间线导入，数学版本仍可独立选择。

| 行为 | 本次接入的源规则 |
|---|---|
| 片段派发 | 只有 `animate` 执行动作，其他类型（包括 `align`、`param`）成为等待；被禁用的片段先跳过 |
| 队列推进 | 每次更新最多处理一个片段，零时长片段也占用一次更新；不把超出的时间转交下一片段 |
| 动作开关 | 源配置不读取动作的 `enabled`；用片段开关控制执行 |
| 相机 | 保留各分量运行状态，只有 theta 参与 Samila 密度显示；环境旋转在队列结束后仍按帧推进 |
| 参数启动 | 初相位来自整条队列构造时的参数快照；按原公式累计相位，完成后替换持续漂移列表；空启动不清空已有漂移 |
| 参数停止 | 停止片段完成时停止全部漂移；过渡期间原有漂移继续 |
| 完成帧 | 启动片段的最后一次参数更新之后，同帧再进行一次持续漂移；队列已结束的后续帧不更新参数 |
| 清屏 | 每次参数写入都产生清屏事件；同值或微小变化清屏后采一批，超过源比较阈值的变化补采六批；单独旋转 theta 不清屏 |

参数上下界在共同的配置边界排序，列表顺序保留。参数字段按 double 字面量读取；片段时长和相机参数按源 float getter／空参数作用域表达式读取。`targetDomain` 不参与 Samila 参数动作。保存文件保留独立参数载荷、原始 JSON、未消费字段和登记的数值词法。引用中的初始参数不能直接删除，须先停用或修改对应片段。

负时长也保留。参数动作所在组可把自身时长夹到零，而相机子动作仍使用原负时长；两者不能共用被夹过的时长。非有限计算、本地容量超限和不支持的标识符明确报错，不伪装成正常输出。

## 验证方法

固定原包 `MathArt-1.7.8-b07191b3e97da6fe465555ef6e61a0be.jar` 的 SHA-256 为 `a6e1da3acfc05c347d2529c1d590657e2dd798e16d38c55df3dc61312be24018`。本地静态审计绑定 19 个相关类，见 `.cache/v2-samila-timeline-audit.md` 和 `.cache/v2-samila-timeline-source/manifest.json`。

独立 Python 参照从固定类字节码推导队列、相机和参数公式，并解释 46 个源缓动函数；期望帧不调用产品代码生成。实际导入及生产回放在无界面的 Chrome 中执行。比较相机／队列 float32 位模式，参数 double 使用归一化误差不超过 `2e-12` 的阈值，以允许宿主数学库的末位差异。

27 组用例包括全部 5 个原包配置，以及零／负／短于一帧的时长、同组启停顺序、旧漂移覆盖新动画、空启动、同值写入、队列结束冻结和冷启动／倒退／恢复。原包 `samila1` 的 74 秒队列完整覆盖于 4 fps 参照中。负时长混合相机与参数的首次对照确实失败，修复后重新通过；失败证据保留在 `.cache/source-samila-timeline-negative/`。

## 本轮实测结果

全套 **314 个测试文件／5,780 项测试通过**，耗时 99.49 秒。首次全套检查有一处断言仍匹配旧提示文字，修正后重新执行全套通过。最终 TypeScript／Web 构建通过，保留既有大 bundle 提示；最后移除不适用的“转为绝对时间线”入口并补充英文提示后，再次构建并重跑公开操作验证。

| 路径 | 结果 | 墙钟时间 |
|---|---|---:|
| 独立源帧参照 | 27/27 组、502 帧、12,613 项断言通过，包含重复／冷启动／倒退／恢复 | 2.31 秒 |
| 真实 App 编辑与持久化 | 原版 samila1 导入；将 a 步长改为 -.02；保存后切换场景再重开；参数载荷保持一致；播放推进并重置 | 与下列导出合计 10.77 秒 |
| 帧率接线 | 在界面设为 24 fps，预览、重开、PNG 和三帧视频的采样帧率均为 24 | 同上 |
| PNG | 192×128 非空，完整 RGBA 与实际 Worker 输出相同 | 同上 |
| MP4 | FFprobe 确认 192×128、3 fps、3 帧；三个上传 PNG 分别与对应 Worker 完整 RGBA 相同，且三帧不同 | 同上 |

公开流程运行于 DPR 1 的无界面 Chrome。夹具使用固定原包 samila1 的公式与参数，明确覆盖为每批 256 点、GPU、关闭拖尾、短的启动→等待→停止→等待队列；它不是原包高批次长期负载测试。原包完整 74 秒时间线由独立标量参照覆盖。最终逐帧对照和公开操作报告的源码哈希均稳定，浏览器、开发服务和导出服务全部清理成功，没有 Worker 错误。

可读报告在 `.cache/source-samila-timeline-release/report.md` 与 `.cache/samila-source-timeline-public-release/report.md`。首次公开流程因脚本误把帧率下拉框当作数字输入框而失败；改用实际可见控件后通过，失败记录保留在 `.cache/samila-source-timeline-public-final/`。

新增界面文字已补英语。整体翻译审计仍因 **71 处既有界面缺口**失败；它们全部属于上一批已记录的 76 处，本次补齐的共用标签减少了其中 5 处。没有把整体翻译审计记为通过。

可复跑的脚本已纳入 Git：

```sh
python3 scripts/source-samila-timeline-oracle.py --check
node scripts/verify-source-samila-timeline.mjs
node scripts/verify-samila-source-math-public.mjs --timeline
```

参照重建需要固定原包和已有本地静态证据；浏览器检查需要现有 Chrome，视频检查还需 FFmpeg／FFprobe。这些脚本不会安装系统依赖。机器可读帧夹具在 `tests/fixtures/source-samila/timeline.json`，本页是其人工可读说明。

## 仍然未验证的部分

这批验证覆盖源代码语义与本地公开链路，**没有运行原版 JVM／JOGL 的整图对照**。Mac 窗口检查仍返回锁定，未继续操作原版窗口。源程序实时线程调度、显示补偿与窗口热更新未验证；固定帧率是本地可重放的声明模型。

本地随机流仍不同于原版逐帧随机种子。噪声颜色和点覆盖的后续验证见[绘制验证记录](samila-source-splat-validation.zh-CN.md)；透明合成和跨设备图像仍未由此次标量验证证明；CPU 与 GPU 的数学差异见[数学验证记录](samila-source-math-validation.zh-CN.md)。与 Worker 相同只说明本地导出接线一致，不能替代原版像素证据。

本批不提出性能提升结论。缓存按内容身份有界保留，并为零帧与向前采样分别持有状态；这是资源约束。记录的耗时仅为对应检查的墙钟时间，完整任务 token、进程族 CPU／峰值内存、GPU 内存和等价原版端到端基线未测量。
