2026-10-21。本轮确认：**上一轮的源着色器修正仍不足以保证原版效果一致，初始化和导入默认值还有明确差异。** 已取得可复现的反例，并完成修正内核后的指南图像复验；没有把这些差异标成已解决。

## 图像复验结果

使用相同指南参数、50,000 粒子、预热 50 步、每帧一步、固定 60 Hz、5 秒累积与 512×384 输出。仍使用本地随机序列、数学视口和调色，只将 Symmetry 切换到上一轮验证的源数值内核。

9 组均通过实际 App 导入、预览、保存重开和 PNG 导出。保存重开后模型标识保持不变；9 张 PNG 完整 RGBA 等于 Worker 输出及新 Generator 会话的冷重放。4 个 Map 对照的 PNG 文件字节完全不变。

| Symmetry 示例 | 与旧内核不同的像素 | 旧／新非主色像素 | 观察 |
|---|---:|---:|---|
| 盾形 | 173 | 3,419／3,419 | 仍是局部曲线，未验收完整盾形 |
| 披风 | 14 | 1,551／1,551 | 图像变化很小，未验收完整披风 |
| 风车 | 1,173 | 3,279／3,280 | 数值修正影响像素，仍待匹配视口与原版 |
| 肋星 | 2,516 | 2,311／1,948 | 更稀疏，仍有明显裁切；未验收完整肋星 |
| 双翼 | 8 | 4／4 | 仍近乎单点，延长累积或只换内核均未改变这一结论 |

非主色像素用于识别稀疏输出，不是视觉质量评分。肋星的累计无效迭代事件由 249,147 增至 14,286,277，与源内核不再重生非有限粒子的策略一致；事件次数不是不同粒子数。不能把恢复重生作为“修好图案”的办法，否则又会偏离原计算规则。

## 初始化差异已经具体定位

固定 MathArt 1.7.8 JAR 的 SHA-256 为 `a6e1da3acfc05c347d2529c1d590657e2dd798e16d38c55df3dc61312be24018`。独立审计复用了保留的类字节码，并核对包内类摘要；独立 Python oracle 没有导入生产模块，也没有运行原版 JVM 或 UI。

原版初始化的关键规则如下：

1. 构造 Mobject 时，按粒子数、构造时阶数、参数键和 Double 位表示计算一个 64 位种子。参数顺序来自源 JSON 的 Java HashMap，再复制到 LinkedHashMap；不能使用 JavaScript 对象顺序代替。
2. 每次初始化都重新创建 `Random(initialStateSeed)`，逐粒子先取 X 再取 Y。退化的有限坐标轴直接返回下界，不消耗随机数；方形纹理的补齐位置保持零，也不消耗随机数。
3. 边界先按 float32 排序，减法、乘法、加法分别舍入为 float32。一次双精度表达式再转 float32 并不等价。
4. 同一 Mobject 的 Replay 复用构造种子，重建同一点流。原地更新参数或阶数不会重算种子；清除密度也不等同于重建初态。实际 UI 在哪些编辑操作下重建 Mobject 尚未完成调用链确认。
5. 缺少参数表时使用源模板默认值；非空的部分参数表不普遍合并这些默认值。数值读取失败后还会尝试布尔值，无法读取的项才忽略。源代码不裁剪参数名两侧空格。

生产路径反例通过 `parseProjectFile → prepareIteratedFrame → iteratedInitialChunk` 实际运行取得：

| 输入 | 当前本地结果 | 静态源规则推导结果 |
|---|---|---|
| 缺少参数表的 Standard／Modified、空参数表 Standard | 默认 4,096 粒子、阶数 5 | 默认 262,144 粒子、构造阶数 3 |
| 只有 gamma 的部分参数表 | 仍使用本地默认阶数与公式默认值 | 参数表保持部分字段；构造阶数缺省为 3，不能套用本地完整默认公式 |
| 包内 Emperors Cloak | 粒子数 6,562,144、阶数 12 一致；所查 7 个初始点均不同 | 种子由源参数顺序和 Double 位计算，随后 Java Random 采样 |
| 含带空格键、布尔值及非整数修正幂次的边界输入 | 在参数名检查时拒绝 | 源配置有自己的保留、转换、舍入规则 |

5 个可导入反例中，共比较了 19 个有效索引处的初始点，均未匹配；另外记录了默认粒子数较小而无法比较的源索引。没有预热、渲染或分配完整 656 万粒子数组来冒充完整场景验证。

独立 fixture 包含 9 组已知顺序的运行时参数、6 组 JSON 输入，覆盖单／双轴退化、float32 边界、有符号零、65536 块边界和 padding。JSON oracle 是有限样例适配器，未复刻全部数字字符串语法、重复键和 HashMap 树桶；产品修复应复用已有格式与映射顺序解析组件，不能直接把该小型 oracle 当完整导入器。

## 下一步修复范围

需要让一个源 Symmetry 配置解析层统一提供：参数存在性与顺序、模板默认值、构造阶数和 GPU uniform 值、初始化盒、64 位种子及其生命周期。生成器、重播、保存重开和 UI 应消费同一份解析结果。只替换随机数函数，仍会保留错误的默认值、参数顺序或种子重建行为。

本轮补充了指南复验模式与初始化审计脚本，未修改生产生成器。原版整窗口验收仍为 **0/11**；原生窗口读取的辅助功能拒绝尚未解决，本轮没有操作主屏、移动窗口或重打包 1.0 应用。

## 复现与证据

```sh
node scripts/verify-guide-density-examples.mjs <新目录> 5 source-kernel
node scripts/audit-source-symmetry-initialization.mjs <另一个新目录>
```

默认省略 `source-kernel` 时保留原有 `legacy-v1` 验证模式。初始化脚本需本机 `.cache/source-symmetry-initialization-audit/` 的 manifest、oracle、fixture 及其引用证据，会验证摘要。`gaps-observed` 表示审计正常运行且发现不一致，不是验收通过；脚本执行故障另报 `audit-error`。

本轮指南任务墙钟 74.91 秒、采样 CPU 95.88 秒、采样进程族峰值 RSS 约 2.24 GiB。它包含浏览器启动、交互、截图、导出及重复生成，不是帧率或性能提升数据。250 ms 采样可能漏峰，共享页可能重复计入；GPU 内存与 token 成本未单独测量。源文件稳定性、App／Worker 无错误及浏览器／Vite 清理检查通过。未启动视频服务，因此其健康检查连接拒绝不计为 PNG 测试失败。本轮没有生产代码变更，未重复完整单元测试或构建。
