# 分形实时预览与当前画面导出验收

2.0 仍在 M3，原版完整窗口对照仍为 **0/11**。本轮把已验证的分形数值宿主接到真实编辑器、Worker 和 WebGL 预览，并补上暂停时保存当前分形状态的 PNG 路径。这里只验收本地公开操作；不把本地测试当作原版整图一致性。

## 使用时的行为

- 修改几何参数或公式，更新当前对象并保留动画进度；动画恢复后继续使用此前捕获的起点。
- 渲染方法、扰动精度、颜色算法先暂存；下一次几何热修改会携带当时的完整分形配置。
- 暂停时点击“应用场景”保留当前队列与时间；播放时点击则从头运行新的时间线。即使项目值没有改变，点击“应用场景”也会执行。
- 时间线编辑只修改待应用配置。界面会提示需要在播放时应用，才能替换正在运行的队列。
- PNG 默认保存“当前暂停场景”。它读取运行中的数值快照，不按编辑器配置从头重算；另有“从初始状态重放”选项，保留固定时间回放用途。

当前 PNG 导出会按指定尺寸独立渲染，再恢复主预览；两次渲染都不推进动画。PNG 放大是本地功能，不包含原版截图增强，也不代表已复刻原版 GL 截图生命周期。实时帧率取本地实际绘制调度的测量值，首次绘制使用所选目标帧率，不声称测得原版 PApplet 帧率。时间轴跳转仍属于本地固定重建。

## 实现边界与修复

Worker 会话持有数值宿主和已经应用的渲染配置。编辑事件携带独立版本号及当时的配置快照，后续暂存编辑不能混入待处理事件。渲染结果返回实际时间和已应用的场景外观，预览叠加层不会误用尚未生效的编辑值。播放控制有独立确认；截图绑定已完成主预览的身份，拒绝过期请求。

公开流程检查发现：当项目对象没有变化时，原先点击“应用场景”没有触发 React 生成依赖变化，Worker 因而收不到请求。现在应用操作递增独立生成事件编号，同值点击也会进入 Worker。候选配置先验证，更新开始后的失败使会话失效；不能继续使用半完成状态。

## 验证结果

- 全量测试：380 个文件、7,159 项通过，Vitest 用时 45.83 秒。包含实时宿主、配置暂存、传输身份、过期截图和失败恢复覆盖。
- TypeScript 与 Web 构建通过，Vite 用时 8.81 秒；仍有现存的大分块提示。
- 真实 App → Worker → WebGL2 → 导出服务：Newton、Nova 两组共 22 步通过，源码摘要与当前文件一致；浏览器、控制台及 Worker 错误均为空。
- 两个 160 × 120 PNG 下载文件通过 CRC、尺寸及全部 RGBA 字节校验，与 Worker 当前状态捕获结果完全相同。导出前后主预览的时间、队列位置、更新序号、像素与画布截图均保持一致。
- PNG 之前刻意将中心热改为 0.875；独立固定回放对应中心约为 0.63125 / 0.64375，确认流程没有悄悄转用固定回放。截图是本地实时状态的导出证据，不是原版像素对照。
- 已有 MP4 公开回归 8/8 通过，包含六个实际下载视频、空队列、零等待、密度 2、取消与重试；源码摘要保持一致。
- 人工检查最终 Newton / Nova 界面截图，确认时间轴已显示实时场景的操作说明。

第一轮带 PNG 的验收因脚本没有启动本地导出服务，打开对话框时健康检查报连接拒绝。保留失败记录后，改为运行真实导出服务，不放宽控制台断言。第二轮通过后修正了截图中发现的过期时间轴文案，最终第三轮再次完整通过。

本轮使用 Node 24.18.0、Chrome 155.0.8059.85。最终检查顺序执行，进程族测量如下：

| 检查 | 墙钟时间 | 观测 CPU 合计 | 抽样峰值 RSS 合计 |
| --- | --- | --- | --- |
| 全量测试 | 46.39 秒 | 350.55 秒 | 4.23 GiB |
