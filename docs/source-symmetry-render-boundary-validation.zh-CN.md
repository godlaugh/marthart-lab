# Symmetry 点绘制修复与原生计算对照

2026-10-25：修复了生产绘图的两处边界——**原生点径量化、齐次投影坐标保留**。给定相同原版粒子后，修复后的生产代码在八帧中，墨迹和核心 RGBA 均逐位一致。实际产品的 WebGL 数学计算仍有差异，因此 Symmetry 全流程及 M3 仍未完成。

本轮继续使用 [冷启动验证](source-symmetry-cold-runtime-validation.zh-CN.md) 的同一个完整 `Emperors_Cloak1` 输入：562,144 粒子、逻辑 405×486、物理 810×972、同一时钟与种子。没有删减粒子、调整参数或放宽比较标准。未再次执行原版 JAR；所有原版输入来自先前正常预览证据，EXPORT=false 的限制保留。

## 两处绘图修复的依据

先在独立诊断中，在每帧最后一次更新后上传该帧原版真实粒子状态，只隔离后续绘图；这不是正常产品计算的替代验收。保持其它生产输入不变，逐项试验如下：

| 诊断／生产边界 | 首帧不同像素 | 第八帧不同像素 |
| --- | ---: | ---: |
| 只对齐粒子，原绘图实现 | 161,646 | 297,851 |
| 再将点径 1.8 对齐到原生覆盖 2 | 1,017 | 1,738 |
| 再直接保留齐次 clip 坐标 | 0 | 0 |
| 正式源码修复后，只保留粒子输入隔离 | 0 | 0 |

最后两组不仅 RGBA 相同，八帧完整 Float32 墨迹也逐位一致。独立 CPU 审计重新读取了诊断的 24 份粒子／墨迹／RGBA 数组，共 197,925,632 字节；只进行明确的行方向、通道排列和活动粒子前缀转换，没有数值补偿。生产色板的 12,288 字节 RGB32F 也与原版纹理相同。

**点径。** 原生 CGL 探针的 30 个样本，在三个不同像素中心观察到整数覆盖区间，包括 1.49→1、1.5→2、2.5→3。原来的 WebGL 绘制保留分数点径，导致覆盖质量不足。本案例原版冷点径为 1.7999999523162842，实际点覆盖为 2。现在 `sourceDensityPointDiameter` 同时供绘制与统计消费，按缩放后的半径量化；原始 Float32 radius 保留给作者状态与 quad 路径。预算仍使用 probe 前的保守上界，覆盖两种路径，没有因尚未选定的 path 缩减预算。

**投影。** 原实现先将 clip 除以 w 得到 NDC，再换成像素、再还原 NDC，产生足以改变边缘覆盖的舍入。现在共同投影函数同时返回 clip 与 projected；源密度 points 绘制直接使用 clip，统计继续消费同一投影事实。没有在下游重新计算第二份相机矩阵。legacy、quad、Samila 的原投影分支保留。

该共同边界也服务源 Map 点绘制。Map 的直接齐次投影有独立原 shader 来源依据，本轮另跑生产 Map GPU 回归；未将 Symmetry 八帧整图结果泛称为 Map 全部画面已验收。旧原生点探针未覆盖所有大小或驱动上限，尺寸 3 的跨驱动 PointCoord 仍有微小差异；不能从本次直径 2 的完整图推出任意点径逐位相同。
