# 隐式曲面原生 PNG 验收（2026-10-24）

原版 CPU 隐式曲面的静态 PNG 导出已接入共享原生绘图后端。此前同一作品填充与线框组合产生的 28 个不同像素，在原生模式下变为 0。真实界面完成导入、生成、导出和下载；送入 PNG 增强步骤前的完整艺术画面（包含公式）与原版逐像素一致。

本轮验证使用 `VITE_SOURCE_RENDERER=native` 和已配置的本地 CGL 后端。默认 WebGL 导出仍保留原有像素；没有把这张静态图的结论扩展为整个隐式曲面家族、预览或视频已经通过。

## 修复边界

旧静态 PNG 流程直接从 ArtRenderer 的 WebGL framebuffer 读取，即使构建选择了原生后端，这个分支也没有消费该选择。

现在 `sourceImplicitPng.ts` 消费已经生成的几何、相机和公式帧，通过共享 `readSourceDrawingPixels` 选择绘图后端，再交给既有公式合成、图像增强和 PNG 编码流程。没有重新运行场景、伪造“当前帧截图”身份或增加逐像素补丁。已移除 renderer 中被替代的专用增强分支，后处理仍由统一编码流程负责。

原生服务失败或请求取消时不会返回 WebGL 替代结果。共享请求槽在旧请求结束后释放，允许用户重试；图像分配前检查尺寸与已有几何容量。JPEG、视频和默认预览未在本轮切换后端。

输入为包内 `Implicit/implicit_sphere.json`，方程 `x²+y²−z²−1=0`，60³ 网格、透明填充和 retained 线条，输出 500×600。名称虽然叫 sphere，方程和画面均按原始输入保留。

| --- | ---: | ---: |
| 完整艺术画面与原版不同像素 | 28 | 0 |
| 原生模式最大 RGBA 通道差 | — | 0 |
| 实际界面 PNG 下载 | 通过 | 通过 |
| 导出后服务遗留进程 | 0 | 0 |

WebGL 下载文件与先前 `implicit-formula-frame-20261022/public-final/export.png` 逐字节相同，SHA-256 为 `5cfc825b7d02dae1b5255f7acdbfcf287ad6ffa8704b369959dce336b3625f84`。原生下载 PNG 的 SHA-256 为 `c6f2e99d140681ce9939a563f722bfbc9615a3c557442b88eda6d2d69da0c1bf`。

零差异比较发生在双方的**完整艺术画面、品牌绘制前、PNG 增强前**。产品侧读取真实增强 Worker 即将接收的像素，原版侧在 `Scene.drawWatermark` 初始关闭深度测试后被动读取 framebuffer。正常品牌绘制和最终 PNG 均保留，未裁剪、遮罩或放宽容差。原版最终 PNG 带品牌，不能将它与产品下载文件宣称为逐字节相同。

原版固定为 MathArt 1.7.8，JAR SHA-256：`a6e1da3acfc05c347d2529c1d590657e2dd798e16d38c55df3dc61312be24018`。正常许可流程执行成功，一次离屏采集耗时 8.935 秒，退出码 0，进程组已回收；10 个检查边界均无窗口。settings/license 状态和摘要未变，正常策略缓存刷新前保留了备份。

早期诊断曾把 250×300 逻辑尺寸、density 2 与物理尺寸约定混用，得到错误的粗线；该结果保存在 `compared-v2/`，未作为产品缺陷或修复证据。最终使用实际公开导出的 500×600 绘图约定、主画布高度 486、保留的参考 density 2，且通过真实界面复核。没有为获得匹配而修改用户输入或显示密度。

本轮证明共享原生后端能够消除这个组合图差异；没有进一步宣称已确定 WebGL 与原生之间每个深度插值或量化差异的根因。

## 测试、成本与复现

4 个测试文件、23 项通过，涵盖公式与增强顺序、原生像素传递、服务错误不回退、取消后重试、缺失公式和容量拒绝。2.0 构建通过，最后的类型检查通过；构建仍有既有大 chunk 提示。
