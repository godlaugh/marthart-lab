# Möbius 深度残差取证

2026-10-23，生产基线 `e5a37b7`。**剩余 1 个像素不是几何生成或点纹理问题：使用相同的原生填充和线段 clip 顶点，浏览器仍产生不同的深度遮挡结果。** 本轮没有改变生产渲染算法，没有调整深度偏移或验收容差，也没有将曲面标为通过。

## 完整图像与顶点证据

复用原版 Möbius 的实际 GL 绘制提交，包括缓冲、索引、uniform、着色器和状态；建立无窗口原生 OpenGL 离屏宿主，分别保存两次绘制后的完整 500×600 RGBA 和深度缓冲。该宿主只复放输入，不启动原版 Scene 或初始化其许可流程，也不修改原版应用文件。

原生独立宿主的填充图与加入线段后的图，均与之前正常原版运行的对应阶段 **逐像素相同**。因此，以下诊断以已经复现原图的宿主为依据。

通过独立 transform feedback 程序捕获顶点着色器输出，结果如下：

| 绘制阶段 | 顶点数 | 原生／WebGL 不同分量数：x / y / z / w |
| --- | ---: | --- |
| 填充 | 3,240 | 0 / 0 / 0 / 0 |
| 线段 | 6,824 | 24 / 2,626 / 1,668 / 0 |

线段 shader 的缩放和投影在两端存在不同的 Float32 合并／舍入行为。当前输入的全部原生 z 分量符合逐步乘法和加法舍入；浏览器结果符合先组合缩放与投影系数的计算。这个观察只适用于此次捕获的输入和后端，不能推广成通用浮点规则。

但它并没有解释残差：把**原生实际捕获的全部填充和线段 clip 顶点**直接送给 WebGL，仅保留透传 shader，组合图仍是同一个像素不同。与先前隐式曲面诊断相比，这次填充 clip 也有真实原生捕获，不再依赖 CPU 推导。

## 目标像素的深度

目标坐标为左上原点 `(71,257)`，即 GL 左下原点 `(71,342)`。原版显示白色线段 `[255,255,255,255]`，本地保留填充颜色 `[139,154,33,255]`。

使用相同原生 clip 顶点，绘制后的深度为：

| 阶段 | 原生 OpenGL | WebGL / ANGLE Metal |
| --- | ---: | ---: |
| 填充后 | 0.986320972442627 | 0.9863208532333374 |
| 加入线段后 | 0.9863209128379822 | 0.9863208532333374 |

原生线段比原生填充更靠前，更新了颜色和深度；浏览器此处的填充更靠前，后续线段没有更新最终结果。目标处可覆盖的线条三角形中，编号 2685 的深度更浅；其原生三角形顶点索引为 `[5370,5369,5371]`。这个编号用于回溯原始提交，不作为产品中的特殊分支。

整张图填充后的深度有 15,160 个不同样本，加入线段后为 15,219 个，最大差均为 `1.7881393432617188e-7`。颜色图只差一个像素，不代表深度缓冲只有一个差异。深度比较使用读取值；没有把样本差异直接当作已证明的硬件内部算法。

原生端另以无符号整数读取目标深度，填充后为 `0xfc7f87fc`，线段后为 `0xfc7f86fc`，也确认深度确实发生更新，排除了只看打印精度造成的假象。

## 排除的候选

| 诊断 | 实际结果 | 是否合入 |
| --- | --- | --- |
| `invariant gl_Position` | 线段顶点分量差异和 1 个颜色残差均不变 | 否 |
| CPU 显式完成线段缩放 | z/w 全等，但组合图仍差 1 像素 | 否 |
| 直接复放全部原生 clip 顶点 | 仍差同一个像素 | 否 |
| WebGL 深度附件改为 32F | 与 24 位请求得到相同深度样本及颜色残差 | 否 |
| 原生离屏附件改为 32F | 仍与原版颜色相同，目标深度不变 | 否 |
| 片段 shader 显式计算深度 | 产生 3 个不同像素，通道绝对差总和 1,126 | 否 |
| Chromium `--use-angle=gl` | 实际 renderer 为 Vulkan SwiftShader，随后上下文丢失；未获得 Apple OpenGL | 否 |

OpenGL 后端试验首次错误被清理时不存在的 `WEBGL_lose_context` 扩展访问覆盖；诊断清理改成可选调用后，记录到真实 renderer 与上下文丢失。两次失败均保留，不能据此宣称本机所有 Chromium 版本都不支持 OpenGL，更不能把 SwiftShader 当作所请求后端。

## 正式验证修正

`scripts/verify-surface-native-reference.mjs` 此前没有消费桌面应用的图形配置。现在直接调用 `desktop/graphics.mjs` 的 `configureDesktopGraphics`，由同一 owner 生成启动开关，并将 owner 文件纳入前后摘要；不在脚本复制缓存策略。

本机生成 `--enable-angle-features=disableProgramCaching`。Chrome `155.0.8059.85` 下重跑真实导入器、Worker、暂停截图与公式合成，结果仍是 Cornucopia / Sphere 零差异、Möbius 1 像素差异。耗时 28.14 秒，严格状态 `differences`、退出码 1；源码和参考前后摘要一致，字形服务剩余进程为 0。这是与桌面配置一致的 Chrome 验证，不冒充打包 Electron 的运行验收。

透传原生 clip 顶点和深度读回也在该桌面配置下重跑，深度及颜色差异不变。没有把不同缓存策略的结果混为一次运行。

## 边界、证据和下一步

本轮三个原生进程分别耗时 4.16、5.07、4.11 秒，均正常退出、已回收、无残留进程组。全部工作在后台完成。墙钟时间来自不同诊断任务，不作为性能前后对照；CPU、家族峰值 RSS、显存和 agent token 未测。生产代码没有改动，未重复与本轮无关的构建或单元测试。

证据位于 `.cache/surface-line-isolation-20261023/`：

- `summary.json`：输入、探针、运行产物的 SHA-256，阶段统计和进程退出记录。
- `result/`：原生 24 位附件复放、两阶段颜色、深度与 clip 顶点。
- `clip-result/`、`desktop-depth-result/`：全部原生 clip 透传、桌面策略下的深度读回。
- `native32/`、`native-depth-int/`、`depth32-result/`、`explicit-depth-result/`：不同附件／读取／手动深度诊断。
- `angle-gl.log`：请求 OpenGL 后实际退回 SwiftShader 的失败。
- `desktop-policy-verification/report.json`：正式完整艺术画面重验。

目前尚未证明两个后端内部具体采用哪种插值或舍入算法，不能直接写一个像素补丁或统一深度偏移。下一步应验证独立原生离屏渲染能否在不依赖原版应用运行代码的条件下复现这些实际输入，再决定是否值得接入产品渲染边界。其余 GPU 曲面、连续动画、其它场景和发行验收仍继续保留；Goal 未完成。
