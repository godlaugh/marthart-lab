# 分形原生服务：保留资源与完整数学画面验证

后续的实际应用接入与 `2.0.0-preview.6` 验证见[生产接入验收](source-fractal-native-production-validation.zh-CN.md)。下文保留服务阶段的历史范围。

2026-10-26。**分形绘制已接通真实浏览器客户端、HTTP 服务与保留 CGL 资源；三个固定 Mandelbrot 样例的完整数学 RGBA 与既有原生参考逐字节一致。** 这是服务边界验收。正常应用的实时预览、当前 PNG、冷导出和录制尚未切换到该服务，桌面包仍为 `2.0.0-preview.5`，M3 继续进行。

## 实现与修复

生产代码由一个共同的参数生产者生成数值、调色与延迟显示绑定；现有 WebGL 和新增原生传输读取同一份解释结果。动态参数保留 32 项，调色板保留实际长度，空调色板不发上传命令。原生端按 OpenGL 的数组前缀语义更新，保留未覆盖的旧尾部；没有通过填零改变原来的含义。原生解析边界另验证具名数组类型、容量及调色板大小。

原生 v11 服务拥有程序、顶点数据、参考轨道和渐变纹理、四个绘制目标，最多同时保留两个分形资源。每次最多请求 65,536 个点，按行合并有限绘制范围后恢复调用方的原始顺序，保留重复点。单次绘制最多承载 2,000,000 次迭代工作。52 字节样本保留数值记录、终止状态、颜色与外部诊断，包括合法 NaN 的原始位。

每次请求按资源标识和检查点确认；仅在绘制、读取和解绑成功后推进检查点。ACK 返回实际绘制次数、目标分配次数及两类纹理上传次数，消费者不再需要猜测。尺寸变化先计入仍然持有的旧目标和待分配目标，遵循共享 256 MiB 预算；释放失败时保留所有权。运行时故障由网关等待确切子进程退出后清空会话，之后可重建。

显示状态也新增异步入口：等待实际绘制确认后才提交进度和延迟渐变参数；拒绝或失败保持上次成功状态，同步入口明确拒绝 Promise。提取公共绑定后，WebGL 预检另计入新增 typed-array 缓冲：有颜色最多 708 字节、无颜色 284 字节，直接 transform feedback 不增加该项。这些数字不是 JS 堆或驱动内存总量。

## 复验、成本与记录

在 `studio/` 使用已安装的锁定工具链、Chrome 和系统编译器：

```sh
PATH="$PWD/../.cache/local-toolchain/node_modules/.bin:$PATH" \
node scripts/verify-source-fractal-native.mjs
```

该命令检查实际生产导入/参数/参考纹理、异步显示进度、完整图摘要、重复点、尺寸恢复、释放和清理。最终运行总耗时 **18.01 秒**；三组验证分别约 5.50、5.02、5.05 秒，包含多个请求和完整读取，不是单帧速度。613 个源码和输入文件摘要前后稳定；浏览器、Vite、HTTP 服务及其原生子进程已关闭。

250 毫秒采样的 Node/Chrome/原生进程族观测到约 **28.62 CPU 秒**、**2,242.75 MiB** 的聚合 RSS 峰值。测量包括编译、启动、三组验证和采样开销，排除最后清理；可能漏掉瞬间进程和峰值，RSS 也可能重复计入共享页。每组创建新资源，后续请求复用该资源；请求耗时逐项记录并标注首次/复用。系统和驱动缓存未清空，GPU/VRAM及逐请求 CPU/RSS 未测量，不能据此宣称前后加速或动画 FPS。

Goal 计数从本工作阶段开始的 98,084,401 到报告快照 98,815,303，增加 730,902 tokens，包含上下文、实现、审查和失败重试；不是渲染成本，快照后的收尾另计。

早期实际测试发现通用原生校验误拒绝合法短数组；改为分形专用前缀规则并补原始畸形请求验证。协议切换期间出现过生产者与 decoder 版本不一致的中间失败。WebGL 测试替身随后补齐 `uniform1iv` 和数组首元素别名语义，原有数值断言保留。所有失败记录与最终通过日志分开保存，没有将失败记录改写为通过。
