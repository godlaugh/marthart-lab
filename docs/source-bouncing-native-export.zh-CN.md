# 弹跳原生导出验收（2026-10-24）

**实际应用的 PNG、MP4 导出及返回预览已通过验证，包括原版 500 万粒子配置。** 同时修复了原生清理失败不显示错误、清理完成前导出按钮就恢复可用的问题。

后续补验：更复杂的公式预设暴露了 Bouncing 误用通用 4:2:0 编码的问题，已改用原版 4:4:4 配置；两个完整百万粒子预设各通过 85 项实际导出检查，见[公式预设验收](source-bouncing-formula-parity.zh-CN.md)。下文的误差数值与检查数量属于此前运行，未改写成新配置的结果。

## 验证范围

使用无窗口 Chrome 打开真实 App，由实际导出对话框生成文件，经过生产 Generator、种子 Worker、HTTP、原生 CGL 和 FFmpeg，最后接收浏览器下载。没有操作主屏幕。

| 场景 | 实际结果 |
| --- | --- |
| 512 粒子合成场景 | 72 项流程检查通过；包含暂停后调整相机，区分“当前视角”与“原始视角”的导出行为 |
| 原版 bouncing2.json，500 万粒子 | 75 项流程检查通过；从固定 JAR 公开导入原始 JSON，确认原文保留、粒子数不减少；仅通过界面将录制时长改为 0.3 秒以验证短录制 |
| PNG | 请求 257×193，在实际 Retina 密度下输出 258×194；解码后的每个 RGBA 字节与原生生成结果经既有暂停图像增强后的结果一致；检查点不推进，相机和投影参考高度保留 |
| MP4 两种起点 | 分别从当前检查点、种子状态录制；每次 256×192、12 fps、3 个编码帧，另有一个不编码的预热帧；Float32 时间、帧序及相机正确 |
| 视频帧上传 | 每个上传 PNG 的 RGBA 与实际原生 Generator 返回值完全相同，无重帧上传、漏帧或预热帧混入 |
| 保存与下载 | 每轮 3 个 PNG、2 个 MP4，共 5 个完成文件；浏览器下载字节与服务端保留文件逐个哈希一致 |
| 返回预览 | 关闭导出后暂停检查点保持不变；重新定位同一检查点能重建相同像素，实际播放可继续推进 |
| 清理与退出 | 每次正常导出释放原生资源；浏览器正常退出后，服务仍运行时原生子进程已归零；无未处理页面错误 |

两份 MP4 均由 FFmpeg 完整解码。H.264 是有损编码，不能要求逐字节相同：合成场景各帧的 RGB 平均绝对误差为 0.476–0.504，500 万粒子为 0.237–0.281，数值范围为 0–255；均低于本流程的 6/255 验收阈值。单通道最大误差分别为 120、93，说明平均值不能代表每个边缘像素。**严格像素一致的结论只适用于 PNG 和编码前上传帧。**

## 清理问题与修复

原先各成功、失败分支会提前调用 `setWorking(false)`，而原生释放在后面的异步 `finally` 中继续执行；此处的拒绝也不经过前面的错误处理。因此按钮可提前启用，清理失败可能变成未处理的页面错误。

现在只有在全部清理尝试结束后才恢复按钮。生成器销毁、原生释放和画布释放分别尝试，失败原因追加到已有错误中。原生协调器继续保留释放失败的资源身份，下一次获取先重试清理。

真实流程分别注入了两种传输条件：

- 延迟释放响应：下载已经收到，但导出和关闭操作仍不可用；放行后恢复。
- 拒绝原生释放：保存文件仍可用，界面显示“导出资源清理未完成”及具体原因，协调器保留待清理资源；解除拒绝后再次导出成功，结果相同且资源释放。

两种粒子规模都执行了这些检查。故障只注入传输层，成功的模拟、绘图、编码和文件保存均使用真实实现。

## 回归与限制

14 个相关测试文件、277 项测试通过。`npm run build:v2` 通过，Vite 构建阶段 9.93 秒，仍有已有的大 chunk 提示。

本轮验证的是**完整导出流程与实际原生生成帧之间的一致性**，不能将本轮结果写成原版全参数效果一致。此前 200 万粒子 62 帧的原版画面对照是[另一组证据](source-bouncing-native-product.zh-CN.md)；后续取得的[500 万粒子独立原版对照](source-bouncing-five-million-parity.zh-CN.md)也已通过 62 帧与 11 份完整状态检查。长时运动和原版 MP4 仍未完成对照。

验证脚本观察真实 Generator 返回值，并复用既有图像增强函数计算 PNG 预期值；增强算法的独立正确性不由这一流程重新证明。录制时长仅 0.3 秒，不能替代长视频、取消和所有故障组合验收。此次未测进程族 CPU、峰值内存、严格冷暖性能或 token 成本，不作性能结论。

原生模式仍由 `VITE_SOURCE_RENDERER=native` 选择。默认后端、已安装的 1.0 应用未更新；其它场景、独立原版效果对照和最终 Apple Silicon 打包发行仍需继续。
