# 域着色：统一逐帧时钟验证

新导入的域着色作品和 8 个内置域着色示例，现在共用一个场景运行实例推进队列、参数、渐变和旋转。已修复此前记录的连续积分差异。旧存档若没有新的时间线标记，仍保留既有行为。

## 已修复的行为

活动队列每个显示帧依次执行受队列剩余时间约束的更新和完整帧更新；队列结束后的帧只执行后者，暂停不推进。每次对象更新按原版顺序处理参数、渐变、旋转。参数注册表保留原版名称顺序和 Start/Stop 生命周期；旋转使用分阶段 Float32 运算。

原版 4 fps、1 秒 LINEAR 变速到 1 rad/s 的六帧角度为 `0.125、0.375、0.75、1.25、1.5、1.75`，新运行实例逐帧匹配。显示帧 0 表示第一次更新后的画面：上述角度对应界面时间 `0、0.25、0.5、0.75、1、1.25` 秒，原版累计更新时长则为 `0.25、0.5、0.75、1、1.25、1.5` 秒。不能把两种时间标签混为同一个采样时刻。

布局、跳转重建和渲染取自同一个状态来源。小数帧率先按原版窄化为 Float32，再求帧间隔；作者设置的帧率仍用于显示帧编号。时间线只提供等待和动画片段，参数动作使用源注册表。失败或取消会使整个运行实例失效，后续请求重新建立状态。

## 原版数值证据

- 5 组、42 帧旋转和队列轨迹：固定及可变步长、暂停、结束后更新、空队列。
- 4 组、64 帧组合轨迹：参数 Start/Stop、渐变、旋转、指定宿主帧率、零步长和暂停。
- 两批原版探针均执行两次并得到一致输出。回归测试逐帧比较角度、转速、时间、曲线和色板偏移的 Float32 位模式；参数与渐变中的双精度结果按明确容差比较，允许 Java Math 与 JavaScript 超越函数的末位差异。

原版证据实际执行了安装包中的场景构造、setupTimeline、SceneManager、DomainColoringScene.update 和 DomainColoringMobject.update，以及活动参数、渐变动画器。JNI 探针初始化了必要的 PApplet、配置和对象字段；没有执行配置与对象的完整构造，也没有绘制、OpenGL 或原版窗口。因此，这些结果证明所列数值链，不能当作整图验收。

参考 JAR SHA-256：`a6e1da3acfc05c347d2529c1d590657e2dd798e16d38c55df3dc61312be24018`。可入库的数值轨迹与来源记录位于 `tests/fixtures/source-domain-clock/`；原始探针和两次执行证据保留在 `.cache/domain-clock-source/`。

## 验证与运行成本

最终全量测试 **391 个文件、7,442 项通过**；`npm run build` 通过类型检查与 Vite 构建，保留既有大体积 bundle 提示。

真实 headless Chrome 公开流程通过 7 步：原版文件导入、时间跳转、播放/暂停、参数动作编辑、队列重排、保存重载、PNG 导出。暂停验证等待已提交的渲染任务完成后取基线。保存重载后相同时间与渲染上下文的状态、角度、完整 RGBA 一致；存档没有持久化运行时快照。160×120 PNG 取显示帧 45，下载图像与冷启动 Generator + ArtRenderer 的完整 RGBA 一致。这是本地管线一致性，不能替代原版像素对照。

最终公开验证前后 471 个源码摘要一致，无浏览器、控制台或 Worker 错误；浏览器、Vite、导出服务全部关闭。测量耗时 7.32 秒，观测进程家族 CPU 18.38 秒，采样合计峰值 RSS 约 1.96 GiB；结束时没有遗留的受测进程。RSS 按约 50 ms 间隔采样且可能重复计共享页，CPU 可能漏掉极短命子进程；未测 VRAM 和完整 token 成本。

可复查 `scripts/verify-source-domain-clock.mjs`；最终公开证据位于 `.cache/domain-clock-public-final/`，成本记录为 `.cache/domain-clock-public-measure.json`，全量日志为 `.cache/domain-clock-full-tests-final.log` 与 `.cache/domain-clock-build-final.log`。诊断 1–3 保留了定位器和异步观察时序问题；诊断 4 及加强保存重载断言后的最终运行均通过。

审查修复了渐变子动作漏计工作量的问题，并去掉回放时被丢弃的中间快照。一次本地测量使用 1,000 个作者参数、10,001 个显示更新：冷重建从约 75.23 ms 降至 14.74 ms，进程 CPU 从约 85.59 ms 降至 20.75 ms；重复命中同一帧分别约 0.264 ms、0.285 ms。前后输出 SHA-256 完全一致。进程累计峰值 RSS 分别约 477、471 MiB，包含 Vite 模块加载阶段，不能据此认定回放节省了相同内存。

这是一对单次本地观察，不是稳定性能基准；CPU/RSS 为单进程统计，未测完整进程家族、VRAM 或 token 成本。脚本和原始数据位于 `.cache/domain-replay-benchmark.ts`、`domain-replay-benchmark-before.jsonl`、`domain-replay-benchmark-after.jsonl`。
