# 分形高分屏当前截图验收

2.0 仍在 M3，原版完整窗口对照仍为 **0/11**。本次修正分形当前帧 PNG 对父画布像素密度的处理，沿用上一轮已经修正的文字合成、增强和放大顺序。

## 用户可见变化

在 2× 像素密度下，请求 161 × 121 像素的当前截图，原版会先取逻辑尺寸 81 × 61，再得到实际图像 162 × 122。此前本地把请求尺寸同时用作逻辑和物理尺寸，现在会分别保存这三个尺寸，界面显示实际输出。

| PNG 倍率 | 请求基础尺寸 | 实际文件尺寸 |
| --- | --- | --- |
| 1× | 161 × 121 | 162 × 122 |
| 3× | 161 × 121 | 486 × 366 |
| 5× | 161 × 121 | 810 × 610 |

这不只是改图片宽高：原版分形着色器读取逻辑尺寸，Nova 的自动收敛阈值等计算也依赖它。现在使用已完成主画布保存的密度，不能从经过降采样的预览宽高推算，也不能被截图请求中的另一个密度覆盖。密度未知或不是有效整数时，仅拒绝截图，保留已完成的场景。

共享尺寸解析统一执行 Java Float32 除法与取整。分形保留原有 128 MiB 单图预算；点场景和既有录制路径继续使用自己的 64 MiB 尺寸预算。放大和 PNG 合成的后续预算仍分别校验，不因共享解析而放宽或收窄其他路径。

## 原版证据

固定 MathArt 1.7.8 的 `savePausedFrameInternal → ensureRenderBuffer(1) → PGraphics3D` 路径继承父画布密度，没有分形专用的 density=1 分支。Scene 向 Fractal 传入逻辑宽高，原版 `renderFractal` 的 `u_resolution` 与 `computeRenderState` 使用这两个值。Processing 的 GL 适配层再将逻辑尺寸乘以有效密度；原片段采样使用插值纹理坐标，而不是把物理 gl_FragCoord 当作逻辑坐标。

详细类摘要、PC 和 shader 哈希保存在 `.cache/fractal-png-source/density-findings.md`。这是已核对原包的静态证据。本轮没有运行原版窗口、GL 场景或截图回调，尚不能证明当前机器原版 surface 的实际像素密度、驱动行为或最终图像一致。

## 验证结果

全量 **387 个文件、7,393 项测试通过**。TypeScript 与 Web 构建通过，保留现存的大分块提示。真实 App / Worker / 导出服务的两组、20 个公开步骤全部通过：

- 密度 1 保留 160 × 120 输出；密度 2 的奇数请求得到表中三个实际文件尺寸，界面提示也逐一匹配。
- 真实 GPU capture 的逻辑尺寸为 81 × 61，基础图像为 162 × 122。相同数值快照在独立 GPU 上下文、正确逻辑尺寸下的原始 RGBA 与 capture 完全一致；换成旧的错误逻辑尺寸 161 × 121 后，实际像素摘要不同。此检查复用本地渲染器，只证明尺寸传递和采样回归，不是独立原版 shader 数学或原版窗口证据。
- PNG 全部 RGBA 与独立的基础尺寸公式位置计算、Python 增强和软件 bicubic 转录结果一致。公式 SVG 字形共用 MathJax，不能据此声称原版字体像素相同。
- 两类取消后重试均通过，数值状态、公式绑定与生成 Worker 保持不变；隐藏公式的当前 PNG 仍增强，独立回放无标注 PNG 仍保留原始 RGBA。
- JPG 与三个真实 MP4 回归通过。MP4 为 3、3、1 帧，160 × 120、8 FPS，最大逐帧平均 RGB 误差 2.8459 / 255，低于既定阈值 8。
- 页面、控制台和 Worker 错误为零；公式 URL 创建 / 释放平衡，浏览器、Vite、导出服务清理完成。471 个源码文件摘要前后稳定并与最终文件一致。已查看实际 3× PNG。

定向测试还覆盖密度 3 / 4 的向上或向下取整、无效密度和尺寸拒绝后继续使用同一预览、伪造尺寸响应，以及分形与点场景预算保持独立。这些是实现边界验证，不是实际多显示器运行证据。

| 检查 | 墙钟时间 | 观测 CPU 合计 | 抽样峰值 RSS 合计 |
| --- | --- | --- | --- |
| 全量测试 | 47.28 秒 | 356.81 秒 | 3.99 GiB |
| Web 构建 | 21.32 秒 | 36.56 秒 | 1.95 GiB |

三项检查依次执行；没有为了测量重复已经通过的公开流程。进程身份按 PID 与创建时间核对，约 50 毫秒抽样；短命进程可能漏计，共享页可能重复计入 RSS，完成时均无仍存活的已观测子进程。没有受控冷 / 暖或等价旧实现基线，不声称性能提升；本次变更的完整 token 成本及 GPU/VRAM 未测。

完整证据为 `.cache/fractal-capture-density-public/report.json` 与 `final-details.md`，测试、构建和公开测量为 `.cache/fractal-capture-density-{tests,build,public}-measure.json`。
