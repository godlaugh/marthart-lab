# 源粒子绘制准入与 Business Cycle 计算隔离验证

2026-10-26。本轮修复了 Map / Symmetry 把本地数学诊断当成原版绘制准入的问题，并验证了 Business Cycle 计算与统计隔离的原型。**Business 原型尚未接入应用；M3 和全部 11 个场景族的验收仍在进行。**

## 已修复的产品问题

原版绘制使用经过缩放、偏移和相机变换的位置，颜色另行处理步长。此前本应用直接使用“位置与步长都有限”的诊断标记，并套用本地的原始坐标 `1e12` 阈值，导致本可绘制的源粒子消失。

现在，源 Map / Symmetry 的几何判断与数学诊断分别处理。步长为正负无穷大时，原版 CLAMP 颜色仍可输出有限颜色；原始坐标很大但经缩放落入画布时，也可以正常绘制。其它本地绘制保留原准入规则。逐步无效计数继续保留，已记为数学无效的位置不会再次重复计入变换错误。

同一 `densitySplat` 事实由共享绘制计划提供给绘制和统计程序，原生的类型化 uniform 接口同步更新。没有取消接口检查或给某个预设添加特殊数值。

首次生命周期运行暴露了新增统计 uniform 尚未加入原生类型接口，以及测试试图修改冻结对象。已分别在接口所有者和测试构造处修正，失败日志保留。旧 shader 历史记录不改；当前演化后的绘制／统计 golden 统一放在 `source-drawing-current.json`。

## Business Cycle 原型：准确性已证明到哪一层

先排除了用 `isnan/isinf`、有限数值范围判断替换位分类的方法：它们仍有 691,131 个状态字与原版不同。问题不能靠简单替换分类表达式解决。

新的离屏原型对每次更新固定同一输入，用不含循环内统计的数学程序分别计算第 1 至 N 步结果；独立程序在各步输出后分类和累计，最终 N 步才成为下一次更新的输入。它没有向数学程序注入期待结果。

- Business Cycle 的全部 18 个逐步观察结果，计数／有效性均与 CPU 对完整状态的独立分类一致；每次最终输出与独立原版片元程序一致，最终第 18 步与实际原版保存的状态逐位一致。
- 构造的 8 粒子案例覆盖 NaN、正负无穷、位置恢复而步长仍无效、最后完全恢复；逐步计数没有丢失，有效标记可以恢复。
- **36 项必需检查通过**，另保留 1 项旧生产结果不同于原版的观察；不能把这项差异描述为通过。
- 四个原型进程均已退出，GL / CGL 清理成功，无进程组残留。

这些证据证明原型的有限案例和观察契约，不证明已经完成生产接入、原生协议故障处理或 Business Cycle 整图验收。下一步是建立明确的纯数学／诊断双程序资源所有者，保留零步、复位、取消、检查点和清理语义。详见[原型中文报告及接口计划](../.cache/source-map-native-prefix-20261026/README.zh-CN.md)。

## 成本与剩余限制

原型单次测量中，完成 GPU 计算的区间从旧 TF 的 **8.79 ms** 增至 **146.32 ms**。原型另有 **106.70 ms** 的完整逐步读回及证据写入；整个独立进程耗时 308.8 ms、CPU 99.8 ms，自身峰值 RSS 156.8 MB。大量证据数据的持留抬高了 RSS，不能当作生产后端必需内存。缓存冷暖未受控，只有单次样本，不作稳定帧率结论。

产品回归完整流程分别耗时 7.16 / 6.66 / 8.14 秒，子进程累计 CPU 21.00 / 18.04 / 21.90 秒，进程组采样 RSS 峰值 1,027,344 / 586,288 / 635,472 KiB。每 0.5 秒采样可能漏过短峰值，未测 GPU 内存；这些流程包含截图、导航和录制验证，不是交互性能测量。

当前只有这一台 Mac，跨设备仍未验证。已安装的 1.0 应用未替换；原版导出／录制没有新增执行。全部其它场景与完整 UI 验收继续保留。
