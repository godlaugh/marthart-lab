# 吸引子原版公式验收

2026-10-27，Apple Silicon 本地预览包已更新至 **2.0.0-preview.12**。新导入的原版吸引子配置采用原版自动公式、字形和居中布局，已有保存项目保留其原布局。本轮完成了有限输入的原版数学与公式完整图层对照、实际界面操作和隐藏桌面包重启验证。整个吸引子场景、M3 和 2.0 仍未验收完成。

## 产品行为

- 新导入的源 CPU/GPU 吸引子共用公式规则：附加公式按原数组顺序绘制，主公式最后绘制。原版附加公式不读取 `enabled`，主公式不读取作者写在源 JSON 中的 `latex`；这些原值继续保留在来源记录中。
- 主公式使用源表达式的符号和点导数格式，标题只转义下划线。参数保持符号，不替换成当前数值。当前 JSON 内容导入入口使用 JSON 名称；不声称等同于原版文件构造器以文件名作为标题的入口。
- 坐标、缩放采用原 Float32 语义；实际主画布逻辑高度由每次生成结果提供，DPR 不会重复乘入布局。空公式仍保留正确的布局身份，但不请求字形。
- 已保存的通用布局继续使用原坐标、MathJax 文字和主公式优先顺序。导入后在本地编辑器明确填写的主公式仍可覆盖自动公式。
- 一个吸引子会话拥有解析后的公式内容。时间和画布尺寸变化只更新呈现信息；标题、公式或作者样式变化才更新文字内容。公式修改不触发粒子重新预热。
- CPU 几何输出和 GPU 栅格输出都必须携带与实际相机视口匹配的公式信息；缺失、畸形或高度不匹配的 Worker 回复会被拒绝。

源透明字色及尚未确认的 Java 字符串转换仍明确拒绝，未以丢失透明度或静默换渲染器代替支持。

## 原版运行与像素结果

原版为 MathArt 1.7.8，JAR SHA-256：`a6e1da3acfc05c347d2529c1d590657e2dd798e16d38c55df3dc61312be24018`。实际正常策略确认 VIEW、RUN、EDIT、EXPORT 均允许。原版保持 FREE 与水印状态，不修改原包、预设、license 或设置；正常策略缓存刷新有前后记录。

输入一是原包 Aizawa，字节未改；输入二是单独创建的四粒子诊断配置，含红、蓝两条重叠附加公式及黄色自动主公式，用于确认顺序、默认位置和忽略字段。诊断配置不被称为原包预设。两者通过原版 `reloadConfig(JSONObject)` 和实际 `Scene.runFrame` 执行。

每组记录初始暂停、更新第 1 帧、第 16 帧及之后暂停，共 8 个完整采样。主画布为逻辑 405×486、DPR2，离屏为逻辑 250×300、物理 500×600、samples0。观察实际数学 draw、每个 TexMobject draw 及之后的品牌 draw；完整含品牌图片同时保存。Aizawa 另做关闭观察器的控制运行，四个采样的 raw PNG、完整 RGBA、增强 PNG 共 12 个文件逐字节一致。

| 独立比较 | 结果 | 结论范围 |
|---|---|---|
| 4 份实际原版字形与独立字形服务 | 尺寸、颜色、文字及 581,659 个完整 RGBA 像素零差 | 本轮四份文字/颜色 |

第 1、16 次原版更新分别对应产品固定时间请求 0 和 0.5 秒。初始暂停没有执行数值更新，仅用于公式叠加检查，未冒充产品固定时间 0。比较覆盖全幅 RGBA，不裁剪区域，不忽略 alpha，也没有误差容限。

这里的完整图层包括数学画面和公式。原版之后叠加的品牌图层另行测量，完整含水印图仍原样保留；没有声称原版整个窗口、品牌画面或全部输入已一致。

## 实际界面与桌面包

实际无头 Chrome 通过 **186 项检查**，覆盖原包 Aizawa、Dadras 与 DPR1/2：

- 导入、原生预览、主画布 resize、实际字形请求与合成结果。
- 500×600 PNG、奇数尺寸在 DPR2 下对齐为 504×608、JPEG、三帧 MP4。
- 新源布局与已有通用布局的保存、重载、坐标和文字顺序保留。
- 原版附加公式默认值；真实字形响应尚未交付时取消旧预览，切换至 Dadras，再编辑新公式并恢复。
- 一个明确构造的 64 粒子 GPU 场景，通过真实 WebGL2 输出和可见公式层验证必需公式信息及消费。这不是原版 GPU 数学画面一致性的证明。

验证器早期失败记录保留：首次因 sandbox 不允许本机监听而退出；随后修正了空公式直接 PNG 路径无需 compositor、对象键顺序不代表配置值变化两项错误断言。第四次完整运行通过，产品源码没有因此变更。所有运行的自有资源已关闭。

preview.12 包构建与 `codesign --verify --deep --strict` 通过。在独立配置的隐藏 Electron 中，原包 Aizawa 完成导入、前进一帧、回到起点、96×80 PNG、保存、完整退出和重启。重启就绪后再重载渲染页面，让观察器从冷缓存开始记录字形；这一步明确属于验收过程。两次均观察到与原版精确文字、颜色、尺寸和完整 RGBA 哈希相同的打包字形结果。

两次对齐后的 PNG 完整 RGBA SHA-256 同为 `3197ab8aac01a2b0246d40ab352d882d0fb0a79ed574fb21430fa2b5189bfa2f`。两个应用进程组均已退出，端口关闭，可见窗口数和显示事件数均为零。ASAR、原生程序、字形运行时入口/库/辅助程序、清单及原输入前后哈希不变。

## 检查与性能边界

16 个不同定向测试文件合计 254 项通过，包括真实 Worker 和真实本机 HTTP 字形边界；TypeScript 与 Vite 构建通过。HTTP 测试首次在 sandbox 下监听被拒，必要权限下单独重跑 25 项全部通过，保留首次失败日志。

公式内容复用另做当前语义的隔离 CPU 观察：Aizawa 每批 1000 次、5 批，重新解析并呈现的中位数为 22.89 ms，复用已解析内容并呈现为 1.56 ms，输出完全相同。这仅比较公式函数的局部成本，不是应用端到端性能，也不与旧版本不同语义的 MathJax 路径作速度比较。实际界面验收约 38.54 秒，原版对照约 10.19 秒，隐藏桌面验收约 12.37 秒，均包含观察开销；本轮未测完整任务 token、进程族 CPU/峰值内存或 GPU 显存。
