# Symmetry 重放、清除与渐变触发规则

2026-10-21。**新增 146 组原版 JVM 运行证据，全部可重复。确认了重建触发条件和计数含义；本轮没有修改生产渲染时序，也未完成原版整窗口对照。** 1.0 Apple Silicon 安装应用未改变。

## 这次确认了什么

原版有两个不同的过程：普通更新/显示，以及修改部分属性后触发的分帧重建。不能把重建过程直接套用到每次打开场景：构造后的 `replayRebuildPending` 和 `replayActive` 都是 false；初始化和创建累积缓冲也会清除 pending 标记。

129 组静态方法实际执行覆盖重放预算、完成判断、计数和三种清除判定；17 组对象探针实际执行构造、开始重放与属性更新。探针没有运行图形初始化、`update`、`display` 或 `advanceReplaySession`。

| 原版操作 | 实际观察到的状态变化 |
|---|---|
| 更新非空色板，包括传入当前色板本身 | 色板标脏，请求重建，退出当前重放 |
| 更新空或 null 色板 | 保持原状态 |
| 更新场景变换，包括传入完全相同的六个值 | 请求重建，退出当前重放；不改变色板标志 |
| 更新余弦色板，即使关闭且四个向量都为 null | 色板标脏，请求重建，退出当前重放 |
| 应用渐变帧，偏移变化绝对值大于 1e-9 | 写入偏移、色板标脏；不请求重建、不退出重放 |
| 应用 null 渐变帧，或偏移变化不超过 1e-9 | 保持原状态 |

对象探针在开始重放后**显式将 `paletteLUTDirty` 清为 false**，以便观察后续方法是否写入；这不是模拟上传成功。配置直接进入 `JsonSymmetryChaosConfig`，Mobject 的主应用引用为 null，所以目标帧率走原版 60 FPS 回退；不代表项目导入或实际主窗口路径已执行。

## 分帧重建与计数

调用原版 `startReplaySession` 后，预热剩余步数是非负 burn-in 值；绘制重放的总轮数被限制在 64 到 256；目标显示帧数为 `max(1, round(float(0.5 * fps)))`。原版 helper 的 Float32 乘法和 Java round 行为不能随意用其他舍入顺序替换。

| burn-in 输入 | 剩余预热步数 | 剩余绘制轮数 | 每帧预热预算 | 目标显示帧数（60 FPS） |
|---|---:|---:|---:|---:|
| 0 | 0 | 64 | 8 | 30 |
| 100 | 100 | 100 | 12 | 30 |
| 200 | 200 | 200 | 12 | 30 |
| 1000 | 1000 | 256 | 12 | 30 |

静态 helper 实测：首帧剩余绘制轮数至少 16 时预算是 2，否则是 1（没有剩余则为 0）；后续按剩余轮数除以剩余显示帧数向上取整。字节码显示调用方再将每帧实际绘制限制到最多 8 轮。预热与绘制可以在同一次重建调用中推进，不能简单理解成“先显示若干空白帧，再开始绘制”。

以下是**字节码推导**，没有执行 GL 调用：

- 普通 `display` 调用 `splatParticles(..., true)`，每次增加一次 `accumulationSampleCount`。
- 重建调用 `splatParticles(..., false)`，循环结束后按实际绘制轮数统一增加计数，没有重复计算。
- 预热步数不加入绘制计数；归一化使用绘制计数乘以批次粒子数。
- 参数变化只有在未暂停、未重放、也没有待重建请求时清除累积。相机投影变化的判定忽略暂停标志，但同样受重放和待重建标志限制。这三种判定已覆盖全部 16 个布尔输入组合。
- `update` 本身也会依据 `warmupApplied` 执行预热和迭代；必须继续核对宿主调用顺序，不能只移植 `advanceReplaySession` 就声称时序一致。

整数极值测试保留了原版 Java int 溢出结果。这是证据，不是让本地无界增长或照搬溢出的实现建议。

## 对当前 MathArt Lab 的影响

当前持续密度所有者会在粒子重置时一次完成预热，通常每个采样帧绘制一批；它报告的是本地实际完成的批次数。上一轮最终调色公式验证仍然有效，但不能把它延伸成原版的显示次数、修改色板后的重建节奏或逐帧画面已经一致。

原版渐变只改变后续绘制所用的色板，和用户直接编辑色板触发重建的语义不同。接入时需要让时间线运行状态与编辑事件各有明确来源，并保留暂停/重放状态，不能仅比较最终颜色或参数 JSON 来猜测事件。

下一步是核对宿主 update/display 调度及渐变动画配置绑定，再在共享帧计划中表达预热、绘制轮数、清除和计数，最后通过真实预览、定位、导出验证消费者。原版完整窗口验收仍为 **0/11**，本轮证据不改变该数值。

后续进展：[渐变动画已接入并验证](source-symmetry-gradient-validation.zh-CN.md)。重建与粒子显示计数仍待接入，不与渐变状态验证混为一项。
