# 曲面接缝与相机原版对照（2026-10-24）

本轮修复了 GPU 网格采样的 Float32 运算顺序。20 组原版输入、40 帧完整艺术画面现已逐像素一致，原有三组 GPU 作品截图回归也保持零差异。

## 原版实测覆盖

| 输入 | 模式 | 覆盖 |
| --- | --- | --- |
| 开放曲面、强制 U、强制 V、同时强制 U/V | CPU 与 GPU | 两方向开关独立生效；四个 CPU 参考图像互不相同 |
| 环面 | CPU 与 GPU | 开关关闭时仍自动识别闭合 |
| 带小缺口的圆柱面，阈值 0.1 与 0.3 | CPU 与 GPU | 原版内部状态由未计算 U 接缝偏移变为已计算；本地整图分别与原版一致 |
| 莫比乌斯带 | CPU 与 GPU | 原版识别 U 扭转接缝，本地整图一致 |
| 四个相机输入 | CPU 网格 | `(0,0,0)`、`(PI/2,0,0)`、`(0,PI/2,0)`、`(PI/4,PI/4,PI/3)`，四张参考画面互不相同 |

相机三元组按 `phi, theta, gamma` 排列。最后一组含滚转，不能当作不含滚转的标准等距视角。各输入都使用 9×7 网格、填充透明度 0.7 和耦合线框；每组执行 4 FPS 录制的预热帧和完成帧，场景时间分别为 0.25、0.5 秒。这批输入是静态几何与固定视角，没有据此声称任意连续相机运动已验收。

缺口阈值两张参考图在所选视角下相同，因此阈值行为的证据是原版读取到的内部状态及字节码，不能把它写成肉眼可见的闭合差异。环面／扭转场景也保留开关值、扭转标志、连续偏移和脏状态，未主动调用会改变这些状态的探测方法。

## 根因与修复

修复前 18 组零差异，GPU 开放曲面每帧有 1 个不同像素，GPU 莫比乌斯带每帧有 10 个，最大通道差都是 1。没有接受容差。

重新执行这两组原版并被动读取实际 GL 参数后，发现：

1. 填充阶段全部像素相同，差异出现在耦合线框之后。
2. 对应 uniform 的 Float32 值相同；原版关闭 DITHER，因此不是抖动设置问题。
3. 每组有 48 个实际绘制角点的 V 种子不同：原版为 `0.8333333730697632`，本地为 `0.8333333134651184`。
4. 原版 `MeshSurface.buildThreejsMeshShape` 先将 `1/stacks` 舍入为 Float32，再乘行索引；CPU 的 `updateThreejsMeshData` 则逐行做除法。本地把两种路径共用了 CPU 规则。

现在网格坐标产生处明确区分 CPU/GPU 采样顺序。GPU 种子及用于选择三角形对角线的 CPU 样本消费同一组 GPU 坐标，两个渲染通道不再自行修补。CPU 网格和参数接缝继续使用原版各自的除法规则。新增测试直接读取实际原版顶点缓冲提取的坐标样本，防止重新合并这两种运算。

重新采集时的原版最终 PNG、品牌前完整像素均与首次参考一致，说明诊断未改变被比较的画面。

## 接缝界面说明

原版的两个布尔开关表示**强制闭合**，关闭后仍会自动判断。自动阈值使用邻近采样点平均距离，不使用整个包围盒对角线。界面已改为“强制闭合 U/V 接缝”，补充采样数也可能影响闭合判断的说明，并提供英文翻译。

本地旧版曲面与原版导入曲面的规则不同，未把这项改动套用到旧版曲面的独立拓扑控件。早期里程碑中“关闭即不缝合／包围盒对角线”的概括不能继续作为源曲面的验收标准。
