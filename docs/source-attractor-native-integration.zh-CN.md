# 吸引子原生 GPU 接入验收

2026-10-27。本轮将源 GPU 吸引子的计算、累计绘制和最终像素接入产品原生服务。在原生构建中，预览与图片／视频导出使用该实际像素，公式继续由原有公式服务合成。普通 WebGL 构建保留已有路径，其累计绘制与原版的差异仍存在。**仅当前 Apple Silicon Mac 的已列输入已验证；M3 与整个 2.0 Goal 仍未完成。**

## 产品改动

种子、颜色、索引、着色器和显示参数由同一个准备模块生成，浏览器与原生后端共同使用。原生服务不再次解释源 JSON、随机序列或表达式。每个持久资源携带明确身份及上传、计算、显示检查点；完整方形状态包含补齐槽位，初始化按内存余量分块，不减少作者粒子数。

反向跳转先确认旧资源释放，再从种子重建。取消发生在原生响应后时，先确认实际完成的检查点，再撤销输出。释放失败保留资源所有者。原生返回的完整图像直接进入预览合成和导出编码，避免再次经过浏览器绘制而产生像素差异。CPU 与原有 WebGL 路径保留各自的执行方式。

独立导出会在当前预览呈现完成后，等待其 GPU 资源释放确认，再创建导出资源；界面保留已完成的画面。关闭导出时先完成导出资源清理，再按原时间和参数重建预览，避免两份大场景同时占用预算。实时录制不使用这项资源交接。

界面完成状态使用发出的请求时间；原版模拟的帧时间继续保留在输出中。两种时间分别归各自的生产者管理，避免非零进度导出因浮点帧归一而一直等待。播放中已经排定的下一帧会先完成，再交接资源。

## 与原版的实际对照

使用此前封存的两个构造输入：17 粒子基础配置，以及 65 粒子预热／相机队列配置。它们不是原包提供的 GPU 预设。原版参考和宿主限制见[前一轮记录](source-attractor-gpu-reference.zh-CN.md)。本轮产品从自己的初始种子运行，没有把原版算出的状态当作输入。

两组全部当前状态、每次更新写出及所采集的完整累计层均逐位一致。两组各 9 张、合计 18 张完整 500×600 数学画面，与原版逐字节相同；关闭诊断观察器后重复运行，输出仍完全相同。未采集的帧、品牌覆盖层、完整应用窗口及其它任意参数不计为通过。

重复请求同一时间不推进模拟；改变尺寸不改变状态；恢复尺寸及反向重建恢复相同像素。取消和模拟的响应交付失败均不发布半成品，实际资源释放后可以恢复。响应失败案例是验证器在收到真实 ACK 后注入的异常，不声称复现了实际网络故障。

200 万粒子以完整状态上传并输出 1024×1024 图像，没有降低粒子数、放宽预算或缩小请求尺寸。共享显示模块不再错误使用 WebGL 全数组预算限制原生后端；WebGL 原限制继续由其自身管理。上传分块在数组分配前校验传输及表示扩展开销。

## 验证记录

| 验证 | 结果 |
|---|---|
| 定向 CPU 测试 | 23 个文件、288 项通过；最终类型检查通过 |
| 原生完整参考与生命周期 | 586 项检查通过；18 张原版数学图零差异；所有者与自有进程清空 |
| 实际公共界面 | 465 项检查通过；CPU/GPU、DPR 1/2、PNG/JPEG、三帧 MP4、奇数尺寸、公式取消恢复 |
| 大场景独立导出 | 200 万粒子、DPR 2、1564×1150 主预览；释放确认后创建导出资源，500×600 PNG 成功 |
| 关闭导出恢复 | 两轮完整预览像素和原请求时间一致；未点击开始的开关流程没有额外导出 |
| 播放中直接导出 | 非零请求时间保持一致，实际 PNG 成功，关闭后恢复同一暂停画面 |

大场景首次验收发现了非零时间的完成身份错误，修复后全量重跑通过。另一次新验证脚本误把进度条显示的取整值当成精确请求时间；修正脚本后仍保留对显示值前后不变的独立检查。失败运行没有删除。一次 HTTP 单元测试被 sandbox 禁止本地监听，使用本地 TCP 权限重跑该文件后 5 项全部通过。

最终界面运行耗时约 68.13 秒；运行前后源码稳定、无页面或未分类控制台错误，浏览器、服务及自有进程均已清理。旧 WebGL 实际回归中，26 个浮点数据、27 张完整图像、6 个上传缓冲、着色器和 18 个绘制日志均逐字节相同。16 份 JSON 增加了两处 `cleanupPending:false`，严格文件比较如实保留为不同；没有删除字段后伪称所有文件相同。对照跨 Chrome 155→156，不由此推断其它浏览器或原版像素一致。

Apple Silicon 桌面预览包 **2.0.0-preview.14** 构建及严格签名验证通过。CPU Aizawa、GPU 17 粒子、GPU 65 粒子分别完成公开导入、前进／回到起点、96×80 PNG、保存、完全退出与重开；每组两次 PNG 的完整 RGBA 一致。GPU 下载图像还逐字节对应本次新建导出资源的实际原生回执；CPU 的封存原版字形核对继续通过。

六次桌面启动全部没有可见窗口，退出后端口关闭、进程组清空；应用包、原生程序、字形依赖、输入和验证器在各次运行前后保持一致。原生完整回归约 29.50 秒；三组桌面验证器分别约 9.00、7.75、7.68 秒。这些是验收运行耗时，包含观察开销，不是性能对比。

应用：[MathArt Lab 2 Preview.app](../dist-desktop-v2/MathArt%20Lab%202%20Preview-darwin-arm64/MathArt%20Lab%202%20Preview.app)。证据保存在本机 `.cache/attractor-native-integration-20261027/` 及关联的原生、界面、桌面验证目录；本页是可直接阅读的验收结论。

桌面进程族监测（每组包括首次启动及重开，采样间隔 0.5 秒）：

| 任务 | 含监测墙钟耗时 | 回收子进程 CPU 时间 | 采样 RSS 峰值 |
|---|---:|---:|---:|
| CPU Aizawa | 9.99 秒 | 13.71 秒 | 1076.8 MiB |
| GPU 17 | 8.27 秒 | 11.94 秒 | 1213.6 MiB |
| GPU 65 | 8.28 秒 | 11.84 秒 | 1199.5 MiB |

CPU 时间包含监测子进程；RSS 是采样值，不是独占显存，也不是精确瞬时峰值。256 MiB 表示准入预算不代表整个 Electron 应用的总内存上限。没有等价旧版完整成本基线，不宣称提速或降耗。

## 验收边界

原版离屏宿主在恢复主目标时已有的 GL1282 记录仍保留，本轮没有重新声称原版宿主无错误。原版跟踪对象所有权及内部消耗 dt 的接收端观察仍未补全。两组输入的逐字节结果不能推广为所有吸引子公式、初始条件、驱动和设备均等价。

用户目前只有这一台 Mac，因此跨设备验收明确未验证；不再把第二台 Mac 当作本机工作的等待条件。其它场景、完整窗口／覆盖层、通用能力的剩余验收以及最终 2.0 发行仍继续。运行耗时可由各报告查看；除上述桌面段外，本轮未测整项任务 token、CPU 时间和内存峰值；显存及分离的冷／暖成本未测。
