# Map 散点与颜色验证

> 后续进展：源最终调色、背景与公开导出已接通，见 [Map 最终呈现验证](source-map-presentation-validation.zh-CN.md)。本记录保留散点阶段的验证范围；原版整窗验收仍未完成。

2026-10-21。本轮完成源 Map 的散点覆盖、固定余弦颜色及导入保存规则，并修复 Symmetry 的亮度上传。当前仍在 **M3：场景补全与效果核对**，原版完整窗口验收仍为 **0/11**。

## 使用上的变化

新导入 Map 使用 `map-splat-1.7.8`。颜色由步长度量、颜色速度和相位计算；散点着色不读取调色板。点尺寸先乘导出比例，再限制到至少 1 像素。支持源配置中的负数、零和小数点尺寸，项目默认 1.5，直接运行配置默认 1。旧的未标记作品继续使用旧模型。

颜色相位保留作者输入的角度，在 uniform 边界按原版 Float32 顺序转换为弧度。度量范围允许负数；非法上下限按源构造规则调整。模式识别保留 Java trim 的边界，未知模式退回 CLAMP。颜色速度和相位仍沿用前一轮已核对的范围与动画目标规则。

点尺寸、度量上下限和颜色字段的数值原文现在完整登记，可保存重开。此前颜色数值原文的登记也有遗漏，本轮一并修正。Map 与 Symmetry 共用散点覆盖和容量检查，不复制几何代码；Map 固定余弦、Symmetry 调色板各自保留。删除旧的 Symmetry 专用散点模块，公开输出仍保留 `symmetrySplat`，Map 新增 `mapSplat`。

## Symmetry 亮度更正

原版上传 `Float32(1 − Float32(作者亮度))`。之前生产路径直接上传作者亮度，而旧验证脚本也复用了相同的错误输入，因此旧“像素零差”不能证明这一项正确。

现已在 uniform 所属边界统一转换，作者设置保持原值；参考脚本从独立输入计算该转换。修复前最大差异为 **161/255**，修复后 **30 组全部 RGBA 字节一致**，并通过取消、纹理过滤恢复与资源清理检查。Map 的原 JVM 归一 helper 36 组与 Symmetry 同参结果一致，但 Map 最终 shader 的最近邻采样、空像素输出和低质量门限不同，不能直接套用 Symmetry 呈现。

## 尚未完成

Map 的最终调色仍是已有兼容路径；源最终呈现和实时界面会话尚未接通。此轮验证的是散点累积，不是完整成图。原版热更新点尺寸 setter 也不同于构造值，后续实时接入必须保留这一差异。

本轮读取 yomado 原生窗口时工具返回“Mac 已锁定，自动解锁失败”；没有移动窗口或发送输入，未确认虚拟屏归属与目标捕获。已请求手动解锁，后台验证继续进行。该结果只说明检查当时的状态。
