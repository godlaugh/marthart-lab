# Business Cycle 原生计算修复与应用验收

2026-10-26。**Business Cycle Map 已通过应用实际调用链的连续 8 帧原版预览对照。** 加上 Clifford、构造的三维 Map、Emperor’s Cloak 对称场景，本轮共 32 帧、100,776,960 个 RGBA 字节，逐字节差异为 0。**M3 仍在进行中，2.0 的全部 11 类场景验收尚未完成。**

## 修复了什么

此前 Business Cycle 的种子、参数和更新次数均一致，但第一个显示帧有 115,299 个 RGBA 字节不同。原因是本地把有限值检查和异常计数写进数学循环，改变了这台 Mac 上 CGL 编译器的浮点运算结果。仅改循环上限或分类写法不能修复。

现在原生后端使用两个独立程序：纯数学程序保留源更新的计算顺序；诊断程序在每个已完成的计算前缀上统计 XYZ、metric 的非有限值。一次推进 N 步时，各前缀都读取同一份推进前状态，只有最终 N 步结果成为后续状态。中间前缀留在 GPU，不复制整条轨迹到 CPU。

计数与粒子位置分别管理，保留以下行为：

- 零步暂停保持位置和计数；单独清零计数保持最终有效性。
- 零步粒子重置直接恢复原始种子字节，不会被数学程序的正步数限制误执行一次。
- 粒子出现 NaN/Inf 后仍可恢复为有限状态，历史异常次数不会丢失。
- 每次源推进最多 16 步；累计观察区间溢出在修改缓冲前拒绝。
- ACK 在整个操作及绑定清理成功后发布；失败保留资源所有权，等待精确释放。

新增协议为 v7 / family 2 / kind 6 `create-source`，显式传入四段 shader。旧 `create`、旧 0–256 步推进及 WebGL 迭代程序保持兼容。内存预算包含全部 shader、两个计算程序及原有粒子缓冲；单次推进、整次显示和重建累计预算都使用实际计算工作量。

## 成本与边界

为了保留逐步诊断，正步数学工作从 N 增至 N(N+1)/2，再加 N 次独立分类。16 步的数学执行量为 136 步，外加 16 次分类；Business 首帧的 16+1+1 更新为 138 步数学执行和 18 次分类。逻辑步数统计仍保持原含义。

以下是一次完整验证流程的测量，包括编译、浏览器、8 帧对照、交互与清理。前一版本三组已完成流程与本轮对比如下，均为单次测量，不能据此断言更快或更省内存：

| 输入 | 总耗时：前→后（秒） | 进程族 CPU：前→后（秒） | 采样 RSS 峰值：前→后（MiB） |
|---|---:|---:|---:|
| Clifford | 7.155 → 7.184 | 20.997 → 19.122 | 1003.3 → 581.3 |
| 构造三维 Map | 6.662 → 6.658 | 18.044 → 18.685 | 572.5 → 539.7 |
| Emperor’s Cloak | 8.144 → 8.132 | 21.896 → 21.834 | 620.6 → 639.0 |
| Business Cycle | 本轮 7.657 | 本轮 19.961 | 本轮 827.9 |

Business 此前在首帧失败，没有可比的完整成功流程。新进程内首次显示分别为 Business 1.283 秒、Clifford 0.970 秒、三维 Map 0.860 秒、Symmetry 1.788 秒；后续 7 帧的中位数分别为 0.341、0.342、0.321、0.320 秒。这是验证流程观测，含传输与比较，不是纯 GPU 帧率。

进程是新建的，系统和驱动缓存未受控；后续帧属于同进程热运行。CPU 包含采样子进程开销，RSS 每 0.5 秒采样可能漏峰值，不是 PSS 或 GPU 显存。GPU 能耗、温度、稳态性能未测。工具计量窗口内 Goal token 增量为 379,546，时间增量 699 秒；工具未提供缓存/子代理细分，也没有等价旧工作流 token 基线，不能把包体减少当成 token 优化。
