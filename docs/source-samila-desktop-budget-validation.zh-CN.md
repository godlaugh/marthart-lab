# Samila 默认窗口修复与桌面预览版 5

2026-10-26。**修复 Samila 原生画布内存重复计费：默认桌面窗口可以连续显示、修改参数和导出。Apple Silicon 桌面包已更新为 `2.0.0-preview.5`。整体仍处于 M3，全部 11 类场景的剩余要求继续保留。**

## 修复了什么

在真实预览版 4 中导入完整 Samila 预设，1724×1160 物理像素的首帧正常，但修改参数后报“Samila 原生显示和保留图像超过 256 MiB 工作预算”。画面保留旧结果，后续计算不能完成。该失败已保留，未通过缩小窗口或减少采样来绕开。

原因在前端预算边界：保留资源已经包含画布，每次显示又重复预留了一份新画布。原生端本来就只在尺寸变化时分配新目标。此尺寸下，重复的画布和临时费用单独就达 259.38 MiB，尚未计算程序等费用，必然超过上限。

现在由原生会话所有者提供**已确认的资源身份、宽和高**，预检和编码共用新增画布费用规则。同一资源、同一尺寸复用已有目标；未知目标和尺寸变化继续预留新目标，尺寸变化期间仍计入旧目标。不同资源不能借用这份额度。创建资源时的另一处重复计费也已清除，但创建请求发出前登记的所有权仍保留。

256 MiB 上限、响应展开、统计读回及调用方图像费用保持原值。尺寸只在响应解析和身份检查成功后更新；响应丢失或清理失败时，旧目标及可能已分配的新目标继续占用预算。这是资源费用模型，不代表整个 Electron 进程族 RSS 限于 256 MiB。

## 实际桌面包验收

使用实际 `.app`、内置 CGL 与正常文件导入，没有注入渲染配置或固定随机数。每个场景先导入未修改的原版 JSON，再在界面将 f₁ 改为原表达式加 0.01、Apply，并热改参数 a。窗口全程隐藏，使用独立测试工作区。

| 项目 | 结果 |
|---|---|
| 默认 Samila | 每次基础采样 1,262,144；1724×1160 主画布通过。 |
| 高批次 samila1 | 每次基础采样 6,562,144；同尺寸通过。 |
| Apply 与热改 | Apply 新建原生所有者；热改复用所有者，分别完成 7,572,864 和 39,372,864 个样本的六倍补采。 |
| 连续播放／暂停 | 原生显示继续推进，未因重复预算而拒绝。 |
| 当前暂停 PNG | 两个场景各实际下载 160×120 PNG，完整 RGBA 等于该次原生图像经过既有增强后的结果；恢复原主画布尺寸和资源。 |
| 独立冷 PNG | 每个场景各导出两次，分别逐字节对照自己的原生响应；独立资源释放得到确认，原预览可以继续播放。 |
| 关闭重开 | 参数与完整编辑公式恢复，并实际完成新的原生显示。 |
| 其它场景回归 | Map、内置及自定义 Symmetry 的预览、编辑、播放、两种 PNG 与重开通过；21 个公式字形及公式开／关图片导出通过。 |

Samila 每次实际显示都使用新的随机输入。本次没有要求不同导出的画面相同，也没有把本地包内的像素传递检查冒充新增原版整图对照。此前原版整图与持续负载的范围见[原生预览验收](source-samila-native-integration-validation.zh-CN.md)及[持续负载验收](source-samila-sustained-validation.zh-CN.md)。

## 验证边界与待办

本轮预算、传输和真实原生生命周期相关的 88 项测试通过；共享传输与 Samila 录制相关的 80 项测试、39 项桌面测试通过。TypeScript 检查、桌面构建和严格签名完整性检查通过，构建仍保留既有 bundle 大小提示。没有执行全部测试套件，也未新增长时间录制或第二设备验收。首次测试命令误用了父仓库测试运行器，收集到缓存中的旧副本并失败；该次不计入通过数量，随后用本项目运行器和明确排除缓存重新执行。

桌面回归曾发现验证脚本的时序问题：导入同名场景时，旧状态的 Ready 先满足，而新原生资源尚未创建。脚本现等待导入触发的实际原生创建和呈现响应，再验收完成状态。另一次 DevTools 响应正文读取失败，使完整 PNG 对照无法成立；增加明确有界的观察缓冲后重新执行。没有忽略丢失正文，也没有修改应用 fetch 或响应交付；这些失败记录均保留。

本轮还补查了原版 Symmetry 的剩余重播权限。实际策略为 VIEW/RUN 允许、EDIT/EXPORT 不允许。最早探索只检查 VIEW/RUN，未检查 EDIT 就调用了调色 setter，因此其记录被明确隔离，**不用于验收或原版一致性参考**。补上 EDIT 检查后，程序在 GL 初始化前拒绝，退出码为 2、进程组为空，未再调用 setter。静态检查未找到普通 VIEW/RUN 流程自然触发 world replay 的路径；不能改用低层 setter 绕过该缺口。原版重播、离屏导出和录制生命周期对照继续标记未验证。

## 成本记录

最终两个 Samila 场景的完整桌面验收耗时 **7.92 秒**，采样观测的进程 CPU 下界 **10.71 秒**，同时进程组 RSS 采样峰值 **1087.2 MiB**。包括应用启动、公式重建、后续复用、导出及重开，不是渲染 FPS。每次使用新进程；系统和驱动缓存未清空，首帧和后续帧的纯渲染耗时未单独测量。RSS 每 0.5 秒采样，可能漏掉短峰，不含 GPU 内存；CPU 不含验证驱动进程。

修复前同工作流在热改时未完成，其 32.20 秒还含脚本等待超时，不能与成功后的耗时作加速比较。这里只证明预算与实际资源复用一致、原本被误拒的流程可以完成。

本轮 Goal 工具计数从 97,415,928 到报告快照 97,787,434，差值 371,506 tokens，包含调查、失败重试和上下文；不是一次渲染的模型成本，也不含快照之后的收尾操作。验证脚本没有模型调用。
