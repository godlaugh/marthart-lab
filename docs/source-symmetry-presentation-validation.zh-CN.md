# Symmetry 最终调色、画布归一化与导出验证

2026-10-21。**新导入的原版 Symmetry 项目已接入源最终调色、物理画布归一化和场景背景混合。27 组完整 RGBA 对照误差为 0；原版完整窗口验收仍为 0/11。** 已有 1.0 Apple Silicon 应用没有重打包或替换，本轮没有操作原生窗口。

## 本次改变

之前色板已经一致，但最终仍使用本地白点调色，原版相机视图还要把浮点累积数据回读到 CPU 后取样。现在，新导入的源项目直接在 GPU 上执行原版最终调色顺序：线性采样累积纹理、按密度归一化、对数与平滑限制、YUV 色彩处理、Gamma，以及前景透明度混合。旋转后越界和没有样本的像素保留场景背景。

原版归一化用主画布的**物理像素尺寸**，不是导出的宽高，也不是点尺寸使用的逻辑高度。现在预览传递实际测得的物理尺寸，导出沿用已经呈现的那一份参考，Worker 传输会复制并保留它。比例先舍入到 Float32，再参与后续计算，最终尺度再次舍入到 Float32；没有用代数化简替代这些舍入。

场景背景先清除为不透明颜色，再使用 `SRC_ALPHA / ONE_MINUS_SRC_ALPHA` 混合。显示端直接复制已合成 RGB，避免再混合一次。PNG 保留目标 RGBA；视频保留相同 RGB，并明确把 alpha 变成不透明后交给 FFmpeg。缺省项目背景改用原版的黑色，有明确背景的项目保留该值。

保存重开保留源呈现模式；这类项目不再显示手动参考尺寸和切回白点调色的控件。旧的本地文档和 direct runtime-config 导入没有被自动迁移。独立调用缺少主画布尺寸时，输出明确标记 `local-output`；提供了无效尺寸则拒绝，不用默认值掩盖错误。

## 证据范围与剩余工作

归一化证据是原版应用随附 JVM 的实际方法执行。着色器证据来自固定 1.7.8 JAR 的 `density_map_present.frag` 和 `quad_attrib.vert`，只适配 GLSL 版本和精度声明；参考与生产使用独立 WebGL 上下文。场景清除、混合系数、固定 invert/alpha 和参考尺寸来源则是字节码推导，相关类 SHA-256 与位置已登记。

这些验证不包括原生 JOGL、窗口抗锯齿、DITHER 实际状态、系统窗口合成或原版导出文件。原版实时批次计数、重放节奏、梯度动画及完整混沌轨迹还需继续核对。当前归一化消费的是本地累积器实际完成的批次；方法一致不等于已经证明宿主时序一致。

## 复核与成本

- 原版输入输出及来源：`tests/fixtures/symmetry/normalization-runtime.json`；JNI 运行源代码：`scripts/oracles/source-symmetry-normalization.c`。使用已有 JNI 头文件编译后，依次传入应用随附 `libjvm.dylib`、应用 JAR classpath 和包含 `cases` 的输入 JSON。它不启动 GUI，不安装 Java。
- 最终着色器：`node scripts/verify-source-symmetry-present.mjs <新输出目录> [原版 JAR]`。
- 应用流程：`node scripts/verify-captured-density-public.mjs <新输出目录>`，同时输出可阅读的 `report.md`。
- 本地日志、截图、参考着色器和详细指标：`.cache/source-symmetry-presentation/`；原版二进制和运行产物不进入 Git。

原版 JVM 36 组约 1.01 秒。最终着色器验证约 1.55 秒，外层进程族约 2.07 秒、CPU 5.29 秒、峰值 RSS 约 1.36 GiB。完整 App 流程约 11.98 秒，外层约 12.82 秒、CPU 25.46 秒、峰值 RSS 约 2.15 GiB。

App 流程比上一轮多了 Symmetry 视频导出，不属于等工作量性能对比。新浏览器/上下文启动与同一所有者内的多次呈现已区分；没有操作系统冷缓存或受控冷/热测速。250 ms 进程族采样可能遗漏峰值和短进程，共享页可能重复计数；GPU 内存、驱动缓存和 token 成本未测量。
