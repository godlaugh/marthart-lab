# 曲面切换与公式叠放验收（2026-10-24）

修复了曲面切换到黑场时公式仍可能显示的问题。原版的顺序是几何、公式、品牌、最终黑色遮罩；此前产品在公式之前就绘制了遮罩。

现在有公式的帧将最终遮罩交给公式合成器，统一在公式后执行。PNG、录像和画布公式层消费同一帧携带的透明度；无公式的帧仍使用原有几何渲染路径。录像校验区分固定的公式内容与随帧变化的遮罩，同时核对遮罩与数值场景状态，拒绝错误透明度和重复覆盖。

还修复了源文件主公式导入：原版曲面忽略 `main_equation.latex`，根据曲面表达式自动生成主公式。导入现在保留原始字段作为来源记录，但不再错误地覆盖自动公式。导入后手动编辑和保存的本地公式仍然有效。该行为有既有原版执行样本 `Explicit`，并由本轮真实帧再次验证。

## 对照方法及边界

原版仍使用 MathArt 1.7.8 的正常授权、品牌和离屏 JVM/GL4 流程，未创建可见窗口。JAR SHA-256 为 `a6e1da3acfc05c347d2529c1d590657e2dd798e16d38c55df3dc61312be24018`。

输入在 CPU 点阵与网格之间切换，背景为 `#123456`，包含自动主公式与一条彩色附加公式。请求尺寸 128×96，原始缓冲 384×288；主画布逻辑尺寸 405×486、像素密度 2。实际 FPS 与固定模拟 FPS 分开传入。每帧检查时间步、实际 FPS、队列完成状态和停止时不额外推进。

半透明场景分阶段验证，未用遮挡区域或容差掩盖差异：

1. 原版开始绘制品牌之前的全部像素，与产品“几何＋公式、尚未覆盖黑色遮罩”的全部像素比较，28 帧相同。
2. 对原版即将绘制最终遮罩的完整帧缓冲（包含品牌），调用产品同一个最终遮罩合成器，再与原版实际最终帧比较。8 次相同，包含透明度 0.5 对应的整数 alpha 128。
3. 对全不透明遮罩，直接解码产品真实 `encodeFormulaRaster` PNG，与原版最终帧比较，4 帧相同。

因此这里证明了所测艺术阶段及最终混合操作，而不是声称带品牌的原版最终画面与不带品牌的产品在所有半透明帧直接相同。未对品牌做移除、像素反推或局部忽略。所有原版最终截图保留。
