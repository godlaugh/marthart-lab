# Attractor 预热修复与原版完整时间线对照

2026-10-26。Dadras 原包预设的首帧预热阻断已修复。Aizawa 和 Dadras 的完整时间线中，27 个选定节点的完整粒子、轨迹、相机数值一致；通过原生绘制诊断路径得到的数学图层，共 **8,100,000 像素，零差异**。

这仍是 M3 的阶段成果。原生 Attractor 的日常预览、图像与视频导出接线正在完成，不能把诊断路径的成功当作这些产品入口已经验收。全部 11 类场景仍在 2.0 范围内。

## 修复了什么

未修改的 Dadras 配置需要 47,965,945 个预热工作单位。此前初始化、更新和快照共用单次 20,000,000 限额，导致该正常预设无法生成首帧。

现在先按原随机数顺序生成全部初始坐标、步长和各粒子的预热次数，再把连续粒子分片交给最多 4 个 Worker。每个 Worker 独立持有公式变量和暂存区；全部结果确认并回收 Worker 后才发布粒子状态。没有降低粒子数、预热次数或公式精度。

本地完整预热任务上限为 320,000,000 工作单位、16 个分片、60 秒；每片最多 20,000,000。分配前进行 256 MiB 表示成本准入。它是本地资源策略，不是原版限制或操作系统 RSS 硬上限。普通更新、跳帧和快照继续使用原有的单次请求限额。

同步与异步路径共用时间线和倒退重建逻辑，只在初始化处等待。原包指令显示预热使用 parallel，普通 update 是串行双循环，因此本次只并行预热。

## 原版与产品对照

原版为本地 MathArt 1.7.8，JAR SHA256：
`a6e1da3acfc05c347d2529c1d590657e2dd798e16d38c55df3dc61312be24018`。

两份原包配置均未改写。原版正常执行每一帧 update 和 draw，直到真实完成谓词成立，随后再执行一个运行帧和一次暂停重绘。窗口对象和可见窗口均为 0；正常策略、许可与品牌水印保持，原配置、JAR、settings/license 摘要前后不变。

| 配置 | 粒子 | 原版完成帧 | 比较节点 | 完整数学像素 | 差异 |
|---|---:|---:|---:|---:|---:|
| Aizawa Attraktor | 300 | 3157 | 18 | 5,400,000 | 0 |
| Attractor_Dadras | 500 | 1805 | 9 | 2,700,000 | 0 |

节点覆盖旋转、缩放、焦距、跟踪、停止跟踪、完成和完成后运行。不是全程每帧都做像素比较。原版 4964 个连续运行帧均有简要时钟、相机和队列记录；完整数组与图像仅在上述节点保留。

数值比较检查所有粒子的 raw/display XYZ、dt、打包颜色，以及 **2,304,900 条完整 FIFO xyzt 轨迹记录**，没有抽样粒子、重新排序或使用误差容差。相机中心在原版 JSON 中采用 Float32 短十进制表示，验证器按该字段的格式恢复 Float32 位后比较；原始报告中十进制字符串不同的记录仍保留。

像素路径为冻结的生产导入器 → Generator → 实际 generation Worker 与预热 Workers → ArtRenderer → 通用原生 CGL。目标逻辑 250×300、密度 2、物理 500×600、samples=0。比较范围是观察到的全部点和轨迹绘制完成、公式和水印绘制之前的整张数学图层。没有裁切 ROI；尚不证明最终公式、品牌叠加或增强后的整图一致。

## 取消、测试与成本

- 实际隐藏 Chrome 中，在四个预热子 Worker 已存在且结果未返回时取消。父 Worker 和四个子 Worker 的目标均销毁，27 ms 后取消操作及目标清理已被观察到；同一 Generator 随后成功生成原包 Dadras，最终无自有 Worker 目标残留。这不是后台 CPU/RSS 测量。
- 相关 CPU 检查：23 文件、470 项通过；其中 7 项属于同时开发的共享图像边界契约。TypeScript 与 Vite 构建通过，构建包含实际的嵌套预热 Worker 资产。
- Node 真实 Worker 单次测量：Dadras 并行 85.93 ms、总 CPU 390.59 ms；相同计划串行 263.19 ms、总 CPU 269.34 ms。计时包含线程启动、传输、确认和终止；并行减少等待时间但增加 CPU 成本。
- 构造的 297,340,945 工作单位近上限任务通过，结果与串行逐字节一致；取消也通过。该任务明确不是原包预设。

这些性能数字是同一进程内的一次测量，未随机化顺序；累积峰值 RSS 不能当作单任务增量。浏览器进程族峰值、GPU 内存、长期吞吐和 agent token 成本未测，不承诺 30/60 FPS。

## 尚未完成

既有 1080p 高配视频会产生约 144 万条轨迹记录。一次性原生快照和上传会超出现有容量，因此正在实现同一原生画布上的有界分批绘制，保持绘制顺序、一次清屏和一次读回。未经验证前不启用会破坏该能力的产品路线，也不静默减少轨迹或切换后端。

接下来还需验证产品预览、PNG/JPEG/视频、公式合成、不同尺寸、GPU Attractor、真实窗口可变帧率以及最终 Apple Silicon 应用包。用户只有当前这台 Mac，跨设备验收保留为未验证，不再重复询问。
