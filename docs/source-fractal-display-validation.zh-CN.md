# 原版分形渐进显示与暂停导出验证

后续数值调查见[原版 Mandelbrot 剩余像素差异核对](source-fractal-native-residual-validation.zh-CN.md)。显示状态匹配与最终像素匹配分别验收。

2026-10-22。本轮补齐了原版分形的单次显示调度、渐变纹理延迟和跨目标状态。原版 Mandelbrot 输入与本地生产 WebGL2 路径的 **9 次显示状态一致**；像素仍有差异，**分形整类尚未通过整图验收**。

## 原版实际观察

原版 MathArt 1.7.8 保留正常策略和水印，连续调用原始方法，读取实际 GL uniform 和对象字段。没有改写原版方法，也没有用可见主屏进行绘制。原始输入为随应用发行的 `Fractal/mandelbrot.json`，SHA-256：`d99ae18ff13011177ee9f0bc2d5f3b1c32a84a5948747d0badf3e0b57ad34207`。

暂停状态下，场景时间保持 0，但重复显示仍推进渐进遍次：

| 显示次数，从 0 开始 | 采样比例 | 实际渐变大小 | 显示后的遍次索引 | 当前绑定纹理 |
|---|---:|---:|---:|---|
| 0 | 0.25 | 0 | 1 | 黑色回退纹理 |
| 1 | 0.5 | 0 | 2 | 黑色回退纹理 |
| 2 | 1 | 0 | 2 | 1024 项渐变纹理 |
| 3–6 | 1 | 1024 | 2 | 1024 项渐变纹理 |
| 稳定后首次换尺寸 | 0.25 | 1024 | 1 | 黑色回退纹理 |
| 返回先前尺寸 | 0.25 | 0 | 1 | 黑色回退纹理 |

最后两次说明：遍次完成不等于显示稳定，切换目标也不保留各目标独立的进度。稳定后的首次换尺寸会保留上一帧的渐变大小，却立即绑定黑色回退纹理；原版对应输出除水印外几乎全黑。

字节码解释了这一现象：`renderFractal` 先绑定参考轨道纹理，此时 `PShader.bind` 消费待上传 uniform；随后才设置渐变大小。第二次绑定时 shader 已绑定，新的大小要等下一次显示才被消费。纹理绑定立即生效，两者不能合并为一个“使用渐变”开关。

原版 `savePausedFrameInternal` 的顺序为分配离屏目标、`beginDraw`、一次 `Scene.render`、`endDraw`、构造输出图片。它不更新场景时间，也不预先跑完所有渐进遍次。

## 生产实现与验证

`SourceFractalDisplay` 为每个保留的分形实例集中管理遍次、原版状态哈希和待上传的渐变大小。哈希按 Java 的 Float32 位模式、Double 折叠和 int32 溢出计算，包含完整调色板及颜色 alpha；不额外加入原版未参与哈希的中心、缩放、旋转、时间或动态参数。

实时显示、暂停截图、主画布恢复和连续录制共用这个状态所有者。热应用只重置遍次，完整重建和录制开始创建新实例。每次显示只运行当前遍次，离屏截图不会偷偷预热。仍保留原有本地文档的独立渲染规则。

独立逐帧录制也有自己的数值与显示状态实例，按完整场景和输出尺寸等输入识别会话。顺序帧复用状态；跳帧、回退或重复取帧会重建显示历史，只为请求帧生成像素。重建的调色板、队列和参数工作共用 200 万工作预算，超限明确报错；顺序录制每次请求重新计预算，不保留增长的帧历史。取消或失败会清理该实例。

真实浏览器的生产 GPU 路径完成 7 次暂停显示、一次切换尺寸和一次返回，共 9 次。采样比例、渐变大小和状态哈希与原版一致：250×300 的哈希为 `1354526813`，405×486 为 `1524166749`。这验证了显示调度，不能替代像素验收。

同一固定区域 `[55,55,445,510]` 的 RGB 比较仍有以下差异。MAE 使用 0–255 通道值；该区域比较不能代表整张图片：

| 帧 | 不同像素 | RGB MAE |
|---|---:|---:|
| 0 | 768 | 0.256553 |
| 1 | 608 | 0.251414 |
| 2 | 411 | 0.120678 |
| 3–6，各帧 | 411 | 0.122682 |

显示所有者、保留实时会话、录制及两类 Worker 传输测试共 **114/114 通过**；独立录制显示、既有录制协议和客户端测试另 **34/34 通过**。其中注入渲染器的测试验证状态和调用顺序；实际 GPU 证据来自上述浏览器运行。后续仍需定位剩余数学或栅格差异，完成原版 GUI 导出整图对照，并扩展输入覆盖；本报告不宣布分形整类通过。

## 实际界面验证

构建版页面导入 Mandelbrot 后，暂停预览依次完成四次显示并稳定；额外观察 500 ms，没有继续生成帧。显式 Apply 后同样收敛，场景数值时间没有随预览细化推进。实际 PNG 下载成功，无浏览器错误；离屏捕获后，主画布继续完成剩余遍次并稳定。

必须保留一个原版行为限制：稳定预览后首次切换输出尺寸，单次暂停捕获会使用延迟的渐变大小与黑色回退纹理，因此数学画面可能为黑色。这已在原版后台绘制和本地实际导出中观察到。当前源兼容路径复现这一行为；此结果不等于一次导出就能得到最终精细画面，也不意味着整图验收通过。

实际界面报告及截图在 `.cache/source-fractal-display-20261022/fractal-ui/`。新增可运行的 `node scripts/verify-source-fractal-display.mjs` 使用已提交输入，在后台 Chrome 验证 9 次生产 GPU 显示与暂停稳定性；原版图像比较仍依赖本地保留证据。最终重复运行 `browser-final/report.json` 已通过。
