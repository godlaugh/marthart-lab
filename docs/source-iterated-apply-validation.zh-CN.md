# Map / Symmetry 显式 Apply 验收记录

后续进展：本轮记录中的全局草稿待办已继续实现，详见 [草稿、Apply 与录制验收](source-iterated-draft-validation.zh-CN.md)。以下保留当时的验证范围。

2026-10-21。本轮完成 **Apply 入口及其配置所有权修正**，是全局草稿暂存的前置步骤。2.0 仍处于 M3；原版完整窗口效果对照仍为 **0/11**，不能据此称效果一致性已验收。

## 用户可见的变化

- Map / Symmetry 检查器提供「应用场景」，即使数值没改也重新创建实例。
- 「应用公式」「验证并应用 GLSL」「应用初始相机」使用同一个显式 Apply 入口。相机 Apply 可在播放中执行。
- 暂停时 Apply 保持暂停，场景时间和普通对象更新数均为 0；播放中 Apply 保持播放。首次显示本身与后续动画推进分开计算。
- 相机 Apply 更新初始视角并重建；暂停时拖动画布仍属于临时导航，保留之前验证的恢复播放行为。
- 无效公式 Apply 在预检失败后保留原实例和已显示图像。
- 选择场景时仍保留已有的本地默认预览；它与显式 Apply 的初始化不是同一操作。手动时间跳转仍走固定步长重建。

安装在本机的 Apple Silicon 1.0 应用没有重新打包或替换。本轮验证的是当前源码和 Web 构建。

## 根因及修正

原实现把「字段差异」作为是否执行 Apply 的依据。相机角度或相同数值不会触发配置重新导出，有时也不会创建新实例。现在配置生产者区分普通字段编辑、参数热更新和显式 Apply；显式 Apply 不再依赖字段差异。

另外修正了两处直接相关的问题：

1. 原始运行配置导入时只保留有效运行参数，会丢失编辑参数是否缺失、是否为空，以及尚未取整的值。现在导入边界分别保存编辑事实与构造事实；Symmetry 使用明确的入口标记区分项目与直接运行配置，旧文档只在解析边界迁移。Map 三维注入默认参数也不会修改编辑参数数组。
2. 暂停 Apply 曾复用 `startAt=0` 的本地时间跳转路径，导致先推进一帧再暂停。显式 Apply 现在不带时间跳转指令；所有会话替换调用必须明确传入时间或 `undefined`，避免再次混淆。

缺少编辑来源的旧运行配置不会被猜测修复。明确 Apply 会要求从原始项目恢复编辑配置；普通加载仍可保留原来的兼容行为。Map 直接运行配置在没有 `settings` 时，原构造器提前返回的路径仍未建立完整编辑来源，此处同样明确拒绝 Apply。

## 原版依据

固定 MathArt 1.7.8 JAR SHA-256：
`a6e1da3acfc05c347d2529c1d590657e2dd798e16d38c55df3dc61312be24018`。

原 JVM 使用 9 组输入、每组 3 条路径，共 27 条观察记录：直接运行配置、ProjectState 导出后构造、相同 ProjectState 再导出构造。记录包含原版拒绝的输入，并非 27 次成功。

- Map 公式空白会在 ProjectState 路径修剪，改变构造种子。
- Symmetry 的参数遍历顺序可能在导出后变化，改变构造种子。
- 缺失或空的编辑参数必须保持空，不能把引擎默认参数写回编辑文档。
- 标准 Symmetry 的编辑值 `delta_power=2.25` 保持 2.25，但完整构造后的有效值为 2；参数热更新则保留小数值。
- Map 缺失参数可在直接构造时使用默认值，但导出空编辑参数后，默认公式会报未知变量；本地保留这个失败语义。

证据和可复现 JNI harness 位于 [tests/fixtures/source-iterated-apply](../tests/fixtures/source-iterated-apply/README.md)。该 harness 执行原版配置和构造类，不启动 GUI，也不直接执行 MathArtSession。它与 Apply 的对应关系来自独立字节码审计：Apply 同步时间线、导出 ProjectState、调用 updateConfig，且没有同值短路。

## 验证结果

- 新增 12 项边界测试，覆盖原版路径、直接配置到 Apply、重复 Apply、保存重开、热参数取整、相机 Apply、旧配置来源缺失和入口校验。
- 实际 App + 浏览器 Worker + WebGL：Symmetry 在 DPR 1 下 15 项、Map 在 DPR 2 下 16 项检查通过。包括重复同值 Apply、暂停及播放中 Apply、热参数、暂停恢复的视角状态、重放、视口调整、取消和恢复，以及 Map 失败原子性。
- 全量测试及构建结果、录制回归和资源测量见文末最终记录。

公开 UI 验证入口：`scripts/verify-source-iterated-live-ui.mjs`。最终报告保存在 `.cache/source-map-lifecycle/apply-ui-symmetry-release/report.json` 和 `apply-ui-map-release/report.json`；本文件是其可读摘要。

首次 UI 检查暴露了暂停 Apply 的一帧推进问题，修正后明确断言时间与普通对象更新为零。没有通过改写原版数值 fixture 来消除失败。

## 尚未完成

全局草稿暂存还没有接完：结构设置、模板、GLSL、公式和相机草稿如何统一提交，以及待应用草稿与热更新、保存、撤销、录制的关系，仍需继续实现。当前「应用场景」尚不等于收集所有组件内部未提交文本。

原版完整窗口、Compose 焦点提交时序、所有控件的完整字段导出、超大粒子数及长时间运行性能均未在本轮验证。原始运行配置的全部视觉字段在 ProjectState 往返后的效果也不能由这组构造测试推断。

所有浏览器检查在无可见窗口模式运行。本轮没有移动用户窗口、发送桌面输入或确认虚拟屏捕获，因此不宣称 Yomado 隔离验收已完成。
