# Samila 实时绘制与暂停截图验证

本轮把源 Samila 的预览从“按时间重放并缓存一帧”接到独立的实时绘制会话。每次真正绘制都会使用一个新的随机字并新增采样；同一个动画时刻可以有多次绘制。暂停截图复用该会话，先绘制导出图像，再绘制主预览，所以截图结束后的预览也会变化。

1.0 Apple Silicon 应用没有重新打包或替换。本轮修改的是 2.0 分支中的 Web 预览与导出流程。

## 使用时的变化

- 已有参数、旋转、视口、批次数和外观调整在当前会话生效，不再因每次修改都新建后台 Worker 而丢失全部运行状态。
- 参数显著变化会清空并补采六倍样本；相同值的明确写入、旋转和视口设置按相应 setter 标记清空。尺寸变化先清空缓冲，保留原相机锚点；随后若检测到参数变化，仍重新锚定并补采。
- 色调与点大小调整保留墨迹。仅颜色偏移变化保留墨迹；替换色板会清空。运行时外观组设置保留原版模型 setter 的整组数值约束与构造期拖尾系数的区别。
- 改名、保存和修改滑块范围只重新关联已完成画面，不触发采样。暂停播放本身也不触发额外绘制。
- 修改公式、结构或重新打开文档建立新会话；完整应用从时间零开始。时间线跳转仍是本地重建操作，按所选时间建立新会话。
- 图片导出默认使用“当前暂停场景”，支持 1、3、5 倍 PNG。先按基础尺寸采样、增强，再放大；选择“从初始状态重放”仍使用独立随机采样，不能复制现有墨迹。

当前界面的即时参数编辑是本地产品选择。原版通用参数桥没有 Samila 分派，且原版 UI 另有限制 alpha、点大小和衰减的输入约束，因此“复用已验证的模型 setter 语义”不等于“原版每个界面回调都已复现”。原版宿主暂停／恢复的全部相机与调度行为也没有在本轮宣称完成。

## 状态与失败处理

一个会话拥有参数快照、相机锚点、累积批数、随机源和墨迹缓冲。实时显示与原有冷重放使用显式不同的请求上下文和采样事实，不用 CPU 冷重放冒充已有 GPU 累积画面。

暂停截图只能选择当前 Worker 的确切已完成画面。尺寸与图像后处理容量在绘制前检查；失败是否保留旧预览由会话确认，不能凭错误文字推断。发生部分绘制失败时清理并使旧完成状态失效，不假设原版具有回滚机制。随机字在本地 GPU 调用之前取得，分配／能力探测失败也可能消耗该随机字；失败路径中的精确随机调用位置没有声明与原版一致。

截图期间的编辑或切换场景会等待截图操作结束；旧 PNG 不再发布，随后处理最新请求。关闭界面或取消预览也先完成会话内的两次绘制，再释放对应 Worker。元数据重绑仅在显式元数据请求、完整渲染输入和上下文都相同时复用已完成输出；普通同时间重绘不会命中该路径。

## 剩余边界

- 模拟仍采用本地固定源队列；真实显示次数已经独立，但原版实时帧间隔、暂停／恢复宿主调度尚未对照。
- 原版窗口工具本轮仍返回 Mac 锁定，未进行新的原生整窗截图或输入测试；全体场景的原生整图验收仍为 **0/11**。
- 上一轮严格跨上下文浮点坐标对照仍为 failed；没有放宽判据，也没有用本轮通过覆盖旧失败。
- 本轮为状态正确性验证，没有进行前后等价性能基准。CPU 时间、进程族峰值内存、驱动实际内存、最大负载取消延迟和任务 token 成本未测量。工作预算是已知表示的保守估算，不能代替这些测量。
