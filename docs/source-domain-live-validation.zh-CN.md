# 域着色：实时 Worker 与编辑状态归属

后续进展：参数修改与暂停导航已接入 Worker，见[域着色编辑验证](source-domain-editing-validation.zh-CN.md)。本文保留初次实时宿主接入时的验证范围。

域着色数值宿主现已接入真实 Generator、Worker 和生成队列。它拥有连续播放状态、暂停快照、完整 Apply 配置和构建时捕获的公式标注。**主界面暂未切换到这条实时路径**；拖拽、参数热编辑、当前帧 PNG 和录制还需要共同接入，现有界面继续使用固定帧回放。

## 本轮实现

- 播放使用实际传入的墙钟间隔，参数动画单独消费 Float32 绘制帧率；不把时间线 FPS 当成实际绘制帧率。
- 暂停后的重复绘制和调整尺寸只渲染当前数值快照，不增加更新序号，也不消费新的帧率观察值。初次暂停绘制和暂停 Apply 仍建立第 0 次更新。
- 完整 Apply 在运行或暂停时都重建队列、对象和公式标注。相同配置版本下的编辑草稿不会混入已应用场景；连续请求合并时保留对应 Apply 的完整快照。
- 播放控制绑定确切的已完成帧。旧帧、错误响应身份、坏数值和无法确认的失败会被拒绝；不把不确定的后台状态继续当成可用预览。
- 单独补上数值层的暂停平移／缩放，以及通用参数值热编辑。热编辑恢复配置中的视口、清空并停止参数动画，但保留已运行的队列、旋转、渐变和动画写入的其他自定义参数。这些新编辑接口尚未接入界面和 Worker 操作。

输出中的 `domainLive` 区分数值更新与重绘快照。`domainRender.sourceClock` 来自同一生产者；实时输出里的 `simulationFps` 只是文档固定回放配置，不能用于反推本帧真实间隔。显示层直接使用生产者交付的配置和数值事实，避免再次按请求时间解释草稿。

## 原版证据与边界

核对目标仍为 MathArt 1.7.8，JAR SHA-256：`a6e1da3acfc05c347d2529c1d590657e2dd798e16d38c55df3dc61312be24018`。

本轮重新核对 12 个相关类与原着色器。完整原文、方法范围和哈希保存在 `.cache/domain-display-source/`。这里的界面路由及覆盖结论来自字节码、调用关系和 shader，**没有新增原版 GUI／GL 执行证据**。

| 用户操作 | 原版路径及实现约束 |
| --- | --- |
| 暂停拖动、滚轮 | 直接修改当前 Domain 对象中心／缩放；保留队列和配置。平移不逆旋转，滚轮不以鼠标位置为中心。 |
| 属性面板中心、缩放、主公式等普通编辑 | 虽标为 LIVE_VISUAL，实际回调执行完整 Apply；暂停也重建。 |
| 通用参数数值修改 | 修改保留配置的参数图，再对同一对象执行 applyConfig；不能简化成单个标量 setter。 |
| 迭代 nextFormula | 暂存，等待显式 Apply 或另一次完整 Apply。 |

Domain 正常 GPU 绘制覆盖完整逻辑画布，fragment alpha 为 1 且没有 discard；CPU 路径写满 RGB 图像。由此推导，成功绘制会盖住之前的淡化／累积历史，随后才叠加公式。本轮没有仅因 accumulation=true 增加可见拖尾。原版抗锯齿边缘、异常 blend 状态和失败路径尚未做 GL 实测。

参数动画对 scale 和曲线只写对象字段，自定义公式参数则写入保留配置的参数图。这一区别决定热编辑应恢复哪些值、保留哪些值，已经在数值拥有者处处理。渲染常量缓存、热编译和原版文字绘制仍不在这个数值接口的验证范围。

## 验证方式

`scripts/verify-source-domain-live.mjs` 在无窗口 Chrome 中运行未替换的生产 Generator、Worker、队列和 CPU／WebGL 渲染器，检查：

- 初次零间隔、连续旋转、暂停像素不变、恢复排除暂停时长；
- 暂停 Apply 重建、公式捕获、草稿隔离、输出无对象别名；
- 显式固定帧重建与实时更新的区别；
- 过期帧控制拒绝、失败后后台实例退役、全新实例恢复；
- 队列合并不丢 Apply 配置、不发布过时帧，元数据编辑复用已完成帧。

恶意／损坏的响应另经客户端边界测试，涵盖身份、暂停值、帧率、缺失时钟、源时钟冲突、公式、尺寸和快照间隔；检查错误会结束待处理请求，避免无限等待。数值层测试覆盖暂停与录制拒绝、精度、配置恢复、参数动画生命周期、预算失败和显式恢复。

测试脚本的时间戳与帧率是明确注入的输入；局部像素重复性不代表原版像素一致。新增原版观察仍以[此前宿主验证记录](source-domain-host-validation.zh-CN.md)所述范围为准。

实际执行结果：全量 **7,495 项／397 个文件通过**，`npm run build` 通过（保留已有的大包体提示）。真实 Worker 验证通过，运行前后源码哈希一致，浏览器无异常，浏览器和 Vite 均正常关闭。

现有主界面的固定回放也重新通过实际导入、播放／暂停、时间定位、动作编辑、保存重载和 PNG 下载检查；PNG 与冷启动渲染逐字节一致。记录位于 `.cache/domain-fixed-regression-after-live/report.json`。这保证当前界面路径没有因新基础设施接入而丢失已验证行为，并不表示界面已使用实时宿主。

本机这次 79×53 小图完整验证耗时约 **3.41 秒**；采样到的进程族 CPU 为 **11.36 秒**，同时 RSS 峰值约 **1.55 GiB**。单次请求冷／暖耗时：CPU 338.7／5.5 ms，WebGL 312.3／8.6 ms。冷请求包含新 Worker，浏览器模块和驱动缓存可能已经温热；暖请求复用同一 Worker，并重新渲染图像。这是一次小图验证的观测，不能外推高分辨率性能，也不是与旧固定回放的等价加速比较。

进程采样目标间隔为 50 ms，可能漏掉短命进程和瞬时峰值，共享页可能重复计数；结束后没有采样到的任务进程遗留。完整 Agent token 成本和 VRAM 未测量。机器可读结果保存在 `.cache/domain-live-public-final/report.json`、`.cache/domain-live-public-measure.json` 和 `.cache/domain-live-full-tests.json`。
