# 原版 Mandelbrot 剩余像素差异核对

2026-10-22。本轮将固定 Mandelbrot 样例的差异定位到宽高比倒数舍入与双浮点补偿运算。组合诊断变体已使这个样例的颜色、最终轨道和退出结果完全一致，但其单精度退化不满足深缩放要求，尚没有可集成的修复。产品 shader、验收阈值均未修改；分形整图及整个场景家族仍未通过一致性验收。

## 结论与范围

原版实际片段着色器只适配 GLSL 接口后，在浏览器中的结果与产品数学区域完全一致，却仍与原版相差 **411 个像素**。本轮独立原生 RGBA8 渲染与原版数学区域 **0 像素差异**；独立诊断输出的 UV 和初始双浮点坐标也逐位一致。随后迭代产生差异，且“迭代次数或退出类型不同”的位置与 411 个 RGBA8 差异像素位置完全重合。

显式关闭 ANGLE 程序缓存后，411 个 RGBA8 差异仍存在，但原先浮点颜色与字节颜色不一致的现象消失。以下结论以这次缓存控制结果为准。这些观察将调查重点缩小到双浮点算术及其编译执行上下文。尚不能判定具体是融合运算、表达式重排、优化器还是其他后端行为，也不能将独立诊断的中间值直接等同于未插桩完整程序内的中间值。

范围仅为原版 `Fractal/mandelbrot.json`，500 × 600，时间 0、zoom 0.5、普通迭代路径、暂停后第 3 帧的稳定 LUT 状态；不覆盖 Newton、Nova、其他公式、深缩放或扰动路径。

## 先校准原图，再比较数值

原生环境为 Apple M2 Max、OpenGL `4.1 Metal - 90.5`；浏览器为同机 ANGLE Metal。使用已确认的下载应用制品，未使用 `/Applications` 下未知副本。

每次原生诊断前先运行原场景 7 次暂停渲染，并核对原始第 3 帧和实际片段源码 SHA-256：

| 项目 | SHA-256 |
| --- | --- |
| 原输入 | `d99ae18ff13011177ee9f0bc2d5f3b1c32a84a5948747d0badf3e0b57ad34207` |
| 原始 PNG | `b66e0de1027809b005f13cad39770dd88026119f8d66db9e06b95d6729993190` |
| 实际 fragment | `57422453d479882bcb4cf296ce115c7d3fa9110048583497bf10cc52dec58188` |

两次运行均匹配。独立 GL 程序使用实际 uniforms、原版实际梯度纹理、四角精确为 0/1 的 UV 和原变换矩阵。完整颜色着色器直接写入 RGBA8 FBO，再与原始 PNG 的固定数学区域 `[55,55,445,510)` 比较，177450 个像素全部一致。区域只用于避开原版水印；原始 PNG 未修改。本轮未直接捕获原场景 VBO，因此这是经过颜色输出校准的独立绘制证据。

## 数值诊断结果

以下统计均为独立缓冲区全部 300000 个像素。除最终颜色字节外，中间量写入 RGBA32F，保存小端、由下到上的原始浮点数据；没有通过 PNG 量化中间值。

| 输出边界 | 原生与浏览器不同像素 | 说明 |
| --- | ---: | --- |
| UV、变换后坐标 | 0 | 4 分量逐位相同 |
| 初始双浮点常量 | 0 | 实部及虚部的高、低字逐位相同 |
| 第 1 次迭代 | 250242 | 最大分量差约 2.38 × 10⁻⁷ |
| 第 8 次迭代 | 300000 | 最大分量差约 4.23 × 10⁻⁴ |
| 最终轨道 | 300000 | 含低字表示差异，不代表全部颜色不同 |
| 迭代次数或退出类型 | 411 | 与 RGBA8 差异位置完全重合 |
| 最终 RGBA8 颜色 | 411 | 最大通道差 217 |

原生初始常量、第 1 次、第 8 次及最终轨道诊断中的实部、虚部低字均数值为 0。浏览器在第 1 次迭代已有 125870 个像素的实部低字非 0，后续更多。这只是当前诊断程序的实测现象，不能据此把产品双浮点实现替换成单精度。

另一个浏览器受控实验将原生初始常量以 RGBA32F 纹理、`texelFetch` 精确注入浏览器迭代输入。第 1 次迭代因此变成逐位相同，但第 8 次仍有 299990 个像素不同，最终 RGBA8 仍差 337 个像素。初始常量单独输出相同、内联使用却不同，说明插桩及表达式上下文本身会影响观察，不能简单归因于输入坐标错误。

## 程序缓存控制修正了 FBO 格式观察

检查首轮 `browser.mjs` 后发现其 launch args 只有 `--disable-features=WebAssemblyTrapHandler`，未启用产品桌面端已有的 `disableProgramCaching`。因此复用全部原生捕获，在全新、独立临时 profile 的 headless Chrome 155.0.8059.85 中重跑 14 个诊断输出。CDP 返回的实际命令行确认包含：

```text
--enable-automation
--disable-features=WebAssemblyTrapHandler
--enable-angle-features=disableProgramCaching
```

`--enable-automation` 用于允许 CDP 读取实际命令行；渲染器仍为 ANGLE Metal Apple M2 Max。未重跑原生程序，也未修改 shader 或 uniforms。

| 检查项 | 未显式关闭程序缓存 | 显式关闭程序缓存 |
| --- | ---: | ---: |
| RGBA8 对原生不同像素 | 411 | 411 |
| 原生常量注入后 RGBA8 不同像素 | 337 | 337 |
| RGBA32F 对原生不同像素 | 272 | 411 |
| 原生常量注入后 RGBA32F 不同像素 | 272 | 337 |
| 浏览器浮点颜色取整与直接 RGBA8 不同像素 | 408 | 0 |

控制运行中，UV、初始常量、全部迭代/退出诊断、RGBA8 以及对应常量注入输出均与首轮文件逐字节相同，只有两个浮点颜色输出改变。RGBA32F 与 RGBA8 的差异位置现在一致，并与 411 个迭代/退出差异位置完全重合。原生浮点颜色取整与原生 RGBA8 始终一致。

因此，旧观察中的“相同 fragment、不同 FBO 输出不一致”受程序缓存控制影响，不能归因为 FBO 格式本身或普通量化误差。关闭缓存消除了该诊断混杂因素，却没有消除当前原生与浏览器的 411 个实际颜色差异。上述中间值仍来自独立诊断程序，不能证明完整程序内每个中间表达式的实际值。

## “低字置零”假设实验

仅在浏览器诊断副本中，将 `ds_add/sub/mul/div/sqr` 改为高字 float 运算、低字返回 0。该变体没有进入产品。

| 比较项 | 原浏览器程序 | 低字置零变体 |
| --- | ---: | ---: |
| 第 1 次迭代不同像素 | 250242 | 172453 |
| 迭代次数或退出类型不同像素 | 411 | 220 |
| RGBA8 不同像素 | 411 | 220 |

上表首先来自未显式关闭程序缓存的早期实验。后续算术实验在关闭程序缓存后复现了 220 个差异，详见下节。单独低字置零没有复现原版，也不能成为牺牲深缩放精度的修复依据。

## 后续算术定位：宽高比舍入与补偿项

继续复用同一原生捕获，仅执行浏览器诊断。所有新浏览器均以实际命令行确认 `--enable-angle-features=disableProgramCaching`，使用独立临时 profile；没有再次启动原版。

先分别将一个 DS 函数替换为高字 float 运算、低字 0，只观察首轮迭代与完整 RGBA8：

| 诊断替换 | RGBA8 不同像素 |
| --- | ---: |
| 原表达式 | 411 |
| 仅 `ds_add` | 380 |
| 仅 `ds_sub` | 410 |
| 仅 `ds_mul` | 410 |
| 仅 `ds_sqr` | 400 |
| 全部五个 DS 运算，包括除法 | 220 |
| 保留原高字计算，仅把返回低字置 0 | 220 |

单独简化加法后，首轮低字差消失，但实部高字仍有 172453 个像素不同。使用已捕获的 `vUv`，以 CPU float32 按相同步骤计算坐标，定位到宽高比的 1 ULP 差异：

```text
float32(500 / 600)                  = 0.8333333134651184
float32(500 * float32(1 / 600))      = 0.8333333730697632
```

第一种宽高比的坐标高字与浏览器首轮高字在全部像素上相同，第二种与原生初始常量、首轮高字在全部像素上相同。这里是在已有捕获值上验证数值等价关系，并非直接读取完整原生程序内的 aspect 寄存器。

随后用两种浏览器干预分别验证：将 aspect 改为 `u_resolution.x * (1.0 / max(u_resolution.y, 1.0))`；或者通过独立 uniform 传入上述倒数乘法结果。两者结果一致：

| 诊断变体 | 首轮高字不同像素 | 首轮低字不同像素 | RGBA8 不同像素 |
| --- | ---: | ---: | ---: |
| 原表达式 | 172453 | 125870 | 411 |
| 仅修正 aspect 舍入 | 0 | 138085 | 356 |
| 修正 aspect + DS 高字 float、低字 0 | 0 | 0 | 0 |

最后只追加最终轨道与迭代退出两个输出。组合变体的最终轨道四个 float 分量，以及 `iteration / exitKind / realHigh / imagHigh` 四个分量，在全部 300000 像素上均与原生逐位相同。这建立了固定样例的完整数值复现，而非只凑合颜色。

`WEBGL_debug_shaders` 返回的实际 Metal 源码也已保存，其中仍包含 DS 拆分、补偿和低字计算表达式。因此现有证据不能声称 ANGLE 在 GLSL→MSL 翻译阶段删除了补偿，更不能确定原生后端具体采用了哪一个优化 pass。独立 UV 输出与内联迭代的差异仍须保留上下文限定。

**尚不集成这些诊断替换。** 它们只验证普通尺度、初始低字为 0 的一个样例；将 DS 退化为单精度会改变精度契约，非零输入低字和深缩放未验。aspect 的倒数舍入已在此尺寸得到数值证据，但跨尺寸、旋转及其他公式尚未验证，也未作全局替换。后续生产方案需要明确原版的运算精度选择边界，不能仅凭此样例的 0 差异开一个浅缩放特例。

源码推导还指出一个关键区别：**输出低字为 0，不等于输入低字被忽略。** 若假设允许实数代数式重排，使误差补偿消去，`ds_add` 的 `t2` 仍保留 `a.y + b.y`；`ds_mul` 的高字仍可能保留 `a.x*b.y + a.y*b.x + a.y*b.y`，平方同理。实际浮点求值顺序另需验证。这只是有条件的代数推导，不是原生机器码观测。当前用高字单精度替换整段函数的实验会丢弃这些输入低字，所以不能把它称为正确的原生降阶模型。保留非零输入低字的贡献，是后续跨深缩放验证与生产方案必须解决的边界。
