# 域着色：实时宿主与录制数值验证

本轮补上了原版实时暂停／恢复和录制时钟的执行证据，并新增对应的数值宿主。**尚未把这个宿主接入界面或编码器**；现有生产预览继续使用已验证的固定帧路径。2.0 原版整窗对照仍为 **0/11**。

## 原版执行确认了什么

### 实时播放

直接执行安装包里的 `Scene.update` 实时分支，以及 `MathArt.togglePause`、`forceResume`：

- 第一次更新时间为零；若毫秒值恰好为 0，下一次仍会命中原版零值哨兵。
- 暂停和暂停中的更新不读取毫秒时钟，不推进对象。
- 普通恢复会重新设置计时起点。例如在 3000 ms 恢复、3016 ms 更新，间隔为 Float32 的约 0.016 秒。
- `forceResume` 不重置旧计时。它不能与普通恢复共用同一种实现，否则会漏掉下一帧的时间间隔。
- 同毫秒、系统时间倒退和有符号 32 位毫秒回绕均保留原版行为。负间隔可以倒退场景时间，但域对象只在正间隔时推进参数、渐变和旋转。

每次探针包含 3 组、26 次确定性操作（20 次更新、5 次切换暂停、1 次强制恢复），另含 12 次使用原 `PApplet.millis()` 的操作；全部执行两次。确定性组只覆写了本地子类的 `millis()` 返回值和调用计数，原场景与暂停方法没有替换。真实时钟组使用原 `millis()`，通过 `millisOffset` 定位并记录调用前后的时间，不声称墙钟本身具有确定性。

### 录制

实际调用原 `MathArt.startRecording`、`getEffectiveFps`、`Scene.setRenderMode`、域场景更新和 `isAutoRecordingComplete`。配置录制 60 FPS 时，`getEffectiveFps()` 返回 60，但域参数仍读取继承的 `PApplet.frameRate` 字段。

| 注入的实际绘制帧率 | 6 次固定更新后的参数 a | 同期旋转角度 |
| --- | ---: | ---: |
| 37 | 0.0862261309960525 | 0.11666666716337204 |
| 24 | 0.055970738171804736 | 0.11666666716337204 |
| 37／24／12 序列 | 0.0511998293591382 | 0.11666666716337204 |

所以，录制模拟步长与参数动画帧率必须是两个独立输入，不能套用分形的有效帧率替代规则。

7 组、23 次原版更新也覆盖了空队列、零等待、一个固定步长等待和两个固定步长等待。前三者第一次更新即完成，最后一种第二次完成。结合静态确认的“丢弃首个预热帧”顺序，推导可供编码的帧数分别为 0、0、0、1；**探针没有实际执行预热绘制或编码器，不能把这些数当成已生成的视频帧数**。

## 新代码与验证范围

`SourceDomainHostSession` 现在分别持有墙钟、完整加载配置和运行中的队列／对象，支持：

- 普通暂停／恢复与强制恢复的不同计时行为。
- 暂停或运行中完整 Apply 都重新创建场景；保持当前暂停状态。输入必须是新配置，不是已求值的显示快照。
- 录制从完整加载配置重新开始，区分预热与后续序号，要求调用者提供实际参数帧率。
- 录制结束只重设墙钟起点，保留最后的数值状态；不额外推进或恢复旧预览。
- 录制句柄按对象身份归属，拒绝伪造、旧句柄和乱序推进；失败后必须重建。一次重建共享有界工作预算。

13 个相关测试文件、**155 项通过**，包括与原版 26 次实时操作和 23 次录制更新逐项比较，以及已有分形、Map、Samila 和导航时钟的回归测试。浮点状态按 Float32 位模式比较，参数双精度结果保留 Java Math／JavaScript 末位差异的容差。本轮没有重复运行上一轮的 7,442 项全量测试。

`npm run build` 已通过类型检查与 Vite 构建，保留既有大体积 bundle 提示。原版实时探针耗时约 0.958／0.375 秒，录制探针约 1.106／0.372 秒；全部正常退出、stderr 为空且进程已回收。它们不是受控冷暖性能基准，未测 CPU、进程家族峰值内存或 token 成本。

## 尚未证明的范围

完整 Apply 的原 UI 导出、重建、暂停首绘，以及录制的重建／预热／最终编码顺序，目前是已核对的静态路由，加上局部真实方法执行；未执行完整原 `MathArt.draw`、GL 或编码器。JNI 初始化了必要字段，没有调用 MathArt、域配置和域对象的完整构造。

Domain 还可启用宿主累积画布（默认关闭、默认 fade 为 6），公式标注在完整构造时捕获。接入实时预览前必须保留这些显示层生命周期，不能直接复用 Map 的清屏策略，也不能把数值重载视为编码器或 GPU 资源已经清理。接入录制时，需等待编码器完成后才结束数值录制。

本轮桌面检查仍返回 Mac 已锁定。未移动窗口、发送输入、捕获原版画面或更改已安装的 Apple Silicon 1.0 应用。
