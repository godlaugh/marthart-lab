# 隐式曲面剩余栅格差异定位

日期：2026-10-22，基线 `aa392e7`。本轮仅调查，没有修改生产渲染代码，也没有放宽验收规则。原始图中心仍有 28 个不同像素；上一轮实际增强 PNG 中心仍有 135 个不同像素。全家族整图验收仍为 0/11。

## 已实际确认的范围

比较继续使用同一原版 fixture、500×600 输出及中心区域 `[55,55,445,510]`。基线原始图 RGB MAE 为 `0.001645533953226261`，最大通道差 26。已有完整 CPU Marching Cubes 世界坐标、颜色、retained 线条缓冲及原版实际 GL uniforms 继续复用；本轮重新确认 modelview 与 projection 的 Float32 值相等。

通过正常许可原版的一次有界离屏运行，临时隐藏 retained PShape 得到纯填充，再恢复可见性并通过原版填充开关得到纯线条，最后恢复原状态。原版恢复前后正常图 PNG 字节完全相同。产品使用真实生成及渲染 owner，在 headless Chrome 中分别绘制对应层：

| 比较 | 中心不同 RGBA 像素 | RGB MAE |
| --- | ---: | ---: |
| 原版纯填充 / 产品纯填充 | 0 | 0 |
| 原版纯线条 / 产品纯线条 | 0 | 0 |
| 原版组合 / 产品组合 | 28 | 0.001645533953226261 |

因此，已观察到的差异只在两层共同绘制时出现。单层颜色图相等不代表其深度缓冲相等，不能据此宣称深度实现已经一致。

第一次原版诊断尝试把输入改成 `SOLID` 以隐藏线条，但该配置未能关闭线条，所得 `native-implicit/fill.png` 是无效的分层证据。它保留在缓存中，不计入上表。上表只使用随后纠正的 `corrected/native-implicit/fill.png` 和 `lines.png`。

## 已排除的简单解释

真实 retained 四顶点、六索引展开绘制，与生产紧凑实例化绘制图像完全相同；改变缓冲表示不能消除差异。WebGL 默认 framebuffer 报告 depth 24、stencil 0、samples 0；另建 stencil 8 的上下文后 depth 仍为 24、samples 仍为 0，组合图差异仍为同样 28 个像素。原版诊断请求的离屏配置为 depth 24、stencil 8，不能将请求值冒充所有内部附件的格式实测。

反转两层顺序得到 18,032 个中心差异像素，明显不匹配。保留的 `PGraphicsOpenGL.shape` 字节码也显示 retained shape 绘制前先执行 `flush()`，因此没有采用“先线条后填充”的修改。关闭线条深度测试会出现大量本应被遮挡的线段，亦不是修复。

## 浮点差异真实存在，但没有解释当前像素

在原版实际 OpenGL 上，以相同 LineVert、原版 uniforms、retained positions/directions，通过独立程序与 transform feedback 捕获全部 81,024 个 clip 顶点。诊断程序恢复 GL 状态，未修改应用着色器或原版文件。WebGL2 使用相同输入及等价 GLSL 捕获比较：50,300 个顶点至少一个分量不同；x/y/z 分量分别有 9,463 / 36,468 / 21,076 个不同值，w 全部相等。

该例深度分量的完整数值检验支持以下两种计算结果。令 F 为 Float32 舍入，z 为 eye z，s 为 F(0.999)，a/b 为投影系数：

- 原版所有顶点符合 `F(F(F(z*s)*a)+b)`。
- ANGLE Metal 所有顶点符合对 `z * F(s*a) + b` 的融合乘加结果。

这是本设备和本次 shader 输入的观察，不是所有 OpenGL/Metal 程序的通用语义结论。诊断中的运行时 uint 位屏障可使所有 z/w 与原版相同，但分别加在线条、填充或二者后，组合图仍是完全相同的 28 个差异像素。`invariant gl_Position` 与 invariant pragma 也未改变结果。

进一步直接重放原版捕获的全部线条 clip 顶点，消除线条顶点计算差异后，单层仍相等，组合仍有同样 28 个差异。再把填充按现有 CPU eye 坐标与逐步 F32 投影预计算为 clip 坐标也没有改善；这些填充 clip 是推导值，并非原版填充 transform feedback 实测，不能与线条实测混称。

因此没有把数值屏障、反转顺序或顶点展开集成进生产代码。它们增加复杂度，却未改善实际目标。

## 当前未知与下一次有效取证边界

证据将问题缩小到两层组合时的深度/栅格交互，但尚未证明是硬件插值、深度量化、原版填充提交缓冲，还是其他仍未捕获的绘制状态。原版是 Apple M2 Max OpenGL，浏览器是同设备上的 ANGLE Metal；后端不同只是事实，不足以作为根因结论。

若继续，应针对相同 draw 的实际填充提交后顶点、深度附件格式及相关深度样本取证，区分提交数据与光栅化结果。无需重做已经全等的 MC 世界几何、颜色或单层截图，也不能依据这 28 个像素直接添加偏移、颜色或容差补丁。
