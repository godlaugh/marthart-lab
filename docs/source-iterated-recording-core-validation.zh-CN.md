# Map／Symmetry 源录制核心验证

2026-10-21。两个场景已共用按原包规则运行的录制核心，实际 WebGL 验证通过。**当前未接入公开 Worker 录制协议、导出按钮和编码器；现有界面 MP4 仍是独立固定时间回放。** 2.0 仍处于 M3，原版完整窗口验收为 0/11。

## 原包证据

固定 MathArt Studio 1.7.8 JAR SHA-256 为 a6e1da3acfc05c347d2529c1d590657e2dd798e16d38c55df3dc61312be24018。本轮重新核对 14 个类的身份及方法指令，证据存于 .cache/source-map-lifecycle/recording-audit.md；属于静态审查，没有执行原版窗口。

| 原版规则 | 本地核心实现 |
|---|---|
| 工具栏先 reset，再 start recording | 从会话最后应用的配置重新构造，保留当前名称等无关元数据；热编辑不自动变成录制初值 |
| 场景固定步长为 Float32(1/fps) | 独立标记固定录制时钟，不借用实时时间戳或 seek |
| 每帧只渲染导出画布，主窗口显示它的副本 | 核心只产生一次 offscreen display，未插入主画布显示；窗口复制由后续消费端完成 |
| 第一帧渲染后丢弃，再检查结束条件 | 返回真实预热帧及 warmup 标记；空／极短队列允许零个可编码帧 |
| Map／Symmetry 继承队列完成条件 | 队列完成帧仍交付，不因参数漂移或 replay 延长视频 |
| 队列未结束时每帧两次对象更新，已结束一次 | 两种更新均进入实际 GPU；粒子 burn-in 与宿主丢弃预热帧分开计数 |
| stop 不暂停，不恢复旧相机 | 保留最终粒子、墨迹、相机和队列，只重设实时钟的 lastTime |
| 视频 exportScaleFactor 原包默认 3，未发现 UI 写入口 | 输入目标采用 3 倍几何尺寸，按父画布密度进行 Float32 舍入；不执行 PNG 增强或 PNG 放大 |

Map／Symmetry 的宿主 Scene 每帧硬清背景，因此不依赖此前宿主导出画布的像素历史；仍须保留 Mobject 内部累积状态。录制结束后恢复主视图时，尺寸变化可清空内部墨迹，这不能误当作重新开始粒子模拟。

最后应用的配置现有独立快照，和每次热编辑后的作者输入分开。共享初始化函数统一负责普通重建与录制重建，未复制一份 GPU／时间线实现。快照的估计保留字节计入会话诊断。

## 实际执行的验证

- 17 组独立有限 Wait 时钟参考 × Map／Symmetry，共 34 组实际 WebGL 录制。覆盖空队列、零／负／极短时长、多片段、恰好一个时间步、Float32 相邻值以及一秒 24／60 fps。
- 逐帧比较独立参考的 rawDt、sceneTime、队列索引、完成标志、预热／编码帧数；独立 Float32 递推核对 4,096 个粒子分量。初始种子使用本地已有生产者，该生产者另有此前 JVM 夹具证据；本轮不声称重新验证原版 RNG。
- 检查一帧一次导出显示、粒子预热只执行一次、录制尺寸、连续帧序号、禁止完成后追加帧、错误录制身份拒绝。
- 两个场景分别验证热变换／点尺寸后从已应用配置重建、保留名称、DPR 2 的 17×13 请求生成 52×40 输入目标、提前停止、相机继续运动、显式暂停、取消清理。
- 注入释放失败后保留录制句柄所有权，拒绝继续生成；重试清理成功后才解除所有权。
- 录制预检拒绝超大目标、伪造主预览宽度／高度／quality，原已完成预览仍可用。
- Map 实时核心／实际 Worker 和 Symmetry 实时核心／实际 Worker 回归通过；包括既有变尺寸暂停截图。
- 完整源码测试 352 个文件、6,638 项通过。随后补齐主预览身份检查，重新运行录制 GPU、两个实时／Worker 回归及 TypeScript／Web 构建，均通过；没有重复运行整套源码测试。

首次 GPU 检查因 Symmetry 测试输入使用了不完整的 runtime-config 导入入口而未进入源会话，改用原公开项目导入后通过；产品未为该测试放宽准入条件。

## 审查修复

独立审查发现 completed primary 身份没有绑定物理宽高与 quality，但录制又使用调用者宽高作为主画布亮度参考。已在共享身份所有者加入这三项。暂停截图入口的宽高／quality 本来表示导出目标，因此其校验从已完成上下文获取对应主画布字段，保持合法变尺寸导出，同时严格校验其余事实。没有仅在录制按钮处添加孤立的补丁。

## 尚待完成

后续需要把 begin／frame／finish 接入实际 Worker 和生成队列，明确零编码帧、编码器失败、窗口关闭、取消和结束响应失败时的恢复责任，再通过公开按钮生成／解码真实视频。消费端还需处理三倍输入与请求输出尺寸之间的编码缩放，以及停止后继续实时播放的状态同步。本文没有将核心检查计为端到端视频验收。

本地编辑器的 Apply 暂存和参数热更新仍与原版存在差异；当前应用快照以实际会话重建事件为边界，不冒充原版所有 UI 事件均已接通。没有原生 GUI 操作，本轮不重复查询锁屏状态；现有 Apple Silicon 1.0 应用未重打包。
