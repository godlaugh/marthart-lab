# 曲面粒子、相机跟踪与拖尾验证

本记录对应 2.0 开发分支的曲面 CPU 点模式。1.0 Apple Silicon 应用包未更新。其余 11 类场景补全与原版效果一致性仍是未完成目标。

## 已实现的行为

导入含有效 `track` 动作的原版 SURFACE JSON 时，CPU POINTS 作品使用显式粒子版本 `mathart-1.7.8-points-v1`。静态拖尾已接入，原版缺省设置为显示拖尾、开启渐隐、寿命 4 秒、线宽 1。

- 两个参数轴均使用半开采样范围，索引为 `U编号 × V数量 + V编号`。不再以另一套本地采样顺序解释跟踪索引。
- 位置、速度与边界处理按源 Float32 运算顺序更新。周期流动使用余数回绕；周期反弹仅在严格越界时反转速度，并丢弃越界余量、夹到边界。
- 绘图和相机跟踪使用同一生产者的位置。过渡更新先读旧位置，粒子更新后相机控制器再读取当前位置；等待片段继续更新粒子，队列完成后的帧不再推进粒子。
- 表达式复用编译结果和变量槽，自定义参数可遮蔽 `u`、`v`。不会凭空增加原版公式没有的时间变量。
- 导入先解析时间线结构，再选定几何字段的解析路径。同一字段不再先由本地解析器处理、再被源规则覆盖。关闭的片段不读取其类型、时长或动作。
- 编辑器支持粒子索引；尚未接入的参数/渐变动画、动态拖尾录制片段、GPU 和网格模式不会被替换为另一种已实现效果。取消或运算失败后的粒子实例无法继续发布部分位置。

拖尾由同一粒子状态生成，保留源程序的以下规则：

- 严格越界时记录出口、断点、入口和最终位置；断点两侧及不同粒子之间不会连线。恰好到达最大端点时会回绕但不插入断点，这是源规则本身的行为。
- 每条记录使用当前帧时间；先追加，再删除年龄严格大于寿命的记录。队列结束后不再推进或过期。每粒子还受源容量 `max(0, int32(float32(寿命×60))+120)` 限制，保留原有溢出规则。
- 渐隐按记录顺序计算，断点也计入分母；不是按年龄计算。输出透明度保留源 8 位量化规则。
- 线宽按 Float32 的 `max(0.1, 线宽×0.95)` 计算，拖尾在点之后覆盖绘制，关闭深度测试。原生线条栅格化尚未对照。
- 显示、录制开关当前是整段重放设置；编辑后从头重建历史。原版 JSON 没有读取 `record_trails` 字段，初始录制为开启；时间线中途开关录制仍待实现。

既有本地作品、此前只接入源相机的作品，以及没有有效跟踪动作的新导入作品，保持各自已有采样行为。本批没有宣称全部曲面都已迁移。

## 实际执行的验证

1. 29 个测试文件、515 项测试通过。覆盖源公式、标量、导入、数字原文保存、曲面运动、相机队列、时间线及旧作品兼容；新增拖尾越界、双轴不同越界时刻、非有限出口、严格过期、容量、透明度与取消覆盖。
2. 独立的 3×5 网格金标检查半开范围、索引、边界反弹、回绕、分步 Float32 缩放，以及跟踪与几何的位置关系。这些金标根据保留产物的指令推导，未运行原版应用。
3. 实际 Chrome App 导入、初始相机编辑、重开、粒子索引 7→6→7 编辑及 PNG 导出通过。拖尾版本另外检查时间跳转、关闭显示后无历史输出、重新开启后重建线段，以及“按记录顺序渐隐”控件。
4. 实际 Worker 在 0、0.25、0.75、2 秒及返回 0.25 秒的请求中返回相同编号规则；过渡完成后，相机中心与输出中被跟踪粒子的坐标完全一致。
5. 关闭拖尾和开启拖尾分别验证：实际下载的 257×193 PNG、隔离导出服务保存的文件、独立冷 Worker/渲染器生成的文件，SHA-256 相同。人工查看拖尾图确认包含可见线条，渲染器检查确认线宽及覆盖顺序。本项证明本地预览/导出流程内部一致，不能替代原版画面对比。

`npm run build` 通过（仍有既有的大文件体积提示），另外 11 组实际普通相机 Worker/渲染器回归通过。

执行入口：

```sh
node scripts/verify-ordinary-source-camera-export.mjs --surface-particles
node scripts/verify-ordinary-source-camera-export.mjs --surface-trails
node scripts/verify-ordinary-source-camera.mjs
node scripts/benchmark-source-surface.mjs --trails
```

上述浏览器验证需要本机 Chrome；过程使用隔离导出服务目录，不覆盖用户作品。

## 本机成本测量

公式任务为 30,000 个点、每点三条相同公式，共 90,000 次 Double 求值。两条路径输出字节哈希一致。编译和模块加载不计入任务计时，首次任务标记为冷，后两次保留运行时/JIT 状态。

| 路径 | 首次耗时 | 后两次耗时 | 首次 CPU 时间 | 后两次 CPU 时间 | 进程峰值 RSS |
|---|---:|---:|---:|---:|---:|
| 每次使用既有源标量解析器 | 143.6 ms | 125.3–126.4 ms | 194.5 ms | 129.6–134.8 ms | 242.6–243.1 MiB |
| 编译一次后更新变量槽 | 13.8 ms | 10.4–15.1 ms | 20.3 ms | 16.7–24.8 ms | 164.2–178.7 MiB |

另测完整本地任务：导入、保存重开、40×20 点曲面及相机、颜色，连续请求 20 个时刻。拖尾开启后另外计算线段、透明度和颜色，全部输出纳入哈希。

| 几何任务 | 首次耗时 | 后两次耗时 | 首次 CPU 时间 | 后两次 CPU 时间 | 进程峰值 RSS |
|---|---:|---:|---:|---:|---:|
| 上次提交，无拖尾基线 | 205.5 ms | 178.6–181.4 ms | 241.0 ms | 182.4–185.8 ms | 219.0–242.4 MiB |
| 本次，无拖尾 | 209.1 ms | 178.8–182.3 ms | 251.3 ms | 182.6–186.8 ms | 221.2–243.0 MiB |
| 本次，开启拖尾 | 282.1 ms | 226.6–230.1 ms | 422.3 ms | 230.2–241.2 ms | 236.8–262.3 MiB |

无拖尾与公式任务保持此前输出哈希。新增拖尾有额外成本；没有此前等价拖尾实现或原版运行基线，不声称性能提升或原版性能等价。

每种任务使用独立 Node 进程，计时区间没有子进程；RSS 为进程累计高水位，不是单次任务新增内存。浏览器进程族内存、GPU/显存、视频编码吞吐和代理 token 成本未测量。当前每次跳转从头回放，顺序视频帧尚未复用粒子状态；不能由小任务结果推断长动画性能。

本地拖尾池最多保留 100 万条记录（含断点），分块分配；池存储最多 20 MB、每粒子索引元数据 12 字节、导出历史快照最多 28 MB。颜色和渲染器线段展开另计，这些数字不是整个进程或显存上限。每次回放另受 2000 万公式/运动工作单位限制，超过后明确报错，不截断历史冒充完整输出。

## 仍需完成

时间线动态拖尾录制、GPU 与网格目标身份、模式切换、参数/渐变动画及更大任务的性能验证。颜色、点外观、原版实时帧率、平台数学函数差异、原版应用完整静态图和逐帧动画尚未验收。非有限粒子头仍明确拒绝；非有限接缝端点已作为断点保留。负线宽仍由本地输入边界拒绝，不声称覆盖源程序对此输入的钳制显示。

源依据为 MathArt Studio 1.7.8 保留 JAR，SHA-256：`a6e1da3acfc05c347d2529c1d590657e2dd798e16d38c55df3dc61312be24018`。本批使用其静态指令证据，没有把本地测试或独立渲染器当作原版应用运行证据。重新访问原版应用窗口时，系统工具仍报告 Mac 锁定、自动解锁失败；原版窗口对照需要解锁后继续。
