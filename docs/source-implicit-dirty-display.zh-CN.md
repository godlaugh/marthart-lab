# 隐式曲面重建帧与参数动画验收

本机已对齐原版 GPU 材质在网格重建时的特殊视口行为。独立生成的 **17 张 500×600 完整数学画面及含公式画面**，与 MathArt 1.7.8 逐字节比较均为 **0 差异像素**。比较包含线框和公式，品牌水印另行保留，不计入产品艺术画面。

这项结果接续[六种稳定 GPU 材质验收](source-implicit-gpu-material.zh-CN.md)，解决此前首次显示和参数更新时画面位置不同的问题。网格仍采用原版 CPU Marching Cubes 回退；本机没有因此获得 OpenGL Compute 能力。

## 原因与修复

原版 GPU 网格计算在这台 Mac 上失败后，会恢复主画布的 GL viewport。离屏目标依然是 500×600，但当次实际绘制视口变成 810×972，数学画面及后绘制的公式都会被缩放和裁切。下一次没有重建网格的显示恢复 500×600。

判断条件是“本次显示前网格是否变脏”，不能用时间是否为 0 判断。原版对已知参数的成功写入，即使数值没有变化，也会触发重建。调色板更新本身不触发网格重建。

产品将显示序号、网格版本、是否重建和实际 viewport 交给现有时间线实例管理；历史重放、保留状态录制和截图共同使用这个实例。几何生成失败时保留待重试事实；同一个原生请求重试不会再次消费显示状态。暂停截图与随后主预览按两个显示依次处理。

原生绘图协议 v16 分开保存 framebuffer 尺寸和 GL viewport，完整帧和分块帧传递同一事实。绘制保留原投影矩阵；公式合成先完整复制数学像素，再使用本次 viewport 绘制公式。录制固定的是文字与作者布局，不把预热帧 viewport 锁死到后续帧。

## 原版与产品整图对照

输入是明确构造的 12×12×12 诊断场景，方程 `x²+y²−z²−a`，初始 `a=1`。保持原相机、调色板、线宽及公式；作者事件计划在采集前固定，包含同值参数动画、变化参数、停止动画和重复暂停显示。

| 原版帧 | 状态 | 实际 viewport | 数学／含公式整图差异 |
|---|---|---|---:|
| 0 | 初始 dirty 显示 | 810×972 | 0／0 |
| 1、2 | 稳定显示、首次更新 | 500×600 | 0／0 |
| 3、4、7 | `a` 仍为 1，但成功写入使网格变脏 | 810×972 | 0／0 |
| 5、6 | 暂停重复显示 | 500×600 | 0／0 |
| 8、9 | 参数动画停止 | 500×600 | 0／0 |

| 13–16 | 再次停止及队列完成后的重复显示 | 500×600 | 0／0 |

原版实际执行 11 次更新，队列在 2.75 秒完成。17 张原版 PNG 解码均等于完整 framebuffer；产品每帧的网格顶点、法线、参数 double 位型和实际 viewport 分别核对，完整与分块原生绘制也逐字节相等。

产品从相同源 JSON 和事先固定的作者计划独立生成，经过公开导入器、Generator、真实 Worker、原生绘制服务、独立公式字形服务及公式合成器。原版像素和属性仅在生产完成后用于比较。

**时间范围必须区分：**产品固定重放的首次请求已执行一次更新，到达 0.25 秒；原版前两张参考仍处于初始暂停、时间为 0。由于这时参数、几何与公式未变化，前两张只证明 dirty／steady 的视觉效果，不证明初始暂停时钟相同。其余 15 张同时严格核对时间、参数、队列完成状态和绘制视口。同一固定时间的重复请求也不能代替保留实例的暂停 API 验收。

## 边界与资源

底层实际 CGL 检查包括：较大 viewport 配合负原点时，小目标图像精确等于大目标的对应裁切；零宽或零高 viewport 精确等于只清屏的图像；MSAA、分块状态不匹配、超硬件限制后释放均通过。请求仍按实际 framebuffer 和缓冲分配计预算，不把 viewport 面积误算成额外画布。

绘图失败后仍可能持有原生目标。服务在发送分块 begin 前保留确切所有权；除非收到明确的所有权拒绝，否则必须等待 release 或子进程退出才清除，避免因硬件拒绝而遗失清理责任。

17 帧独立比较墙钟 14.89 秒，抽样进程族 CPU 12.56 秒、峰值 RSS 约 2.19 GiB，包含验证器、浏览器、开发服务及后端；采样错误为 0，退出后自有服务进程为 0。这是验收成本，未做等价冷暖性能基准，未测 VRAM 或本轮独立 agent token。

## 实际界面与应用包

实际界面通过正常录制、带参数公式录制和取消后重试三组流程。两组完整视频共 14 个编码帧，上传 PNG 与实际原生像素和当帧公式对应，视频解码与独立原始帧输入的 FFmpeg 编码一致。暂停、改变窗口大小、恢复播放、重复 PNG、3 倍放大、取消截图后恢复、从初始状态导出 JPEG，以及暂存后 Apply 均通过。

每帧公式使用自己的 viewport。带参数公式录制中，9 帧的公式完全落在目标之外；验收实际检查了这些字形的裁切范围，没有继续要求“每一帧必须看见公式”。这一情况与上方原版视口规则一致，不表示字形加载失败。首次检查仍采用旧可见性断言而失败，其报告保留。后续还发现多场景验收会覆盖同名截图，已改用场景专属文件名，并在退出前重新校验全部 PNG/JPEG 摘要；最终记录没有文件覆盖或摘要错误。

最终界面验证墙钟 61.85 秒，抽样进程族 CPU 105.58 秒、峰值 RSS 约 3.24 GiB，包含浏览器、开发服务、观察器和编码器。采样错误、清理错误和残留服务进程均为 0；这不是日常运行占用或吞吐量承诺。
