# 分形参数、队列与公开预览验证

2.0 仍在 M3。此轮将 Newton / Nova 的原版公式参数、普通动画、参数启停和渐变接入文档、编辑器与实际预览；原版完整窗口对照仍为 **0/11**，录像的原版预热帧和终止帧运输尚未接入。

## 可以使用的流程

原版 Newton / Nova 文件导入后，公式参数由独立的 `fractalSource` 保存，时间线按原版逐帧队列运行。参数未提供、显式空集合和填入默认值是不同状态，编辑器保留这一区别。可修改公式、传统初值、复数参数、视口、后端和精度；动画编辑器可设置普通目标、有序参数启停和渐变。

预览、时间跳转和 PNG 生成都读取同一个已求值场景。渲染器使用其传统 4 槽、动态 32 槽、整数指数和双精度 Julia 值；公式标签、配色能力和视口类型也使用同一个公式身份，不再由旧 settings 中的公式名决定。向后跳转重建参数及渐变，取消或失败不保留半完成帧。

时间线真正写入中心、缩放或旋转后，手动视口操作会给出已有的时间线控制提示。尚未开始或已停用的片段不锁定视口。未知精度值保留原文并显示，无法计算时明确报错。

已保存的旧本地分形作品仍按原有时间采样方式执行。新原版导入在时间 0 就执行首个固定步长更新；不能拿旧本地作品的中点采样代替新队列验收。

## 已执行的验证

- 公共导入、序列化、重开后，复用真实原版 JVM 的 3 组、30 次组合更新，比较队列、bailout / Julia、参数槽和渐变偏移。此轮未重新执行原版 JVM 或 GUI。
- 后台 Chrome 中通过真实文件输入、编辑控件、Worker 和 WebGL2，检查参数及渐变播放、后退重建、Newton 切换 Nova、渐变速度编辑、保存重开和 PNG 导出。
- 保存前后先匹配实际逻辑画布尺寸，再比较同一时刻的完整 native 状态和像素哈希。Nova 的阈值和坐标受实际逻辑画布尺寸影响，仅导出分辨率相同不足以构成等价比较。
- 另回归旧本地作品的放大、缩小、等倍率中心移动，编辑模式切换、目标修改、保存重开及 PNG。两种配置路径分开验证。
- 边界检查覆盖共享动作预算、无效渐变枚举、数字动作名称的原始词法保存、未来/停用视口写入、取消和倒退。未知动作名称仍按原版无操作处理，来源词法不会丢失。

最终验收：

- 全量回归：373 个文件、7,064 项通过，57.44 秒。
- `npm run build` 通过，Vite 22.53 秒；仍有既有大包体积提示。
- 后台浏览器：10 项检查通过，页面异常 0；两个 PNG 均为 257 × 193。
- 公共报告：`.cache/fractal-source-zoom-public-1792596112834/report.json`。
- 可读界面截图：同目录 `source-chain-ui.png`；验收汇总 `.cache/v2-source-fractal-public-acceptance.json`。
- `git diff --check` 通过。最终回归、构建和浏览器检查并行执行，耗时不用于前后性能比较。

## 工作量与缓存

队列与参数循环共享每次请求的工作预算；累计动作和参数名称在复制前检查。布局缓存最多保留 4 项，以规范化时长、分组规则和帧率为键；命中前仍校验当前文档，修改片段身份不会复用旧身份。

对同一条 10 段、每段 1 秒、60 fps 的完整布局调用进行了局部测量，结果一致：

| 调用 | 次数 | 墙钟时间 | CPU 时间 |
| --- | ---: | ---: | ---: |
| 无缓存，首次 | 1 | 2.69 ms | 3.80 ms |
| 有缓存，首次 | 1 | 1.70 ms | 3.09 ms |
| 无缓存，重复 | 100 | 96.13 ms | 143.58 ms |
| 有缓存，重复 | 100 | 1.67 ms | 2.86 ms |

这是布局微基准，不代表整体预览提速。Node/Vite 进程的累计峰值 RSS 为约 468–476 MiB；未隔离各次运行，也未测完整进程族峰值内存或完整任务 token 成本。记录位于 `.cache/fractal-layout-performance.json`。
