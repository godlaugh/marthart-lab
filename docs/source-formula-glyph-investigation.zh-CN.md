# 原版公式字形与窗口验证进展

2026-10-22。已找到不依赖 MathArt 产品代码的公式字形生成路径：官方 JLaTeXMath 加本项目自有封装，在 21 组输入、84 次实际执行中，与原版字形纹理的尺寸及完整 RGBA 逐字节一致。**这仍是隔离验证，尚未接入产品；2.0 处于 M3，11 类场景的原版整图验收仍为 0/11。**

## 字形差异的原因

Cornucopia 的原版公式纹理为 1100 × 259，非透明范围为 `[12,9,1085,249]`。原版使用字号 50 的 JLaTeXMath，包含自己的字体度量、分段公式行距和透明边距。本地 MathJax 的排版不同，因此不能靠统一拉高、移动或降低透明度来修正。

原版 Processing 的默认纹理路径使用非预乘 RGBA、线性放大和三线性 mipmap 缩小；透明像素 RGB 为零，边缘像素 RGB 保留指定颜色。它与直接用 Canvas 缩放 SVG 的取样、混合不同。这是打包类的静态证据，原版当前 GL 上下文是否覆盖默认 mipmap 设置尚未直接读取。

使用真实原版字形纹理做隔离 WebGL 实验，在不含水印的第三行 3,300 像素区域：普通线性采样平均绝对差约 6.796，非预乘三线性 mipmap 约 0.925；最佳模型仍有 458 个不同像素、最大差 56，不能判定通过。原图前两行被免费版水印覆盖，含水印区域的整体亮度不能用作字形验收指标。

## 独立上游实现的实际验证

独立取得的官方 `org.scilab.forge:jlatexmath:1.0.7` 与原版所带依赖的 JAR 容器摘要不同，但 278 个文件成员全部一致，其中包括 196 个 class。上游模式的 classpath 只有该官方库，不加载 MathArt 或 Processing；自有封装调用公开 TeXFormula、TeXIcon 和 BufferedImage API。

| 输入 | 原版与独立上游共同尺寸 |
| --- | ---: |
| Cornucopia | 1100 × 259 |
| Feder | 952 × 323 |
| MobiusStrip | 1038 × 353 |
| ParameterSurfaceII | 1344 × 229 |
| ParameterSurfaceV | 1343 × 319 |
| Sphere | 820 × 229 |
| x²+y² | 170 × 72 |
| 分式 | 163 × 138 |
| 平方根／立方根 | 334 × 87 |
| α、β、γ、π 数学命令 | 396 × 81 |

每种公式分别使用白色及 `#4ab37e`，短式另加纯黑，共 21 组。原版、独立上游各重复两遍，共 84 个新的有界 JVM 进程，全部尺寸与完整 RGBA 一致。所有非零 alpha 像素的 RGB 都等于指定颜色，透明像素 RGB 都为零；更换颜色不改变 alpha。

两次编译与 84 次渲染全部退出 0，没有超时，所属进程组均已回收。矩阵墙钟 43.45 秒，最多并发两个进程，每个渲染上限 45 秒、JVM 堆限 256 MiB。没有测量 CPU、进程族峰值内存、显存或完整代理成本，堆限不能当作峰值内存。

此验证仍共用原版已有的 Java 21.0.7 测试宿主；它证明可以独立于 MathArt 代码生成字形，不证明另一个发行 JRE 的像素相同。未安装系统 Java，没有把原版运行时当作发行资产。

## 原版窗口验证与清理

| 尝试 | 实际结果 |
| --- | --- |
| 默认界面后端、辅助功能按钮打开 Settings | 原版记录 `EDT-HANG` |
| 默认界面后端、截图坐标打开 Settings | 原版再次记录 `EDT-HANG`；不能归因于某一种按钮操作 |
| 仅测试进程使用打包库支持的 `SKIKO_RENDER_API=SOFTWARE` | 应用首帧就绪，无已观察到的原版 `EDT-HANG`；但窗口工具返回空辅助功能树、虚拟屏捕获超时或 `noWindowsAvailable`，不能作为可操作方案 |
| 备份正常设置后临时关闭 `debug.show_info` | 启动日志和真实 Cornucopia 画面均确认调试文字关闭，水印保留 |
| 在虚拟屏选择 Mandelbrot，暂停并 Apply | 场景名称及配置正确，作品区域为空；返回原显示器后仍空，未取得有效分形参考图 |

两次 Settings 挂起的栈都涉及 AppKit 辅助功能焦点等待，以及 AWT 中的 Skiko Metal 设备创建。记录没有给出完整原生锁关系，不能证明确切死锁原因。Mandelbrot 空画面也未建立根因，不能据此修改本地分形算法来匹配黑图。

本轮只移动了任务所属原版窗口，使用“虚拟屏 3 · MathArt Lab · 原版对照”。挂起实例的返回请求被 Yomado 拒绝并保留位置记录；软件模式和分形尝试执行了正常返回。所有本轮测试实例已核对启动身份后结束，受监督会话均以 143 退出，任务虚拟屏最终为空并保留运行。精确原窗口坐标未独立验证。虚拟屏仍共享焦点和输入，不代表完全隔离。

`settings.conf` 在测试前、恢复前均有备份；最终恢复原始字节，SHA-256 为 `6bbae3340c7189d267fa169e28633a30cf548902b6b4c9de772a113e21d61f26`。没有修改应用二进制、全局渲染后端或系统防护。

## 接下来要完成什么

产品接入需要一个共同的有界字形生成与缓存所有者，供预览、PNG、录制使用，保留字号、透明边距、非预乘 RGBA 和渲染器身份。需要验证独立来源运行时、允许的数学指令范围、取消与进程回收，以及多种缩放／像素密度／背景下的最终纹理合成。字形生成失败不能静默替换成排版不同的 MathJax 并宣称一致。

上游库和字体有各自许可声明，发行依赖时应保留完整许可与来源；未将其作为产品依赖加入。本轮没有更改产品渲染代码，没有重跑产品全量测试或构建，既有 Apple Silicon 1.0 应用未替换。
