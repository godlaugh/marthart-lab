# 隐式曲面填充与切片线验证

2026-10-22。原版 `implicit_sphere.json` 的实际公式是 `x²+y²−z²−1`。此前导入后显示大量白色三角边，遮住了原有黄、橙、红渐变；现已改为源 CPU 网格专用的无光照填充和两轴切片轮廓线。

这项修复已通过真实页面导入和 PNG 导出，但尚未达到原版整图一致，Implicit 家族仍未验收。

## 修复的产生边界

原版 WIREFRAME 配合半透明填充使用独立采样的 Marching Squares 切片线，不是填充三角网格的每条边。新产生器统一拥有线坐标、顺序、调色板字节、透明度和线宽，Worker 将完整外观数据交给渲染器。源路径不再先生成一份本地颜色再覆盖。

原版 `iso_threshold` 用于筛选粒子；网格等值面为零。导入时纠正了把粒子阈值当成网格等值面的行为，原始输入仍保留在来源记录。原版保留式线条使用构建时线宽；后来在 `beginShape` 外调用的 `strokeWeight` 被 Processing 拒绝，不能再乘一次推测的尺寸比例。

新模型只作用于新导入的 CPU mesh。已有本地作品、GPU 和 points 路径保持各自规则；切换模式保留来源标记。共享导出目标更名为 `source-offscreen-export`，曲面和此隐式路径都采用已经核验的无 MSAA 导出规则。

## 实测结果

原版 JVM 生成的两组完整切片流，分别包含 121,536 和 2,136 个 Float32，均与新产生器全部字节及顺序一致。数值 fixture 保存在 `tests/fixtures/source-implicit-presentation/native.json`；完整原生运行记录保存在 `.cache/implicit-wireframe-oracle-20261022/`。这只证明线数据，不证明 GPU 线条覆盖像素。

同一原版输入、预览逻辑尺寸 405 × 486、DPR 2、PNG 500 × 600 的实际产品对照如下。RGB 平均绝对误差按 0–255 通道值计算，越低越接近。

| 比较区域 | 修改前平均误差 | 修改后平均误差 |
| --- | ---: | ---: |
| 全图 | 35.09408 | 3.42240 |
| 固定中心区域 `[55,55,445,510]` | 55.52140 | 2.04350 |

中心区域仍有 93,357 个像素的至少一个 RGBA 通道不同；全图仍有 100,893 个。没有通过裁掉水印或放宽误差阈值宣布验收。原版参考图保持原有水印，局部指标仅帮助定位几何差异。

重新构建后再次执行真实页面导入和导出，页面无异常，PNG 摘要仍为 `90614db28a8116ea5709bcedf95470b1bb412ac5d6749e571b64c48023617d4f`。共享曲面的 Cornucopia 导出在更改前后摘要完全相同：`4eea2f11ecbfb8b1afc790428d3e017e0e64002ee12dc6483c5d1ca9c2ba0a18`。

最终 `npm run build:v2` 成功；43 个相关测试文件、839 项测试通过，覆盖隐式、导入、材质及共享曲面路径。构建仍有既有的大 bundle 提示。记录位于 `.cache/native-reference-progress-20261022/`，图片对比位于 `.cache/implicit-appearance-product-20261022/comparison.json`。

## 成本与剩余工作

同一真实导入／导出脚本、每次新浏览器进程的单次采样：修改前耗时 3.918 秒、CPU 5.777 秒、进程族峰值 RSS 1,565,212,672 字节；修改后顺序执行耗时 4.151 秒、CPU 6.056 秒、峰值 RSS 1,574,158,336 字节。并行执行的中间采样不参与该表述。OS 缓存没有清空，不能称为冷缓存基准，也未重复多轮估计噪声；50ms 采样可能漏掉短命进程和瞬时峰值，RSS 相加可能重复共享页。既有服务、GPU 内存和 agent token 未测量，不宣称性能改善。

填充仍是独立 Marching Tetrahedra，原版使用 Marching Cubes；切片线遮挡和原版 PShape 保留式渲染仍需验证。公式布局仍有差异。不能把全部残差归因于网格拓扑，后续应分别核对填充和线条的真实提交边界。
