2026-10-26。已生成独立的 **MathArt Lab 2 Preview 2.0.0-preview.1**，并通过两个源场景的实际打包应用操作。原生渲染现在可以随包启动。**M3 仍在进行，全部 11 类场景的一致性验收尚未完成。**

## 如何使用

在 Apple Silicon Mac 的项目目录运行 `npm run desktop:build:v2`，需要已安装的固定 Node/npm、项目依赖和 Xcode 命令行工具。脚本不安装系统软件。

本机已构建的应用为：

`dist-desktop-v2/MathArt Lab 2 Preview-darwin-arm64/MathArt Lab 2 Preview.app`

磁盘占用 304,228 KiB，约 297 MiB。双击入口使用普通可见窗口；验证使用隐藏窗口及单独的测试数据目录。预览应用默认工作区为 `~/Library/Application Support/MathArt Lab 2 Preview/`。1.0 的应用输出和工作区保留在原位置。

这仍是开发预览：源公式字形服务没有随包提供，带有相应画布公式的项目尚不能据此声明可用；Map/Symmetry 的冷重放及自定义 Symmetry 仍走既有 Worker 路径。当前验证覆盖下面两个无画布公式的源输入，不建议据此替换 1.0 日常交付。

## 修复的接入缺口

此前普通 `build:v2` 默认使用 WebGL，而桌面包没有携带原生 helper；前几轮原生对照依赖外部测试配置。新 `desktop:build:v2` 显式选择 native，编译并签署自有 CGL helper，把它放在应用资源目录。应用通过包内元数据选择该后端。

资源 manifest 固定平台、架构、文件名和 SHA-256；读取失败或结构不符时明确报错，不寻找替代文件。文件身份、可执行性、哈希和进程生命周期仍由原生渲染服务统一检查。显式指定的外部后端配置保留优先级。

本地预览使用 ad hoc 签名。Electron 嵌套代码与外层应用由已安装的签名库按依赖顺序签署；已签名 helper 保留原字节，打包后再次检查 manifest 哈希。签名配置只保留 JIT entitlement，不查找或嵌入用户的 provisioning profile。`codesign --verify --deep --strict` 通过；这不是 Developer ID 发行签名或 Apple 公证。

隐藏验证模式同时约束初始窗口、应用激活和第二实例事件。本轮实际发出两个事件后可见窗口数量仍为 0。启动失败也只记录错误并退出，避免验证失败时弹出系统错误框。

## 实际操作结果

验证启动的是最终 `.app` 内的 Electron 可执行文件，清除外部渲染器覆盖变量，通过公开界面导入、编辑、播放及下载。没有修改场景引擎或替换 HTTP 响应。

| 输入 | 原始粒子数 | 界面参数变化 | 结果 |
|---|---:|---|---|
| Business Cycle Map | 262,144 | a：1.46 → 1.47 | 导入、热改、播放/暂停、PNG 通过 |
| Emperor’s Cloak 1 | 562,144 | alpha：2.500 → 2.525 | 同上，并通过退出后重启恢复 |

两个场景均观察到真实 native compute 创建及 native present 请求；热改后继续推进时没有重建计算资源。表中是编辑及短暂播放后的界面最终值，不等同于尚未播放时的输入值。

两张 PNG 均为 160 × 120、1×，通过正式下载处理器保存。比较使用本次导出的原生 RGBA，再执行产品共用的边缘增强/锐化，**153,600 个 RGBA 字节全部一致**。该检查证明本地导出交付链路；共用增强函数不是独立原版算法 oracle，也没有调用原版付费导出。原版预览 32 帧对照的证据另见[此前报告](source-map-prefix-production-validation.zh-CN.md)。

重启使用同一隔离工作区和新的本地端口，Emperor’s Cloak 名称、alpha 值均恢复。两次应用退出码均为 0，所观察的 Electron/native 专用进程组退出后为空，旧端口拒绝连接。运行前后 app.asar 和 helper 哈希不变；页面及最终观测器错误均为空。

## 检查、失败记录与成本

- `npm run desktop:test`：25 项通过，含 22 项资源 manifest 边界测试及 3 项既有桌面检查。测试入口已包含新增加载器检查。
- `npm run desktop:build:v2`：TypeScript、Vite、严格 native 编译及打包通过；保留既有大 chunk 提示。
- 最终完整包签名校验、实际 UI 验证、Git diff 空白检查通过。额外缺失配置启动案例在 0.56 秒内返回预期退出码 1，记录 ENOENT，未挂起，进程组为空。

调查期间保留三类失败记录：首次包未重新签署外层资源封装；首次 PNG oracle 错把增强后的图片与原始像素直接比较；早期调试协议对不用于导出断言的预览响应返回“无 body”。现分别补齐外层签名、按实际增强路径比较，并仅采集指定尺寸的本次导出响应。页面错误和导出观测错误仍会使验收失败，没有忽略它们。最终通过记录为 `ui-accepted/report.json`。

一次最终完整验证耗时 **9.69 秒**，包括启动、两组操作、重启与清理；子进程累计 CPU **12.86 秒**，含采样开销。主验证应用进程组采样 RSS 峰值 **986.5 MiB**；重启验证为 **233.5 MiB**；外层验证驱动组为 **294.3 MiB**。这些峰值分别采样，不能相加声称是同一时刻的总峰值。

Playwright 的 Electron 使用独立进程组，因此外层监督器的 RSS 不包含应用；这里额外采集了应用组。两组每 0.5 秒采样，可能遗漏短峰值，不包含 GPU 显存、温度或能耗。首次启动与重启的任务量不同，系统/驱动缓存未控制，不能据此比较冷暖性能。没有等价旧包的完整原生流程成本基线，不宣称性能提升。收尾计量窗口内 Goal token 增量为 66,015，时间增量 398 秒；这不是全轮成本，也没有缓存/子代理拆分或等价旧流程 token 基线。
