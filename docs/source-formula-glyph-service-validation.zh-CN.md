# 独立公式字形服务验收

2026-10-22。已实现本项目自有 Java helper、有界 Node 进程所有者和本机 HTTP 字形接口。实际生成的 21 组完整 RGBA 与原版记录一致。**这完成了字形生成后端；预览、PNG、录制的共同纹理合成尚未接入，2.0 原版整图验收仍为 0/11。**

## 不再依赖原版运行时

从官方 Eclipse Adoptium 归档取得 Temurin 21.0.7+6、macOS arm64 JDK，校验官方 SHA-256 后解压到项目私有缓存。下载 190.44 MiB，解压普通文件 334.09 MiB；没有安装系统 Java、执行安装器或更改全局 PATH。

独立运行时先对上一轮 21 组输入各重复两次，42 次尺寸与 RGBA 全部相同。此步骤仍使用调查用 JNI 包装器，随后新 Java helper 的实际执行另行验证，没有把两者混为一次产品测试。

新 helper 只加载本项目封装和官方 JLaTeXMath 1.0.7。字号固定为 50，保留原排版与透明边距；逐行输出非预乘 RGBA，非零 alpha 像素使用指定 RGB，透明像素 RGB 为零。6 个打包曲面公式、短式、分式、根号和希腊数学符号均有原版夹具；白色、非白色和纯黑共 21 组。

## 已接通的服务边界

`POST /api/formula-glyph` 接受明确的公式与六位 RGB 颜色，返回二进制像素和尺寸／格式／渲染器身份头。服务沿用本机来源检查和上传上限。未配置后端时明确返回不可用，不寻找原版应用，也不静默退回另一种字体排版。

输入命令与环境在 Java 解析前由单一白名单检查，文件／图像加载、宏定义、动态命令构造和字符重写不在支持范围。公式最长 8,192 个 UTF-16 单元、64 层分组；图像最多 1,600 万像素、单边最多 16,384。它是有限数学标注接口，不声称完整 LaTeX 兼容。

每个请求启动独立 JVM，默认并发 1、堆限 256 MiB、期限 10 秒；忙时返回容量错误。取消、超时和服务器关闭都等待子进程退出后才释放所有权。编译目录被封装成 helper JAR，避免目录里新增类改变执行内容；使用 canonical 路径并检查 Java classpath 分隔符，运行时文件及目录结构变化会要求重新初始化。渲染器身份覆盖运行时、字体栅格库及配置、自有 helper、上游库和主机身份，子进程使用最小环境。

审核发现的取消参数泄漏、可重定向路径、可追加 classpath 类，以及超长错误消息问题已在生产边界修复。相应实际检查保留在验证脚本中；没有通过下游吞掉错误来掩盖这些问题。

## 执行结果

- 独立 Temurin 调查矩阵：42 次运行，全部与此前原版基线一致，正常退出并回收；墙钟 16.06 秒。
- 自有 helper／本机 HTTP 验证：81 项检查通过，墙钟 28.96 秒；21 组原版 RGBA 全部一致，并检查格式身份、非法输入、指令范围、嵌套预算、并发预留、运行中取消、取消后重试、超时、关闭、后端变化、符号链接重定向及协议截断。
- HTTP 检查包含完整纹理传输、来源拒绝、无效 UTF-8 拒绝、保留错误分类、客户端断开后回收实际子进程、服务器关闭时清理字形进程，以及未配置时的明确不可用。
- 现有导出／桌面服务 38 项回归通过，没有跳过；包含实际 FFmpeg／ffprobe 的 PNG、JPEG、MP4、WebM、GIF 与编码质量检查。

完整结果保存在下述 `verify-fixture/report.json`。本轮没有改浏览器代码，没有重跑 Web 构建或全量场景测试，也没有启动原版 GUI。未测量完整进程族 CPU、峰值内存、显存及代理 token 成本；没有性能改善结论。当前每次请求的运行时检查和新 JVM 启动都有成本，后续应在共同字形缓存所有者处复用结果，而不是逐帧重复请求。
