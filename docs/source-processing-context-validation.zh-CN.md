# 动态 Processing 上下文与自定义参数验收

2026-10-26。**七组、56 帧原版运行记录的上下文对照通过；其中六组、48 帧有效粒子数据共 5,376 字节逐位一致。动态上下文准备已实现，尚未接入桌面应用，M3 仍未完成。**

## 改好了什么

自定义 Symmetry 着色器现在可以从一个持续存在的 graphics 对象取得矩阵和自动参数。该对象保留跨帧状态；着色器只在首次绑定时选择对象，之后即使当前绘制目标改变或结束，仍读取原对象的最新状态。

普通更新发生在本帧设置场景相机之前，因此会读到上一帧留下的矩阵。绘制世界坐标中的内容时，还需要加入缩放、旋转和平移。叠加层的 `camera(); ortho(); popMatrix()` 会恢复相机和模型矩阵，却留下正交投影。现在分别建模这些操作，不再使用固定首帧值或按帧号选择矩阵。

切换场景时，原版依次执行默认相机、默认透视投影、重置矩阵。复核发现初稿少了前两步，会错误保留旧场景的叠加层投影；已在场景初始化的统一事件序列中修正，并用实际切场景记录验证。

逆矩阵保留 Processing 的 Float32 运算顺序：相机设置求逆；平移、缩放和旋转增量更新缓存的逆矩阵。54 组实际 Processing `PMatrix3D` 数学调用提供独立回归数据，包含奇异矩阵、负零和下溢。原版 JSON 中的 `-0` 在提取时保留符号，再保存为 uint32 位模式。

## 自动参数的兼容行为

自动绑定读取已链接程序的反射事实，先选择主名称，再考虑别名。未选中的别名和普通作者参数保持已有值；矩阵数组只更新首项。作者的匹配 float 参数在自动阶段之后写入。

原版不会因为一次自动 setter 类型错误而中断后续参数写入。构造的实际原版输入确认：`float perspective` 最后得到作者值 `0.75`；声明为 vec3 的 `resolution` 保留初值 `[12,34,56]`，因为自动 vec2 setter 无效。实现现在记录 `rejectedSetters`，跳过确定无效的写入并继续后续阶段；主名称类型冲突不会触发别名回退。

另一个实际原版输入确认 float 向量 setter 可以写入对应的布尔向量。现在按零/非零转换，并让正式通信与原生资源支持 bvec2/3/4；畸形布尔值会在改动资源前被拒绝。不认识的自动参数类型返回明确的“未支持”错误，不将未知兼容性当成无效写入。这里覆盖无光源的 MathArt 更新路径，未实现任意 Processing 光照配置。

每组为 7 个有效粒子的构造输入，通过原版正常 ProjectState → initScene → VIEW/RUN 取得参照，不是原版预置作品。世界矩阵还对照了实际绘制时的 graphics 快照；该组粒子计算仍发生在普通更新阶段，**未实际覆盖世界变换内部的 replay 计算**。

重放消费原版观测到的种子、pass 调度和链接反射；矩阵、相机动画及自动值由产品模块计算，再通过正式 codec → 服务 → CGL → codec 核对粒子状态。原生服务尚未自动提供这份反射，也没有证明应用自己选择正确的 graphics 生命周期。七个验证进程组退出后均为空，已创建的原生资源全部释放。

原版各组仍有 `endDraw 1282` 记录。类型冲突组在 compute 观测前还捕获到 `1282`；观察器读取并记录了这些错误，会影响后续错误队列。因此本轮证明的是捕获到的 uniform、矩阵和粒子状态，不声称原版无 GL 错误，也不声称重现了完整错误队列和日志时序。

本次原版运行的 JAR、采集器等输入前后哈希一致，license/settings 文件保持不变。原版自身刷新了策略缓存，每次运行前均有备份；没有把缓存变化描述成“所有用户文件不变”。未调用或绕过原版 EXPORT。
