2026-10-26。**生产后端现已接通自定义片元计算 → 保留墨迹 → 像素呈现 → 重置及释放。562,144 个粒子、810×972 画布完成八帧真实运行；261 项相关测试通过。应用默认入口仍未切换，M3 尚未完成。**

本轮输出：[第八帧 PNG](../.cache/native-fragment-ink-20261026/final-performance/last-frame.png)。这是 MathArt Lab 生产后端的实际输出，不是原版截图，也不是原版整图一致性的证明。运行使用既有标准自定义输入，所有帧的 562,144 个粒子均通过绘制分类，最终有 336,471 个占用像素。

## 实现与修复

此前墨迹资源只接受按 iteration 统计的状态，自定义 shader 的 completed-pass 状态无法进入同一绘制通路。现以显式 `source-fragment` profile 使用 v10 墨迹协议，原有 v7 字节保持兼容。墨迹资源创建时从实际计算资源读取并保存执行类型与诊断单位，后续绘制、替换程序、呈现、释放和响应确认均验证它们。资源不存在时，单位保持未知。

自定义状态使用完整的 `ceil(sqrt(count))` 方形纹理，墨迹直接借用该纹理；绘制只消费有效粒子。容量、状态宽度和归约目标由同一 profile 决定，不再套用普通迭代的长条形纹理和额外复制视图。

帧准备现在支持显式原生 GLSL 方言，直接消费原始自定义输入。宏、`discard` 等不会先经过 WebGL ES 的有限循环解析器。原生后端要求宿主明确提供 Processing graphics 快照，缺失时拒绝执行，不按粒子纹理尺寸猜自动参数。计算程序、推进计划和工作量估算集中在同一生产边界，原有 Map／内建 Symmetry 路径继续使用原来的逐次迭代诊断。

无效计数的单位现已保留到实时、重放、冷生成和界面统计。completed-pass 表示每个计算批次结束时观察到的无效粒子状态；绘制时的无效样本仍单独计数。界面使用“计算批次结束时发现 … 次无效粒子状态”，不会把它误说成逐次迭代或全部已略过绘制。一个保留历史或显示批次内发生单位变化会被拒绝。

审查还发现：直接调用后端时，等待 create 响应期间修改输入，可能使后续种子块采用新的配置，或污染帧序号与绘制尺寸。现在首次等待前固定种子配置、目标、绘制开关、帧序号及程序绑定名称；等待后只消费这些已固定的事实。正常 Session 原本已有输入副本，此修复覆盖后端自身的公开调用边界。65,537 粒子的测试在等待期间修改输入，验证两个种子块和最终检查点仍一致。后端只保留执行需要的程序字段，避免额外持有原始、展开后及重复的源码身份字符串。

## 实测成本

使用 562,144 粒子的既有标准自定义输入，独立启动本机 HTTP 服务及 CGL 程序，生成八张 810×972 图像。宿主上下文由脚本明确准备；没有使用生产界面的实时 Session。每帧时间包含计算、墨迹绘制、呈现和像素读回。

| 项目 | 实测 |
|---|---:|
| 完整受监督任务，含载入、编译、服务及清理 | 5.131 秒 |
| 子进程 CPU 时间 | 8.814 秒 |
| 同时进程组 RSS 采样峰值 | 671.3 MiB |
| 新资源首帧 | 984.96 ms |
| 同进程后续七帧中位数 | 29.81 ms |
| 呈现八帧后的已知保留资源预算 | 71,056,367 字节 |
| 呈现八帧后的请求数／请求字节 | 44／9,145,890 |
| 清理后的自有进程 | 0 |

44 次请求的快照取于最终释放之前。保留资源预算是已知存储的逻辑核算，不等于 RSS 或 GPU 实际占用。RSS 每 0.5 秒采样，可能漏掉短峰值；CPU 包含采样进程。GPU 内存、能耗及温度未测。首帧不是清空系统／驱动缓存后的严格冷启动，后续为同一进程热运行；这些数字不等于界面帧率。

旧通路不能完成同样的原生片元墨迹工作，因此没有等价旧基线，不声称加速。实现与主要验证阶段的 Goal 计数窗口从 95,889,365 到 96,553,240，增加 663,875 tokens、1,063 秒；该窗口不含后续字段保留清理、最终性能复核、报告与提交。没有等价任务的旧 token 基线。

## 接下来需要完成的接线

原版源码复核确认，Symmetry 的 shader 是懒初始化的，update 或 display 都可能触发第一次 bind。Processing 的 graphics 对象、当前绘制对象选择器和 shader 首次绑定的对象是三个不同的状态。普通更新发生在本帧相机设置之前；world replay 发生在世界变换之后；离屏输出不一定改变 shader 已绑定的对象。因此下一步必须在宿主保留真实的初始化与绘制顺序，不能统一使用当前输出目标。

暂停 PNG 的原版路径是离屏 render、没有 update，返回后外层正常 draw 继续；录制先 update，再离屏 render，随后将图像绘制到 primary。这些离屏顺序来自已有字节码证据，**本轮没有调用原版 EXPORT，也未执行新的原版离屏／world replay 验证**。已有 VIEW/RUN 粒子回归不能替代这些覆盖。

仍需完成：应用的 graphics 生命周期与路由、实际 world replay、交互和取消、原版完整画面、PNG／视频一致性及桌面重新打包。任意作者 shader 的及时终止也不能由有限用例证明。当前桌面仍为 `2.0.0-preview.3`，自定义场景默认仍走原有 Worker；本轮只更新了源码及 Web 构建。所有 11 类场景的整体验收要求保留，M3 继续进行。用户仅有这台 Mac，跨设备保持未验证。
