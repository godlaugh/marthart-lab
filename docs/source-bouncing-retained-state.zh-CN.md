# 弹跳原生状态持有验证（2026-10-24）

**原生 GPU 现在可以保留粒子状态、连续更新并直接绘图，62 帧完整画面与原版一致。** 这是内部状态组件的验收；应用预览、HTTP 会话、截图和录像尚未接入它，不能据此宣布弹跳场景交付。

后续进展：独立资源身份、真实 HTTP 分块上传及纯显示准备已完成，见[状态通路验收](source-bouncing-state-protocol.zh-CN.md)。以下保留本轮组件验收的原始范围。

## 这轮解决了什么

此前虽然原生绘图已一致，每帧仍需从 WebGL 读回约 32 MB 粒子状态，再传给 CGL。新组件在同一 CGL 上下文中持有两个 RGBA32F 状态纹理、更新程序和点绘图程序。初始数据分块上传一次，后续按明确的起止更新索引推进，绘图直接读取当前纹理。

暂停重绘不会推进模拟，也不会按秒数猜测更新次数。状态纹理包括填充区域，初始化时明确清零。当前显示和碰撞着色正文由同一 TypeScript 模块提供，WebGL 与 CGL 只使用各自的版本前缀，没有重写碰撞数学或修补颜色。

通用 CGL 帧缓冲、边界绘图和类型化 uniform 检查仍复用原有实现。新增状态拥有者持有 CGL 上下文引用，防止上下文销毁后指针被复用；清理成功才清除句柄和释放引用。

## 500 万粒子验证的准确范围

另执行了 500 万粒子的合成容量用例：分块上传、跨行写入、全部 20,000,000 个粒子分量和纹理填充位检查均通过，过大块与过大画布在执行前被拒绝。

它证明原生状态组件能够持有这些数据，**不证明原版 500 万粒子场景的画面或动态已一致，也不证明产品端到端的内存预算已经接通**。后续上传策略还必须计入浏览器／Worker 持有的完整种子数组；不能直接把组件测试中的 16 MiB 块大小照搬为产品默认值。

## 成本与限制

- 62 次原生绘图本身没有读回粒子状态。11 次明确的诊断读回合计 352,391,600 字节；测试准备阶段另有一次初始 GPU 快照，尚待产品接入时去掉。
- 原生状态的逻辑缓冲预算约为 61.1 MiB（200 万）和 152.7 MiB（500 万），不等于整套进程 RSS。
- 最终复跑：准备约 1.96 秒，原生验证阶段约 1.86 秒；后者包含参考读取、输出写入和额外的 500 万容量／错误用例。
- 原生阶段采样进程族 CPU 约 0.81 秒、峰值 RSS 约 616 MiB。250 ms 采样可能漏掉短进程或短暂峰值。

这些数字不是产品帧率，也不能直接与上一轮的浏览器／HTTP 工作流作速度比较。系统／驱动缓存没有受控，独立 GPU 时间、严格冷暖启动与 token 成本未测量。
