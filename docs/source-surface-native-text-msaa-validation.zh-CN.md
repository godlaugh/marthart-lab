# 曲面自动方程与原版导出抗锯齿对齐

2026-10-22。本轮在上一轮公式布局修正之后，修正了自动方程文本与离屏多重采样设置。最终构建的实际导出中，Cornucopia 固定几何区域的最大 RGB 通道差由 119 降到 3。**这不是整图通过；11 类原版场景的完整效果一致性验收仍为 0/11。**

## 修复了什么

源曲面自动方程现在使用原版表达式语法的同一个解析器，由它的 AST 生成 LaTeX。保留原版场景名称、分段括号、指数、乘法间距、函数及希腊字母规则；不再交给另一套数学解析器重新解释。主方程在 Scene 构造／Apply 时生成，预览、暂停 PNG、保留录制继续使用已经交付的公式事实，草稿不会改写旧帧。

格式化过程使用迭代遍历与分段文本，避免长的左结合表达式产生递归溢出或反复复制。节点数和输出字符数均受本地预算约束。原版的特殊行为照实保留，例如 `%` 和部分函数产生的 TeX 未必能被当前 MathJax 接受；没有用另一套表达式输出悄悄替代。显式自定义 TeX 仍是本地功能，不声称它与原版 `main_equation.latex` 的行为相同。

原版 `MathArt.ensureRenderBuffer(F)` 在绘制之前调用 `noSmooth()`，真实运行日志也明确记录导出关闭 MSAA。本地原来创建导出上下文时默认开启抗锯齿。现在由绘图上下文的创建者明确选择主预览、普通本地导出、源曲面导出三种用途：源曲面导出不启用 MSAA。暂停截图、普通图片重放、逐帧导出和保留录制都已接入；实际主预览及复制主画布的实时录制保留自己的设置。

此策略只接入已核对的源曲面。其它场景后续逐类核对，不因为共享一个底层渲染器就声称它们已完成对齐。已安装的 Apple Silicon 1.0 应用没有替换。

## 原版执行证据

使用现有原版 JAR 和其 bundled JVM，在两个独立进程中实际执行：

- 119 个 `FastExpressionParser.parse → toLatex` 样例，115 个输出与 4 个原版异常均一致；包括运算优先级、函数参数、具名常量、六个打包曲面的表达式及次正规数。
- 11 个 `JsonSurfaceConfig` 自动主方程样例，包括六个打包曲面的方程／参数组合、名称和下划线处理。全部匹配本地生成的文本。

配置检查只构造了无界面的 PApplet 以满足原方法的非空参数，没有调用 runSketch、Scene、TexMobject、GL、窗口或编码器。最初传 null 的失败记录单独保留，未当作成功证据。夹具保存原始输入、输出、JAR／JVM／相关 class／验证程序摘要，可查看 `tests/fixtures/source-surface-formula-labels/README.md`。这些有限样例不证明所有 double 值和所有可能表达式都一致，也不证明字形像素一致。

比较复用同一张原版 500 × 600 PNG。固定区域为 x=300、y=180、宽 150、高 270，排除可见公式、调试信息和水印；分析未对图像重采样，也未移除或修改原版水印。
