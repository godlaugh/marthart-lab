# 曲面公式布局与暂停 PNG 顺序修正

后续进展：[自动方程文本与导出 MSAA 修正](source-surface-native-text-msaa-validation.zh-CN.md)。本页保留布局修正当时的观察。

2026-10-22。原版稳定尺寸对照确认了两个本地问题：导入公式被套入固定参考画布，造成偏小和偏位；暂停 PNG 在叠加公式之前就完成了增强和放大。本轮修正了新导入源曲面的这两条路径。**原版整图一致性仍未通过，保持 0/11。**

## 已修正的行为

新导入源曲面使用版本化的居中坐标模型，保存原始水平／垂直偏移和缩放值。主预览的位置以实际画布中心为原点；离屏导出按目标高度与主画布逻辑高度之比换算，改变导出宽高比不会另行拉伸水平偏移。

公式文本在 Scene 构造或 Apply 时解析并保留，逐帧只绑定主画布高度。已交付的几何帧携带公式事实，主预览、普通导出、实时录制、曲面队列录制和暂停截图使用同一份事实。客户端检查布局版本和参考尺寸，不从新的编辑草稿补算旧帧公式。主预览覆盖层直接读取实际 canvas 的矩形，按画布区域裁剪，避免把横向／纵向留白算进公式尺寸。

暂停 PNG 现在先合成基础尺寸的公式，再统一增强并放大整张图；复用现有 PNG 后处理工作进程，不再由曲面截图另做一次增强／放大。截图不推进场景时间。

已有本地项目和旧保存的公式布局不自动迁移。其它场景的源公式布局尚未在本轮接入；自动方程文本与字体的剩余差异见下文。已安装的 Apple Silicon 1.0 应用没有替换。

## 真实原版与本地前后对照

本轮重新启动原版，等待日志确认首帧就绪，全程没有移动显示器。暂停并 Apply 到时间 0 后，原版实际保存 Cornucopia PNG：配置为 500 × 600，导出缓冲逻辑尺寸为 250 × 300，实际像素为 **500 × 600**，密度字段为 2。此前跨屏运行得到的 250 × 300 图不再作为稳定基线；这组观察尚不足以确定原应用内部尺寸异常的唯一原因。

原版保存 PNG 后再次报告 `EDT-HANG`。文件已生成，随后窗口读取超时。保存线程记录并核对进程身份后，结束本任务启动的实例，受监督会话以 143 退出；该次运行未移动任何窗口，任务虚拟屏继续保留。

本地通过实际 2.0 构建页面导入同一份原配置，显式补入原运行日志中的 500 × 600 项目尺寸，暂停在时间 0，以密度 2 导出相同尺寸。原版主画布逻辑高度 486 来自窗口截图推导，尚非独立运行字段读取；本地实际生成帧确认使用高度 486。

## 实际验证

- 曲面、公式布局、PNG 编码、后台传输、录制、语言及旧分形／域着色兼容回归：18 个文件、238 项通过。
- 后台普通生成与进度响应拒绝错误的几何／栅格类型，保留原有源分形边界，并检查新曲面公式布局。
- TypeScript 与 `npm run build:v2` 通过；保留已有的大资源包提示。
- 真实 Generator → Worker → ArtRenderer：CPU 点／网格／切换及 GPU 点／网格，5/5 通过，包括真正编码后的 3× PNG。
- 实际 App：CPU／GPU 点和网格，以及空时间线／等待时间线，6/6 通过。每例启用自定义公式，下载两张 195 × 147 的 3× PNG，像素稳定；暂停导航、Apply、播放恢复正常。
- 构建后的实际界面：横向和纵向画布两例的覆盖层与 canvas 矩形一致，公式偏移误差小于 0.02 CSS 像素；项目 JSON 保存、刷新重开均保留新布局。
- Cornucopia 构建产物实际导入及 500 × 600 PNG 下载通过。

首次 App 验证失败是验证脚本连接了环境中已有的导出服务，临时网页来源被拒绝。验证脚本现创建并清理自己的导出服务，只允许本次页面的来源；产品来源白名单没有放宽。后台验证脚本也允许 Vite 在端口被占用时选择空闲端口，并读取实际监听地址。修复后的界面验证约 25.29 秒，后台验证约 6.69 秒，均是整套脚本墙钟时间，非单次导出延迟；没有等价的性能前后实验，CPU、峰值内存及完整代理成本未测量。
