# 分形当前帧 PNG 顺序修复验收

2.0 仍在 M3，原版完整窗口对照为 **0/11**。本次修正分形当前帧 PNG 的文字合成与整图处理顺序，不替换已安装的 Apple Silicon 1.0 应用。

本页记录提交 613b87a 的验收。后续对高分屏逻辑尺寸和实际图像取整的修复见[分形高分屏当前截图验收](source-fractal-capture-density-validation.zh-CN.md)。

## 修正内容

之前把分形底图放大后再绘制公式，且没有对分形当前截图执行原版的整图增强。现在先在基础尺寸合成公式，再对包含文字的完整图像增强，最后按 1×、3× 或 5× 导出。1× 也执行增强；隐藏公式不会跳过增强。

数值 Worker 返回未合成、未放大的基础图像，并明确标记处理阶段。客户端拒绝旧的已放大响应，避免重复放大。独立图像 Worker 完成增强、bicubic 放大和 PNG 编码，成功、失败、取消时都会结束；取消不会终止保留当前场景的数值 Worker。公式仍取场景构建时保存的事实，导出不重新运行数值队列。

独立回放图片、视频及其无标注 RGBA 路径保持原行为。当前图像的内存预算包含原始帧、合成读回、增强/放大和编码工作区；单图仍受 128 MiB 限制，明确计算的阶段峰值上限为 768 MiB。此预算不包含浏览器、GPU 和压缩库内部工作区。

## 原版依据与边界

固定 MathArt 1.7.8 JAR 的 SHA-256 为 `a6e1da3acfc05c347d2529c1d590657e2dd798e16d38c55df3dc61312be24018`。已对照原包校验七个相关类的缓存反汇编。

`savePausedFrameInternal` 的顺序是：PC90 创建基础缓冲区；PC108 调用 Scene.render；PC124 对完整缓冲区执行 buildEnhancedImage；PC141 可选放大；PC234 写 PNG。ComplexFractalScene 继承 Scene.render，非 overlay 的 Fractal 先画，overlay 的 TexMobject 随后画。因此文字参与整图增强和放大，这是原版静态调用链证据。

还实际执行了原版 TexMobject 的无窗口构造路径：`x^2 + y^2`、50F、白色生成 170 × 72 字形纹理，原 RGBA 与可视化 PNG 解码一致，进程已回收。该实验只证明原版字形纹理生成可用，没有执行 GL 合成或原版窗口截图。

本地仍使用 MathJax 字形；完整原版字体采样、GL 混合、像素密度、渐进渲染及最终窗口画面一致性未验证。不能把本地检查或静态调用链当成原版整窗验收。

## 本次验证

全量 **387 个测试文件、7,358 项测试通过**；TypeScript 和 Web 构建通过。现存的大分块提示仍在。公开流程两组、20 个步骤全部通过，使用真实 App、数值 Worker、独立图像 Worker 和导出服务；参考结果独立计算基础尺寸的文字位置，再用 Python 中保留的原版增强 / OpenJDK 软件 bicubic 算法转录计算。比较全部 PNG RGBA，不调用生产端合成、增强或放大函数。字形 SVG 生成共用 MathJax，因此这仍属于本地导出链验证。

具体结果：

- 当前 PNG 的基础图像均为 160 × 120，1× / 3× / 5× 文件分别为 160 × 120、480 × 360、800 × 600，全部 RGBA 与独立参考结果一致。
- SVG 解码期间取消、图像 Worker 回应交付前取消，都没有发布图片；资源释放并可重试，数值 Worker、场景时钟和参数状态保持不变。取消检查使用明确的延迟注入，没有替换数值结果。
- 隐藏公式的当前 PNG 确实经过增强；独立回放的隐藏公式 PNG 仍保留原始 RGBA。分形画面不透明，低透明度行为由既有图像算法测试覆盖，不由本次整图证明。
- 三个真实 MP4 分别为 3、3、1 帧，160 × 120、8 FPS；最大逐帧平均 RGB 误差为 2.8459 / 255，低于既定阈值 8。JPG 的 128 个文字采样点更接近期望文字，而非原背景。
- 浏览器、控制台和 Worker 错误为零；公式 URL 的创建/释放数量相等。浏览器、Vite 和导出服务清理完成，471 个源码文件摘要前后稳定且与最终文件一致。已查看 3× PNG，红色 A 与绿色 E 随整图一起处理。
