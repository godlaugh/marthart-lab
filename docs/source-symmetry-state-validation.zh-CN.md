## 本轮实现

新增持久的方形纹理资源，保留有效粒子、补齐单元和两侧纹理的历史。它与内建顶点计算资源共享绘图采样契约，绘图端可以直接借用当前纹理，不必另建纹理副本或把粒子读回 CPU。容量按完整方形计费：每单元 64 字节，加程序文本计费及 1 MiB 固定预留；这不是驱动实际内存承诺。

原版 reset/replay 只重新上传纹理 0，纹理 1 保留历史；初次分配的写入侧内容不可断言为零。本实现遵循该规则。自定义 `discard` 跳过写入时保留原目标值，不用初始数组覆盖两侧。

每个原版更新 pass 只执行一次。自定义函数可以读取 `iterations`、使用片元导数或跳过写入，缩短次数重跑并不等于观察原调用的内部前缀。因此诊断只统计实际完成的 pass，显式单位为 `completed-pass`；内建资源继续使用 `iteration`。应用接入时必须保留这一差别，不能把前者显示为内部迭代错误次数。

绑定层接收已解析的类型和值，支持标量、向量、矩阵及数组。匹配的自定义 float 每次必须提供明确值；未绑定输入保留 GL 链接初值。原版 Processing 自动绑定的生成规则仍由后续应用适配负责，资源层不猜测视口或矩阵。

上下文探针实测：此离屏场景的 `viewport/resolution` 是逻辑尺寸 405×486，不能替换成 810×972 像素尺寸或 3×3 计算纹理尺寸；实际 draw 时 `ppixels` 与 `stateTex` 都使用 unit 0 的同一状态纹理。同一次运行中，scale、transform、modelview 和 projection 各出现两组不同值，不能只取首帧常量。以上是这一明确运行环境的事实，不是任意窗口的固定常量。该组本地验证使用捕获的绑定值，尚未证明应用会自行准备正确值。

状态资源在每组参照后还通过 13 个实际检查：错误控制、容量不足和错误绑定不改变状态；有界读回保留位表示；计数溢出提前拒绝；零步、计数清零、种子恢复、重播正确；错误上下文保留所有权；GL 失败后禁止继续使用；重复释放安全；编译失败的临时资源保留至明确释放。所有释放成功后计费归零、上下文释放。

独立 CGL 测试另验证了负零种子、矩阵和数组绑定、数组局部更新保留其余值、未绑定作者初值，并确认两次各三步的无效更新计为 **2 个失败 pass**，不误报为 6 个已观察的内部步骤。实际 GL 删除函数自身失败的故障注入尚未覆盖。
