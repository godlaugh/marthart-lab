## 这次接通了什么

生成器现在可通过本机 HTTP 服务调用保留状态的 CGL Samila 会话。公式程序、噪声表、色板和历史墨迹由独立资源持有；每次绘制提交当前参数和一次随机种子。参数变化、六倍补采、暂停计时、旋转锚点和截图顺序仍由同一个 TypeScript 语义会话管理，WebGL 与原生适配器共用这些规则。

原生端同时支持两个独立 Samila 资源，共用一个受控进程、上下文和单请求通道。两者可分别保留墨迹；精确释放一个资源不会释放另一个。完整协议校验、实际统计读回和 256 MiB 共享预算在服务端再次执行。预算是保守的资源估算，不是实测显存。

同一资源的显示检查点只能前进一次。响应丢失或取消后不重发可能已经执行的绘制，也不把新随机历史冒充旧会话。清理失败继续保留所有者；必须确认释放或结束拥有的进程后才能回收。尺寸变化但响应丢失时，预算同时保留旧目标和可能分配的新目标，防止其它会话低估占用。

本次审查另修复了生成器的失败恢复边界：同一热会话失败后，排队中的普通生成请求继续报错；重新应用、重启或显式取消所建立的新会话才可重新创建。截图失败也保留这项约束。页面卸载后的失败清理继续由既有队列注册表持有，顺序重试释放，避免多个旧会话争抢共享请求槽；截图和释放同时失败时保留两个原因。

## 实际生命周期与显示验证

真实生产生成器和 HTTP/CGL 流程通过以下检查：

- 两个会话交替使用，A 的三帧与独立运行 A 的相同种子历史逐字节一致；第三个资源及重复检查点被拒绝，释放 B 不改变 A。
- 修改参数后执行六倍采样、只消耗一个新种子，已编译程序仍保留。
- 暂停截图先绘制导出目标，再恢复主目标；实际发生两次绘制、两次种子消费和双向 resize。
- 超容量截图在消费种子前拒绝，仍可使用原来的已完成主预览；暂停／恢复本身不绘制。
- 公开 `Generator` 完成预览、播放控制、1×／3× 暂停截图及增强；旧截图凭证和无效尺寸被拒绝。
- 取消及 dispose 等待资源释放；显式新会话从检查点 0 开始。
- 真实 CGL 已完成绘制且响应已完整收到后，在测试传输边界故意丢弃确认；同一会话的普通重试不再发送请求，明确新会话才能释放旧资源并从头绘制。

另外四条真实 CGL 服务测试覆盖：与 generic v3 帧共存；非法请求后的结果与独立进程参考历史一致；尺寸清屏与幂等精确释放；真实子进程已产出响应字节后取消，两个旧资源均保持失效，禁止隐式重建。每项结束后服务拥有的进程数和保留资源数均为 0。

隐藏 Electron 44.7.2 中，实际 `Generator` → 原生服务 → `ArtRenderer` 的完整 500×600 显示也已通过：300,000 像素的 RGB 与生产输出完全一致，显示 alpha 全为 255；PNG 解码后的 RGBA 与原始目标完全一致，保留非不透明 alpha。生成只发送 create 和 display 两次原生请求，显示与 PNG 编码没有额外采样。窗口始终隐藏，没有操作用户桌面。这是生产画布组件检查，不是完整应用交互验收。
