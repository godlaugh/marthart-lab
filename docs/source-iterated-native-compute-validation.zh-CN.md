## 这次接上了什么

| 环节 | 实现与验证边界 |
| --- | --- |
| 程序生成 | 使用现有 `iteratedDensityGpuPrograms('native-gl41')` 和公式 owner，直接生成完整 GL 4.1 程序，不转换捕获的 shader。当前 retained 计算接口限于二维 `calculate_next` TF 路径；不代表 custom fragment 或三维路径已接入。 |
| 资源 | 一个明确 token 对应 seed、两侧粒子状态、两侧 metadata、程序及 CGL context。与既有 Samila／Bouncing 共享服务进程和浏览器请求槽、lease。 |
| 操作 | 创建、连续上传初始种子、推进、明确请求的有界诊断读取、精确释放。每次核对资源与检查点，收到成功确认才提交进度。 |
| 容量 | 每块最多 65,536 粒子；保留预算为 `64 × 粒子数 + 3 × shader UTF-8 字节 + 1 MiB`。与其他原生 owner 共用 256 MiB 准入上限，另计协议副本和读取缓冲。此预算不是整个工具链 RSS 或物理显存上限。 |
| 数据 | 上传仅接收有限初始种子；计算后的 NaN／Infinity、原始 F32 位、无效计数保留，不重新播种或截断粒子数。 |
| 取消与清理 | 传输层沿用已拥有的 child handle；坏响应或强制传输取消会退休共享进程。未完成清理继续阻止替换和获取 lease。未来上层 retained backend 应使用已有异步会话的边界取消，避免把每次显示取消变成进程取消。 |

修复了真实执行中发现的三类问题：

- 无窗口 CGL 没有完整默认 framebuffer，TF 推进实际报 1286。现在 owner 持有一个 1×1 离屏目标，随计算绑定、解绑和释放；修复后真实 GPU 测试通过。
- 客户端在等待传输期间，调用方可以修改原请求。响应现在绑定发送前冻结的标量事实，不再重新读取可变请求，也无需复制整个种子数组。
- Gateway 曾把 `released` 且粒子总数为 0 的坏确认当作成功。现在直接拒绝并退休不确定的进程；只有 `absent` 可携带全零状态。

## 已执行的其他验证

- **197 项测试／11 文件通过**：原生协议、客户端、流式 gateway、HTTP、既有会话，以及真实 CGL 的 Iterated／Samila／Bouncing 生命周期。部分传输故障使用受管 Node 子进程模拟 ACK，明确不作为 GPU 数学证明。
- 其中新增协议 29 项、客户端 30 项、受管 CPU 子进程 22 项、真实迭代 CGL 生命周期 4 项；覆盖不完整上传、错误参数不改变状态、过期检查点、非有限结果、显式 reset、独立 owner、编译失败清理和释放重建。
- TypeScript 和 `build:v2` 通过；保留既有大 chunk 提示。

实测整段验证墙钟 5.13 秒，包含 Vite 模块加载、编译、两轮计算／读取／比较／落盘及清理。新进程轮 1.20 秒，同进程重建轮 0.59 秒。监督采集的进程族 CPU 为 9.40 秒，0.5 秒采样峰值 RSS 为 717,216 KiB，包含 Node／编译器／renderer 和采样开销，可能漏掉短峰值；没有测量物理显存。新进程轮不代表系统 shader cache 冷态，推进 ACK 时间也不等同 GPU 完成时间。

尚未做等价完整呈现工作流的前后性能对照，agent token 增量未测，因此不宣称性能提升。选择完整原生绘制还是原生计算配合 WebGL 绘制，仍需比较完整工作流成本。
