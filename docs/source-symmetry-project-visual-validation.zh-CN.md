# Symmetry 项目显示参数与 GPU 着色修复

2026-10-21。**已修复项目默认缩放、浮点转换与 GPU 颜色输入；原版整窗效果验收仍为 0/11。** 本轮没有移动窗口或输入，没有重新打包、替换已有 1.0 Apple Silicon 应用。

## 修复结果

原版“打开项目”先经过 ProjectState，再进入渲染配置。之前本地直接使用通用表达式解析，导致 `1+2` 被算成 3、缺省缩放使用底层配置值、部分边界值提前被拒绝。现在由一个入口解析这些项目设置；通用导入逻辑不再重复解释它们。

| 设置 | 原版项目缺省值与本次行为 |
|---|---|
| XYZ 缩放 | 35、35、35；直接 runtime-config 入口继续区分其 100、100、0 默认值 |
| XYZ 偏移、点大小 | 0、0、0 和 1.5；保留原版项目允许的有限值 |
| 亮度、对比度、Gamma | .3f、1f、2.2f；先转 Float32，再按原版边界限制 |
| 动态范围、饱和度 | .2f、.8f；同样保留 Float32 精度 |
| 累积衰减 | 项目保存原值，渲染时才限制到 0–1 |
| 非法数值文本或类型 | 回退原版默认值，不执行数学表达式 |
| NaN 与未被限制的无穷值 | 与原版项目输出一样明确拒绝 |
| 有边界色调字段的 ±Infinity | 按原版限制到上下界，不错误回退默认值 |

Symmetry 项目不读取步长上下限、归一化方式、颜色速度和相位这些输入。它们现在保留在原始来源中，不再造成错误拒绝。活动 GPU 模型复用原版固定规则：步长范围 0–2、ROBUST 归一化、颜色速度 1、相位 0。内置数学和自定义 GLSL 都使用同一组规则；旧 legacy 模型保留原有设置。

这些固定值由同一处定义，渲染、控件过滤和累积缓存共同使用。无效控件已隐藏，修改休眠字段不会错误清空累积。新增原始数值文本的保存校验路径也已登记，避免“可以导入但不能重新打开”。

## 验证证据

- 原版 JNI/JVM 后台运行得到 **34 组成功样本**，包括缺省、合法数值、十六进制浮点、错误文本/类型、边界与舍入。每组修改 alpha 后，原版输出设置仍保持一致。
- **9 组非有限输入独立失败**，实际错误发生在原版 ProjectState.toJson；没有把失败算作默认值成功。
- 新增 **45 项测试**，经过公开文件导入、参数编辑、保存重开，并检查原始来源。原版输出文本会规范化负零，不据此宣称中间浮点位模式完全一致。
- 实际 WebGL 使用已知步长 0、2、6 和黑白线性色板，回读浮点累积颜色，得到 0、.5、.75；最大绝对误差约 **1.85×10⁻⁸**，GPU 资源清理后保留量为零。
- 实际 App 验证 Map 和 Symmetry 的导入、参数/相机编辑、保存重开、播放暂停、定位与 PNG 导出。PNG 与同次 Worker 输出逐像素一致；另验证 Map 的 3 帧 MP4。已检查 Symmetry 预览截图。
- TypeScript + Vite Web 构建通过。完整回归初轮发现一项旧测试仍期待项目缩放为 100/100/0；现按原版运行证据修正，并增加 direct 配置入口的独立断言。最终完整回归 **328 个文件、6014 项测试全部通过**。

## 尚未完成的效果差异

这次不是完整原版画面复现。兼容白点调色仍是当前默认呈现方式；源归一色调参数已正确保存，原版参考画布尺寸与最终呈现仍需对齐。原版 LUT 插值、散点覆盖、实时帧节奏及窗口合成尚未验收；本地稳定形式的 ROBUST 计算也未证明与原版浮点运算顺序逐位相同。

原版项目允许负数、零或很大的点大小；此处当时记录的本地 .1–32 渲染限制，已在后续[散点尺寸与覆盖修复](source-symmetry-splat-validation.zh-CN.md)移除，改为源最小点径与实际工作量预算。背景颜色和整个项目的其他字段也不在这 34 组标量验证的完整性声明内。

窗口工具本轮仍返回“Mac 已锁定，自动解锁失败”。没有尝试重复解锁，也没有移动应用到虚拟屏。原版整窗截图与输入验证等待原生窗口访问恢复。

## 成本与复核位置

原版成功样本运行约 1.01 秒。WebGL 检查脚本约 1.90 秒；外层进程族采样墙钟 2.38 秒、CPU 5.70 秒、峰值 RSS 约 1.35 GiB。App 流程脚本约 11.58 秒；外层墙钟 12.25 秒、CPU 25.31 秒、峰值 RSS 约 2.17 GiB。

上一轮同类 App 流程为 11.49 秒、外层 12.20 秒、CPU 27.35 秒、RSS 约 2.56 GiB。两次不是受控冷/热配对，不宣称提速。采样间隔 250 ms，可能漏掉短进程及峰值，共享页可能重复计数；token、GPU 内存与操作系统冷缓存成本未测量。

可提交的原版输入、输出与 JAR/JVM/harness SHA-256 在 `tests/fixtures/symmetry/project-visual-runtime.json`。当时的灰度接线检查现已由 `scripts/verify-source-symmetry-splat.mjs` 的原包着色器＋原版 JVM 色表对照取代；公开流程脚本为 `scripts/verify-captured-density-public.mjs`。本地运行栈、截图、日志和测量保留在 `.cache/source-symmetry-project-visual/`；原版二进制与缓存不进入 Git。

后续进展：静态色板、采样方式与 ROBUST 运算顺序已在[色板验证](source-symmetry-palette-validation.zh-CN.md)修复。上文灰度值是旧 4097 格采样的历史结果，不能用作原版 1024 格 LINEAR/REPEAT 的期望值。
