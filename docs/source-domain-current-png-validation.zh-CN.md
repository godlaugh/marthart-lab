# 域着色：保存当前状态的 PNG

域着色的当前帧截图已贯通保留状态的会话、实际 Worker、Generator 和生成队列，并连接公式合成与 PNG 后处理。**这是后台 API 的完成；主界面尚未启用 Domain 实时会话，录制与界面接入继续推进。原版整窗对照仍为 0/11。**

## 已完成的行为

截图读取当前数值状态，先绘制离屏图像，再将同一状态重绘到主预览。两次绘制共享渲染器的失败状态，不重建时间线，不增加更新序号，也不消费新的帧率观测。

手动参数值提交可能已经生效，但尚未产生新画面。截图会读取这个最新状态，而不是复制旧画面的像素；未应用的公式或标注草稿仍不参与绘制。截图与主预览的新状态相互核对，客户端也检查时钟、尺寸、公式和当前画面身份，拒绝过期或损坏的响应。

尺寸继承已完成主预览的像素密度。例如请求 161×121、密度 2，基础图像为逻辑 81×61／物理 162×122。后处理顺序为：

1. 在实际基础尺寸绘制当前图像。
2. 合成构建场景时捕获的公式标注。
3. 对完整图像增强。
4. 按 1、3 或 5 倍放大，再编码 PNG。

因此三种最终尺寸分别为 162×122、486×366、810×610。放大倍率不改变数值采样，不在最后的大尺寸上重新绘制公式。

分形原有的运行时 `fractalCurrentImage` 已统一为共享的 `sourceCurrentImage`；生产者、传输校验、编码器、测试和验证脚本全部迁移，不保留第二套字段或后处理实现。这不涉及持久化作品格式。

## 错误与取消

无效尺寸、资源预算或未暂停等前置拒绝保留已确认的主预览。开始绘制后的不确定失败会使旧画面身份失效，避免继续控制已失效的会话。PNG 编码在独立 Worker 中运行；取消编码不会取消数值会话，随后可以重新编码或再次截图。截图完成后，队列发布重绘的主画面，拖拽继续使用这个新的有效身份。

## 已执行的像素验证

`verify-source-domain-current.mjs` 使用实际生产 Worker 和 PNG 编码器，验证 CPU／GPU、隐藏／显示公式、1／3／5 倍共 8 组图像。公式 SVG 字形复用 MathJax，但摆放位置独立计算；增强和双三次放大使用独立 Python 字节码／OpenJDK 规则实现。最终检查 PNG 格式、CRC、尺寸和完整解码 RGBA，8 组全部逐字节一致。

用例从已经推进到 0.25 秒的动画状态开始，暂停后提交一个尚未重绘的参数修改，并暂存无效公式草稿。实际导出与恢复预览使用新参数，像素区别于先前画面；草稿没有被应用，更新序号仍为 1。另有容量拒绝后重试、编码取消后重试、过期画面拒绝，以及真实生成队列截图后继续导航的验证。

本轮验证仅证明本地当前状态与导出流程的上述行为。原版 JOGL 完整像素、JLaTeXMath 字形度量及真实窗口交互尚未对照；不能把这些 PNG 比较算作原版整窗一致性。
