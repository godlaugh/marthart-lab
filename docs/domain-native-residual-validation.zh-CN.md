# 域着色原生残差调查

后续已取得原版实际顶点提交数据，并将旧诊断的坐标偏差定位到它自身的 UV 算术表示。当前结论与可复验输入见[真实提交边界验证](source-domain-native-residual-validation.zh-CN.md)；以下保留此前受控实验的范围，不能将其手写顶点当作原版真实提交。

2026-10-22。当前证据表明坐标产生方式和坐标之后的复数数学执行都能独立造成像素差异，但尚不能把实际原版 Scene 的残差全部归因于驱动。因此本次没有修改产品数学模型，也没有放宽一致性要求。

## 已确定的边界

同一原版域着色场景在两次独立原生运行中输出了完全相同的原始图像。把原版 raw 图送进本地增强处理，得到与原版增强后全图完全相同的 RGBA，排除了该样例的后处理为残差来源。

原版保留 shader 与产品 GPU-only 在同一 ANGLE Metal 后端仅有 3 个 ±1 的局部像素差异；原版 Native OpenGL 与该保留 shader 的同一中心区域仍有 744 个像素差异。这组设备先前被误标为 SwiftShader，已根据实际 renderer 记录纠正为 Apple M2 Max 的 ANGLE Metal。

一次有界的原生诊断先保留原始 Scene 图像，再在独立 GL program/FBO 中使用实际 shader 与 uniform。两端使用同一诊断顶点时，300,000 像素的 UV 和复平面坐标完全一致；但 `c_pow(z,2)` 有 64,952 个像素出现低位差异，最大有限分量差约 4.77e-7。一次迭代后有 47,542 个像素不同，27 次后有 43,594 个像素不同，并出现 266 个非有限值分量不一致。注入原生坐标纹理后结果不变，证明这组受控差异发生在坐标之后。

同一 Metal 后端改用另一种顶点构造时，坐标会出现低位差异；强制双方使用同一坐标后最终颜色完全相同。这另外证明了坐标路径也会影响结果。

## 为何没有直接修改产品

独立诊断重放自身仍与原版 Scene 相差 729 个中心区域像素，尚未复现真实 Processing 提交过程。浏览器矩阵顶点重放相差 1,354 个，而直接裁剪空间版本相差 746 个。未经校准便替换顶点会让该测量更差，不能作为修复。

显式 SwiftShader 对照相差 44,700 个中心区域像素，不能替代本机原版作为参考。以上区域为 `[55,55,445,510]`，共 177,450 像素；区域比较不是整图验收。

原生运行遵守正常许可证、策略和导出检查，保留 FREE 水印；退出码 0，耗时 7.818 秒，GL 检查均为零，无 AWT 窗口，无桌面激活或输入，进程组已退出。原设置和许可证状态未变，正常策略缓存刷新前已备份。

下一步需要捕获原版 Processing 的实际顶点输入或片段坐标，先让诊断重放复现真实 Scene，再划分坐标与数学误差。当前未完成该场景原版 GUI 等价性、全部预设或动画验收。

完整可复现证据、设备记录、脚本和分阶段数值对照保存在 `.cache/domain-native-residual-20261022/float-boundary/`。本次属于定位证据，Domain 家族仍未验收。
