# 弹跳场景：速度输入、保存与重新播种补验

2026-10-26。**初始速率现在可以输入和保存 101，重开后仍显示 101；实际模拟按原版规则使用上限 100。** 修改 101 → 102 会用相同种子重新初始化，不会继续沿用修改前的粒子位置。

修复已进入 Apple Silicon 本地应用 **2.0.0-preview.8**。这项缺口已关闭；整体仍处于 M3，11 个场景家族的剩余一致性验证继续进行，未宣布 2.0 完成。

## 为什么原来会报错

旧实现只保存模拟配置，而模拟配置需要限制在 0–100。数字编辑器虽然能解析 101，提交到保存模型时却被拒绝。

现在文档单独保存超过模拟上限的有限作者输入，模拟配置由同一个规则生成。保存文件若同时带有作者输入和模拟值，会验证两者一致，拒绝冲突数据。旧文件没有新增字段时，继续以其已保存的模拟速度作为输入值，不重新解释来源记录。

重新初始化的判断也使用作者输入，因此 101 → 102 会重置同一 seed 的粒子序列；颜色、相机和录制时长的修改不会因此重新播种。

## 原版证据

实际调用原包的数字解析器、Float 回调包装、JSON 往返和配置构造，共 **16 项**。101、102、最大有限 Float32 以及 `100+1` 都确认了“保存输入值、模拟限制为 100”；`1/20` 保留 0.05 的 Float32 值。

这些调用使用惰性 PApplet 进行颜色解析，没有创建 renderer、surface 或窗口。它们不是原版 GUI 保存测试。原版 ProjectState 的保存规则和成功提交后重新初始化的规则另由字节码核对。

还发现一个需要明确区分的边界：原版 ProjectState 的文件导入只读数字字面量，直接 JsonConfig 配置导入则支持表达式。产品继续采用已有的直接配置导入路线，并从有限的截断前结果初始化本地输入值；不宣称完整复现原版 ProjectState 的表达式文件导入。非有限表达式仍按既有配置规则处理，不会被保存成非有限作者输入。
