# 弹跳场景：2.0 实现与验收进度

更新时间：2026-10-19。当前处于 **M3：场景补全与一致性验证**。

原版运动、初始化、粒子点绘制及容器边界已独立实现。粒子和边界在同一 GPU 画面中按源顺序合成。**尚未接通界面的完整原版弹跳流程**；播放时钟、导入相机与公开导出仍待接通，当前界面的旧本地模型仍使用自己的采样与碰撞算法。原版 JVM／JOGL 整图验收仍为 **0/11**，1.0 Apple Silicon 应用包没有替换。

## 已实现的行为

- 原版配置默认 20 万粒子、2 个子步；内置 `bouncing1` 示例请求 200 万粒子。这两个来源分别保留。
- 使用 Java 48 位随机数序列和完整有符号 64 位种子。每个粒子先采位置，再采速度；没有角度抖动时不额外消耗随机数。
- 支持全部 14 个初始化模式及填充／轮廓选项。原版 `ARCHIMEDEAN_SPIRAL` 实际落到 BOX，依照这个分派保留。
- 保留各形状的原版公式、Float32 运算顺序和丢弃随机值的行为；没有改成数学上更常见的曲线定义。
- 外层最多尝试 512 次，失败后仍保留粒子并放在容器中心或多边形顶点均值处。部分形状内部还有独立的 512 次尝试。
- 支持均匀、随机、径向向外／向内、顺时针／逆时针切向六种速度模式。
- 公式使用原版 FastExpression 语义，只绑定世界坐标 x/y。语法错误明确返回失败；轮廓模式是接受采样点后加抖动。
- 初始状态为连续的 `[x, y, vx, vy]` Float32 数组；GPU 负责纹理补齐和后续运动。圆、椭圆和多边形更新均保留原版每子步最多四次碰撞。
- 点绘制直接读取当前 GPU 状态纹理，按原版色板插值、速度亮度与圆形柔边输出。保留默认六色、空色板白色、最多 25 个绘制颜色，以及忽略色板 ARGB alpha 的原版行为。
- 点大小分别经过主机端和着色器端的下限处理；导出缩放来自视口高度比例。绘制单独上传投影和模型视图矩阵，使用普通透明混合，不借用吸引子的密度绘制。
- 每次绘制清屏，重复绘制不会推进粒子。背景整数 0–255 按 Processing 规则显示为不透明灰度；其他 packed ARGB 保留透明度。普通绘制只读回图像，不将全部粒子读回 CPU。
- 容器边界在粒子之后绘制：椭圆按逻辑投影尺寸细分 20–200 段，使用 720 项 Float32 三角函数表；多边形保留作者顺序、重复点和凹角。缩放后的线宽达到 2 时生成原版闭合 bevel 连接。
- 边界保留 alpha 210；Processing 的边界 alpha 混合与粒子不同，按源顺序分别设置。共用已经验证的 Processing 描边着色器、方向变换和视口规则；GPU 缓冲预分配后复用，改变尺寸或关闭边界不会污染粒子状态。

配置解析保留设置节是否出现、多边形来自根对象或设置节、被读取字段路径及数字字段路径。初始化与视觉配置各自拥有对应解析事实；尚未接入公开作品格式，不宣称完成整个原版文档或相机播放行为的验证。

## 验证范围

初始化批次通过 11 个测试文件、160 项测试；点绘制批次通过 6 个文件、99 项测试。本轮边界与相关回归通过 **10 个测试文件、133 项测试**；TypeScript 检查与 Web 构建通过，构建保留已有大 chunk 提示。各批包含重复测试，不相加为总数。

运动模块已与独立提取的原版着色器在同一浏览器 GPU 上核对：13 组案例、72 份完整纹理状态零差异，包含 20 万与 200 万粒子。缺失浮点能力、编译失败、取消、上下文丢失、删除失败重试五类检查通过。

点绘制另以独立提取的原版着色器和独立 uniform／背景转换核对：**18 组、72 张完整 RGBA8 图像、180 份完整 RGBA32F 粒子状态零差异**，共比较 657,108 个像素。覆盖 20 万与 200 万粒子、色板省略／空／超过 25 色、透明背景、速度倒数溢出、点大小、不同矩阵、改变尺寸、修改显示参数以及交替绘制与运动。7 项失败、取消和清理重试检查通过，遗留资源为 0。重复绘制没有改变状态，正常绘制每次只做一次图像读回。

这项对照使用同一浏览器 GPU，并将 GLSL 410 改为 ES 300；本地明确关闭 DITHER，原版继承的抖动、MSAA 和驱动精度尚未确认。**像素一致仅指独立参考与本地点绘制之间一致，不是原版 JVM／JOGL 整图一致**；容器边界、累积历史和界面导出也不在这 72 帧的范围内。

边界另用保留字节码执行原版路径和三维描边算法，**29 组路径、位置、方向和索引逐位一致**。覆盖细分上下限、线宽阈值两侧及等于 2、凹角与闭合缝、重复点、负缩放、零轴、倾斜相机，以及有限投影值产生 Infinity／NaN 后的 Java 整数转换。解释器只对有界数组分配、样式记录、三角函数表和距离数学提供适配；没有代替原版 JVM 或证明 Java／JavaScript 数学库的末位一致。

将这些独立几何结果与原包 Processing 着色器结合后，在同一浏览器 GPU 上得到 **116 张完整合成图像、290 份完整粒子状态一致**，共比较 1,350,722 个像素。检查包括同一对象反复开启／关闭边界、改变尺寸、继续运动、粗线与粒子重叠；11 项失败、取消和清理重试检查通过，遗留资源为 0。原粒子层 72 帧及初始化 74 组回归也通过。共享描边代码的曲面和吸引子轨迹另有 50 组既有 GPU 对照保持零差异。

本轮只证明本地实现与独立字节码／适配着色器参考的一致性。单个边界最多 200 点，未覆盖原版更大索引批次拆分；未验证原版 MSAA、驱动精度、累积历史、窗口整图或公开导出。记录为 `.cache/v2-source-bouncing-boundary-geometry.json` 和 `.cache/v2-source-bouncing-boundary-render.json`，代表性测试图为 `.cache/v2-source-bouncing-boundary-preview.png`。

初始化另用独立 Python 解释器执行保存的原版字节码：**74 组配置、1,258 个粒子、5,032 个 Float32 通道及全部最终随机数状态一致**。其中 24 组公式案例执行原版比较包装和采样字节码，但内部表达式只用独立的有限算术适配器核对常量、x/y、四则运算和比较；完整 FastExpression 解析与函数库不属于这项独立对照。解释器使用 Python 数学库和显式 Java 基础类型适配，不能代替原版 JVM 的数学库或完整画面验证。原应用自带 Java 库的直接加载探针停在系统动态库加载阶段，尚未执行 Java 初始化方法；未修改原应用、运行时签名或隔离属性。

## 完整初始化成本

每组使用三个独立 Node 进程，各执行一次冷首任务和一次暖新任务。任务包括配置解析、全部粒子初始化、世界边界和完整结果哈希；重复结果一致。耗时与 CPU 取中位数，RSS 取三次最大值：

| 配置 | 冷／暖耗时 | 冷／暖 CPU | 冷／暖进程峰值 RSS |
| --- | --- | --- | --- |
| 默认 20 万粒子 | 120.46／106.17 ms | 134.20／115.63 ms | 64,096／67,456 KiB |
| 原包 bouncing1，200 万螺旋粒子 | 781.29／790.48 ms | 792.94／802.34 ms | 92,224／125,424 KiB |

任务期间没有子进程，因此进程族为该 Node 进程。模块加载与输入读取不计入耗时／CPU，但计入累计峰值 RSS；暖任务 RSS 也包含此前冷任务，冷启动没有清空操作系统缓存。这项初始化单项测量未覆盖原版 JVM、浏览器／GPU、视频导出及 token。此前没有等价的原版初始化实现，旧本地算法的随机序列和形状不同，未拿它充当性能基线。这些数字不代表实时播放帧率。

## 初始化、运动和点绘制的完整任务成本

边界实现前（提交 `678a224`），每个配置在独立启动的 Chrome 进程族中执行一次冷首任务和一次暖新任务。每次重新解析配置、生成全部初始粒子，再连续进行 **31 次更新及 640×360 点绘制**，读回每张完整图像并计算哈希，最后释放资源。冷暖两次的 31 张图像逐帧哈希一致，每个任务的 31 帧均各不相同：

| 配置 | 冷／暖总耗时 | 冷／暖观测 CPU | 冷／暖采样峰值 RSS |
| --- | --- | --- | --- |
| 默认 20 万粒子 | 241.60／211.00 ms | 210／170 ms | 1,003,920／1,043,184 KiB |
| 原包 bouncing1，200 万螺旋粒子 | 1,147.60／1,180.00 ms | 860／1,050 ms | 1,162,160／1,232,032 KiB |

这是每组一次冷暖测量，不是多轮中位数。浏览器启动及模块加载不计入任务耗时；每 250 ms 和任务边界采样 Chrome 及其子进程，20 万任务仅得到两次边界样本，因此 RSS 只是观测下界，CPU 也可能漏掉极短命进程。包含浏览器本身开销，不含 Node／Vite 和显存；暖任务的浏览器状态包含之前冷任务影响。上述历史记录保存在 `.cache/v2-source-bouncing-display-cost-before-boundary.json`。

这些数据只衡量明确的粒子层任务，未包含边界、原版播放时钟、界面交互或 PNG／MP4 编码，不能据此认定完整场景达到某个帧率。测量固定采用共享 Scene 相机 phi=Float32(π/2)、theta=gamma=0，未采用尚待接入的原版弹跳配置相机。原版 JVM／JOGL、GPU 设备时间、显存和 token 成本未测，也没有等价的旧实现性能基线。

边界实现后，按相同测量方法分别重跑原粒子任务及新增合成任务。原粒子任务在改动前后的全部输出哈希一致；新增合成任务的每次测量均完成 31 次边界绘制、每帧图像与纯粒子任务不同，冷暖结果逐帧一致：

| 任务／配置 | 冷／暖总耗时 | 冷／暖观测 CPU | 冷／暖采样峰值 RSS |
| --- | --- | --- | --- |
| 纯粒子回归，20 万 | 248.70／210.10 ms | 210／190 ms | 1,007,184／1,042,352 KiB |
| 纯粒子回归，200 万 | 1,129.40／1,162.40 ms | 860／970 ms | 1,128,944／1,170,752 KiB |
| 粒子＋边界，20 万 | 245.70／213.20 ms | 220／190 ms | 1,002,736／1,045,040 KiB |
| 粒子＋边界，200 万 | 1,148.40／1,209.70 ms | 880／960 ms | 1,129,952／1,144,176 KiB |

记录分别为 `.cache/v2-source-bouncing-display-cost.json` 和 `.cache/v2-source-bouncing-boundary-cost.json`。测量范围和采样限制同上，新增任务包含真实路径生成、描边展开与同画面绘制，但仍不包含原版播放时钟或公开导出。单次波动不代表优化或退化；只有纯粒子改动前后属于相同任务，新增边界任务不能冒充相同负载的性能比较。

## 资源限制与剩余工作

初始化数组最多 128 MiB，总工作预算为 6,400 万单位（采样候选、公式节点、边界边与速度计算）。先检查完整请求的最低工作量，再按实际尝试扣费；超额或取消会返回失败，不减少粒子数，也不返回不完整数组。它不是 CPU 指令数或时间保证。

GPU 状态与绘制表示合计最多 256 MiB，暂不支持原版 500 万粒子示例；不会自动降低粒子数量。边界按 200 点上限在分配前额外预留 85,728 字节，覆盖路径及 CPU／GPU 展开缓冲；驱动内部开销不属于这个表示预算。每次更新的工作量预算覆盖多边形面积、最多四轮碰撞、点内判断与最近边恢复，按每子步最多八轮边扫描预检。每次绘制还受图像容量、设备点大小及最多十亿点片元上界约束；单个 GPU 对象最多更新、绘制各一万次。超预算明确失败，不裁剪请求。

字节码审计确认：原版 JSON 弹跳场景不解析时间线，空队列仍持续更新粒子；`showTrails=true` 本身不会创建历史拖尾。通用界面另有累积模式，尚未实现。源弹跳配置相机三角度默认全 0，缺失 settings 时不读取 camera；不能直接套用共享 Scene 相机缺省值。原版录像从当前粒子状态开始，先更新一帧作为不编码的预热，再逐次 Float32 累加场景时间并检查停止条件；现有通用导出帧数规则不能代替它。

下一步接通源配置文档、相机与持续运动的播放时钟，以及导入、编辑、保存、回放和导出。之后做原版窗口的匹配画面对照、长时高粒子验收和 2.0 发行验收。本轮复查原版窗口时 Mac 仍锁定，未取得原版画面。其余十类场景的未完成要求继续保留。
