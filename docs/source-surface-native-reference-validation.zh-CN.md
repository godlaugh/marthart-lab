# 曲面原版完整画面对照与剩余差异

2026-10-23。**Cornucopia 和 Sphere 的完整艺术画面现已与原版逐像素一致；Möbius 网格仍有 1 个高对比像素差异，曲面整体验收未通过。** 本次修复了点纹理的各向异性过滤设置，以及 CPU 点坐标变换的位置和 Float32 舍入顺序。没有放宽容差。

## 当前实测结果

三份原版参考和本地结果均为完整 500×600 图像，共 300,000 像素。艺术画面是原版完成几何及配置启用的公式、尚未绘制品牌叠加层的阶段；比较没有裁剪、重采样或掩码。

| Sphere | CPU 点，800 个点 | 5,821 | **0** | 0 |
| MöbiusStrip | CPU 网格 | 1 | **1** | 222 |

Cornucopia 的自动主方程也参与完整艺术画面对照，另两份原配置关闭主方程。Möbius 唯一不同像素位于 `(71,257)`：本地为 `[139,154,33,255]`，原版为 `[255,255,255,255]`，通道绝对差总和为 439。

最终含原版品牌叠加层的增强 PNG 仍另外整图比较，Cornucopia、Sphere、Möbius 分别有 7,955、7,140、7,151 个不同像素，最大通道差均为 222。没有移除或修改原版标志／水印；**上述两个零差异结论仅指完整艺术画面，不表示含品牌的最终文件字节一致**。增强文件差异包括品牌叠加及其后处理传播，尚未逐项核销。

## 根因与修复

独立复放原版实际顶点、索引、uniform、纹理和着色器后，CPU 点仍有残差。随后读取原版 GL 状态，确认本机原版纹理各向异性过滤为设备最大值 **16**，本地 Three 纹理此前使用默认值 **1**。在独立复放中仅补上该状态，两张点图都归零。

原版 Processing 的 CPU 点路径先把中心坐标逐乘法、逐加法舍入到 Float32，再在 shader 中使用单位模型视图矩阵；此前本地把这一变换留在 GPU。全部 1,724 个原版中心点、5,172 个坐标与分步 CPU 计算完全一致，直接双精度计算后仅最终舍入有 725 个坐标不同。仅改 CPU 变换而不改过滤时，Cornucopia 从 3,905 降至 3,898 个不同像素，Sphere 不变，不能独自解决残差。

生产修复包括：

- 渲染上下文提供实际支持的最大过滤值；扩展不可用时为 1，不硬编码本机的 16。
- CPU 点、CPU 网格填充与隐式曲面共用同一个 Processing 视图坐标转换实现。去掉旧网格包装和隐式曲面的重复循环，保留容量检查及非有限值槽位。
- CPU 点拥有新的 vec4 视图坐标数组，继续借用源颜色与透明度数组；GPU 曲面点保留原来的 GPU 数学变换和种子所有权。材质释放时仍释放精灵纹理。

点纹理 64×64 至 1×1 的全部 7 级 RGBA 原先就一致。关闭 DITHER、改用归一化 Uint8 顶点颜色均不能消除残差，未集成这些诊断改动。

Möbius 使用实际原版输入的独立复放显示：**填充阶段零差异，加入线段后出现同一个像素差异**。后续已用全部原生 clip 顶点复放并读取完整深度缓冲，将残差缩小到相同顶点下的深度／光栅交互；见 [深度残差取证](source-surface-depth-residual-validation.zh-CN.md)。仍不能凭“只有一个像素”判为通过。

## 原版运行边界

固定 MathArt 1.7.8 JAR，SHA-256 为 `a6e1da3acfc05c347d2529c1d590657e2dd798e16d38c55df3dc61312be24018`。输入为包内原始 `SurfaceConfigs` JSON，没有改变采样、公式、时间线或模式来制造一致结果。

后台 staged-loader 宿主使用原版 bundled JVM，调用原 Scene 的 `runFrame(buffer,true)` 一次，保持初始暂停时刻。主画布逻辑尺寸 405×486、density 2；导出逻辑尺寸 250×300、物理尺寸 500×600，关闭导出 MSAA。通过被动 GL 转发读取分阶段完整图像及实际纹理／属性，原绘制参数和返回值不变。完整 raw PNG 和增强 PNG 由原版方法输出。

首次三个原始采集分别耗时 8.80、6.12、9.46 秒，退出码均为 0，进程已回收、进程组不存在，窗口对象和可见窗口检查始终为 0。正常执行 VIEW / RUN / EXPORT 权限检查并保留水印，500×600 未超过许可导出上限。策略缓存写入前有备份；settings 与 license 文件的存在状态和摘要保持不变。两个点场景独立重复采集的几何图与首次字节相同。

## 修复成本

与固定提交 `8f957bd` 的点渲染实现比较，使用相同真实 Worker 输出和另一个 40,000 点合成重复负载。每项完成 20 次创建对象、上传、绘制、500×600 全帧读回、像素摘要与释放；每个变体单独启动后台浏览器，首轮后再测两轮。该任务不包括公式合成、UI、生成或完整暂停导出，不能换算为产品帧率。

| 输入 | 首轮墙钟毫秒，旧→新 | 两轮热运行墙钟毫秒，旧→新 | 热运行浏览器家族 CPU 毫秒，旧→新 | 家族采样峰值 RSS MiB，旧→新 |
| --- | --- | --- | --- | --- |
| Cornucopia，924 点 | 112.6→112.9 | 95.5–99.6→91.9–97.1 | 100→90–110 | 1,004.0→1,007.0 |
| Sphere，800 点 | 97.7→98.1 | 89.8–90.9→89.8–90.4 | 80–110→90 | 1,012.9→1,016.0 |
| 合成重复负载，40,000 点 | 108.9→178.6 | 101.6–105.2→166.6–180.0 | 100–170→200–260 | 1,024.6→1,061.7 |

小参考场景的测量接近；较大合成负载存在明确开销，本次以画面正确性为先，不声称性能改善。CPU 视图数组每点 16 字节，40,000 点为 625 KiB；在已有 262,144 点上限下最多 4 MiB。GPU 上传由 float3 改为 float4，额外每点 4 字节；GPU 种子路径没有这份 CPU 转换数组。

RSS 是浏览器进程家族 250ms 加边界采样的最大总和，可能重复计入共享页或漏掉瞬时峰值；CPU 是已观察进程的累计时间增量。冷运行不代表清空操作系统／驱动缓存，后面的输入也使用同一变体浏览器。模块和输入准备、Node/Vite、显存及 agent token 未测。各轮输入未改写、图像摘要稳定、20 份几何／材质／纹理均收到释放事件；事件本身不证明驱动立即归还显存。
