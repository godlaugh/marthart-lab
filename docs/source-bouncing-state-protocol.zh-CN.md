## 已完成

粒子初始数据只上传一次，以 4 MiB 块传输。原生进程保留状态纹理，后续按明确的起止更新索引推进并绘图；暂停重绘不推进模拟。显示参数、相机和容器边界由同一纯函数准备，不再先创建 WebGL 状态、再读回到原生端。

状态资源使用独立的随机身份，与 HTTP 请求序号分开。创建、上传、绘图、释放各有明确操作；上传响应返回已确认的粒子数量。只有持有同一身份的调用方才能访问或释放该状态。正常无状态绘图可以穿插执行，第二个状态资源会被拒绝，避免悄悄替换第一个资源。

进程取消或图形上下文出错后，旧状态明确报告丢失。失效响应不能被当成成功帧或自动退回 WebGL。客户端的自动重建与重放属于下一步应用接入工作。

## 数据量与成本

相同 62 帧的真实请求体总量从 **1,986,905,010 字节降到 34,926,080 字节，减少约 98.24%**。新通路只上传一次 32,000,000 字节粒子初始数据，后续没有浏览器 WebGL 上下文或粒子读回。此数字不含 HTTP 头和图像响应。

每个上传块的准入计算包含底层完整种子数组、原生纹理、协议副本与输出，而非只计算子数组的可见长度。500 万粒子用例允许 4 MiB 块、拒绝 8 MiB 块。

| 本地运行 | 总耗时 | 进程族 CPU 采样 | 峰值 RSS 采样 |
| --- | ---: | ---: | ---: |
| 保留状态 HTTP 对照 | 5.86 秒 | 8.57 秒 | 约 2,615 MiB |
| 原有无状态 HTTP 复验 | 11.65 秒 | 19.76 秒 | 约 3,117 MiB |

两项工作负载的状态诊断不同：前者只对照初始 CPU 种子，后者对照 11 个完整纹理。耗时差不能直接归因于协议优化，也不是产品帧率。采样可能漏掉短进程或瞬时峰值；严格冷／暖运行、独立 GPU 时间和 token 成本未测量。
