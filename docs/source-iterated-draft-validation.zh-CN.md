# Map / Symmetry 草稿、Apply 与录制验收

2026-10-21。本轮完成 Map / Symmetry 的统一编辑草稿及运行状态分离。2.0 仍在 **M3**；原版完整窗口效果对照仍为 **0/11**。本轮通过的是本地 App、Worker、WebGL 和 FFmpeg 工作流，不代表 11 个场景已经完成视觉一致性验收。

## 现在如何使用

修改公式、GLSL、批次数、预热步数或初始相机时，检查器显示「有未应用的修改」。当前动画继续使用原来的运行配置；点击「应用场景」会一起提交这些修改。Map 的维度、初始范围和点尺寸，Symmetry 的模板选择，也使用这条草稿路径。

- 参数数值仍可热更新，不会顺带应用尚未完成的公式。模板草稿新出现的参数也可写入当前实例；修改版的 `delta_power` 保留完整 Apply 行为。
- 变换、调色板、点尺寸和运行显示设置各自更新对应字段组。Map 点尺寸等待 Apply，Symmetry 点尺寸直接更新。
- 「应用公式」「应用初始相机」和全局「应用场景」会收集同一份草稿。背景、参数增删、结构参数、时间线与项目分辨率的完整应用入口，也携带当前草稿。
- 暂停中 Apply 保持暂停，播放中 Apply 保持播放；重新构造后从头开始。无效输入保留当前实例和草稿。
- 改过的自定义 GLSL 先用独立 Worker 执行真实 GPU 首帧验证，成功才提交。验证期间的新编辑会使旧结果失效。
- 只撤销或重做草稿，不要求重新计算画面。「放弃未应用修改」只清除草稿。

安装在本机的 Apple Silicon 1.0 应用未重新打包或替换；本轮针对当前源码和 Web 构建。

## 保存与录制是不同操作

保存和导出项目保留尚未完成的输入，不触发 Apply。`.mathart.json` 在有效运行文档外保存可选的 `iteratedDraft`，包括明确删除的字段及尚未输入完的相机文本。重新打开本地文件会分别恢复运行配置和编辑草稿，不会尝试把不完整文本送入渲染器。

这是本地恢复格式的明确选择。原版 Save 导出完整 ProjectState；本地格式额外保留有效运行配置，因此不能把本地重新打开的行为宣称为原版重新打开行为的复现。原版 JSON 的导入仍走已有配置入口。

原版录制会重建最后一次 Apply 的配置，不把之后的热参数或未应用结构草稿自动算进去。本地录制沿用该锚点。录制结束后，编辑器仍保留这些待应用值；它们与恢复后的运行文档重新计算差异，因此不会丢失，也不会误成为新的录制配置。

## 原版依据与实现边界

复用已核验的 MathArt 1.7.8 JAR，SHA-256：
`a6e1da3acfc05c347d2529c1d590657e2dd798e16d38c55df3dc61312be24018`。

字节码审计表明：REINIT 字段先写 ProjectState 并抑制即时回调；普通参数回调只写名字和值；运行、变换和调色板回调各读取对应字段组。完整 Apply 导出整个 ProjectState；Save 不调用 Apply；录制从保存的 currentJsonConfig 重建。相关数值来源及 JVM 配置边界见 [前一轮 Apply 记录](source-iterated-apply-validation.zh-CN.md) 和 [原 JVM fixture](../tests/fixtures/source-iterated-apply/README.md)。

实现把草稿所有权集中在 `sourceIteratedDraft`：运行状态不携带草稿，检查器只读叠加视图，保存时才打包两者。删除与继承使用不同表示；解析边界检查类型、有限数值及文本容量。热更新仅提交选定组，再根据归一化后的运行配置重算剩余草稿。录制结束保留队列返回的精确实例引用，避免破坏暂停、截图和继续录制所依赖的实例凭据。

新增参数名需要明确的参数写入意图；删除或混入构造字段仍要求完整 Apply。真实 GPU 检查确认新名不会重新播种或替换已有粒子、构造宏；相应 dirty 状态在显示时确认。

验证过程中发现独立 GLSL 预检缺少相机画布上下文，会把合法源码也拒绝。现在两个源码编辑入口共用完整的首帧请求，明确传入相机视口、像素密度和亮度参考尺寸。实际着色器编译错误与合法源码应用分别验证。

## 仍未验收

原版整个窗口、Compose 焦点提交顺序、各控件所有竞态和超大工作负载仍未完成验证。GLSL 独立预检目前覆盖源码改变路径，不是对所有未来配置或设备故障的提交前保证。缺少编辑来源的旧配置仍明确拒绝 Apply，不猜测补齐。

所有本轮浏览器验证均为后台无窗口模式，没有向用户桌面发送输入或移动窗口。本轮未检查 Mac 锁屏状态或 Yomado 目标屏截图隔离；虚拟屏可用性和原版整窗对照仍需后续实测。
