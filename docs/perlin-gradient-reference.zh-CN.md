# Perlin 渐变参考行为核对

2026-10-19 初次记录，2026-10-21 补充。固定参考 MathArt 1.7.8 JAR 的 SHA256 为 `a6e1da3acfc05c347d2529c1d590657e2dd798e16d38c55df3dc61312be24018`。本节为包内类文件的静态观察与推导；后续原版运行记录及其限制见末节。

原验收清单把“Cosine／Curve／HSV 缺函数参数渐变”当成 Perlin 的原版缺项，这个判断不准确。

原版 Perlin 编辑器可用 Manual、Cosine、Curve；Cosine 和 Curve 会先生成 2–25 个普通颜色，写入作品 palette 数组，再交给同一个运行时动画器。相关枚举没有 Sine／HSV。不能把本地函数色图的参数动画当成原版 Perlin 的运行合同。

| 原版动作 | Perlin 实际消费方式 |
|---|---|
| HUE_ROTATE | 色板主偏移，并非直接对 RGB 色标做 HSV 色相旋转 |
| OFFSET_CYCLE | 内外两个偏移的平均值 |
| CROSS_FADE | 同一色板在两个偏移处的采样混合，并非两组任意色标的单程过渡 |
| PALETTE_MORPH | 主偏移与外部偏移的采样混合 |

RGB、Linear RGB、OKLab、OKLCH 四种颜色插值确有执行路径。Perlin 动作构造器强制启用两个影响区域；CPU 粒子、曲线及 GPU 纹理均接入动画器。停止动画本身不触发颜色重新生成，只有实际状态变化才刷新；GPU 使用 256 项颜色纹理。曲线模式下，初始化时生成的空间色圆还保留自己的固定颜色，不能随每帧渐变重新生成。

旧本地模型的色相变换、双色板过渡、动画速度、停止刷新时机和 GPU 色板采样与这些源规则有差距。源 GPU 现已单独接通导入、编辑、保存、回放及导出，最新验收见本文末节；旧作品保留原模型。CPU 粒子／曲线和原版整图对照仍待完成，因此 MAS-NOI-033／034 **仍未完成**。

## CPU 运动与曲线路径（2026-10-19）

本批补齐源 CPU 几何生产者：粒子的三种流场／两种角度映射、曲线角度场、固定种子分布和双向积分路径。它们尚未替换界面里的旧 CPU 渲染；颜色、拖尾、实际绘制和公开导入／编辑／导出仍需接通。

- 种子由共同模块拥有：32 位范围内保持原值，范围外执行源 64 位混合；粒子随机数使用完整 long，Processing 噪声使用低 32 位。曲线使用原始种子另行混合，避免与 GPU 纹理随机流混用。
- 角度场保留原始 Float32 运算顺序、建表与采样不同的步长下限、有符号角度余数和采样后偏移。
- 曲线保留固定种子，先计算后向半条，再从种子重新计算前向半条；越界路径继续延伸。重建失败或取消保留上一份完整几何。
- 粒子越界直接放到对边，重生只重抽位置、保留方向；负／零时间步、实时尺寸变化与随机消费顺序均按源方法处理。运动失败后拒绝交付部分状态，调用者须重建。

主画布的逻辑尺寸决定模拟范围；预览质量改变取样尺寸及所选像素密度，不改变粒子初始化范围。浏览器显示比例允许分数，而 Processing 密度是整数，因此本地预览将显示比例选择为最近的 1×／2× 源画布密度，显示层仍按原始比例取样；这是明确的本地适配规则，不冒充原版显示器检测。按原包调用规则，主画布请求 smooth(8)，在同一设备查询最大样本数后选择；透明曲线缓存显式请求 smooth(4)，不支持时报错；导出关闭 MSAA，按父画布像素密度换算逻辑尺寸并继承密度。导出初始画布先填配置背景。新建本地预览也显式使用当前配置背景；原版热切换场景可能保留前一场景背景，本批不模拟该历史。导出尺寸不能整除密度时，对实际画布作最终取样以保持用户指定文件尺寸，这属于本地输出政策。

## CPU/GPU 切换的状态规则（2026-10-21）

本批对固定 MathArt 1.7.8 原包的切换路径进行了静态核对。`MathArtSession.updateRenderMode` 对 Perlin 只经 `ProcessingBridge` 改变绘制标志，不调用重建；`ProjectState.toJson` 同时保存 CPU 和 GPU 设置。切换应保留粒子位置、随机序列、轨迹、曲线缓存、参数动画与渐变状态。GPU 模式继续更新时间和渐变，暂停 CPU 运动、参数漂移及轨迹过期；时间线直接设置参数仍然生效。原包相关时间线分派没有 CPU/GPU 切换动作，本地也不把新动作冒充原版支持。

切换还有一个需要保留的噪声副作用：首次真正绘制 GPU 画面时，原版依次生成六种流场纹理，并把共享 Processing 噪声状态留在第六种纹理的种子上。只切换标志而未绘制不触发它；纹理尺寸跨档时重新生成。返回 CPU 后粒子使用改变后的噪声，已缓存的曲线角度场则保留至重建。因此两个各自重新初始化的 CPU/GPU 会话不能代替原版切换。

当前只完成底层模型准备：可原地改变后端标志，GPU 更新继续颜色／时间但保留 CPU 运动状态，GPU 调色纹理按实际显示请求懒生成，模型允许注入宿主拥有的噪声对象。**尚未接通同时保存两套设置的公开编辑流程、共享噪声副作用和跨后端画布历史，不宣称 CPU/GPU 切换已可用。** 这些结论来自静态字节码与本地模型验证，未实际操作原版切换或证明原生画面相同。

证据固定于主 JAR SHA256 `a6e1da3acfc05c347d2529c1d590657e2dd798e16d38c55df3dc61312be24018`，`PerlinNoiseField` 类 SHA256 `ef1de66f25e6fed5a126cb260005d0b5d7fd161118cc83993f0648009de96d92`。逐方法偏移及证据文件索引保留在本机 `.cache/v2-perlin-backend-switch-audit.md`。

## 长拖尾与冷跳转的容量修复（2026-10-21）

公开生成接口的容量测试发现两个实际问题：冷跳转为每个中间时刻展开并绘制整条拖尾，反复消耗本次请求预算；长拖尾一次性展开成全部宽线顶点，又同时保留 CPU 数组和 GPU 上传，触及 256 MiB 表示预算。

现在，不累积的粒子冷跳转仍执行每一步运动、参数、颜色与轨迹插入／过期，只绘制最终被请求的画面。需要显示历史的累积模式及曲线缓存继续逐帧绘制。轨迹按原版已有的 ushort 索引缓存顺序逐块生成、上传与绘制，复用约 1.69 MiB 的工作数组，背景每帧只处理一次。完整输出与分块输出共用同一拓扑生成器，保留连接、换块颜色和非有限点规则；没有提高预算或减少粒子数量。

## 暂停截图保留运行状态（2026-10-21）

暂停 PNG 现在使用已有预览 Worker 中的同一个 Perlin 场景，保留 CPU/GPU 切换后的粒子位置、拖尾、曲线、渐变和噪声状态。导出界面默认选择“当前暂停场景”；“从初始状态重放”保留为另一种明确的输出方式。旧单后端作品仍使用重放导出。
