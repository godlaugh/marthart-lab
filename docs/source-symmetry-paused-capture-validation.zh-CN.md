# Symmetry 当前暂停画面导出验收

2026-10-21。Symmetry 的完整源模型现在可以从编辑器导出当前暂停场景的 PNG，保留实时会话；也可选择从初始状态按固定时间重放。**本阶段完成当前画面的导出链路，不代表 2.0 或原版画面一致性验收完成。原版整窗口对照仍为 0/11。**

本轮使用后台 Chrome、真实 Worker 和 WebGL，未操作主屏幕，未启动原版窗口，未重新打包或替换已安装的 1.0 Apple Silicon 应用。

## 用户可见行为

在支持实时预览的 Symmetry 项目中，打开「导出作品」，图像来源默认「当前暂停场景」。截图会额外绘制导出图，然后重绘主预览；动画时间保持不变。

- 与主画布相同尺寸：继续累积当前粒子。如果后台正在重播，截图会推进重播。
- 不同尺寸：清空累积图像并取消重播，保留粒子；恢复主画布时再次清空和绘制。导出窗口明确说明此行为。
- 3 倍和 5 倍 PNG 在基础图像增强后放大，不增加粒子或采样分辨率。按屏幕整数像素密度创建基础目标，因此奇数尺寸在 2× 密度下可能多一个像素。
- 完成后主预览更新，仍可继续播放同一实时场景。独立的固定时间导出不消耗这个会话。
- 超限请求在绘制前拒绝，可直接调整尺寸重试；绘制中失败则废弃无法确认的状态，保留资源清理责任。不能把它描述为原版的事务回滚。

旧模型、非零本地累积起点和关闭记录的文档仍使用固定回放，不显示不适用的当前场景捕获选项。

## 原版依据与实现边界

复核已有 REA 字节码，并重新校验 MathArt 1.7.8 JAR 和五个相关类的摘要。JAR SHA-256：`a6e1da3acfc05c347d2529c1d590657e2dd798e16d38c55df3dc61312be24018`。

| 原版观察 | 本地对应行为 |
|---|---|
| `MathArt.savePausedFrameInternal` PC108 先 `Scene.render(export)`；返回 `draw` 后 PC409 `Scene.update(true)`，PC497 绘制 primary | 导出只显示当前状态；随后进行一次暂停的场景更新并绘制主画布 |
| `SymmetryChaosMobject.display` PC112 调整累积目标先于 PC116/129 的重播判断 | 改尺寸先取消 pending/active；不恢复旧墨迹、不恢复已取消的重播 |
| `ensureAccumulationBuffers` PC368/373 清除重播标记，但不释放粒子 | 同一粒子所有者跨导出尺寸保留 |
| 重播分支 PC166 提前返回，不经过 PC171 相机捕获或 PC188 参数确认 | 同尺寸重播跳过相机/参数确认；普通截图可以确认之前未确认的参数 |
| 相机捕获仅由首次显示或 zoom/center 变化触发 | 尺寸变化不能把累积相机锚点替换成导出投影 |
| tone reference 来自 `p.g.pixelWidth/pixelHeight`（PC627/660） | 以主画布物理尺寸归一，保留 Float32 中间舍入 |
| `togglePause` 不直接写 mobject.paused | 首次导出保留最近一次场景更新的 paused 字段；中间的暂停更新再刷新它 |

`SymmetryChaosMobject` 类摘要为 `f994fa6fc9dcf984c9ffad6e4e539e497ed038935ab701f8c7450d1f5caba54c`。完整静态审计保留在 `.cache/source-symmetry-capture/native-audit.md`，包含其他类摘要与方法位置。上述是字节码控制流与字段写入证据，未观察原版的回调并发、JOGL 像素或异常恢复。

原先实时生成把场景更新、显示和呈现放在同一入口，直接复用会错误推进截图状态。现在在时间线所有者处提供「只显示」操作，共享相同的参数确认逻辑；会话分别负责更新、显示、呈现和捕获。Worker/客户端/队列沿用已完成预览的精确身份凭据，不接受复制或过期输出。截图期间的取消、换文档和销毁等待双显示操作结束，再释放所有者。

内存预检由 GPU 资源所有者完成：在修改主图前核算导出和恢复两个方向，包括旧/新累积目标重叠、呈现目标、两张返回图像及增强/放大临时存储。已知缓冲预算为 768 MiB；这不是显卡驱动实际总内存测量。

## 执行的验证

`scripts/verify-source-symmetry-capture.mjs` 使用实际 WebGL 和 Worker，覆盖四种组合：普通累积/重播 × 同尺寸/异尺寸。确认双显示顺序、暂停零粒子更新、队列时间不变、锚点保留、主画布归一参考、重播推进/取消、粒子保留、容量拒绝不损坏预览、取消后清理和新会话重试。实际 Worker 的增强 RGBA 与独立同输入会话结果全量相等，旧输出不可选择新捕获，放大后可以恢复播放。

`scripts/verify-source-iterated-capture-ui.mjs` 在 1×、2× 屏幕密度下操作真实编辑器、导出窗口、文件服务与下载，覆盖同尺寸、异尺寸、3×/5× 放大、独立固定时间导出和返回播放。逐一校验 PNG CRC、解码全部 RGBA，再与 Worker 返回的完整像素比较；还确认主预览实际收到恢复后的输出。PNG 解码器由 Samila/Symmetry 验收脚本共用。

首次 UI 测试中，测试公式把粒子压在极小区域，2× 密度下缩小到 66×46 的目标没有占用像素，因此「非空图」断言失败。保留该失败报告，改用明确展开粒子的小负载公式（2,048 粒子、16 预热步），未放宽像素一致性断言，也没有将失败记为通过。此自定义公式是功能测试数据，不是原版作品效果验收。

时间线单测另验证「只显示」不推进帧号/队列、不重复上一轮粒子更新，但可以确认待处理参数。队列测试覆盖 Samila 和 Symmetry 在截图中换文档、取消及销毁的延迟释放。

最终全量测试 **340 个文件、6,241 项通过**；TypeScript/Vite 构建通过，保留已有大 chunk 提示。Samila 回归在 1×/2× 完成编辑、播放、截图及固定导出，1× 离线视频通过，1.5× 覆盖初始尺寸/呈现。随后检查发现保存的主画布参考尺寸还需复制，避免调用者修改原输入对象影响恢复图；该修复已通过新增的输入别名隔离 GPU 检查、完整捕获探针及重新构建，未再重复全量单测。

node scripts/verify-source-symmetry-capture.mjs NEW_OWNER_REPORT_DIRECTORY

脚本要求新的输出目录，并检查运行前后的源摘要一致；自行关闭浏览器和服务。费用采样为 250 毫秒进程族观察，可能漏掉短进程和峰值，CPU 为观察下界，RSS 会重复计入共享页，未排除 PID 复用；GPU 实际内存与每个任务的 agent token 未测量。每次启动新进程，内部有连续热会话；未独立拆分系统缓存冷/热成本，也无等价旧版捕获链路性能基线，不声称性能提升。
