# Map 参数动画与重播验证

本轮把 Map 的源参数动画接入导入、编辑器、保存重开及固定帧率 GPU 生成，并完成共享重播模块的实际 GPU 验证。当前仍在 **M3：场景补全与效果核对**；原版完整窗口验收仍为 **0/11**。

## 使用上的变化

新导入的源 Map 项目使用显式 `map-registry-1.7.8` 参数模型。开始／停止参数动作保留原名称、顺序、范围、步长和边缘缓动。时间线编辑器可以直接编辑这些配置；已有未标记的本地项目保持原动画规则。

队列进行中，一帧按顺序执行两次对象更新，各自读取当时的参数；队列结束后仍更新一次，暂停则不推进对象。首次更新承担预热，后续参数动画保持原始粒子种子。小于 Float32 精度的参数变化仍用 double 比较，超过原版 `1e-9` 门限才确认累积变化。

`colorSpeed` 和 `colorPhase` 是两个精确保留名称，分别控制着色速度及相位，不写入公式参数表。即使公式里已有同名参数，颜色动画也不改变它。颜色 setter 先转 Float32，再分别限制到 `[0.1,2]`、`[0,360]`；默认值为 Float32 的 0.22 和 180。项目入口读取 Java float 字面量，直接配置入口允许原 ConfigUtils 表达式，两条入口没有合并解释。

原 Map 初始参数确认表复制构造参数；Symmetry 初始确认表为空，这项差异已保留。重播期间跳过显示确认；暂停的普通显示可以确认参数，但不因此清空墨迹。相机仍由独立模块处理：Map 的角度、缩放或中心变化都参与重新捕获，Symmetry 不因单独角度变化清空。

## 结构修正

Map 与 Symmetry 的参数振荡器、对象更新计划、队列和 GPU 重播预算共用实现，删除旧的 Symmetry 专用运行模块，没有复制第二套状态机。Map 的颜色目标由独立 host 分派；Symmetry 仍使用自己的渐变、调色板和散点规则。

共享 GPU 重播模块保留普通更新先于重播、重播重新设置初态、分帧预热、每帧最多八次重播绘制、只剩预热的尾帧，以及尺寸变化取消重播但保留粒子状态等规则。模块接收明确事件，不用“文档变了”猜测原生重播事件。

## 实际验证

| 检查 | 结果与边界 |
|---|---|
| 原 JVM 参数 | 72 组、405 个快照通过；运行原 builder、Start/Stop、animator、标量目标及参数变化查询。没有运行主应用或原 GL。 |
| 原 JVM 重播 helper | 129 组通过；支持的有限数值域与 Symmetry 同参结果一致。 |
| Map GPU 重播 | 六组逐位轨迹、不同参数的有序更新、暂停及 resize 通过；大预热案例有 51 个只预热尾帧，墨迹不变。 |
| 代表负载 | 4,096 粒子、320×240、30 帧／100 次绘制、1,228,800 步通过，清理后已知 GPU 保留字节为零。 |
| 参数公开生成 | 四种输入各 12 帧通过，含普通、微小变化、新参数和颜色保留名；向后跳转、保存重开后的像素及墨迹与独立冷算一致。 |
| 实际应用界面 | Map 数值编辑保留 Worker/context，编译／链接计数保持 16/8；公式编辑变为 18/9。保存重开及 257×193 PNG 与独立冷算一致。 |
| 全套自动测试 | 348 个文件、6,495 项通过；Web 构建通过。 |
| Symmetry 回归 | 实际 GPU 重播及参数公开生成脚本通过；界面脚本另检查旧兼容 Symmetry 编辑。 |

Map 参数公开 GPU 检查要求位置分量逐位一致。步长度量中，GLSL 编译器对 `(x+gain)-x` 的化简与 CPU 分步舍入出现差异：本次最大绝对误差为 `4.470348358154297e-7`，在按位置 Float32 精度设置的界内。该度量不是逐位一致声明；独立的二进制精确增量重播案例仍要求全部四个状态通道逐位一致。

第一次完整回归有一项旧文档测试失败：它只删除数学模型标记，却留下新增参数模型。测试现在删除两者来模拟旧格式，生产端仍拒绝不完整的新模型。最终全套结果及成本见下表。

## 尚未完成

**Map 主界面的实时会话和热编辑触发尚未接入本轮共享重播模块。** 当前公开预览／导出仍是本地固定帧率重放。低层模块的暂停、resize、重播测试通过，不等于所有用户界面操作已具有原版生命周期。

Map 原版散点覆盖、最终调色链、实时颜色变化触发 Replay、原生暂停截图及窗口整图对照仍需继续。原版没有观察到 Map 的渐变动作实现；现有本地渐变功能保留为扩展，不冒称源行为。

本轮未重试原版 GUI，也未创建或移动 Yomado 屏幕。之前的锁屏记录是历史状态；下次原生检查前需要重新读取当前屏幕和窗口归属。所有浏览器验证在后台运行，已安装的 1.0 Apple Silicon 应用未重新打包或替换。

各脚本独立冷启动浏览器／进程；脚本内部有连续帧、冷建及后退重建断言，没有单独测量冷／暖时延。监测器请求每 50 ms 采样，实际间隔受读取进程开销影响；用 PID 与创建时间区分进程身份。CPU 是已观测下界，RSS 可能重复计入共享页并漏掉峰值；完整任务结束时未发现存活的已观测子进程。GPU 驱动内存与代理 token 未测量。

此前独立 Symmetry 重播记录的墙钟／CPU／RSS 为 34.52 秒／7.87 秒／约 1.42 GiB，本次为 4.64 秒／7.76 秒／1.46 GiB；历史采样器、等待开销及源码状态不同，因此仅列历史参照，不据此声称重构提速。新 Map 参数时序改变了实际计算次数，旧实现不是等价任务，未给出无意义的前后速度比。
