## 已实现及补验

- 迭代状态以 GPU 缓冲和受当前步数约束的纹理视图连接到绘制，正式设计无需每帧将全部粒子读回 JavaScript；本轮的大块读回只用于逐位比对。
- 绘制和呈现共用一份相机、色板、尺寸及调色参数计划。源步长度量与 RGB1024 色板使用独立片元程序，本地扩展色板和其他着色模式保留各自语义。
- 原先通用绘制程序在这组输入上产生微小 RGB 累积差异，8 帧最终有 2 个字节不同。独立源片元程序消除了这些差异；具体驱动编译优化原因仍未证明。
- 重置直接读取不可变初始种子缓冲，移除多余 GPU 复制；实际运行已无原来的 `gldCopyBufferSubData` 警告。零步重置也覆盖了已经演化的双缓冲状态。
- 暂停、404 × 484 截图后恢复原预览、608 × 728 尺寸调整均保持粒子和元数据不变。重复重播得到相同状态与图像；最终保留资源计数归零、子进程退出且进程组为空。
- 108 项相关 CPU/会话测试通过，其中原生墨迹边界记录器包含 238 项断言、34 类情况；另有 4 项实际 CGL 生命周期测试通过。CPU 记录器不代表真实驱动验证。
- 170 个实际 WebGL 点/四边形散点用例通过；Map 与 Symmetry 的 18 个同步/异步流程检查通过，覆盖导航、重播、截图恢复及录制。`build:v2` 通过，仍有既有的大包体积提示。

旧散点验证器有两处与当前合同不一致：ANGLE 没有按已观察的 CGL 点直径取整；热色板参数被随后的冷重开覆盖。这两种失败均在修改前的 Git 版本复现。修正验证器的输入准备后通过，原有像素容差保持不变。

## 本次测量的范围

最后一次完整诊断运行耗时 6.609 秒，子进程 CPU 合计 11.945 秒，采样峰值进程组 RSS 930,656 KiB。新资源首帧 0.890 秒，随后 7 帧为 0.155–0.307 秒；所有帧均包含大块诊断读回、文件写入和参考比较。

已计费保留资源约 83.94 MiB，并非驱动实际显存。总耗时还包含编译、Vite 和清理；CPU 包含采样开销，0.5 秒间隔可能漏过短峰值。驱动缓存是否冷、显存、功耗和 agent token 成本未测。未完成与混合原生/WebGL 方案的同负载比较，因此不作用户帧率或加速结论。
