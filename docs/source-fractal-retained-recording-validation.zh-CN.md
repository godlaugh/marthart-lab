# 分形保留录制状态验收

2.0 仍在 M3，原版完整窗口对照仍为 **0/11**。本轮接通“从上次完整应用的场景录制”，并让编码结束后的实时预览继续使用录制留下的运行状态。原版手动停止并保存部分视频尚未接入，不能把“取消导出”视作同一功能。

## 录制行为

源分形的工具栏“录制”现在打开分形录制窗口，默认 500 × 600、60 FPS；普通“导出作品”的视频选项也可选择“从上次完整应用的场景录制”。原有按当前配置新建回放与按时长导出仍保留。

录制起点取上次完整加载或播放中点击“应用场景”时的完整配置，包括几何、色板、背景、叠加内容和时间线。热修改、暂停时应用以及尚未应用的时间线，不会自动改变这个起点。录制结束不会覆盖作者的这些编辑；预览显示录制实例的实际状态。

开始录制时重建上述起点，使用固定模拟步长，实际绘制一帧预热但不编码。随后把每个录制帧交给编码服务，队列完成的那一帧也写入视频。编码完成后退出固定时钟，保留数值状态和队列位置，重置墙钟并继续实时播放。

输入画布采用三倍导出尺寸，按实际显示密度进行原版 Float32 / Java 舍入；编码输出另作偶数修正。显示密度由视口测量单独传入，不能从低质量预览的采样尺寸反推。录制模式的帧率同时用于模拟与编码。

## 原版依据与实现边界

依据固定 MathArt 1.7.8 字节码审计与此前 JVM 数值证据：工具栏先恢复播放、按 currentJsonConfig 重置场景，再开始录制；停止先完成编码，再退出录制模式，不暂停或回退。完整渲染文档锚点与数值宿主的锚点分别保留，热应用不会覆盖它们。队列、Worker 和界面继续使用同一录制所有者及显式完成确认。

本地结束交接会按停止后的数值快照恢复主预览，不增加数值更新；随后由真实 RAF 继续运行。这是本地展示安排，不声称与原版下一次 GL draw 的资源操作完全相同。原版 GL 目标、shader passIndex、逐帧累积和原版视频编码输出仍需直接验证。

同时修复了高质量实时预览被拒绝的问题：质量级别用于渲染采样，主预览身份由目标视口确定；不能把 high 质量使用的 export 标记误当成离屏导出。

## 本轮验证

- 全量测试：382 个文件、7,198 项通过，Vitest 用时 46.65 秒。覆盖完整配置锚点、录制租约、失败恢复、传输身份、连续帧和高质量主预览。
- TypeScript 与 Web 构建通过，Vite 用时 8.81 秒；仍有现存的大分块提示。
- 真实 App → Worker → WebGL2 → 本地 FFmpeg 服务通过：Newton / Nova 各两次录制，共下载 4 个 MP4。先验证热修改、暂存时间线之后仍使用旧完整配置，再验证播放中应用之后使用新配置。工具栏录制和普通导出的保留录制入口均覆盖。
- 视频均为 160 × 120、8 FPS；两组分别写入 3 / 5 帧，预热帧不写入，队列完成帧写入。Nova 使用 161 × 121 请求验证密度 2 下的舍入与编码偶数尺寸；Newton 使用 high 预览验证主画布身份不依赖质量标记。
- 每个上传 PNG 的完整 RGBA 摘要均与 Worker 输出一致；逐帧解码 MP4 后与相应输入比较，最大单帧平均 RGB 误差为 2.7084 / 255，低于预设有损阈值 8。这是本地编码传递检查，不是原版视频像素对照。
- 编码服务完成响应先于 Worker 释放录制实例；结束快照不增加数值更新，下一次 RAF 在同一实例继续。实际控件、持久化草稿和后续 RAF 请求均保留未应用的作者编辑。Nova 取消后不产生下载、服务会话删除，随后同实例重录成功。
- 最终源码摘要稳定；浏览器、控制台及 Worker 错误为空。检查最终界面截图，确认实际预览、作者公式选项和 0.75 秒时间片仍保留。

前三轮诊断修正的是验证脚本的读取边界：high 质量实际使用密度 2；尚未应用的时间线属于作者草稿，无须立即产生 Worker 请求；作者保留应检查实际控件、持久化草稿和后续 RAF，而不是要求旧已完成请求的结束响应凭空携带新草稿。没有放宽像素、视频或作者数据丢失检查。第四轮诊断和最终测量完整通过。

已有 MP4 公开回归 8/8 通过；Newton / Nova 实时预览与暂停 PNG 共 22 步通过，两个 PNG 的全部 RGBA 字节与当前状态捕获一致。三组公开验证均确认源码摘要仍与最终文件一致。

## 剩余差距

- 原版工具栏手动停止会完成已录制的部分视频。本轮“取消”会取消导出，不替代这个行为；后续需接入部分帧完成协议及实际视频验证。
- 数学标注尚未合成到源分形 PNG / 视频：预览的 FormulaOverlay 是 DOM 层，而当前这些导出路径直接编码栅格。原版 ComplexFractalScene 将 TexMobject 加入 Scene，Scene.render 会把标注画到录制目标中。无标注的测试不能证明带标注导出一致；后续需让导出消费实际帧的场景事实并共用标注合成。
- 原版完整窗口匹配对照仍为 0/11；本地公开流程与数值证据不证明原版整图一致。
- 录制期间的原版 pending 热编辑事件交错仍未复刻；当前录制界面阻止这些编辑。

本轮未替换已安装的 Apple Silicon 1.0 应用。此前实时预览与 PNG 的结果见[分形实时预览验收](source-fractal-live-validation.zh-CN.md)。
