# 弹跳场景：手动色板编辑验收

2026-10-24。2.0 弹跳场景加入可视化色板编辑：直接选色、改 RGB、编辑颜色原文、拖拽或按键排序、增删及反转，不必先编辑 JSON。

当前仍在 **M3：场景补全与一致性验证**。本记录只确认列出的手动编辑、保存及导出流程；随机配色、通用生成器和完整家族验收仍待完成。

## 已实现的行为

| 操作 | 当前行为 |
| --- | --- |
| 选色及改色 | 前 25 色显示为色块，点击选择；RGB 修改保留该项原有 alpha。RGB 不变时，保留原文拼写 |
| 原始颜色文本 | 可编辑 ARGB、数字字符串及无法解析的原文。无法解析项仍保存，以实际渲染器的白色回退预览 |
| 排序 | 拖拽、左右方向键、前移／后移按钮改变列表顺序，不重新采样颜色；键盘焦点跟随选中项 |
| 添加颜色 | 在选中色之后插入与下一色的中间色；末尾以该色自身参与计算。按原版 Float32 和 Compose 量化输出新的 `#RRGGBB`，保留其它条目。达到 25 色后停用新增 |
| 超过 25 色的导入 | 保留完整数组，GPU 仍使用前 25 色。后面的颜色可通过序号选择、编辑或移动，不会在打开编辑器时被截断 |
| 缺失／空／单色 | 缺失色板使用原版 Base 六色；显式空数组使用白色；导入单色不自动复制。查看默认颜色不把缺失字段变成显式数组 |
| 删除及清空 | 普通删除保留至少两色；独立的“清空色板”明确写入空数组。“恢复默认六色”恢复缺失色板状态 |
| 高级输入 | 完整颜色字符串数组入口保留在“高级色板数据”中 |
| 模拟、保存与导出 | 改色不重新播种或推进模拟；保存刷新、项目下载和 PNG 使用当前色板 |

颜色解析与白色回退由显示配置层统一提供给渲染器和编辑器。颜色原文始终是保存数据，不用预览 RGB 覆盖未经编辑的项目。共享色板草稿与源字符串数组具有不同语义，本次没有把两者隐式合并。

## 原版证据与指南差异

参考原包为 MathArt 1.7.8，JAR SHA-256：`a6e1da3acfc05c347d2529c1d590657e2dd798e16d38c55df3dc61312be24018`。

原版 `AppearanceSectionKt.FractalGradientSection` 的场景判断**没有为 Bouncing 开放 Cosine／Curve**，仅开放 Manual。指南 MAS-BOU-019 则同时描述了三种模式；这一冲突保留在验收中，不能用指南文字声称原版窗口存在相应功能。通用 Cosine／Curve 能力仍在 2.0 范围内。

共用原版 Curve 辅助方法实际采用 Float32 分段线性采样，不能把现有本地 PCHIP 曲线直接认定为原版算法。原版随机配色另有 HSB、OKLab、量化与扰动步骤，现有本地 HSV 随机配色也不能代替其一致性验证。

这些适用范围、调用链和生成算法结论来自保留哈希的字节码审计，**不是原版 GUI 操作实测**。源工程的颜色数组按顺序序列化；原版手动编辑器会先规范化局部列表，所以一次编辑可能改写其它颜色的空白、大小写和回退值。

产品有明确的保留策略：未编辑颜色保留原文，RGB 修改保留选中项 alpha，空／单色／长数组不自动补齐或截短。原版编辑器会规范化局部列表，RGB 选择器输出会去掉对应 alpha，非法颜色预览可能为黑色。这些差异不计作“原版窗口完全一致”。

**新增颜色已用原版实际纯函数的 43 个样本对照。** 覆盖中间及末尾插入、ARGB、非法文本、正负号、Unicode 数字／全角十六进制、空／单色、25／32 项与无效索引。产品匹配插入结果和保留的条目；空列表原 helper 返回越界索引 1，产品选择实际新增的第 0 项。原版窗口会先把空／单色补到两项，产品保留其原始状态。

插色计算遵循原版 Manual 专用解析：去掉一个开头 `#`、不去空白，六／八位十六进制按 Java Long 读取，失败按黑色参与。它与配置渲染的白色回退不同；两种格式各自负责解析和恢复，仅复用 Java 十六进制字符规则。新颜色不含 alpha，其它颜色的 alpha 和原文保持不变。这里没有用预览 RGB 反推原文。

原版探针还保留了规范化及按位置插色的辅助样本，共 96 项；其中仅上述 43 项 Add-after 向量被接入本次产品对照。两次原版 JVM 运行均无窗口，编译／运行退出成功，原 JAR 与依赖哈希稳定、所属进程组已清空。探针未创建原版项目、会话或渲染器，也未运行随机生成器。

## 实际产品验证

使用无头 Chrome 操作真实 App，分别经过原生 CGL 和 WebGL 生成器。验证以 64 粒子作品为主，保留 32 项原始色板；不把小规模编辑检查扩展成新的高负载或原版整图一致性声明。

已验证改动有效颜色会改变画面，改动非活动尾部颜色不改变画面；改色前后的更新次数保持不变。PNG 解码后的 RGBA 与实际生成器交付并按产品规则增强的像素逐字节一致，导出不推进模拟。关闭导出后，实际画布像素保持不变；重新定位到同一检查点后，生成像素和实际画布也保持一致。

两条实际 App 流程各 **40 项通过**，包括所选后端确实生成非黑画面、实际呈现画布非空、键盘移动到导入尾部后的焦点、原始字符串保存以及资源退出。无未处理页面异常，运行期间源文件稳定，结束后无所属辅助进程残留。相关 6 个测试文件共 **45 项通过**，其中包括 43 项原版插色向量与原有边界颜色解析回归。

`build:v2`（含 TypeScript 检查）通过，保留已有的大文件体积提示。中英文静态审计及自检通过，无必需翻译缺口。

| 本机实际编辑流程 | 耗时 | 进程组 CPU | 采样峰值 RSS |
| --- | ---: | ---: | ---: |
| 原生 CGL | 6.66 秒 | 14.36 秒 | 2,053,808 KiB |
| WebGL | 7.19 秒 | 16.75 秒 | 2,053,520 KiB |

数值包含页面交互和检查开销，未区分冷／热缓存。新增编辑流程没有同等旧版流程作为性能基线；GPU／显存和 token 成本未测，不能据此宣称性能提升。原版纯辅助方法两次捕获分别约 2.28 秒和 1.70 秒，包含编译和身份核对，未测其 CPU／RSS。

历史失败记录保留：首次验证器使用了错误的英文按钮名；补查预览时把浏览器截图的 RGB PNG 交给仅支持 RGBA 的导出检查器；WebGL 补查先选错了原生画布，另一次命令漏传 `--webgl`。分别修正界面标签、实际画布读取和调用参数；没有修改产品渲染或放宽像素一致性断言。
