# Map／Symmetry 已有参数热更新验收

2026-10-21。普通参数面板修改已有数值后，Map／Symmetry 保留当前粒子、时间、动画实例和构造种子。暂停时只提交参数控制，不绘制新的图像；恢复后从已有粒子继续计算。输入文字在失焦或 Enter 时提交，重新输入同一个数值也会送出 setter，避免正在运行的参数动画吞掉这次操作。

这是 2.0 M3 的局部行为修正。原版完整窗口效果验收仍为 **0/11**，Goal 未完成。

## 原包证据与边界

固定 MathArt 1.7.8 JAR SHA-256：`a6e1da3acfc05c347d2529c1d590657e2dd798e16d38c55df3dc61312be24018`。本轮重新比对 16 个类的字节身份；方法、偏移和回调绑定记录在 `.cache/source-map-lifecycle/inspector-hot-update-audit.md`，原始证据位于 `inspector-hot/`。

原版通用参数面板调用 `updateParameter`，没有立即 redraw。Java 空白名称被忽略。运行中的对象从下一次更新使用新值；暂停显示时可以确认参数变化，但不会因此清空累积。动画仍保留原来的相位与启停状态，后续动画更新可能再次覆盖手工值。

同名字段不一定有同样的编辑语义。Symmetry 的 Geometry 参数控件走 Apply；普通参数面板的 standard 模板不排除 `symmetry_degree`，modified 模板排除 `delta_power`。本地保留后者的重建路线。自定义 GLSL 中 `n` 是普通用户参数，不作为 `symmetry_degree` 的别名；构造时的宏 N 与实时参数值也保持分离。

## 实现与结构修正

- 热修改与完整 Apply 使用显式不同的操作意图。完整 Apply 保留原包 ProjectState 导出／重建的规范化和种子规则；配置所有者处理纯参数值修改时，保留原始 double、公式文本和参数顺序。避免重新执行导入的规范化，例如 standard 自定义 Symmetry 的 `delta_power=2.25` 不再被取整为 2。
- 一个共享的编辑分类器使用配置所有者的结果核对修改范围，拒绝将新增、删除、公式或结构变化冒充热修改。显式参数写入与文档数值差异分开保存，因此同值提交仍然有效。
- 队列在已有 Worker 上串行发送 `iterated-parameters` 控制，以完成的主预览身份关联响应。参数控制保留同一张图像的能力，可继续暂停／播放、截图或录制；不可靠响应会使该 Worker 失效。
- 实时会话分别持有当前文档、初始化粒子的构造锚点以及最后应用的录制配置。更新参数不重新预热，不改变随机种子或自定义编译宏，也不将热修改偷偷提升为新的录制起点。
- Timeline 持有可写运行参数与显示确认快照；setter 不推进时钟、不确认显示，空白名称保持 no-op。录制和显示继续使用既有所有者及清理路径。

## 验证

真实 GPU／Worker 验证保存在 `.cache/source-map-lifecycle/parameter-hot-final2/report.json`，共 4 个场景／层级案例。检查了更新前后完整粒子与累积缓冲区不变，下一次暂停显示不推进粒子，恢复后四个粒子的 x 分量严格符合独立 Float32 加法结果，且录制仍恢复最后应用的参数。实际队列验证连续热修改保留同一张输出图像，随后恢复播放继续使用原会话。

公开 App 验证分别位于 `parameter-hot-ui-map-final3/report.json` 和 `parameter-hot-ui-sym-final3/report.json`。两组各通过 12 项检查。Map 使用 DPR 1，Symmetry 自定义 GLSL 使用 DPR 2；覆盖打字未提交、blur 提交、同值 Enter 提交、暂停图像不变、同会话恢复，以及原有变换重播、播放／暂停、显式定位、缩放尺寸、取消和重算流程。

首次同值界面探测发现 React 的 onChange 不保证为相同值触发，已改用 onInput 保留编辑动作并重跑通过。另一次自定义 Symmetry 探测发现旧的数学模型判断漏选了自定义 GLSL 输入，已改为判断源构造配置，重跑通过。两次失败均保留记录，没有算作通过。

首轮全量测试还发现两项原版保存／重开种子校验失败：原因是热修改与完整 Apply 共享隐含的编辑路径。已在配置入口拆分显式意图，保留原始 JVM 对照数据与既有测试断言。

独立原包审查发现并复核修正了三处边界：同值提交、Java 空白名称、standard `delta_power` 小数。审查记录为 `.cache/source-map-lifecycle/parameter-hot-implementation-review.md`。它属于源码／字节码审查；公开界面和 GPU 的运行结论来自上述实际流程。
