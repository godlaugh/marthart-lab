# Symmetry 散点尺寸与覆盖验证

2026-10-21。**已接通原版点尺寸换算、原生点与三角形替代路径，并完成 32 组原包着色器对照。** 原版整窗效果仍未验收，Goal 保持进行中。已有 1.0 Apple Silicon 应用未重打包或替换，本轮没有操作原生窗口。

## 修复了什么

之前本地把点大小限制在 .1–32，并始终绘制同一种带线性柔边的圆盘。原版 Symmetry 使用不同规则：

- 预览的显示比例为 1；导出使用“导出逻辑高度 ÷ 主画布逻辑高度”。这条规则来自 Scene.render 的传参，不使用 Samila 的主画布物理像素高度换算。
- Float32 点大小乘显示比例后，最小取 1。负值、零、超过 32 的有限值现在都能进入正确的绘制路径；很大的尺寸由实际像素工作预算拒绝，不再误称源格式不允许。
- 先实际绘制 16 个点、读取浮点累积结果，判断当前 WebGL 上下文是否支持点绘制。失败时使用三角形替代路径。这里确认的是本地驱动能力，不能推断原版 JOGL 最终选了哪条路径。
- 原生点按距离平方做圆形裁切和 smoothstep 边缘；替代路径使用 `.6×radius`、最小 `.8` 的直径，加上覆盖率与指数衰减。其阈值是距离平方 1.35，与 Samila 的距离阈值不同。

尺寸事实由同一个模块产生，帧准备、工作量检查、GPU 绘制、裁切统计和输出记录共同使用。已有 Samila 点能力探针被复用，没有增加第二套资源管理。原版累积纹理的“质量/R/G/B”通道顺序在本地适配为“R/G/B/质量”；后续呈现继续消费已有本地表示。

## 接下来仍需完成

色板和最终呈现仍未对齐。本轮进一步确认 Symmetry 使用 PaletteRuntime 生成 **1024 格 RGB32F** 色板，纹理使用 LINEAR 和水平 REPEAT；它没有 Samila 的 85 格末端平滑。当前 Symmetry 颜色仍使用本地 4097 格采样，这将作为下一项修复。

默认兼容白点调色与原版参考画布归一化仍有差异；实时更新节奏、混沌轨迹、梯度动画及完整窗口合成也未验收。上一轮窗口工具报告 Mac 锁定，本轮未重复尝试，也未移动应用。原版整窗验收计数仍为 0/11。

## 成本与复核

32 组原包着色器验证脚本约 2.47 秒；外层进程族采样墙钟约 2.99 秒、CPU 6.45 秒、峰值 RSS 约 1.38 GiB，此时另有 Web 构建，不据此评价性能变化。

App 流程约 11.49 秒，外层约 12.22 秒、CPU 24.87 秒、峰值 RSS 约 2.16 GiB；上一轮同类流程为 11.58 秒、12.25 秒、25.31 秒、约 2.17 GiB。两次不是受控冷/热配对，不宣称提速。250 ms 采样可能漏掉短进程与峰值，共享页可能重复计数；token、GPU 内存、驱动开销和操作系统冷缓存成本未测。

复核脚本：`scripts/verify-source-symmetry-splat.mjs <新输出目录> [原版 JAR 路径]`。原版 JAR 需由使用者提供，不进入仓库。输出包含着色器副本、SHA-256 和逐组结果。本地证据在 `.cache/source-symmetry-splat/`，其中 `oracle-final/report.json`、`public/report.json` 和构建/测试日志保存本轮结果。
