# 吸引子高质量视频验收

本轮完成了 MAS-ATR-023 的两组源 CPU 高质量视频组合：1000／2000 粒子、5／10 子步、5／10 秒拖尾、200 次预热，均实际导出 1920×1080、30 FPS、10 秒 MP4。每个文件为 300 帧。

修复前，上限组合在第 51 帧因“100 万记录预算”失败；修复后保留完整的原版每粒子容量，没有降低粒子数、子步或拖尾设置。原版 MathArt 完整窗口对照仍未完成，GPU 大规模实时性能也不由这次 CPU 视频验收证明。

## 修复

原版每粒子拖尾容量按 `lifetime × 60 + 120` 计算，10 秒设置对应 720 条。2000 粒子需要最多 144 万条，超过此前的本地总限制。

吸引子现在采用明确的 **32 MiB 记录池预算**，每条记录 20 字节，最多 1,677,721 条；元数据、快照和渲染缓冲另外计量。曲面和 Perlin 保留各自原有的 100 万条策略。记录回收、时间过期、NaN 断点和每粒子 FIFO 语义保持不变。每个完整请求的 2000 万工作单位限制继续生效。

线条渲染改为实例化表示：每条线保存两个变换后的端点、方向和颜色，复用四顶点的三角形拓扑。从每条 **216 字节**降为 **96 字节**，另加整个绘制共享的 40 字节。缓冲仍受 256 MiB 上限约束。端点变换、方向舍入、宽度符号、重复线条顺序、颜色和混合方式均经过对照。

产品的独立 LINES 渲染统一使用实例化；原来的展开式边界仅保留给原版细分结果的验证和对照基准，不作为运行时回退路径。

## 实际视频结果

| 项目 | 范围下限组合 | 范围上限组合 |
|---|---:|---:|
| CPU 粒子数 | 1000 | 2000 |
| 每帧子步 | 5 | 10 |
| 拖尾设置 | 5 秒 | 10 秒 |
| 预热 | 200 次 | 200 次 |
| 最终保留拖尾记录 | 420,000 | 1,440,000 |
| 输出 | 1080p／30 FPS／10 秒 | 1080p／30 FPS／10 秒 |
| 请求、上传、编码、解码帧数 | 各 300 帧 | 各 300 帧 |
| 与上传 PNG 的最大逐帧平均 RGB 误差 | 4.645 以下 | 4.494 以下 |
| 新建连续生成器重放第 0、49、149、299 帧 | PNG 完全一致 | PNG 完全一致 |
| 生成、上传、编码到下载的耗时 | 69.77 秒 | 182.20 秒 |
| 含解码、重放、启动及清理的完整验收耗时 | 112.36 秒 | 248.37 秒 |

两组均检查了每一帧的请求参数、实际 CPU 后端、粒子数、时间和原版拖尾容量，包含真实跟踪相机及渐变动作。修改前保存的上限组合前 50 帧，与修改后对应 PNG 逐字节一致。

H.264 是有损编码，不能要求其解码图像与 PNG 完全相同。这里逐帧比较完整 RGB，使用平均误差小于 6 的阈值；另核对所有解码帧都有内容且 300 个帧哈希各不相同。保留的输入 PNG 和独立重放则使用精确比较。

视频测试使用隔离的无头 Chrome 和实际导出服务。PNG 拦截写盘、检查和其他并行测试会增加耗时，上表不是实时帧率或正式性能排名；也没有修改或重建 1.0 桌面应用。

## 线条表示的测量和回归

同一机器、同一图形策略下，10 万条线的完整创建、绘制、读回及释放任务：

| 测量 | 展开式对照 | 实例化 |
|---|---:|---:|
| CPU 几何缓冲字节 | 21,600,000 | 9,600,040 |
| 同一上下文的首次任务 | 88.6 ms | 54.9 ms |
| 暖运行第 1 次 | 80.6 ms | 45.0 ms |
| 暖运行第 2 次 | 90.0 ms | 43.4 ms |
| 含启动清理的进程任务墙钟时间 | 2.09 s | 1.78 s |
| 进程族 CPU 采样累计值 | 4.19 s | 3.63 s |
| 进程族 RSS 采样峰值 | 1,519,264 KiB | 1,411,408 KiB |

六次结果的完整 RGBA 哈希相同。这是一个完成任务的对照，不能据此推导所有视频的加速比例。帧内计时不含浏览器与上下文创建；进程任务计时包含它们。冷运行不表示清空操作系统缓存。

完整视频验收的进程族 RSS 采样峰值分别约 2.70 GiB、3.87 GiB，CPU 采样累计值分别为 165.65 秒、317.49 秒。RSS 是进程相加，可能重复计算共享页；250 ms 采样可能漏掉短进程和峰值，CPU 为观察到的累计下界。GPU 实际显存与整个代理任务的 token 成本未测量。

- 17 组粒子拖尾：独立 Python float32 细分与保留的 Processing 着色器对照，所有缓冲事实、完整 RGBA 均一致。
- 33 组曲面线条：完整 RGBA 零差异，覆盖透明度、重复边、裁剪、投影、像素密度和填充叠加。
- 全量测试：323 个文件、5871 项通过。
- Web 类型检查与构建通过；现有大包体提示仍存在。
- 新增边界覆盖：完整 144 万记录、池预算、回收后复用、实例化颜色和索引、方向正负零及变换舍入；其他场景原有测试通过。

```sh
node scripts/verify-attractor-high-quality-video.mjs .cache/attractor-hq-repeat-lower
node scripts/verify-attractor-high-quality-video.mjs .cache/attractor-hq-repeat-upper --upper
node scripts/verify-source-particle-trail-lines.mjs
node scripts/verify-source-surface-mesh-lines.mjs
node scripts/benchmark-processing-line-instances.mjs .cache/lines-expanded --expanded
node scripts/benchmark-processing-line-instances.mjs .cache/lines-instanced
```

这些结果证明本地高质量 CPU 视频组合及保留代码的线条一致性。原版窗口、原生 JVM／JOGL、其他驱动和 GPU 数百万粒子的实时表现仍需各自的证据。
