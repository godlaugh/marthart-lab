## 实现与所有权

原生实现从诊断目录移至 `server/render/SourceCglRenderer.m`。单帧文件入口和 `--stdio` 常驻入口共用同一套解析与绘制代码，没有另建一套场景数学或参数解释逻辑。常驻入口通过私有管道读取既有二进制帧，返回有长度上限的 RGBA8 响应，不创建窗口或网络监听。

`server/source-renderer.mjs` 负责程序身份、请求占用、响应关联和进程生命周期：

- 配置必须明确提供程序绝对路径和 SHA-256，初始化校验实际文件，后续请求检查文件身份是否变化。不搜索原版应用、不自动编译或下载后端。
- 一次只接受一个请求，不建立无界队列；同一进程内请求的代次／序号必须递增。响应还必须来自当前拥有的子进程、匹配当前帧身份及尺寸，不能把旧响应交给新请求。
- 在异步检查前复制请求缓冲，之后调用者修改原缓冲不会影响已提交帧。响应按头部和 payload 分段接收，只分配一次有界像素缓冲。
- 只操作由自己创建的 `ChildProcess` 句柄，持有到 `close`。不通过 PID 或名称查找／终止进程。该自有 CGL helper 不启动子进程；这不是任意进程树管理器。
- 默认截止时间 10 秒；取消／超时先终止，再在宽限期后强制终止，并等待退出确认。只有旧进程退出后才可建立替代进程。
- 未确认退出时返回清理失败，保留原进程所有者，拒绝新渲染。再次关闭可重试清理，不把“发出了 kill”当作“已经退出”。
- 程序文件发生变化或不可用时，停止已有进程并要求重新初始化；不会留下一个已失效却继续占用的空闲后端。

MathArt Lab 是独立子仓库，不引用父 REA 仓库的进程实现作为发行依赖。这里沿用本项目独立字形服务的自有子进程句柄方式，补上常驻响应关联和清理失败保留规则；数值 PID 只用于只读成本观测，不作为控制权限。

## 原生资源与恢复

CGL 上下文保留在会话内，FBO、颜色／深度缓冲、shader、program、VAO、属性缓冲和纹理仍由每次绘制明确释放。program 在删除前解除绑定，避免把待删除 program 意外保留到下一帧。每帧明确设置尺寸、清屏、颜色写入、深度写入和相关状态，前一帧不会改变下一帧背景。

无效输入返回对应错误，保留尚未被改动的良好上下文。shader 编译等运行时错误可能污染 GL 状态，因此销毁上下文，下一个有效请求重新创建。每个响应记录上下文序号；宿主另外记录进程会话序号，两种重建可以区分。

取消会退出整个当前渲染进程，下一次请求新建进程和上下文。没有承诺在 GPU 命令中途保留上下文或无成本取消。若系统不能及时结束进程，服务进入保留所有权的失败状态。

## 私有响应布局

请求沿用 [二进制帧协议](source-drawing-frame-validation.zh-CN.md)。响应为 44 字节 little-endian 头部，后接 RGBA8 或 UTF-8 错误文本：

`magic 0x31524c4d / version 1 / 总字节数 / 请求代次 / 请求序号 / 宽 / 高 / 状态 / 格式 / payload 字节数 / 上下文序号`

状态 0 为成功，1=input、2=unsupported、3=capacity、4=runtime。成功格式 1 表示 bottom-up RGBA8，长度必须严格等于宽×高×4；错误格式为 0，文本最多 8 KiB。错误版本、身份、格式、尺寸或尾随内容触发会话退出。截断的输入管道也退出，不扫描下一段内容猜测新帧边界。

基线 CPU／RSS 来自 `/usr/bin/time -l`，常驻进程来自 250ms 加边界的进程家族采样。任务很短，实际只有边界采样；CPU 的 0 表示本次观测分辨率内未分辨出增量，不表示零计算，RSS 也可能漏掉短时峰值。原生进程的 Node 宿主 CPU／RSS 未计入。两种测量方法和缓存状态不同，不据此宣称内存降低。
