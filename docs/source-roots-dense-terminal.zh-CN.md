# 复根高密度终点对照（2026-10-27）

本轮已让原版和 MathArt Lab **各自独立求完 131,072 个十次多项式，绘制全部 1,310,720 个根**。四个工作线程均结束，计算队列和待绘制队列归零，终点后的两次暂停显示也保持稳定。

严格一致性仍有残差：本地第二轮的完整数学画面、叠加三组公式后的完整画面均与原版逐像素一致；第一轮各有 **1 个像素、1 个蓝色通道相差 1 级**。底层 Float32 密度在两轮中都有差异，因此严格比较保留 `differences`，不将第二轮通过扩大为所有独立运行均精确一致。整体仍在 M3，2.0 Goal 继续进行。

## 测试输入与真正完成的条件

输入沿用原版 `Degree10_UnitCircle_T1T2_Formula06.json`，只做三项明确变化：样本数从 47,550,000 改为 131,072、显式指定 4 个工作线程、清空时间线。原公式、种子、相机、配色和批次大小 32,256 均保留。两边使用相同输入文件字节，物理画幅为 500×600。

原版在原 bundled JVM/JOGL 的离屏上下文中运行真实 Scene；MathArt Lab 通过正式 `Generator → generation Worker → computation Workers → RootsNativePresentationSession` 独立计算。原版点流没有作为本地独立运行的输入。

原版正常查询 VIEW/RUN/EDIT/EXPORT，四项均允许；原设置、许可证和 JAR 的前后摘要保持不变。正常远端策略刷新产生的缓存变化有备份和前后记录。原版公式和品牌叠加层完整保留，未裁剪图像。

原版实际最大堆为 512 MiB，本地显式使用相同参考堆策略；本次待绘制阈值为 7,829,367 点，每次基础绘制预算 20,000 点。每轮必须同时满足：

- 131,072 个样本全部接受、失败数为 0，全部 1,310,720 个根已实际提交。
- 四个线程的结束事实全部消费，工作线程存活数、计算队列和待绘制队列均为 0。
- 当前显示成功，Scene / Mobject 或本地对应完成谓词成立。
- 再显示两次暂停帧，完整密度、数学图、公式图及 PNG 均保持该轮终点状态。

帧数和时间上限仅用于失败退出。原版首轮在零基帧 65 完成，本地两轮均在零基帧 142 完成；这些次数受线程到达和显示请求节奏影响，不能当作动画帧或性能等价。

## 完整图像的严格比较

每项均比较完整 500×600 图像。下表为终点结果；同一轮的后两次暂停图结果相同。

| 比较 | Float32 密度不同像素 | 数学图不同像素 | 三组公式后的艺术图不同像素 |
| --- | ---: | ---: | ---: |
| 本地第 1 轮 → 原版首轮 | 10,387 | 1 | 1 |
| 本地第 2 轮 → 原版首轮 | 6,971 | 0 | 0 |
| 本地第 1 轮 → 本地第 2 轮 | 11,549 | 1 | 1 |
| 原版首轮 → 原版独立重复 | 7,988 | 0 | 见下文完整品牌图 |

原版独立重复关闭详细 VBO / 纹理绘制捕获，仍保留终点检测和必要读回。两次原版的密度有 8,830 个 Float32 分量不同，最大绝对差为 0.000152587890625、最大 5 ULP；完整数学图、含公式和品牌的最终图、raw PNG 及增强 PNG 全部像素一致，PNG 编码字节也相同。这个重复表明原版自身也存在低位密度差异，不能单凭它认定观察器完全无影响。

本地两次运行的 44 个实际批次，按工作线程与批次序号对应后，原始求根结果摘要全部相同；实际绘制前的世界坐标和度量值也逐批完全相同。两轮的到达顺序不同，密度累计出现低位差异，最终只有一个蓝色通道为 43 / 44。两轮呈现 uniform 完全相同，曝光归一化系数均为 Float32 的 `1.0922666788101196`，确实跨过了低密度下系数为 1 的范围。

原版与本地的数学结果并非逐位相同：按完整世界坐标 / 度量四元组多重集比较，双方各有 37,814 个元组未精确匹配。这些元组的坐标全部在原点附近，最大绝对坐标为 `4.1359030627651384e-23`，未匹配部分的度量位模式计数相同。原版 VBO 没有工作线程或样本身份，因此没有把排序后的元组冒充逐样本配对。

再让这两组点经过正式本地视图坐标变换，未匹配数降到每侧 29,579，仍未消失。它是本地坐标变换诊断，不是原版 GPU 中间值捕获；因此不能把原版与本地的全部底层差异都归因于到达顺序。

为隔离绘制器，另做了一次明确的诊断：把原版实际 66 次提交的世界坐标，按原顺序及原矩阵、点径、色板送入正式本地 GPU 绘制器。全部 1,310,720 个点绘制后，完整 Float32 密度与完整数学 RGBA **均逐位零差异**。这个结果证明该输入和顺序下的绘制器一致；它有意使用原版点流，不能替代前面的独立求根验收。

完整原版品牌图仍参与比较。本地两轮与原版 raw PNG 分别有 7,484 / 7,483 个像素不同，增强 PNG 分别有 7,981 / 7,980 个像素不同。原版额外叠加的标志和品牌文字已保留在参考文件中；艺术图的比较使用原版真实第三组公式绘制完成后的整幅缓冲，并非裁剪品牌区域。不能把艺术图通过写成最终原版品牌图通过。

## 证据与复跑

本地验收器为 [`verify-roots-dense-terminal.mjs`](../scripts/verify-roots-dense-terminal.mjs)。采集和离线比较分开记录源码摘要，后续加强比较器不会冒充先前采集时的版本。

```sh
node scripts/verify-roots-dense-terminal.mjs --check-sources

node scripts/verify-roots-dense-terminal.mjs NEW_CAPTURE_DIR \
  --capture-only .cache/roots-next-action-20261026/four-input.json \
  --reference-heap-bytes 536870912 \
  --glyph-backend .cache/source-glyph-service-20261022/build-final/backend.json

node scripts/verify-roots-dense-terminal.mjs --compare \
  .cache/roots-dense-terminal-product-20261027/capture-r2 \
  .cache/roots-dense-terminal-20261027/reference-r1
```

最后一条命令当前预期返回退出码 1，因为严格密度及第一轮画面存在差异。它不是测试进程未能完成。

原版宿主源码、编译记录、授权、每轮终点、输入及进程清理证据位于 `.cache/roots-dense-terminal-20261027/`；本地采集、完整 PNG、两轮差异及原版对照报告位于 `.cache/roots-dense-terminal-product-20261027/capture-r2/`。失败的首次沙箱监听尝试保留在 `capture-r1/`，没有创建浏览器。

同顺序绘制器诊断位于 `.cache/roots-dense-renderer-diagnostic-20261027/run-1/`，耗时 3.16 秒，完整源码摘要稳定，GPU 资源数归零。比较器另通过四项拒绝检查：空运行列表、缺失暂停阶段、结束时仍有积压、缺失世界坐标文件摘要均不能产生通过结果。当前 615 个 `src` 文件及 27 个 `server` 文件与采集时摘要相同。

两轮本地完整采集共耗时 16.72 秒；原版首轮及独立重复分别为 11.74 秒、9.91 秒。原版首轮观察到的进程族峰值 RSS 约 513 MiB；包含编译和监测的子进程 CPU 时间约 10.90 秒。以上是带诊断的验收成本，采集内容和运行方式不同，不构成双方性能比较或冷暖基准；本地进程族 CPU/RSS、GPU 显存和任务 token 成本未测。

整个过程使用后台浏览器和离屏原版上下文，可见窗口为 0，已创建的浏览器、服务和原版进程均清理。此次增加验证与诊断记录，生产算法和已安装的 `2.0.0-preview.14` 未变。
