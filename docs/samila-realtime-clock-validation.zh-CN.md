# Samila 实时播放、暂停和恢复验证

Samila 的实时预览已改为按实际经过的毫秒推进。暂停会保存当前相机角度，恢复会还原角度并重设计时基准，因此暂停等待不会让动画在恢复时突然跳过一段时间。暂停、恢复本身不绘制、不新增随机采样；暂停 PNG 仍复用当前场景，按导出画面、主预览的顺序绘制两次。

这项工作属于 2.0 分支，1.0 Apple Silicon 应用没有重新打包或替换。原版整窗一致性验收仍未完成。

## 操作上的变化

- 实时播放采用连续运行方式。动画队列结束后，参数更新停止，相机与绘制继续，直到用户暂停。
- 时间栏显示后台实际完成的场景时间。更新这个读数不会额外触发一次绘制。
- 暂停等待当前正在计算的画面完成，再保存播放状态；恢复得到后台确认后才继续请求画面。
- 暂停后调整相机角度可以预览；普通恢复会还原暂停时保存的角度。已有墨迹仍按当前绘制规则处理。
- 改名、保存、滑块范围修改继续复用已完成画面；即使修改发生在计算期间，也不会因时间读数尚未更新而重复采样。
- 时间跳转、重新应用和重新打开仍会建立新会话。跳转是本地固定步长重建功能，不代表原版支持任意跳转，也不能恢复原来的随机墨迹。
- 视频导出保持独立的固定帧率重算。实时预览速度与视频导出帧率现在分开说明；无效的循环／往返选项不再出现在实时 Samila 的播放栏中。

## 实现与证据

时钟合同来自固定 MathArt 1.7.8 包中的 `PApplet.millis`、`Scene.update`、`MathArt.togglePause` 和相机更新顺序。来源审计重新核验了八个类的包内身份，报告保存在 `.cache/v2-samila-realtime-clock-audit.md` 和对应 manifest。它们是静态字节码证据，不是原应用运行记录。

运行时使用本地 Worker 的墙钟，按原版的有符号整数毫秒、Float32 秒和差值顺序计算。没有额外固定步长、最大间隔截断或负间隔归零。原版相机在间隔不大于零时不更新，包括跟踪中心；队列的剩余时长约束仍由原有队列负责。

固定重放与实时推进共用同一个队列推进实现，保留原有冷重放行为。播放控制通过确切的已完成画面身份选择 Worker 会话，和后续编辑串行执行。响应身份或状态不确定时释放该 Worker，防止后续画面沿用不明的暂停状态；界面允许明确重新计算。

## 尚未证明的部分

- 原版窗口完整画面对照仍为 **0/11**。本轮采用无界面的 Chrome 验证，没有操作用户桌面，也没有取得新的原版窗口截图。
- 本地 Worker 的时钟起点、浏览器调度、暂停消息到达时刻以及随机流不等于原版 JVM 宿主。重建 Worker 也会重建本地时钟起点；没有声称重现原版完整宿主生命周期或线程竞争。
- 原版另有 `forceResume` 路径，语义不同。本轮实现的是普通暂停／恢复，不把它替换成该路径。
- 此前严格 GPU 浮点坐标对照的失败仍保留；没有放宽像素判据，也没有用这次状态测试覆盖旧失败。
- 测试耗时是功能验证记录。未做前后等价性能基准；CPU 时间、进程族峰值内存、驱动实际占用、最大负载取消延迟和任务 token 成本未测量。
