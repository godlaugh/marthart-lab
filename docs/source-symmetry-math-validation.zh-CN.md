# Symmetry 源数学计算验收

2026-10-21。新导入的 GPU／AUTO Symmetry 场景已改用 MathArt 1.7.8 包内生成的 Standard／Modified 多项式计算。**17 组输入、136 次状态对照通过；这证明当前设备上的计算环节一致，尚不代表原版整窗口画面一致。** 原版应用整图验收仍为 0/11，2.0 Goal 继续进行。

## 这次修正了什么

旧内置公式使用极坐标幂运算，粒子越过本地逃逸半径或出现非有限值时会重生。原包 GPU 函数使用连续复数乘法，更新着色器保留计算结果，没有这层逃逸重生。即使数学表达式等价，浮点运算顺序和重生策略也会改变混沌轨迹。

新导入的非 CPU 场景保存 `symmetryMathModel=mathart-1.7.8-gpu-v1`，采用源运算顺序、最后一步距离和非有限状态传播。源 Modified 在原点且 delta 非零时产生的 0/0 也保留；无效点跳过绘制并报告，不另造轨迹。GPU 不可用时明确报错，界面隐藏不适用的逃逸半径和 CPU 选项。

已有本地项目未携带新标识时保持旧数学规则。明确选择 CPU 的原版文件仍进入本地 CPU 兼容路径，不能据此宣称复现了原版 CPU 实现。自定义 GLSL 优先拥有计算规则；切回内置模板会恢复保存的源模型和修正幂次。自定义参数可超出内置范围，切换时由模板选择入口明确校验，避免静默改成默认值。

## 证据与实际验证

源 JAR 为 `MathArt-1.7.8-b07191b3e97da6fe465555ef6e61a0be.jar`，SHA-256 为 `a6e1da3acfc05c347d2529c1d590657e2dd798e16d38c55df3dc61312be24018`。独立提取 `SymmetryChaosFunctionGenerator` 的字符串和拼接顺序，保留方法／字节码位置，作为对照函数；实际运行的是该函数加包内 `symmetry_chaos_update.frag`。为在 WebGL2 运行，仅替换 GLSL 版本头、精度声明及函数占位符。没有启动原版 JVM 应用。

对照与生产状态管理器接收相同的 64 个初始 float32 状态和参数。每组推进 8 次，覆盖每帧 1／2／16 步；Standard 阶数 2／3／5／12／50，Modified 阶数 2／5／50 与修正幂次 1／6，以及原点、delta 为零、越过旧逃逸半径、非有限状态、预热 200／257 步。有限值数值完全相等，非有限值分类一致；不比较 NaN 的位载荷，也不区分正负零。最大有限绝对误差为 0。

实际 App 使用包内 Clifford／Emperors Cloak 文件，将工作量明确缩为 256 粒子、预热 4 步，并关闭公式文字叠加以比较 Worker 图像。它是功能验证，不代表原版完整工作量或视觉验收。此轮公开界面脚本没有重新执行保存按钮／刷新重开；新模型的保存检查来自文档序列化测试。先前指南图片也没有在本轮重生成。

两套浏览器验证均确认运行期间所记录的源文件不变，浏览器、Vite 和导出服务清理成功；数值对照还检查生产 GPU 状态释放后保留字节数为零。使用无界面浏览器，没有移动窗口或操作用户主屏。

## 双翼示例与尚未完成的部分

静态证据确认原包默认初始盒确实是 X/Y 各 `[0.001,0.002]`，默认缩放为 `(100,100,0)`。指南双翼参数在此前独立双精度计算中收敛到约 `(0.6832249491,0.2609687086)`；其雅可比特征值约为 `0.5527864045`、`-0.4472135955`，支持局部吸引固定点的解释。不能仅凭“看起来像一个点”认定初始化错误，也没有为生成好看的图修改指南参数。

尚未对齐或验证：Java 随机序列、原版平方状态纹理布局、原版运行时帧调度、最终密度／调色／合成、物理尺寸及跨驱动行为。生产内置核仍使用 Transform Feedback；独立源核使用片元纹理更新。这里验证了相同输入下的数值，不把两种存储方式称为相同实现。原版默认相机路径也未找到按点云范围自动适配的依据，本地旧自动视口仍需单独处理。

此前原生窗口读取遇到辅助功能拒绝，与权限查询结果矛盾；本轮没有重复尝试解锁或窗口读取。原版整窗对照继续保留为未完成。
