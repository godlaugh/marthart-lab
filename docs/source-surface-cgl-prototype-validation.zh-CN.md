# 独立 CGL 后端原型验证

2026-10-23，产品基线 `93f3e9c`。**独立 macOS OpenGL 原型已经使用产品真实 Worker、产品着色器和实例化缓冲，把 Möbius、Cornucopia、Sphere 三张完整艺术画面都做到零像素差异。** 这证明了一条可行的修复路径；原型尚未接入产品，当前应用的 Möbius 浏览器渲染残差仍未关闭。

## 两层验证

先建立只链接系统 Foundation / OpenGL 的 Objective-C 命令行程序，以 CGL 创建无窗口 OpenGL 4.1 上下文和离屏 framebuffer。第一轮复放保存的原版实际绘制输入，三个场景均与原版几何图相同，包括 Möbius 原来差异的那个像素。

随后移除对原版绘制数据的输入依赖，执行正式验证：

1. 用产品 `parseLegacyScene` 导入原始配置，交给真实 `Generator` Worker。
2. 执行正常暂停截图请求，保留 Worker 返回的截图准备结果。已有浏览器截图路径也正常运行，但不作为原生结果。
3. 用产品 `ArtRenderer` 创建截图材质和几何，导出它实际拥有的 shader、uniform、属性、索引及实例数。没有重算曲面方程或改用原版 VBO。
4. 独立 CGL 程序绘制这些产品输入。网格线保持 1,706 个实例，每实例 6 个索引；点分别保持 924 / 800 个实例。精灵使用产品生成的 64×64 基础纹理，由该上下文生成 mipmap 并使用设备最大各向异性过滤。
5. 使用现有产品公式合成器和独立字形服务合成完整艺术画面，与原版品牌叠加前的完整帧比较。保存可查看的 PNG。

| 场景 | 几何阶段不同像素 | 完整艺术画面不同像素 / 300,000 |
| --- | ---: | ---: |
| Möbius | 填充 0；加入线条后 0 | **0** |
| Cornucopia | 0 | **0**，包含配置启用的主方程 |
| Sphere | 0 | **0** |

比较没有裁剪、掩码、缩放或放宽容差。原版正常运行留下的品牌／水印参考未被修改；本次通过的是品牌叠加前的完整艺术画面，并非含原版品牌的最终 PNG。已实际查看原型输出的 Möbius 与 Cornucopia PNG。

## 依赖与执行边界

CGL helper 的 `otool -L` 结果只有系统 Foundation、OpenGL、CoreFoundation、Objective-C runtime 和 libSystem。helper 不加载 MathArt、Processing、JOGL 或 JVM，也不创建 AppKit 窗口。完整公式合成仍使用项目已有的独立 Java / JLaTeXMath 字形服务；不能把 helper 的系统库依赖误写成整个产品不需要其它依赖。

构建使用本机已有 Xcode clang，没有安装或升级任何工具。CGL 请求 GL 4.1 core，实际 renderer 为 `Apple M2 Max`，版本 `4.1 Metal - 90.5`；浏览器导出阶段为 Chrome `155.0.8059.85`，图形开关来自桌面应用的同一个配置 owner。

输入配置、原版采集记录与探针摘要、参考像素、产品源码和 helper 源码均绑定摘要。原生输入文件在绘制后再次核对，没有被 helper 改写。正式运行的源码／参考前后摘要一致，所有受管命令正常退出且无残留进程组，字形服务剩余进程为 0。

## 如何复跑

```sh
node scripts/verify-source-surface-cgl.mjs
```

前提是本机已有 Xcode 命令行工具，以及已采集的本地参考和独立字形服务构建。脚本默认读取：

- `.cache/surface-native-reference-20261023/`：原始输入身份与完整艺术画面参考。
- `.cache/surface-draw-isolation-20261023/`：实际绘制阶段参考及其采集来源。
- `.cache/source-glyph-service-20261022/build-final/backend.json`：已有独立字形服务。

前两个参考目录可作为两个位置参数传入。每次创建新的 `.cache/surface-cgl-*` 目录，编译 helper、运行后台浏览器和原生进程，结束时打印 `report.json` 的位置；不覆盖已有构建或配置，不自动下载依赖。helper 源码在 `scripts/probes/SurfaceCglReplay.m`，仅供这个诊断工作流使用。

本次最终记录为 `.cache/surface-cgl-9UR6Df/report.json`，严格状态 `matched`、退出码 0。每个 `render-<场景>/artwork.png` 是可查看的完整艺术画面；`product-<场景>/` 是实际产品绘制输入。早期复放、编译失败与修正记录保留在 `.cache/surface-cgl-prototype-20261023/`。

第一次原型编译因辅助函数名称与系统 `read/write` 冲突、CGL profile 常量名称错误而失败；已按本机 SDK 头文件修正。最终编译没有诊断输出。正式脚本的语法和 whitespace 检查通过。

## 接入前仍需完成的工作

当前 helper 是受控本地证据复放器：固定 500×600、黑底、1 至 2 次绘制，只实现本次所需属性、索引和 uniform 类型。它没有产品 HTTP / IPC 接口，也不具备通用画面协议、任意尺寸或持续帧会话。输入上限与正常退出已在这三个真实任务中执行，但未完成恶意输入、故障注入、取消和容量边界的产品级验证。

后续应在现有渲染 owner 处定义有类型、受容量约束的绘制计划，供 WebGL 与原生端共同消费。正式实现不应解析 GLSL 来猜 uniform 类型，也不应在 helper 中再次解释场景方程。需要同时处理：

- 不同尺寸／密度、背景、材质与全部相关场景，保留非有限槽位和源坐标语义。
- 有明确请求身份的常驻上下文、最新帧交付、取消、超时、资源释放和失败恢复。
- 主预览、暂停截图、录像的统一选择，避免只修导出而预览仍不同。
- 其它家族的原版完整画面对照、连续动画、macOS 打包与签名；非 macOS 后端另行验证，不能由本机结果代替。

因此，本轮达到的是**原生后端可行性及真实产品输入／完整艺术画面验证**，不是 2.0 发行完成。Goal 保持进行中。
