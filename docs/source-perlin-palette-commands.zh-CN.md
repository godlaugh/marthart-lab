# Perlin 相同色板再次应用

本批处理一个使用上的缺口：先热改色、再录制，录制按原版行为恢复冷配置；此后即使手动颜色值没有再变化，再次提交也应让预览重新使用这些颜色。此前只比较保存值，漏掉了这次操作。

现在 CPU 粒子、CPU 场线、GPU 色板控件会明确提交一次操作。普通重绘和重复交付同一操作不会再次应用色板；新的操作即使颜色相同也会执行。录制返回的作品仍保留作者颜色，运行中的冷色板不会写回作品。

## 状态边界

- 界面为每次色板操作分配递增序号；撤销/重做造成颜色变化也会分配新序号。序号只属于运行会话，不进入保存项目。
- 运行实例保存最后接受的序号和对应颜色。旧序号、同序号更换颜色、在已启用序号的会话中省略序号，均在修改已完成预览前拒绝。
- 录制重置保留已接受的操作身份，结束后普通刷新不会误把作者色板重新应用。录制期间排队的新色板操作会保留到结束后。
- 客户端校验预览、截图、录制开始与结束的操作序号；不能只让返回的上下文和像素元数据彼此一致，而与实际录制会话不符。
- 原有不带序号的调用保留文档差异适配；同一运行实例可首次切换到显式序号，该次操作不会只被确认而遗漏执行。

颜色解析仍由既有规范配置拥有；本批没有新增第二套字符串解析器。实时热更新仍强制不透明颜色，保存值和冷配置保留原 ARGB。新增回执最多保留现有 65,536 色预算内的一份已解析颜色数组，不保留操作历史。

## 操作序号的成本比较

单独串行运行同一 GPU 工作量：48×36 像素、相同种子、128 粒子，建立暂停实例后连续提交 8 个不同色板。旧实例代码固定为 `09482b86`，只替换 `sourcePerlin.ts`；其余依赖均为当前版本。因此比较隔离的是命令回执开销，而非两个完整历史版本。

| 阶段 | 修改前 / 后耗时 | 修改前 / 后采样 CPU | 修改前 / 后峰值 RSS |
| --- | --- | --- | --- |
| 首次导入、初始化及暂停定位 | 1101.7 / 1091.4 ms | 1640 / 1670 ms | 1,218,432 / 1,223,456 KiB |
| 保留实例的 8 次改色 | 19.7 / 19.5 ms | 10 / 20 ms | 1,218,336 / 1,224,480 KiB |

两组完整 RGBA 摘要序列相同，暂停时钟均未推进。每组仅一次样本，短阶段 CPU 接近采样精度，不能据此宣称提速或显著退化。未清空系统/驱动缓存；不含浏览器启动、Node/Vite 开销，未测 GPU 时间、显存和代理 token。两组 Worker 与浏览器均已退出。

可追溯的缓存路径和 SHA-256 见 [证据索引](../tests/fixtures/source-palette-live/followup-20261024.json)。

## 仍在后续范围

- Roots 的独立冷色板快照尚未接入；不能把 Perlin 的结果扩展到 Roots 录制。
- 空/单色色板的 Appearance 补齐、空热命令、原始非标准颜色字符串仍需单独实现。
- 显式完整应用、结构编辑、尺寸重建与热命令合并时的统一顺序仍沿用既有本地自动应用策略。本批只解决保留实例上的色板命令，不宣称所有重建组合已经与原版相同。
- 原版画面对照、其余场景和通用能力、Apple Silicon 最终集成发行仍在 2.0 Goal 内。已安装的 1.0 应用未更新。
