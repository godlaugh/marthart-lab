# 源曲面公式合成接入验收

2026-10-22。本轮已把独立字形服务接到源曲面预览、PNG 和录制。Cornucopia 公式第三行的平均 RGB 差异从 **18.57394 降到 0.92515**，约减少 95%。这仍是局部区域比较，11 类场景的原版整图验收保持 **0/11**。

## 实际改变

新导入曲面的 `source-surface-centered-v1` 布局使用独立 JLaTeXMath 字形的原始宽高、50 字号和 straight RGBA。纹理生成 mipmap，缩小时采用三线性插值；RGB 混合采用 SRC_ALPHA / ONE_MINUS_SRC_ALPHA，alpha 采用 ONE / ONE。依据是已保留的原版 Texture 与 PGraphicsOpenGL 代码证据。

预览合成完整底图与公式，支持透明底图的源混合规则。底层交互画布只设透明度，不禁用命中测试；退出公式显示后恢复原透明度。每个呈现帧都会更新底图，字形快照在相同公式内容期间复用。预览与导出共用同一 GL 合成器。

PNG 合成直接使用原始 framebuffer RGBA，避免 Canvas2D 的 alpha 转换。暂停 PNG 先合成公式，再执行已有增强和放大。实时录制在等待字形前保存该帧的底图、尺寸和呈现信息；源布局发生尺寸变化时明确拒绝继续。视频交付使用合成后的 RGB 和不透明 alpha。

字形客户端按后端身份缓存，缓存上限 64 MiB / 66 项，请求队列上限 66 项并串行提交。新准备过程会验证后端身份；服务端 health 和 render 共用文件新鲜性检查。失败不会静默回退到 MathJax。已有录制和显示拥有其已准备的字形快照，不在每次绘图时重新启动 Java。

单帧字形逐个取得并累计检查，保留预算为 64 MiB，准备下一字形时临时存储上限为 128 MiB（客户端共享缓存、基础图像和 GPU 存储另外计算）。取消一个消费者不会取消其他等待同一字形的消费者；最后一个消费者退出才取消共享网络请求。

旧布局和其他场景仍沿用原有 MathJax 路径。本轮没有把未验证场景标成原版字形一致。

## 真实输出与原版比较

比较输入为原版 Cornucopia，500 × 600 像素、暂停后 Apply、时间 0。原版 PNG 未修改。水印影响前两行，因此公式指标只使用第三行固定区域。

| 区域 | 修改前 | 修改后 |
|---|---:|---:|
| 公式第三行：110 × 30，共 3,300 像素，平均 RGB 绝对差 | 18.57394 | 0.92515 |
| 公式第三行：最大 RGB 差 | 255 | 56 |
| 公式第三行：有差异像素 | 846 | 458 |
| 几何固定区域：150 × 270，共 40,500 像素，平均 RGB 绝对差 | 0.011539 | 0.011539 |
| 几何固定区域：最大 RGB 差 | 3 | 3 |

原版 PNG SHA-256：`f9fec58288178d02e6a5c4665581c1f621943cb962778138d53706bc6e737b8a`。

实际产品新 PNG SHA-256：`64b0eebb78f6d52d51e87aef9a7cc1f36c7de252246efe042eb313ccaa69a175`。

剩余边缘差异尚未归因；不能把字体纹理完全一致等同于不同图形驱动上的缩小采样完全一致。

## 执行过的验证

- 独立 Java / HTTP 后端：**90 项检查通过，21 组字形与原版逐像素一致**。包括后端变化、关闭和健康检查竞态。
- 真实 Chrome / WebGL / HTTP：**10 项检查通过**。包括纹理原版哈希、缓存热读、合成缓冲区不变、持久预览与一次性导出逐字节相同、实际 PNG、暂停 PNG 后处理顺序、半透明底图混合、取消和实际 MediaRecorder。
- 半透明底图在 1:1 字形采样测试中，RGB 和 alpha 最大误差均为 **0**；低 alpha 原始底图上传和回读逐字节一致。
- 实际 MediaRecorder 多次运行提交 10–11 个完整帧，另有 captureStream 初始帧。ffprobe 验证较早一次运行得到 VP9-in-MP4、500 × 600、11 个解码帧。第一解码帧包含完整公式；与未增强 PNG 的公式区域平均 RGB 差为 1.07593。此项是有损本地视频验证，不是原版视频一致性验证。
- 实际构建页面：底图透明度为 0 时仍能命中交互画布；播放时完整公式预览继续重绘；关闭公式后恢复画布并移除合成层。
- 源公式客户端、布局、合成所有权及相关曲面／分形／录制 **123 项回归通过**。录制另有等待前快照、宽高交换、取消和正常停止的媒体边界测试；这些模拟测试不替代真实视频验证。
- 导出服务与桌面回归：**38 项通过、0 跳过**，包含实际 FFmpeg / ffprobe。
- `npm run build:v2` 通过。构建仍有已有的大 chunk 提示。

## 测量与复现

同一台机器上的一次真实 Chrome 运行：首次字形准备 1,260.4 ms，缓存热读（含新鲜性检查）9.7 ms；500 × 600 合成连续 30 次提交耗时 9.0 ms，连续 30 次绘制并同步回读耗时 57.6 ms。整组浏览器检查耗时 7.59 s。它们是此输入的冷／热探针，不代表整项应用性能或原版速度比较。没有测量 CPU 时间、进程族峰值内存、VRAM 或完整任务 token 成本。

先按[独立字形服务说明](../server/glyph/README.md)构建自己的 helper 和后端清单，再运行：

```sh
MATHART_GLYPH_BACKEND=/absolute/path/backend.json npm run server
npm run build:v2
npm run preview:v2
node scripts/verify-source-formula-compositor.mjs \
  --backend /absolute/path/backend.json \
  --out /absolute/path/new-verification-directory
```

输出目录的父目录需要存在，验证脚本不覆盖已有目录。当前本地 5178 服务已配置独立后端，5179 继续提供 2.0 预览。现有 Apple Silicon 1.0 应用没有重新打包。

私有完整证据保存在 `.cache/source-formula-integration-20261022/`，包括原版区域比较、实际 PNG、视频、UI 记录和测试日志。早期探针的来源配置错误、绘图计数器错误和测试编写期间的类型检查失败已保留，修正后重新验证；不把失败记录当成通过。
