## 使用行为

点击“录制”，或者在“导出作品”的 Samila 视频模式中选择“从上次完整应用的场景录制”。设置尺寸、帧率和质量后开始：

- 按最后应用的配置重新开始，第一帧实际更新并采样，但不写入视频。
- 后续帧按固定步长推进；动画队列完成的那一帧也会保存。
- 可“停止并保存”已有帧，或者取消导出。没有可编码帧时明确提示，不补造画面。
- 编码结束后继续播放录制后的场景。录制不会恢复录制前的旧累积画面；尚未应用的作者值仍保留在编辑器中。
- 原有按时长独立重放导出仍可选择。

本轮确认并修正了此前“继续当前热预览”的假设：原版公开按钮先恢复运行并 reset，再开始录制；低层 `startRecordingInternal` 本身不 reset，不能把这两个入口混为一谈。[原版入口与字节码证据](../.cache/samila-hot-recording-20261024/README.zh-CN.md)保留精确方法与偏移。

## 实现与失败处理

录制复用现有 Samila 状态所有者、已应用配置快照及源动画队列，没有增加第二套参数/时钟解释。公开重录释放旧原生资源后建立新资源；后续录制帧共享这个资源。每个实际绘制只取一次随机种子。

验证错误和容量错误在重建前拒绝，保留可用预览。已经提交的绘制若结果不确定，不自动重发；结束操作只释放其确切资源，并明确报告未恢复画面。释放失败仍保留句柄，可重试清理。窗口关闭后尚未完成的清理也保留所有权。

停止先重置墙钟基线，再执行本地第一个正常主画布更新与绘制；编码所用时间不会进入下一帧动画步长。这个交接帧有明确标记，**不是原版停止瞬间的导出纹理窗口合成图**。队列测试另发现并修复了恢复时覆盖新屏幕像素密度的问题；恢复保留新尺寸/density，并采用录制后的版本与运行时钟。同 ID 的新会话不会被旧录制覆盖。

初次 UI 诊断在一次性通过调试通道读取多帧大像素数组期间发生原生传输超时；失败记录保留。改为紧凑事实、单帧二进制读取，并在检查后立即暂停，最终验证通过且没有修改产品超时阈值。观察开销是当前推断，没有单独隔离确认超时原因。另一次诊断误把 ffprobe 的 full-range `yuvj444p` 名称当成格式不符，已按实际像素格式与 range 检查。

尚未验证原版 toolbar/事件循环/编码器的完整操作链、录制窗口合成及公式/品牌层、原版停止后主窗口图像、跨设备画面，以及所有 Samila 预设和热操作组合。完整 Float32 墨迹通道没有经生产协议全部回读；本次精确比较的是完整 RGBA 和实际墨迹统计。其它场景的剩余验收及最终 Apple Silicon 2.0 打包继续保留在 Goal 中。
