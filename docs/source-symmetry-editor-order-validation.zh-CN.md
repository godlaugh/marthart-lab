# Symmetry 编辑顺序与种子验证

2026-10-21。**已修复有限数值参数在编辑、保存、重开后的构造顺序。原版整窗效果验收仍为 0/11。** 这是[初始化修复](source-symmetry-initialization-validation.zh-CN.md)的后续；此前未知的 Compose 参数遍历规则现在有原版 JVM 实测证据。

## 修复了什么

原版检查器通过 Compose `SnapshotStateMap` 保存参数，再生成 `JSONObject` 并重建 Symmetry。参数顺序进入初始随机种子的计算，顺序不同会改变图案。原先只保留当前键顺序，不能重现原版删除参数后保留的树结构。

现在单独保存编辑参数树，由该树产生遍历顺序，再经已有 JSONObject 顺序转换生成构造快照。替换数值保留树位置；删除、再添加和保存重开保留历史结构。原构造快照继续服务动画和重播，不把动画中的临时参数当作一次检查器编辑。旧本地文档没有编辑树时按已有构造参数初始化，不声称能恢复此前未记录的删除历史。

Java 字符串哈希归入共享实现，移除了种子与 JSON 顺序中的重复代码。保存数据校验成员数量、文本长度、层深、路径、重复键和子节点顺序；遵守原有 65,536 成员／8 Mi 字符容量限制。

## 原版运行环境

此前 JVM 在加载动态库时停住。按用户已批准的“仅此 MathArt.app”例外，备份后清除了该应用 556 项下载隔离属性。未改应用字节、签名或系统整体防护，未安装 Java；原包自带 JVM 随后成功运行上述 39 组测试，耗时约 1.15 秒。

原版固定为 MathArt 1.7.8，主 JAR SHA-256：`a6e1da3acfc05c347d2529c1d590657e2dd798e16d38c55df3dc61312be24018`。JNI 采用 headless 模式和 256 MiB 堆上限，调用明确的集合／配置／构造方法；没有执行应用入口、图形初始化或操作原生窗口。库能运行不等于辅助功能窗口读取、虚拟屏输入或整图对照已经恢复。

## 尚未证明的范围

- 原版 `ProjectState.fromJson` 对不能读取为数字的参数会写入零；底层 Symmetry 配置的转换／默认值规则不同。本地编辑树当前以已接纳的有限参数集初始化，尚未完整复现原版 UI 对畸形值、布尔标志和缺少参数表时旧状态的导入行为。
- 完整原版画面、颜色噪声、窗口适配和实时帧行为仍须验证。本轮只运行原版标量方法，没有原版 GPU 图像；本地 PNG 与 Worker 一致不等于与原版一致。
- 原生 AX 窗口读取此前被拒绝，本轮没有重试同一权限失败，也没有移动或操控主屏窗口。

## 开销

比较上一提交与新实现完成同类任务：修改一个系数、序列化构造配置、解析重开。顺序和种子本来就不同，因此这不是输出等价的性能优化声明。首次调用不代表操作系统冷缓存；每轮热运行 500 次。

| 参数数 | 旧／新首次墙钟 | 旧热运行，每次 | 新热运行，每次 | 新热运行 CPU，每次 |
|---|---|---|---|---|
| 8 | 0.405／0.452 ms | 0.009–0.014 ms | 0.023–0.032 ms | 0.042–0.047 ms |
| 257 | 0.762／1.337 ms | 0.344–0.380 ms | 0.840–0.854 ms | 0.840–0.923 ms |

保存配置示例由 222 增至 397 字符、9,534 增至 15,702 字符，这是保留历史树的代价，不是 token 测量。两版本模块加载合计约 1.99 秒；整个测量进程族采样峰值 RSS 约 907 MiB。实际 App 验证脚本耗时 11.56 秒，外层采样运行 12.23 秒、CPU 27.29 秒、峰值 RSS 约 2.54 GiB。250 ms 进程采样可能漏掉峰值和短进程，共享页可能重复计入；token、GPU 内存与操作系统冷缓存成本未测量。
