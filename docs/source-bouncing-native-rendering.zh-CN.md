# 弹跳原生绘制：62 帧完整画面一致（2026-10-24）

**新增 CGL 绘制通路已通过 62/62 帧严格对照，消除了此前四个单像素残差。** 这是渲染层的真实原生服务验证；弹跳的应用预览、导出和已安装版本尚未切换到这条通路。默认 WebGL 的同次复验仍为 58/62 帧一致，不能把渲染层通过写成整个场景已交付。

## 为什么这次能一致

[上一轮诊断](source-bouncing-native-animation.zh-CN.md)已经证明：两个后端的粒子状态和混合前颜色相同，差异出现在原生 GL 与 ANGLE Metal 的 8 位颜色混合边界。

这次复用项目自己的无窗口 CGL 服务，明确传递点图元、色板数组、粒子混合方式和边界混合方式。没有修改粒子颜色、增加偏移或容忍误差。模拟仍使用实际产品种子生成和 GPU 更新；原生帧读取完整状态，以顶点属性传入相同绘图算式。点的编号、顺序、位置、速度、相机与色板均保留。

产品的 WebGL 与原生帧现在共用显示参数、相机矩阵、边界生成和着色运算。两个适配器只在状态读取方式以及实际图形后端上不同，避免维护两套粒子数学。

通用帧协议增加了三项明确能力：

- 点图元与三角形图元，分别保留真实绘制数量。
- 粒子的 source-alpha 混合，以及原有边界／曲面的 additive-alpha 混合。
- 显式 vec3 数组和原版离屏完成时的不透明背景 alpha 恢复。

新编码使用版本 3；原生服务仍读取保留的版本 1、2 证据包。旧服务程序不支持新版本，需要使用新编译并校验摘要的服务程序。Apple GL 将系统生成的 `gl_VertexID` 报告为活动属性，现按其明确名称和类型识别；外部数据仍不能声明 `gl_` 保留绑定。

## 实际结果

继续使用未修改的原版 `Bouncing/bouncing1.json`、200 万粒子、60 次固定更新、500×600 输出和相同相机。参考来自原版正常许可／水印流程下的暂停重绘；不是活动窗口或原版视频的验收。

| 检查 | 新原生绘制 | 默认 WebGL 复验 |
| --- | ---: | ---: |
| 完整艺术画面 RGB，62 帧、1,860 万像素 | **62 帧零差异** | 58 帧零差异，4 帧各差 1 个绿色级别 |
| 11 个完整状态纹理，88,097,900 个浮点分量 | 逐位相同 | 逐位相同 |
| 62 帧相机矩阵 | 相同 | 相同 |
| 完成帧 alpha 与原版最终 PNG | 相同 | 相同 |
| 严格验证结果 | **passed，退出码 0** | failed，退出码 1 |

原生服务通过实际浏览器客户端、HTTP 网关、受管子进程和 CGL 执行。全程没有打开桌面窗口。源码与参考摘要稳定，结束后浏览器、GPU 对象及受管原生进程均已清理。

## 回归与当前限制

- **135 项测试、9 个测试文件通过**：包含真实 CGL 点绘制、色板、混合、旧协议兼容、无效输入拒绝、取消、超时、身份检查和进程清理。
- **2.0 构建通过**，仍有已有的大 chunk 提示。
- Cornucopia GPU 点阵、Sphere GPU 点阵和 Möbius GPU 网格的原生截图回归，三例完整艺术画面仍均为零像素差异。

目前每帧原生快照需要读回约 32 MB 状态，62 帧共读回约 **1.99 GB**。这条传输通路尚不适合直接据此承诺实时预览性能。500 万粒子的完整快照还会被当前 256 MiB 表示预算明确拒绝；不会减粒子数、降采样或回退成不一致的后端。

下一步要把状态与绘制的持续执行放到合适的资源所有者中，避免逐帧大量读回／重传，再接通实际预览、截图与录像，验证取消、恢复及更大粒子配置。其他场景和最终 Apple Silicon 发行仍在 Goal 范围内。
