# 曲面暂停视口交互验收

2026-10-22，开发分支 `codex/v2-scenes-parity`。本轮补完曲面暂停时的拖拽旋转、滚轮缩放及恢复播放的状态同步。**2.0 整体未完成，原版整窗效果一致性仍为 0/11。**

## 用户可见变化

导入原版曲面配置后，可以在暂停画面上拖拽旋转、滚轮缩放，并直接保存这一视角的 PNG。恢复播放会还原暂停前的旋转角度，保留缩放；已有动画如果控制缩放，后续仍由它原先捕获的起点与目标继续计算。导航不会重新应用编辑器配置或重建曲面对象。

浏览器指针位移按逻辑像素处理；一行滚轮对应一个计数，像素滚轮以 16 像素对应一个计数。这是本地浏览器的映射，不能声称与原版 macOS 设备事件频率或粒度完全相同。右键也可拖拽，视口会抑制浏览器默认菜单。

引擎验证同时检查：暂停导航改变可见像素，但曲面参数、动画时间、队列位置和对象构造次数不变；恢复播放后当前帧返回正确的旋转角度与缩放。App 验证检查导航后的两次 PNG 像素一致，PNG 导出不会改变主预览。

错误处理覆盖过期图像身份、错误队列状态、播放返回结果缺失或含非法角度、导航期间取消，以及导航尚未完成时请求恢复播放。恢复请求等待正在处理的导航结束，并丢弃尚未执行的后续手势。

## 根因和结构性修改

新增导航验证发现：恢复播放已经在 Worker 中还原相机角度，但客户端只更新 paused 标记，仍用上次显示的角度校验随后返回的当前帧，出现“曲面当前帧响应状态不匹配”。

修复后，Surface 的播放操作返回由会话生成的当前帧状态。客户端把“后台已确认的状态”与“调用方持有的已完成图像身份”分别保存：前者用于验证恢复后的当前帧与截图，后者继续防止过期画面控制新场景。恢复只允许角度变化，队列、缩放及其他状态必须保持一致；没有放宽成任意接受返回值。

导航与截图的生命周期也保持区分：原版鼠标操作请求 redraw，draw 会调用 Scene.update(paused)；当前 PNG 保存直接 render。Surface 导航因此执行一次 dt=0 的暂停更新，增加本地更新序号并清除 dt，不推进动画；PNG 仍只显示当前状态。这里的 draw 调用关系来自保留字节码，暂停更新的数值行为另有既有原版 Surface traces；不是本轮原版 GUI 实测。

Map、Symmetry 和 Surface 现在共用 `sourceViewportNavigation.ts` 的事件验证与相机运算，原来的 `sourceIteratedNavigation.ts` 已移除，所有消费者和测试都改用唯一实现。队列及 Viewport 共用导航排队与手势路由，Surface 会话仍独立持有曲面、动画队列和暂停角度。

## 验证限制与未完成项

本轮没有取得原版窗口截图，未做新的原生桌面输入或移动窗口；上述数值一致、浏览器像素稳定不能替代原版整窗对照。曲面录制流程和空 CPU 点时间线的源场景导入仍待完成，完整 Goal 继续保留全部 11 类场景。

最初的验证保留在本机：浏览器脚本同时启动造成端口冲突；共享 UI 首次运行在第二个案例准备阶段超时；新测试曾因直接写 readonly 字段导致编译失败。随后分别顺序运行脚本、复验共享 UI、改为创建新的畸形测试值，最终检查通过。没有通过扩大超时或删除断言取得通过结果。

本轮引擎整套验证墙钟约 6.63 秒。原版方法两次执行墙钟约 0.90 秒和 0.35 秒，均正常退出并回收进程。这些不是单手势延迟，也不是有控制的冷暖性能对比；没有测量代理 token、CPU 总时间或进程族峰值内存，不作性能改善声明。

已安装的 Apple Silicon 1.0 应用没有重新打包，本轮功能位于开发分支。
