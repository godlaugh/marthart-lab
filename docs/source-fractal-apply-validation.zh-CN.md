# 分形热更新与宿主生命周期验收

2.0 仍在 M3，原版完整窗口对照仍为 **0/11**。本轮确认并实现了分形运行核心的同实例配置更新；公开编辑器与 Worker 的生命周期接线仍待完成。已有「当前配置新建回放」视频导出继续保留独立语义，见[录像验收](source-fractal-recording-validation.zh-CN.md)。

## 与原版一致性有关的发现

原版分形有三种不同操作，不能统一当成重新加载：

| 操作 | 更新对象与队列 | 录制重置使用的配置 |
| --- | --- | --- |
| Geometry / 公式参数热编辑 | 给现有对象应用完整 ProjectState；保留队列进度与捕获起点 | 不改变 |
| 暂停时 Apply | 更新现有对象；保留队列和宿主时间 | 不改变 |
| 播放时 Apply | 完整重建场景与队列 | 更新为这次完整配置 |

原版颜色参数的普通编辑走 Apply 路径，因此是否暂停会影响结果；渲染方法、扰动精度和颜色算法 ID 的 REINIT 编辑先暂存，但后续热编辑会带上整个 ProjectState，不能套用 Map / Symmetry 的字段组隔离。

录制工具栏先重置到最后完整加载的 `currentJsonConfig`，再启用固定步长与一帧预热。停止录制只退出固定模式、重设墙钟锚点，保留当前对象和队列继续运行。这里的 UI 路由与宿主顺序来自固定原包字节码审计，尚未直接操作原版 GUI 验证。

## 同实例原版数值证据

对固定 MathArt 1.7.8 JAR（SHA-256 `a6e1da3acfc05c347d2529c1d590657e2dd798e16d38c55df3dc61312be24018`），两次独立 JVM 运行得到了完全相同的 5 组、75 个状态快照。探针实际调用原版 `JsonComplexFractalConfig`、既有对象的 `applyConfig`、Scene / SceneManager、动画、公式参数映射和渐变模块。

- 普通动画进行中 Apply：中心、缩放、迭代、公式等立即改变；恢复后原动画继续使用此前捕获的起点，不从刚输入的新值重新起步。
- 目标缩放进行中 Apply：原先的缩放与 DD 中心起点保留；配置中心自身按原版 Double 写入，低位重新为零。
- 参数停止片段期间 Newton 切换 Nova：队列位置和已启动子动画状态保留，新公式按现有 native bailout / Julia 参与映射，再按参数集是否存在决定传统字段覆盖。
- Apply 清除参数注册表并停止参数、渐变动画。已有 Start 子片段之后的 scale 回调不会重启；未来尚未开始的 Start 仍能重新注册和启动。
- 角速度、相机角度与速率、对象 currentTime、渐变旧相位及基准偏移保留。渐变停止后 speedScale 可能被已有子片段再次改写，但 running 仍为 false，不能据此误判在运行。

可提交探针与证据位于 [原版 Apply fixture](../tests/fixtures/source-fractal-apply/README.md)。图形构造通过 AllocObject 绕过，时间间隔及 PApplet frameRate 为明确输入；没有执行原版 GL、窗口、编码器或 MathArtSession UI 回调。

另两组探针确认了参数注册表的容量历史会影响数值结果：Java HashMap 清空后保留容量；从 64 桶清空再注册 `exponent` 和 `exponent_im`，更新顺序与新建的 16 桶表不同，最终虚部分别为约 `0.1621092790743515` 与 `0.125`。本地在注册表所有者处保留清空时的容量，再重放此后的插入顺序，避免排序与扩容历史丢失。

## 实现与本地渲染

配置更新入口位于运行状态的所有者：公式映射接收既有 bailout / Julia，场景时钟更新对象字段但保留队列与动画起点，参数与渐变模块分别清理或停止自身状态。无效替换在提交前拒绝；提交中预算失败会使实例失效，不能读取半完成状态。

参数振荡现在可接收明确的宿主 effectiveFPS。原版录像取配置的模拟帧率，实时运行取 PApplet.frameRate，不从 dt 倒数或编码器帧率推算。原版参数模块对 fps ≤ 1 使用 60；本地额外拒绝非有限或超 Float32 数值，这是本地准入限制。

新增的 `SourceFractalHostSession` 统一持有墙钟、对象和队列，并分别保存编辑配置、最后完整加载的录制配置、当前运行状态。它提供热应用、按暂停状态分支的 Apply、独立暂停/恢复，以及从录制配置开始的固定步长更新。录制句柄只在本实例内有效；序号必须连续；结束录制不额外推进一帧，也不恢复录制前的画面。候选配置拒绝时保留旧状态；已经开始的更新失败后必须完整加载恢复。这是数值状态所有者，尚未管理 GPU 画布或公开 Worker 会话。录制期间暂拒绝实时编辑和暂停操作；尚未模拟原版 pending 配置与录制开始的事件交错。

后台 Chrome 的真实 WebGL2 检查通过三组配置，覆盖 Apply 前后画面变化、暂停保持、恢复后的旧队列推进，以及改变物理渲染尺寸后恢复原尺寸的像素一致性。每次渲染前后还检查数值状态未被渲染器改变。该检查直接走公开文件解析、场景绑定和生产渲染器，未走 App 控件或 Worker，因此不能记作公开 UI 生命周期验收，也不能记作原版图像对照。

- Web 构建与 TypeScript 检查通过；Vite 构建用时 8.95 秒。仍有现存的大分块提示。
