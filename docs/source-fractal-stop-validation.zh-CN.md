# 分形手动停止与部分视频验收

2.0 仍在 M3，原版完整窗口对照仍为 **0/11**。本轮补上分形录制的“停止并保存”：提前结束时保存已经录下的片段，再从实际停止状态继续播放。“取消导出”仍会丢弃任务。

## 使用行为

工具栏“录制”与普通导出的“从上次完整应用的场景录制”均提供“停止并保存”。点击后等待已经发起的那一帧完成生成、PNG 编码及上传，随后不再请求下一帧。视频保存完成后才结束固定步长录制，并从同一个数值实例恢复实时播放。

没有编码帧时显示“没有可保存帧”，清理空编码任务，不生成下载；预热帧不冒充视频帧。如果点击停止时最后一帧已在处理中，完整保存最后一帧，按队列自然完成处理，不额外复制末帧。

停止已接受或正在保存时禁用普通取消，避免两个结束操作互相覆盖。若保存结果无法确认，会保留当前录制状态并显示“重试保存”和“丢弃导出”；重试继续同一个编码任务。“丢弃”显式放弃未完成任务，但不会删除已经确认生成的成片。

## 所有权与失败处理

队列拥有帧的停止边界，编码服务拥有已经上传的帧。计划帧数是不可变上限；完成请求另带一次性最终帧数，必须恰好等于已收到的连续帧数。相同最终帧数的重试共享原完成结果，不同值会被拒绝。封定之后的编码由服务端持有，HTTP 响应断开不会自动取消，超时与显式取消仍有效。

浏览器为每次编码持有独立传递对象。上传响应丢失后先查询实际帧数：已经接收就补认确认，未接收且服务可用才重传同一 PNG，不重新生成数值帧。完成响应丢失后查询同一任务；已完成则使用原文件。状态仍未知时等待显式重试，队列的录制实例不会提前释放。确定的编码失败如实报告；没有持久保存全部输入 PNG，因此不声称能无损重建失败的编码任务。

本轮同时修复完成超时与文件提交交错的清理问题：失败会等待已开始的重命名，再清理两个可能的文件路径和容量记录；已确认完成的文件不会被迟到的超时撤销。清理失败的任务标识继续由清理模块持有。

原版依据是固定 MathArt 1.7.8 的 TimelinePanel → EngineBridge.stopRecording → MathArt.stopRecording 字节码：先完成编码，再退出录制模式，不暂停或重建场景。HTTP 上传、响应恢复及最终快照是本地实现，不代表已运行原版 GL 或视频编码对照。

## 验证结果

- 全量测试：383 个文件、7,213 项通过，Vitest 用时 46.30 秒。包含连续帧计数、在途上传完成后停止、零帧、结束竞态、未知结果保留以及显式丢弃清理。
- TypeScript 与 Web 构建通过，Vite 用时 8.85 秒；仍有现存大分块提示。
- 服务端 34 项检查通过：真实 FFmpeg 将计划 5 帧的任务保存为 2 帧 MP4，并通过 ffprobe 计数；原有 MP4 / WebM / GIF、缩放和四档质量检查仍通过。另以故障注入验证上传锁、断连重试、编码失败、完成超时、提交竞态和清理。
- 真实 App → Worker → WebGL2 → 编码服务完成 6 个公开场景：中途保存 2 帧、保存 1 帧、预热后零帧停止、最后一帧停止竞态、完成响应丢失后自动恢复、完成与首次查询响应均丢失后的显式重试。
- 共下载 5 个 MP4，分别为 2、1、3、2、2 帧，全部为 160 × 120、8 FPS、全范围 YUV444 / BT.709。每个上传 PNG 的全部 RGBA 摘要与 Worker 输出一致；逐帧解码后最大平均 RGB 误差为 2.3542 / 255，低于预设有损阈值 8。此对照检查本地帧传递与编码，不证明原版视频一致。
- 每个有视频的场景只提交一个文件。未知保存结果和显式重试等待期间没有提前释放 Worker 录制实例、请求下一帧或新建实例。零帧场景无下载，空编码会话被删除，运行状态正常恢复。
- 浏览器和 Worker 错误为空；两个故障注入场景仅出现特定任务 URL 对应的 1 / 2 次预期 `ERR_FAILED`，未放宽其它控制台错误。故障注入先取得真实服务响应再丢弃浏览器响应，并未伪造成功内容。
- 首次诊断与最终测量均完整通过，无需修改测试判定。最终源码摘要稳定并与当前文件一致；已检查最终界面截图。

已有保留配置录制两组、4 个 MP4 及取消重试通过；独立回放导出 8/8 通过。三组公开报告的源码摘要都与最终文件一致。没有修改历史验收记录；旧自动录制脚本的说明改为引用手动停止专用检查，避免继续生成过期的“未实现”声明。

## 剩余差距

- 源分形 PNG / 视频尚未合成数学标注；当前预览的 DOM 标注不在原始栅格中。下一步应让所有导出路径消费实际帧的场景状态并共用标注合成。
- 原版 GL 目标、shader passIndex、逐帧累积以及完整窗口一致性仍需直接验证。原版整窗对照为 0/11，不能用本地测试替代。
- 原版录制期间 pending 热编辑事件的交错尚未复刻；当前录制对话框阻止这些编辑。

本轮不替换已安装的 Apple Silicon 1.0 应用。录制锚点与自动完成行为见[上一轮验收](source-fractal-retained-recording-validation.zh-CN.md)。
