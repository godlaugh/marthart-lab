# 原生 Map 应用链路验收

2026-10-26。二维、三维源 Map 已接入应用的原生计算与绘制链路。一个原版二维预设、一个构造的三维输入分别完成 8 帧精确对照，Symmetry 回归也通过。**Business Cycle 预设仍有差异，M3 和完整 2.0 尚未完成。**

## 本次完成

- 原生计算协议接受明确的 2D / 3D，保留 XYZ、最终步长、检查点和资源所有权；其它维度仍拒绝。
- Map 与 Symmetry 共用已准备的绘制参数和会话所有者，切换场景先释放旧会话。Map 的余弦颜色在独立片元程序中计算。
- 接通实时预览、暂停、截图、视口导航、录制预热、逐帧生成和停止后的主预览恢复。
- 修复 Map 首帧预热步数。原版把一次更新调用限制为最多 16 步；配置中的 200 步仍保留，但首帧实际是 `16 + 16 + 16`，此前错误地执行 `200 + 16 + 16`。修复位于共享帧计划，WebGL 和原生后端一起消费。
- 修复源面片绘制丢失齐次裁剪坐标的问题，保留原始深度与 w，避免先除 w 再重建坐标。

## 尚未解决的差异

Business Cycle 的全部 1,048,576 个初始 Float32 字、`16 + 1 + 1` 更新调用、公式、相机和呈现参数均已核对。生产状态读回发现 691,131 个有限 Float32 字不同，最大绝对差 0.0966468；非有限状态位没有差异。这说明偏差已经发生在计算阶段。

独立 CGL 诊断逐字复现生产结果。只把循环上界从 256 改成 16，或把统计改写为无分支加法，差异仍存在；把循环内的无效粒子统计移到循环外，数学结果可与原版片元程序及实际原版状态完全一致。后一个变体改变了逐步统计语义，**没有作为产品修复合入**。下一步需要保持数学计算和诊断语义各自正确，不能通过放宽像素阈值掩盖差异。详见[计算隔离诊断](../.cache/source-map-native-loop-diagnostic-20261026/README.zh-CN.md)。

面片专项检查的 68 个样本中，RGBA32F、覆盖范围、有效顶点的裁剪 z/w 全部精确一致；最终复跑对 RGBA32F 使用逐字位比较，包含正负零的区分。Symmetry 有 6 个样本的裁剪 x 仍差 1–2 ULP，严格顶点诊断继续报告这 6 项失败。它们没有造成这些样本的最终像素差异，但不代表所有顶点或全部场景均一致。详见[面片验收说明](../.cache/iterated-source-quad-20261026-fixed2/验收说明.md)与[最终复跑记录](../.cache/iterated-source-quad-20261026-final-bits/report.json)。
