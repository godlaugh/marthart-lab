# 域着色界面与导出验收（2026-10-22）

域着色已在 2.0 开发分支接通实时预览、完整应用、参数提交、暂停导航、当前 PNG 和保留状态的录制。**本轮是本地 App/Worker/FFmpeg 流程验收，原版整窗口效果一致性仍为 0/11。** 已安装的 Apple Silicon 1.0 应用没有在本轮重新打包或替换。

## 可以怎样使用

导入带有源顺序队列的域着色项目后，首帧默认暂停显示。点击播放后按实际经过时间推进；暂停后可拖拽、滚轮缩放，参数输入在回车或失焦时提交。参数修改保留当前时间和队列，但按源规则停止参数振荡、恢复配置视口并重新捕获常量。点击“应用场景”则重新开始动画，原先暂停的项目仍然暂停。

“导出作品”默认可保存当前暂停状态，不额外推进数值动画，支持公式叠加和 1/3/5 倍 PNG。点击“录制”从上次完整应用的配置开始，先绘制预热帧，再把后续帧写入视频。可以等待队列结束，也可以中途停止并保存；取消时删除临时导出任务。录制结束或取消后恢复主预览并继续播放。还没有可编码帧时会显示明确提示。

低／标准质量预览保留计算预算，手势使用实际主画布的逻辑尺寸。高质量预览和离屏导出使用明确的尺寸与像素密度，避免将降采样图像尺寸误作交互尺寸。未声明源队列的旧域着色文档保留原有固定回放行为。

## 实际验证

| 验证 | 结果 |
| --- | --- |
| 完整测试 | 7,567 项、402 个文件全部通过 |
| TypeScript 与生产构建 | 通过；保留既有构建资源块体积提示 |
| 域着色真实界面 | CPU 低质量／密度 1、GPU 高质量／密度 2，各 11 步，共 22 步通过 |
| 导入与交互 | 暂停首帧、播放、暂停、热参数、拖拽、滚轮、暂停完整 Apply 均通过 |
| 当前 PNG | 解码及 CRC 校验通过；CPU 输出 195×147，GPU 按密度取整后输出 198×150；均为 3 倍放大，保留公式事实且无数值推进 |
| 正常 MP4 | 实际本地服务和 FFmpeg 编码、下载、解码；两组均为 64×48、4 FPS、3 个有效帧，预热帧不入视频，首尾帧不同 |
| 中途停止 | 两条后端均只保存已请求的 1 个有效帧，未额外请求下一帧 |
| 取消与零帧停止 | 均不下载视频；临时服务任务已删除；主预览恢复且没有额外数值更新 |
| 分形停止/恢复回归 | 6 组通过，包括停止、零帧、末帧竞争、保存响应丢失和显式重试 |
| 分形公式导出回归 | 2 组完整流程通过；涵盖捕获文字、暂存标注、密度 2，以及当前/重放 PNG、JPEG 和 MP4 的公式合成 |

录制的模拟步长与参数动画的实际 FPS 分别传递。界面通过 `performance.now()` 观察相邻绘制请求的间隔，首次或恢复后的初值明确使用预览帧率设置；录制模拟步长和视频编码仍使用用户选定的 4 FPS。测量样例中 CPU 三帧观察值约为 11.35、22.08、27.86 FPS，GPU 为 21.60、18.18、41.84 FPS，Worker 消费值逐帧匹配 Float32 观测值。它们说明本地链路没有把模拟 FPS 当作观测 FPS，不代表原版 PApplet 时序一致。

本轮截图已查看：主画布、公式标签和控件可见，旧的“固定帧率预览”时间线说明已经按实时模式修正。主画布的完整原版像素和字体仍未获得对照。

## 测量与复核

独立运行完整域着色界面验证时，进程族墙上时间 **26.02 秒**、观测 CPU 时间 **32.46 秒**、峰值聚合 RSS **2.14 GiB**；结束后未观测到遗留的所属进程。进程身份按 PID 与创建时间确认，目标采样间隔 50ms；短命进程与瞬时峰值可能漏采，共享内存可能重复计入 RSS。没有等价的改动前流程基线，没有分别测量完整冷/热任务、token 成本或显存，不能据此声称性能提升。

复核入口：`scripts/verify-source-domain-ui.mjs`。它使用真实 App 控件、未修改的 Worker 请求与结果、实际导出服务和 FFmpeg；观察包装仅记录消息，停止测试在 HTTP 请求处设置等待点。测试前后源文件哈希相同，资源清理成功。本轮没有向用户桌面发送鼠标或键盘输入。

本机原始记录：

- `.cache/domain-ui-measure.json`、`.cache/domain-ui-measure.log`。
