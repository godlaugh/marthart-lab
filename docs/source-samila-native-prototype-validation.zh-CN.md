## 本次实际验证了什么

原版仍是 MathArt 1.7.8，JAR SHA-256 为 `a6e1da3acfc05c347d2529c1d590657e2dd798e16d38c55df3dc61312be24018`。五个资源 JSON 与 JAR 成员逐字节相同，正常 VIEW／RUN／EXPORT 策略检查通过；保留原版品牌及 raw/enhanced PNG。每次启动前备份策略缓存，用户 settings 摘要保持不变，`license.dat` 前后均不存在。全部实例离屏运行，没有可见窗口或桌面输入。

每个预设保持原公式、参数、完整批量和三次实际随机种子；主画布像素高度为 972，目标为 500×600。三次显示均在场景时间 0，累积计数为 1、2、3。这是连续暂停显示，尚不覆盖完整动画、参数热改、窗口缩放或录制。

本轮从实际原版上下文取得：

- 两张 500×600 RGBA32F 历史纹理、256×256 R32F 噪声纹理、1024×1 RGB32F 色板，以及最终 RGBA8 附件。
- 纹理全部字节、过滤与环绕参数，逐阶段 framebuffer 绑定、混合、viewport、point origin 和光栅状态。
- 实际上下文为 `Apple M2 Max / 4.1 Metal - 90.5`。五个预设的 15 组噪声及色板数据与生产 owner 导出全部逐字节相同，过滤和环绕契约也相同。

先用原版已捕获程序在新的独立 CGL 上下文复现，45 个阶段全部一致，确认这些输入足以重现参考。随后换成生产代码实际生成的 shader、LUT 和完整分块调用。只做 GL ES→GL4 版本／precision 适配和移除未绑定的诊断输出声明，不改变公式与采样数学。生产 history 使用三角形三顶点，present 使用 strip 四顶点；生产输出纹理的 NEAREST 过滤也保留，没有为对照改成原版的 LINEAR。

两个历史附件从独立零数据开始，之后连续计算；**没有把原版中间墨迹上传给本地历史**。期望浮点数据只按两端声明的通道 ABI 做四字节换位 `[1,2,3,0]`，不算值、不翻转行；两端均为 GL 底行在先。每个阶段比较完整缓冲，不裁剪、不掩码、不设置容差。

## 差异原因与生产修复

初始原生原型已经具有相同像素覆盖和 mass，但 RGB mass 有低位差异。五个预设的 15 张最终图中，11 张完全相同，4 张各差 1 个字节。以 Samila 为例，第三帧不同 RGB 浮点值的最大绝对误差不超过 `6.676e-6`；这仍然算差异。

原版把 `noiseFrequency`、`noiseAmplitude`、`noiseLutScale` 作为运行时 uniform 参与乘除。本地把相同数值写成了 GLSL 常量，改变了 GPU 编译时可优化的表达式边界。仅恢复这三个 uniform 的独立实验就使 Samila 的 9 个阶段全部一致；另一个只把分块绘制合并成单次绘制的实验，其 9 个输出与原先分块输出完全相同，没有支持分块导致此次差异的假设。具体编译器指令或优化步骤尚未反汇编归因。

修复在 [sourceSamilaSplat.ts](../src/engine/sourceSamilaSplat.ts) 统一参数值及噪声映射 GLSL；[sourceSamilaGpuDirect.ts](../src/engine/sourceSamilaGpuDirect.ts) 保留运行时运算，[iteratedDensityGpu.ts](../src/engine/iteratedDensityGpu.ts) 的另一实际绘制路径也复用同一 owner 并绑定三个值。CPU 近似查询读取同一参数定义，删除原来重复的映射表达式。

## 观察限制与下一步

原版捕获的 45 次绘制在 uniform 观察之前均已有 GL 错误 1282；观察器记录并取走该错误，后续 uniform／状态读取检查为 0。错误来源尚未定位，不能声称原版整次运行没有 GL 错误。早期采集还遇到错误检查位置和 RGB32F 格式支持问题，失败目录及退出记录均保留；本报告只使用完整成功的 run5。

独立原型还借用了已捕获的外围桌面 GL 状态和历史附件连接；它尚未成为产品的类型化 native 合同。现有原生服务、会话取消、暂停截图、独立导出保留预览和热录制都需要实际接入及验证。热会话没有完整随机种子日志，历史丢失时不能用新随机画面假装恢复。

下一步把已验证的完整绘制链接入持久 Samila 原生资源 owner，复用既有进程监督，并保持 TypeScript 为唯一的队列／时钟／seed 语义 owner。随后补热改、resize、暂停截图、冷导出、录制和中断恢复的真实产品矩阵，再验收整类及 Apple Silicon 发行包。

五次成功原版捕获耗时合计 49.490 秒、子进程 CPU 22.402 秒，不含编译；最终五组原型任务耗时合计 8.386 秒，包含输入检查和完整比较，renderer 子进程 CPU 0.387 秒。真实 WebGL 对照耗时 16.603 秒，仅 Node CPU 11.736 秒。生产数据导出时单个 Node 进程最大 RSS 为 557,024 KiB；不代表完整进程族峰值。

更完整的运行和清理事实记录在证据索引中。各次都是新进程，但系统／驱动缓存未清空；原型与应用工作量不同，不能作为冷暖或性能提升比较。进程族峰值内存、GPU 时间／显存和本任务的 agent token 成本未测。
