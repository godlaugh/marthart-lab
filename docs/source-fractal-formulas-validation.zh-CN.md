# 分形公式标注验收

2.0 仍在 M3，原版完整窗口对照仍为 **0/11**。本轮让分形预览、当前截图、独立回放图片和视频、保留配置录制共同使用场景构建时保存的公式标注。

## 使用行为与原版依据

分形参数动画可以继续变化，但已经构建的公式文字和样式保持不变。热修改和暂停时“应用”保留现有标注；播放时完整“应用”重建标注。录制从上次完整加载的场景重新开始，因此也使用那次保存的标注。隐藏所有标注时，当前草稿里新开启的标注不会重新出现在旧场景截图中。

这是对先前推断的纠正：预览没有把 evaluatedFractalScene 放进公式依赖，并不能证明缺陷。原版 MathArt 1.7.8 的 JsonComplexFractalConfig 使用初始 ParamSet 与 metadata 模板生成主方程；TexMobject 构造时生成纹理，其 update 方法直接返回。热修改只更新分形 Mobject，完整重载才重建 Scene。文字不应从逐帧 shader 参数重新推导。

原版主方程不读取 main_equation.latex；本地可编辑的主方程及附加标注继续保留，但本轮不把这些编辑能力当成原版功能一致性的证据。Newton / Nova 的自动主方程改用已核对的原版模板和初始参数。特别是 Nova 的 Mandelbrot 变体，主公式仍取初始 julia_seed，不能擅自改成运行时 start_value。

## 实现与验证边界

FormulaPresentation 由生成器解析并随实际栅格帧交付。实时场景分别保留当前构建标注和上次完整加载的标注；导出消费这份事实，不重跑队列，也不从编辑草稿补齐空标注。Worker 交付边界检查标注结构，校验规则与作者配置共用轻量模块。

本报告记录提交 7a889ac 的历史验收：当时当前 PNG 在底图放大后绘制文字。后续固定原版调用链已证明这个顺序有差异，现已改为基础尺寸合成文字，再对整图增强和放大，详见[当前帧 PNG 顺序修复验收](source-fractal-png-order-validation.zh-CN.md)。独立回放无标注 PNG 仍保留原始 RGBA；视频仍在 FFmpeg 缩小前合成。字体排版继续使用本地 MathJax SVG，未证明与原版 JLaTeXMath / GL 像素相同。

解码取消、解码失败、序列化失败会释放本次创建的图片 URL 和画布，不修改输入 RGBA。图像大小、单个公式解码像素和合成工作区都有容量检查。预算不涵盖浏览器或 GPU 内部工作区。

## 验证记录

原版 JVM 的两次独立执行返回了 106 条相同结果。其中 104 条属于本次支持的格式化和 Newton / Nova 配置范围，全部与本地实现吻合；两个旧公式族 / 未知注册项的 fallback 结果原样留存，未纳入支持声明。此检查没有构造原版 Scene、字体纹理或 GL 窗口。

真实 App → Worker → WebGL2 → 编码服务完成两组、17 个公开步骤：

- Newton 参数动画、热切换 Nova、暂停应用、当前截图、旧配置录制和播放时完整应用，分别检查应保留和应更新的标注。
- 自定义主公式 A、可见附加公式 E、隐藏公式 H，暂存主公式 B 并隐藏 E 后，当前截图仍保留 A / E；独立回放使用 B；保留配置录制及停止保存使用 A / E。
- 当前 PNG 的 3× 放大、密度 2、奇数目标尺寸 161 × 121、全部隐藏后的原始 RGBA、SVG 解码取消后释放资源并重试。
- PNG 和上传帧的全部 RGBA 与独立位置计算的合成结果一致。比较器只复用 MathJax 字形 SVG，不调用生产端的标签解析、位置计算或合成函数。
- JPG 实际文件类型和尺寸正确，有损解码后的文字像素更接近预期字形而非原背景；不声称 JPG 无损。
- 三个实际 MP4 为 3、3、1 帧，160 × 120、8 FPS；逐帧解码平均 RGB 误差均小于预设阈值 8 / 255。保留配置提前停止实际保存 1 帧。
- 浏览器、控制台与 Worker 错误均为空，公式图片 URL 创建和释放数量一致，浏览器和服务正常退出。

无标注低透明度和隐藏 RGB 的字节保留另由独立 PNG 解码测试验证；本轮分形画面本身不透明，不能用它证明低透明度行为。取消解码使用明确的延迟注入，实际数值计算与渲染结果没有被替换。

首次 JPG 诊断因夹具文字和背景对比不足失败，保留了失败产物。改用大号白色文字后，最终验收仍使用原定的高对比采样阈值，没有删去文字存在或相似性断言。全量测试后的复核还移除了源公式旧分支及重复交付校验；最终结果以所有清理完成后的源码为准。

最终全量测试 **386 个文件、7,339 项通过**，Vitest 用时 46.96 秒；TypeScript 与 Web 构建通过，Vite 用时 8.94 秒，仍有现存大分块提示。既有独立回放导出 **8/8** 通过；保留配置录制两组、4 个 MP4 与取消重试通过。三个公开报告的源码摘要均稳定，并与最终文件一致。

标注验收的 MP4 最大逐帧平均 RGB 误差为 **2.8459 / 255**；JPG 的 128 个文字采样点平均误差为 13.2005 / 255，对原始背景的对应误差为 82.4453 / 255。这些是本地像素传递与有损编码检查，不能推出原版像素相同。

最终产物已查看：当前 3× PNG 保留红色 A 和绿色 E，独立回放 JPG 显示新草稿 B，隐藏标签未出现。全部检查结束后，没有仍存活的已观测子进程。使用 Node 24.18.0 与 Chrome 155.0.8059.85。

## 剩余差距

原版整窗对照、GL 目标与逐帧累积、字体像素以及原版录制期间的热编辑交错仍待验证。本轮后台浏览器检查不替代这些证据，也没有替换已安装的 Apple Silicon 1.0 应用。

完整公开结果为 `.cache/fractal-formulas-public-release/report.json`、`.cache/fractal-formulas-fresh-regression/report.json`、`.cache/fractal-formulas-retained-regression/report.json`；测量及日志为 `.cache/fractal-formulas-*-measure.json` 与对应 `.log`。

本轮仅以 yomado 的只读诊断确认存在物理主屏和运行中的虚拟屏；现有虚拟屏的本任务归属、目标截图和输入隔离仍未确认。没有移动窗口或向桌面发送输入，原版窗口没有新增对照证据。

原版公式证据入口为 `.cache/fractal-formula-source/findings.md` 与 `tests/fixtures/source-fractal-formula-labels/`。前一轮停止保存验收见[分形手动停止与部分视频验收](source-fractal-stop-validation.zh-CN.md)。
