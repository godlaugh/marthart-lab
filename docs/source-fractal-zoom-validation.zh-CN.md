# 分形目标缩放：轨迹修正与验收

本轮补齐了原版分形缩放的中心移动规则，2.0 仍在 M3。完整原版窗口对照仍是 **0/11**；本报告不把数值一致认定为整幅画面一致。

## 用户能看到的变化

- 新建分形缩放片段默认使用「随缩放移动到目标」。目标中心、中心低位、缩放和缩放上限可以编辑，起点取片段开始时的有效视口。
- 例如从 1 倍放大到 100 倍：动画到一半时是 10 倍，中心已走过约 **90.91%** 的距离；旧实现只走过 50%。从 100 倍缩小到 1 倍时，中点只走过约 **9.09%**。
- 修改初始视口或前一个动画后，后续片段会重新取得正确起点。导入时省略的目标字段仍按原配置加载时的默认值确定，两者不混用。
- 原配置的 `keys` 选择最大 Float32 时间的目标，并列取后者；它不是逐关键帧播放。选择后保留原输入作为来源。
- 已保存的本地关键帧轨道保持原行为。界面可明确切换回「关键帧线性中心」，保存的数据只保留所选模式的一份定义。

## 修正了什么

时间轴之前把原版目标变成两个固定关键帧，既丢失缩放感知的中心轨迹，也把动态起点错误地固化为导入时的状态。现在目标动画有独立数值所有者，由导入、文档校验、时间轴和界面共同使用；旧关键帧分支保持独立。

实现保留了原版 Float32 缓动、双精度对数缩放、中心高低位的运算顺序、最大缩放裁剪及没有强制终点写入的行为。目标中心进度使用未裁剪的缩放倍率。初始视口先按原版归一中心高低位，并把小于 `1e-6` 的初始缩放提升到该下限。

原配置的标量解析区分缺省和显式 null；表达式失败、中心数组覆盖次序、Float32 时间并列/NaN、无效缓动默认值及 `max_zoom` 非有限值默认也经过验证。超过本地数值或渲染范围会明确报错，不静默改成另一条轨迹。

## 已执行验证

| 验证 | 结果与边界 |
| --- | --- |
| 原版 JVM 数值方法 | 64 个动画采样、22 个目标解析样本、12 次时间更新；执行真实原版类，不使用复制实现生成期望值 |
| 数值所有者测试 | 69 项通过；覆盖源采样、高低位归一化、裁剪及不支持的输出 |
| 导入/保存/时间轴集成 | 77 项通过；含 22 个原版解析样本、48 个范围内动画采样、前后片段起点、控制字段、模式冲突及容量失败 |
| 实际无头浏览器 | 6 项通过：放大、缩小、等倍率中点，明确切换模式，目标编辑后保存重开，实际 PNG 导出 |
| 实际渲染 | App → Worker → WebGL2 → 画布；数值从实际完成帧的视口信息读取，并与原版 JVM 采样比较 |
| PNG | 实际导出 257×193 图片，尺寸与哈希已记录 |
| 全量回归 | 359 个文件、6863 项通过；随后新增初始缩放下限回归，补跑相关 169 项与最终集成 77 项 |
| Web 构建 | TypeScript 检查和 Vite 构建通过；保留现有包体积提示 |

原版与 JavaScript 的超越函数末位可能不同，测试使用有界的相对误差；中心低位按低位本身的量级比较，不借高位容差掩盖精度损失。未声称逐位相等，也未测量本轮 CPU、峰值内存或跨设备性能。

## 尚未验收

本轮补齐的是目标轨迹和它的公开使用链路。原版按 Float32 增量推进的队列、片段边界不结转剩余时间等逐帧行为，与本地按秒采样的时间轴仍有区别；此项继续保留为待办。全部公式的极深缩性能、原版完整窗口、DPI 和跨驱动画面一致性也尚未建立。

本轮原生窗口检查仍返回 Mac 已锁定、自动解锁失败；没有移动窗口或发送桌面输入。Yomado 的目标截图隔离未验证。所有新的界面检查使用无头浏览器，已安装的 Apple Silicon 1.0 应用没有重新打包或替换。
