## 确认的原版行为

原版每次更新最多执行一个片段。零时长等待也占用一帧，当前片段未用完的时间不会传给下一个片段。队列剩余时长每帧重新按 Float32 求和；用总时长减播放时间不能替代它。

最后一个片段结束的这一帧，分形对象先按有效动画间隔更新，再按原始帧间隔更新一次。因此旋转、参数振荡与渐变可能推进两次。相机角速度晚一帧同步；暂停时不更新这些状态。新实现复用已有 Scene/SceneManager 队列算法，只单独表达分形的更新次序。

普通 animate 的 center、zoomFractal、rotation、fractalRotate、iterations、bailout、julia 操作数学对象。zoomFractal 做线性缩放，独立 fractal_zoom 做上一轮验证的对数缩放与缩放感知中心移动。普通动画不会在结束时强制改写终点；原版零时长动画可能产生 NaN，本地明确报错并要求重置。

参数振荡依赖当前公式的元数据，不能把所有本地设置都当作可动画化参数。完整复数参数固定启动时的虚部；_re/_im 分量写入读取当时的另一分量。替换、全部停止、具名停止和重启保留各自的注册表语义，未知元数据不产生参数写入。范围上下界按原版排序。

渐变保留三个独立起始偏移。只影响一侧时，HUE_ROTATE 改变该侧偏移；两侧都启用时才改变调色板偏移。其它模式也按各自标记决定写入位置，不能先计算双侧结果再简单屏蔽字段。

## 证据和已执行验证

- 固定原包 SHA-256：`a6e1da3acfc05c347d2529c1d590657e2dd798e16d38c55df3dc61312be24018`。
- 队列：真实原版 Scene → SceneManager → Animation → FractalMobject 调用链，9 组、107 次更新。100 个有限状态帧与本地逐项比较；另验证原版 NaN 在本地明确失败。两次独立 JVM 运行结果相同。
- 参数：真实原版参数动画回调、参数注册表与数值更新，12 组、80 个状态步骤。包含复数分量、HashMap 顺序、反向区间、帧率回退、启停及替换。
- 渐变：真实原版 GradientAnimator 与 Fractal 数值目标，19 组、266 个快照；比较三个双精度偏移、实际 Float32 写入、启动/更新/停止/重启和写入变更标志。两次独立 JVM 结果相同。
- 核心回归：队列 12 项、参数 15 项、渐变 19 项，共 46 项通过。共享渐变及 Surface/Symmetry 相关 84 项也通过；其中包含队列测试，不与 46 项相加统计。
- 最终全量回归：362 个测试文件、6910 项全部通过（43.12 秒）；TypeScript 检查与 Web 构建通过，仍有既有包体积提示。未重新打包桌面版。
- 复核修正：初始完成标志保留 Java 默认 false；重置复用已归一的 Float32 相机初值；回调或重置失败后禁止读取半完成状态。

原版类通过随应用提供的 JVM 执行；图形构造使用 JNI AllocObject 绕过。这里没有执行原版窗口、OpenGL 绘制或视频编码。数值步骤和图形效果是不同的验收层次。Java Math 与 JavaScript Math 超越函数末位差异使用小范围容差，其余状态直接比较。
