# 弹跳原生生成与应用接入（2026-10-24）

**弹跳原生渲染已接入实际 Generator、种子 Worker 和应用预览。** 原生模式使用同一入口生成预览、截图像素和录制帧。完整界面的 PNG／MP4 导出、更多原版配置及最终发行仍未完成验收。

## 现在实际接通的流程

页面持有原生资源，专用 Worker 只计算初始粒子，再转移数组给页面。粒子分块上传一次，后续直接更新原生 GPU 纹理。显示参数、相机、像素密度、公式标注和绝对更新检查点由共享准备函数解释；显示编辑不重新播种，倒退定位明确重建状态。

预览与导出通过同一个协调器使用当前状态。相同配置和检查点可以直接重绘；导出接管后，旧预览对象的延迟销毁不能释放新拥有者的状态。取消保持界面调用同步，但后续请求会等待实际清理完成。释放失败会保留资源身份，下一次获取先重试清理。

原生模式的预览使用已有像素合成器，避免把完成图再次当作三维场景渲染。界面显示 `GPU · Native`，原生后端失败不会静默退回 WebGL。

## 页面生命周期修复

仅在组件销毁时释放资源不够：刷新、退出或浏览器返回缓存都可能绕过通常的清理流程。

现在页面建立一条持续连接，原生请求附带该连接的身份。服务端在连接关闭后回收自己持有的实际子进程，并等待退出确认；回收失败仍保留占用。其它页面不能接管现有连接，也不能通过新连接释放旧诊断调用方已持有的状态。

实际 App 检查发现浏览器可能在页面切换时保留旧连接，因此还在 `pagehide` 和开发模块替换时关闭连接。短暂连接交接使用有截止时间的退避重试，不创建后台无限队列。

## 回归与成本

13 个测试文件、254 项测试通过，2.0 构建通过，仍有已有的大 chunk 提示。Cornucopia、Sphere、Möbius 三例曲面回归的完整艺术画面均为零差异。

最终 62 帧产品流程验证耗时约 5.42 秒；采样进程族 CPU 约 10.53 秒、峰值 RSS 约 2799 MiB。流程包含浏览器、实际种子 Worker、HTTP、参考读取和画面对照，不能当作产品帧率。它不再执行此前的 11 次完整状态纹理诊断，不能直接用于宣称相对旧流程的加速比。

严格冷／暖运行、独立 GPU 时间与 token 成本未测；采样可能遗漏短进程和瞬时峰值。专用种子 Worker 的本次构建产物约 35 kB，避免把显示与公式依赖带入种子计算模块。
