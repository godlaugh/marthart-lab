# 原生渲染接入：本机通道与完整绘制列表

2026-10-23，基线 `0854926`。**浏览器现在能通过实际本机 HTTP 通道调用常驻原生渲染器；真实产品 Worker 的三张完整艺术画面经过这条链路后，仍与原版逐像素一致。** 桌面代理通道也经过实际请求验证。普通应用的预览、暂停截图和录像尚未切换到这条路径，不能把本轮当作完整应用接入或 2.0 发行验收。

## 本轮变化

`createExportServer` 新增可显式配置的原生后端，提供健康查询与二进制帧请求。桌面 host 转发同一个通道，不另建原生渲染实现。独立服务器和桌面启动入口可从 `MATHART_SOURCE_RENDERER_BACKEND` 指定的 JSON 文件读取配置，内容是已有会话层的程序绝对路径、SHA-256 及可选资源期限；默认未配置时返回不可用，不自动安装、搜索或启用后端。桌面打包脚本已包含新的 Node 模块，但尚未把原生 executable 打进发行包。

同一个服务为所有窗口分配递增的内部传输编号，保留调用方帧代次／序号并在响应中返回。不同页面即使提交相同编号，也不会与原生子进程的旧响应混淆。只重标拥有的传输副本，不修改调用方传来的缓冲。

本机来源和 Host 检查、二进制 MIME、64 MiB 上传上限、上传／写出期限继续由 HTTP 边界负责。原生通道在读取请求体前就占用唯一处理槽，直到响应交付或失败后释放；没有无界排队。客户端断开、服务关闭会取消对应原生请求；原生清理失败会传回关闭错误，保留所有者，服务器和桌面 host 都能重试同一份清理。

浏览器 `renderSourceNativeFrame` 编码快照、提交请求，检查响应帧身份、尺寸、格式、后端摘要及长度。像素按已确认的大小一次分配，分片写入，再原地从 bottom-up 转成 top-down，保留透明像素的 RGB。页面内也只有一个活动请求，取消和 20 秒传输期限会中止 fetch；失败不会悄悄返回 WebGL 像素。

## 绘制数据由渲染器拥有

新增 `ArtRenderer.sourceDrawingFrame`。它消费 Three 已实际排序的 render list，并把最后的渐隐覆盖层作为后续绘制追加。验证器不再按 `userData` 标签挑出部分 mesh，也不自行猜测绘制顺序。

背景取自 renderer 已经应用的 GL 清屏状态：源打包颜色与旧 Three 背景的颜色空间／透明度换算本来不同，不应在导出器里重算。未知材质、分组、透射、非 mesh、裁剪、丢失的上下文和多重采样目标会明确拒绝。**主显示的多重采样策略仍待实现和验证**，当前成功范围是受支持的完整离屏源几何帧。

真实接入暴露了两个此前被手动选择绕过的问题：

1. 点场景没有源打包背景时，不能简单判定它缺少有效清屏值；改为读取已应用的状态。
2. Cornucopia 初始帧的空拖尾被生产者标为可见，尽管实际实例数为 0。修正 `createThickTrails` 的空边可见性，仍保留输入校验和资源所有权。有内容的未知材质继续报错，不能被筛掉。

渐隐层已改用共享的有类型材质入口和 GLSL3，使它能通过同一快照／原生通道。其 alpha、混合方式、几何与绘制顺序没有改动。

渐隐记录：`.cache/source-renderer-transport-20261023/overlay-report.json`。以基线提交的旧 shader 为对照，使用两种背景 alpha 和十个渐隐 alpha，逐字节比较旧 WebGL、新 WebGL、公共原生通道。它验证材质改写，没有声称完成原版全部渐隐动画时间点的验收。

早期整帧失败记录保留在缓存中，分别指出清屏状态与空拖尾问题；最终记录已在修正后重跑，未把失败结果当作通过。
