# 隐式曲面原生预览验收（2026-10-24）

CPU 隐式曲面已接入与 Surface 共用的原生预览流程。在 `VITE_SOURCE_RENDERER=native` 模式下，主画布显示原生后端返回的像素，并等待公式准备完成后一次性呈现。播放、暂停、尺寸变化和切换回普通本地场景已通过真实 App 验证。

这证明产品预览正确消费原生画面，不等于原版完整窗口已逐像素验收。上一轮静态 PNG 与原版完整艺术画面的零差异结果继续通过；原版主窗口的 DPI、平滑和实时调度仍需独立核对。

## 实现与时序修复

预览资格判断扩展到有明确源标记的 CPU 隐式网格，原先仅针对 Surface 的函数和状态命名同步改为几何预览。普通本地曲面、GPU 隐式模式不会因此自动进入这条路径。未新增第二套原生请求或公式合成实现。

固定时间回放现在也等待“生成完成且原生画面已呈现”再发出下一次求值，避免数值帧不断替换尚未呈现的画面。等待期间不推进播放位置；下一次就绪时仍按既有固定时间回放规则消费经过的墙钟时间，不冒充原版实时线程时钟。

另一个实际发现的问题是：预览响应被延迟时，“开始导出”仍可点击。当时原生绘图请求槽尚未释放，且导出依赖的预览相机、主画布高度和密度尚未交付。本轮通过实际界面复现了这个错误的可点击状态，没有把它写成已观察到的导出后端异常。

现在 App 将完整呈现就绪状态传给导出对话框；未就绪时显示既有等待说明、禁用开始按钮，执行入口也再次检查。延迟预览后打开对话框，开始按钮保持禁用；释放预览后自动恢复，实际 PNG 下载及原版整图对照均通过。

## 已执行的验证

扩展 `verify-source-native-viewport.mjs`，使用 headless Chrome 和实际服务，运行六种场景：

| 场景 | 已核对的完整呈现帧 | 检查 |
| --- | ---: | --- |
| Surface CPU 动态点 | 7 | 显示 framebuffer 与对应原生响应逐字节相同 |
| Surface GPU 动态网格 | 7 | 显示 framebuffer 与对应原生响应逐字节相同 |
| Surface 原版公式 | 6 | 字形未到齐时不呈现半成品，完成后包含公式 |
| Surface 已保存的本地公式 | 6 | 继续使用本地公式布局并完成合成 |
| Implicit CPU 网格，无公式 | 5 | 显示 framebuffer 与对应原生响应逐字节相同 |
| Implicit CPU 网格，有公式 | 5 | 字形未到齐时不呈现半成品，完成后包含公式 |

合计 36 个完整呈现帧，其中 19 个无公式帧直接核对全部显示像素。带公式帧检查等待和合成，不把“与底图不同”单独当作文字像素与原版一致的证明。隐式测试输入复用包内 60³ 曲面，并缩短初始等待，让相机动画在测试期间实际进入播放阶段。

六组均验证：延迟原生响应时没有继续交付数值帧；调整视口后，新尺寸画面先完成，之后释放旧响应不会将旧画面覆盖回来。另一次完整六组运行明确记录被取消响应的 generation/sequence，断言它从未进入呈现列表，全部通过。各组都实际请求了 4 samples 的原生预览。

无公式隐式场景还实际导入普通本地曲面：原生画布隐藏、普通画布恢复；再次导入隐式场景后原生画布重新呈现。此切换后的额外呈现没有计入上表 36 帧。

静态 PNG 回归使用上一轮原版参考，核对送入图像增强 Worker 的完整艺术像素：500×600、公式在内、零差异；下载正常。参考阶段为品牌前、增强前，不声明原版带品牌的最终 PNG 与产品文件相同。

相关测试实际执行 4 文件、27 项：原生预览所有权 7 项、隐式 PNG 4 项、隐式公式帧 6 项、实时录制合成 10 项。首次命令误写了录制测试文件名，实际只运行前三个文件；随后单独执行正确的 `realtimeRecorder.test.ts`，没有把未运行文件计作通过。2.0 构建和类型检查通过，仍有既有大 chunk 提示。

共享导出就绪判断还通过既有 Surface 三组真实 PNG 工作流回归（Cornucopia、Sphere、Möbius），包含取消后重试。首次启动与仍在退出的预览验证共用端口而失败，确认前一个进程结束后改用新证据目录顺序重跑；只采信最终通过结果。

## 证据与成本

本地证据在 `.cache/source-implicit-native-viewport-20261024/`：

- `ui-final/report.json` 和六张界面截图：呈现、延迟、尺寸变化、场景切换；源文件摘要在任务期间稳定。
- `ui-stale-guard/report.json`：六组重新运行，明确核对被取消响应编号未呈现；全部通过、遗留进程为 0。
- `export-before/report.json`：预览被延迟时导出按钮错误地可点击。
- `export-after/`、`export-final/`：修复后的等待、实际下载和原版完整艺术画面对照。
- `export-cost/`：不注入延迟的完整导出成本及参考比较。
- `surface-export-final/`：三组既有 Surface PNG、取消与重试回归。
- `tests.log`、`recorder-tests.log`、`build.log`：实际检查结果。

六组 UI 任务墙钟 34.550 秒，观察到的进程族 CPU 64.090 秒，采样峰值 RSS 2441 MiB；114 次采样无错误。包含主动延迟和窗口尺寸变化，不能当作纯渲染吞吐。

相同“启动 → 导入 → PNG 下载 → 清理”任务，上一轮原生 PNG 加 WebGL 预览为 9.032 秒 / CPU 20.560 秒 / RSS 2846 MiB，本轮原生 PNG 加原生预览为 10.679 秒 / CPU 21.560 秒 / RSS 2890 MiB。每次新建服务与浏览器，未控制 OS/驱动冷暖缓存；前一轮与本轮运行时间不同。它们记录新增预览步骤的实际任务成本，不构成跨设备性能结论。GPU、token 成本未测量。所有服务均报告遗留进程为 0。

## 后续工作

隐式曲面的离线视频仍使用既有路径；本轮没有把预览接通等同于视频原生化。更多隐式配置、原版主窗口与实时调度对照、其它场景族一致性和 Apple Silicon 原生组件打包发行仍待完成。2.0 Goal 保持进行中。
