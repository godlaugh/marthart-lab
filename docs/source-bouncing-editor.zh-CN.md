# 弹跳场景：数字控件与多边形编辑验收

2026-10-24。2.0 弹跳场景现在可以直接拖动、增删和输入多边形顶点，切换三角形／正六边形并调整半径。七类数字控件加入步进、表达式输入、简短显示及无效输入恢复；利萨如相位改为角度输入。

当前仍在 **M3：场景补全与一致性验证**。这一批编辑功能已在实际 App 验证，完整场景家族与正式发行尚未完成。

## 已实现的行为

| 控件 | 当前行为 |
| --- | --- |
| 粒子数量 | 整数输入向零截断，例如 `3+0.9 → 3`；最小 1，整数上限 2,147,483,647，按钮步进 1,000。可输入范围不代表设备可承载该数量 |
| 每帧子步数 | 输入限制为 1–16；当前值 1–14 时步进 1，15–16 时步进 2 |
| 物理步长 | 输入限制为 Float32 的 0.0001–0.25，步进 0.001，最多显示 4 位小数 |
| 初始速率 | 非负，步进 0.05，最多显示 3 位小数；当前模型仍限制到 100，超过时恢复原值并显示原因 |
| 初始方向／方向散布 | 使用度，步进 5°；方向可为负数或超过 360°，散布限制为 0–360° |
| 利萨如相位 | 使用度，步进 15°；保存仍使用原模型的 Float32 弧度 |
| 数字提交 | 失焦或回车提交，方向键／按钮步进；无效输入恢复上次有效值。仅聚焦再离开，不会把显示舍入写回原始数据 |
| 多边形 | 拖动结束提交；逐点 X/Y、方向键微调、首尾边中点添加、删除、恢复原版不规则六顶点轮廓；保留 3–64 个顶点 |
| 规则形状 | 三角形／正六边形按钮使用半径 0.6；半径 0.62 的六边形逐坐标匹配已固定的原版算法配方 |

编辑器 Y 轴向下，手动修改的坐标限制为 −2 到 2。导入中已有的范围外坐标、重复点、凹角及退化边不会被其它坐标编辑静默改写。高级顶点数组保留完整输入能力。

数字显示与保存值由不同层负责。例如原始方向显示为 `134.4°`，只聚焦再离开仍保留原来的精确弧度；不会重新播种。无效数字与无法表示的巨大半径也不会进入保存的数据。

## 证据与检查

**原版实际数值调用：91 项。** 使用已安装的 JDK 21.0.7 调用原包 `NumberDraggerKt` 的三个纯辅助方法，获得 33 项格式化、48 项解析和 10 项步进结果。产品逐项匹配格式文本、解析的 Double/Float32 位模式及步进 Double 位模式。窗口数为 0，没有创建原版项目、会话或渲染器。详细范围见[原版数值说明](../tests/fixtures/source-bouncing-number-controls/README.md)。

多边形规则来自原包字节码，并与此前已运行验证的六边形配方衔接。本次没有操作原版多边形窗口，不把静态规则称为原版 GUI 实测。

**真实产品页面：原生 CGL 48 项、WebGL 47 项通过。** 使用无头 Chrome 操作正常 App，经过实际生成器、Worker／原生服务及持久化流程，验证数字输入与步进、无改动精度、拖动提交、键盘焦点、取消拖动、增删限制、异常半径、原始坐标保留以及保存刷新后的完整配置。两条路径均渲染可见画面，无未处理页面异常，源文件未在运行中变化，结束后资源清理通过。原生多一项检查为所属服务子进程退出。

这次编辑验证以 64 粒子作品为主，粒子步进另实际到达 1,003；它不替代此前完整预设和录像的高负载验收，也不新增 WebGL 与原版的像素一致性声明。

相关 7 个测试文件共 **50 项通过**，覆盖原有多边形模型、源配置、持久化、控件和翻译。`build:v2` 通过，保留已有的大文件体积提示；中英文静态审计无必需翻译缺口。两个既有公开流程验证器已更新数值显示／无效输入断言，本轮没有重跑它们的完整导出流程。

## 仍待完成

- 原版速度控件允许作者输入 101，但场景配置构造限制到 100。当前产品保存的是已解析的模拟配置，尚未增加独立的作者输入层；101 会被拒绝，不能宣称这一链路与原版完全一致。
- 数字横向拖动、输入字符清洗、未修改值按回车的阈值规则，以及原版窗口的全部提交时机尚未逐项对照。
- 多边形提供自动适配按钮、始终可见的逐点编辑和 Esc 取消回滚。这是产品交互选择：原版按点数 3／6 隐藏逐点列表，取消拖动也不回滚。三／六点时的半径显示由当前几何推导；改动会重建规则形状，不表示保留了原版不可见的作者半径状态。
- 色板的完整手动／渐变编辑、其它 2.0 场景、通用能力及 Apple Silicon 正式集成和打包仍在 Goal 范围内。已安装的 1.0 应用未更新。
