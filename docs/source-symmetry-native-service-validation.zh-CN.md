# 自定义 Symmetry 通信与原生服务验收

2026-10-26。**正式通信协议与持久 CGL 服务已接通。六组原版参照、48 帧有效粒子状态共 71,958,912 字节逐位一致。整体仍在 M3，应用尚未切换到这条自定义原生路径。**

## 本轮结果

客户端现在可以明确创建自定义片元资源，分块上传种子，以带类型的参数推进，读取结果，并释放同一个资源。已在真实无窗口 CGL 子进程中完成这些操作，没有打开窗口或占用主屏。

源片元与原有顶点迭代资源共享状态生命周期接口。资源的执行类型由已经创建的所有者决定；错用旧版上传、推进、读取或释放请求会在改动状态前被拒绝。子进程回执还绑定诊断单位，错误单位或错误类型的回执会触发清理，不能解释成成功结果。

自定义诊断继续使用 **完成的 pass 数**：一个 pass 内执行三次迭代，连续两个 pass 的输出都无效时，计数为 2。它不表示六个内部步骤分别无效。现有墨迹协议只有迭代步单位，因此暂时拒绝这种资源，避免统计被错误命名。

类型绑定支持 float、int、bool、向量、mat3/mat4 和数组；整数保持有符号 32 位，浮点保留负零。数组部分更新保留尾部，未绑定值保留作者的链接初值。GL 反射仍负责检查实际类型及数组长度。`stateTex` 与 `iterations` 属于资源自身，不能被调用方覆盖；普通自定义 `steps`、`dimension`、`oldState` 不再被通用迭代协议误判为保留参数。

## 协议及容量边界

| 项目 | 约定 |
|---|---|
| 旧请求 | v6/v7 字节布局及原有处理继续保留 |
| 自定义请求 | v8，family 2；kind 7 创建、8 推进，2/4/5 上传、读取、释放 |
| 明确选择 | 创建/推进由操作名区分；上传/读取/释放显式提供 `profile: source-fragment` |
| 诊断回执 | 64 字节头部：偏移 52 表示单位、56 表示资源类型；自定义均为 1，旧版均为 0；60 保留为 0 |
| 单次输入 | 0–16 次内部迭代；完整类型绑定最多 65,536 个标量 |
| 粒子传输 | 上传/读取每块最多 65,536 个有效粒子；初始种子必须有限 |
| 状态驻留 | 完整方形每单元 64 字节，程序 UTF-8 长度 ×3，1 MiB 固定预留，另计匹配名称 |
| 名称计费 | 每名称 256 字节加 UTF-8 长度 ×3；新增明确计费，修正上一轮仅计程序和固定预留的说明 |
| 绑定瞬时计费 | 256 KiB scratch，加每绑定的名称计费和每标量 32 字节；解析为对象前先检查容量 |
| 绘图副本 | 此资源可直接借用纹理，额外状态视图分配为 0；当前墨迹协议尚未接入 |

以上是 256 MiB 逻辑预算的保守预留，包含协议副本与解析展开，不是驱动内存或进程 RSS 的测量结论。达到容量限制仍允许释放资源。清理失败保留进程所有权，只有确认退出才允许重新使用服务。

## 已执行的验证

**216 项不同测试通过**。主回归 215 项；随后增加一项真实墨迹单位拒绝测试并运行该文件 12 项，不重复累计旧测试。TypeScript 检查通过；真实 CGL 构建使用 `-Wall -Wextra -Werror`，全部无编译警告。

实际进程验证包括 65,541 个粒子跨块、跨纹理行传输；带符号整数、矩阵、数组、默认值；重置后逐位重放；畸形参数拒绝后状态不变；源片元与旧资源并存；精确释放、重复释放；编译失败后进程清理。受控 CPU 子进程另外验证了错误单位回执和清理失败时保留所有权。后者不构成 GPU 数学验证。

六组使用先前正常 VIEW/RUN 取得并封存的原版输入与状态：标准 custom（562,144 粒子）、邻居读取、每 pass 多次迭代、4,100 次有限循环与非有限输出、discard 历史、Processing 上下文绑定。每组 8 帧。该轮经过正式 codec → 服务 → 原生子进程 → codec，所有有效粒子零差异，六个进程组退出后均为空。

本轮公共读取接口只返回有效粒子，因此**没有重新把补齐纹理单元算入对照覆盖**。完整方形覆盖属于[上一轮资源验证](source-symmetry-state-validation.zh-CN.md)。上下文矩阵等值仍来自封存的原版观测，没有证明应用自己生成这些值的过程正确。

## 实测成本

每组新建服务，包含编译、读取参照、创建、传输、计算、读取比较及释放。首帧和后续七帧中位数包含协议往返和状态读回，不代表桌面预览帧率，也不是完全清空系统/驱动缓存的冷启动。

| 参照 | 全流程秒 | 子进程 CPU 秒 | 同时 RSS 峰值 MiB | 首帧 / 后续中位数 ms |
|---|---:|---:|---:|---:|
| standard-custom | 3.092 | 3.922 | 357.4 | 99.42 / 77.09 |
| layout-custom | 2.076 | 1.850 | 282.3 | 3.43 / 1.52 |
| layout-multi | 2.087 | 1.857 | 282.7 | 3.03 / 1.41 |
| nonfinite-custom | 2.075 | 1.900 | 279.4 | 5.20 / 3.46 |
| discard-custom | 2.089 | 1.874 | 282.3 | 3.36 / 1.35 |
| context-custom | 2.086 | 1.849 | 286.0 | 3.56 / 1.65 |

RSS 每 0.5 秒采样一次，可能漏掉短峰值；CPU 包含采样子进程。GPU 内存、能耗未测。此前直接资源诊断包含不同的读回与生命周期检查，不是等价性能基线，不能据此宣称加速。两次 Goal 计数读数窗口增加 97,332 tokens、557 秒，包含工具交互；不含之后报告收尾，也没有同等任务的旧 token 基线。
