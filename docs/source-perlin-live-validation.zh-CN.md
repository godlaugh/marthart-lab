# Perlin 实时预览与录制恢复验证

2026-10-22。Perlin 的统一 CPU/GPU 场景已接入保留实例的实时预览：录制保存完成后继续运行，暂停、截图与后端切换不会重新创建数值模型。**这是本地功能验证；不等于 Perlin 原版整图验收完成。**

## 使用上的变化

- 打开统一源 Perlin 场景时，暂停显示时间 0；播放按实际经过时间推进。
- 动画队列结束后，场景时间、相机及绘制继续；Perlin 对象的动画时间、参数、渐变和运动保持队列结束时的状态。CPU 累积画布仍可以因重复绘制发生变化。
- 暂停后切换 CPU/GPU 或保存当前 PNG，不推进模拟。恢复播放不会补算暂停期间的时间。
- 工具栏“录制”使用逐帧录制，先预热一帧，再录到队列完成；也可“停止并保存”。编码完成后，从录制结束的实例继续播放。取消导出删除临时视频，并释放录制占用。
- 明确拖动时间线仍是从起点重建。缺少可核验来源、无法恢复完整配置的旧版单后端 `perlinCpuSource`／`perlinGpuSource` 文件继续使用固定回放；普通按时长导出也保留原入口。

## 修改为什么放在这些边界

原版依据见 [队列完成后的更新与绘制边界](source-perlin-post-queue-validation.zh-CN.md)。原版 `stopRecording` 关闭固定步进并重置墙钟锚点，没有重新构造场景或暂停；队列完成后的对象更新保护也必须保留。

[SourcePerlinSession](../src/scenes/sourcePerlin.ts) 现在拥有实时会话、时钟和录制交接。共享时间线新增明确的 fixed → live 转换，转换本身不更新或绘制。录制交接只补一次主画布绘制；消息发送失败后的重试仅重新读回像素，避免 CPU 累积画布被重复绘制。暂停后的 seek 会保存重建后的相机角度，恢复不会误回到初始视角。

Worker／Generator 校验返回的会话、尺寸、场景时间与实际队列帧；Queue 在释放播放控制锁后才完成暂停确认 Promise，允许调用者连续 `await resume`、`await pause`。录制期间排队的作品切换不会被旧完成帧覆盖；同会话明确编辑保留，未修改的后端与模拟帧率使用录制拥有者的实际结果。

App 直接使用已完成帧的场景时间；导出界面先完成视频编码，再交还实时控制。工具栏录制共用模拟／编码帧率；“导出作品”中的原有独立帧率选项仍保留。

## 证据与复现

使用项目固定工具链，在 `studio` 目录运行：

```sh
PATH="$PWD/../.cache/local-toolchain/node_modules/.bin:$PATH"
node scripts/verify-source-perlin-live.mjs
node scripts/verify-source-perlin-live-public.mjs
node scripts/verify-source-perlin-retained-recording-public.mjs
node scripts/verify-source-perlin-capture-public.mjs
npm run build:v2
```

脚本使用自有 headless Chrome、实际 WebGL、真实 Worker 和本地编码服务，不操作主屏幕。公开流程的参数与时间线有明确的小样本覆盖，不冒充原包未修改作品。原始报告保存在本地 `.cache/`，不进入仓库；此文为可阅读摘要。最终证据为 `perlin-live-transport-complete.json`、`perlin-live-public-20261022-final4/report.json`、`perlin-retained-live-20261022/report.json`、`perlin-live-capture-20261022-final2/report.json`。

截图回归改用真实 GPU 播放推进热场景，再暂停切回 CPU。显式 seek 会创建新的实时会话并冷重建，不能把它当作保留旧 CPU 运动历史的继续播放。已有录制回归也改为在确认同实例续播后主动暂停，仍逐像素核验上传帧，没有沿用旧的“停止后保持暂停”假设。

## 尚未通过的范围

原版自然窗口播放、可变时间间隔与录制停止后续播，还需同条件实际对照。本轮不能消除已有 GPU 少量颜色差、CPU／其它模板整图及相机视角验收缺口。系统时钟回拨产生负 dt 时，本地 Perlin 数值模型仍明确拒绝；没有静默裁剪成零，也未声称已匹配原版这一边界。

未测本次改动的前后性能、进程族 CPU／峰值内存及 token 成本；上表耗时仅是验证任务耗时。1.0 Apple Silicon 已发行包未被替换。2.0 各家族完整验收仍未完成。
