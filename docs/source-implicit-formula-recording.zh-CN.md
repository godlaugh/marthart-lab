# 隐式曲面公式与录制验收（2026-10-24）

**带公式的隐式曲面参数动画，已完成本轮原版画面对照和实际视频、PNG 导出验证。** 同时修复了原版项目导入时主公式与附加公式的几处差异。这是 2.0 源码增量，尚未发行或替换已安装的 1.0 应用。

后续更新：本报告所列 3 个分形时间线失败已在[分形导入与时间线验收](source-fractal-import-clock.zh-CN.md)中依据原版运行记录解决。下文保留当时的执行结果。

## 修复内容

| 导入内容 | 原版规则与修复后的行为 |
| --- | --- |
| 主方程文字 | 按初始场方程生成；忽略源文件的 `main_equation.latex`。原始值仍保留在来源记录 |
| 关闭的主公式 | 不读取其位置、缩放、颜色；这些未使用字段即使格式异常，也不会阻止导入 |
| 主公式启用值 | 使用原版布尔规则，接受大小写不敏感的 `true` / `false` 字符串；不去掉首尾空格 |
| 附加公式默认值 | 默认居中偏移为 `(0, 0)`，缩放为 `1`；此前误用了主公式的 `(0, 200)` 和 `0.25` |
| 附加公式 `enabled` | 原版不读取这个成员；导入时不会误把它当成开关 |
| 位置与缩放 | 使用 Java Double 字面量解析后转 Float32；不会把 `1/2` 当成本地表达式执行 |
| 保存与重新打开 | 保留已解析配置和相关数字原文，包括关闭的主公式中未执行的超范围数值 |

以上规则只作用于原版文件导入。导入后主动编辑主公式文字、显隐和位置，以及已有本地布局的作品，仍按保存的作者设置执行。

公式内容在场景创建时确定；参数动画改变几何，不会把公式重新解释成当前参数值。录制、停止后继续和暂停截图共用同一份初始公式内容，各输出帧再绑定实际主画布高度。

- **公式文字、顺序、位置、缩放及颜色**逐帧与原版配置记录一致；同一轮也检查了相机、时间、队列和参数。
- **实际 App 录制**生成 4 fps、10 个编码帧的视频。逐帧检查含公式 PNG 上传内容和视频交付；没有把本地编码结果宣称为原版 MP4 字节相同。

原版参考使用 MathArt 1.7.8、CPU 24³ 网格、384×288 画布，截取品牌叠加前、包含公式的作品区域。原版 JAR SHA-256 为 `a6e1da3acfc05c347d2529c1d590657e2dd798e16d38c55df3dc61312be24018`。离屏探针明确初始化主画布 RGB/255 默认颜色状态；所有成功参考均确认窗口对象数为 0、授权检查通过、退出后进程已回收，许可证与设置文件摘要未改变。

实际 App 验收使用 12³ 网格、真实 Worker、原生绘图与字形服务、FFmpeg。PNG 交付检查使用共享合成编码器，原版独立像素依据来自另一组离屏对照。原版主窗口整图、原版增强后的最终 PNG 和默认 WebGL 全套 UI 不在本次通过范围。
