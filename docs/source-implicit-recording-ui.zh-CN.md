# 隐式曲面录制界面验收（2026-10-24）

**2.0 预览已接通隐式曲面的录制入口。** 对已导入并完成预览的原版 CPU 隐式曲面网格，可以点击顶部「录制」，按动画队列完成条件生成视频；停止保存后从录制状态继续播放。原有「导出作品 → 动画视频 → 按时长导出」继续可用。

本轮改动在预览源码和 `dist-v2` 构建中，尚未替换已安装的 1.0 应用，也未宣告 2.0 发行完成。

## 使用方式

1. 打开支持的 CPU 隐式曲面场景，等待预览完成。
2. 点击「录制」，设置尺寸、帧率和视频质量，然后「开始录制」。首个推进帧用于预热，不写入视频。
3. 可以等队列结束，也可以「停止并保存」。保存完成后会下载视频，预览从停止位置继续播放。
4. 「取消导出」丢弃当前编码任务；关闭窗口后重新点「录制」可以重试。空队列显示「没有可保存帧」，不会制造空视频。

「导出作品」的视频页新增「按动画队列录制」选择；默认仍为原有按时长导出。录制使用同一个帧率推进动画和编码，文档中的离线预览 FPS 不会被改写。

## 已通过的实际操作

验证使用真实 App 页面、浏览器 Worker、原生绘图后端、编码服务和 FFmpeg，没有用界面替身代替这些链路。

| 场景 | 实际结果 |
| --- | --- |
| 自然结束 | 5 次推进，首帧预热，保存 4 帧、1 秒的视频 |
| 提前停止 | 在首个编码帧上传期间点击停止，保存 1 帧、0.25 秒的视频 |
| 取消后重试 | 取消不下载视频，编码任务删除；重试保存 20 帧、5 秒的视频 |
| 空队列 | 一次预热，零编码任务、零下载，显示无可保存帧 |
| 导出入口 | 选择按队列录制，同样保存 4 帧、1 秒的视频 |
| 保存恢复 | 注入上传响应丢失、完成响应丢失和一次查询失败；重试仍使用原任务，最终保存 4 帧，未提前释放数值会话 |

所有视频为 128×96、4 FPS，离屏输入为 384×288。自然结束、提前停止、导出入口和保存恢复的 PNG 均与原生绘图像素逐通道一致；最终 MP4 的每个解码 RGB 通道也与独立原始 RGBA 输入编码的参考视频一致。这里验证的是内容、顺序和缩放的交付，不是原版 MP4 文件的字节等同。

六组操作都验证了：停止不会额外推进一帧，继续播放沿用同一个会话，暂停后改变窗口大小不改变相机与动画时间，恢复后继续更新。编辑场景或返回起点会结束延续状态，重新计算预览。文档 FPS 始终保持 30。录制期间不会因为显示时间更新而插入一般预览重放。

为让 UI 验收保持快速且画面非空，本轮使用 12³ 网格。此前原版完整网格的数值和整图对照见[录制时钟](source-implicit-recording-clock.zh-CN.md)及[停止后连续播放](source-implicit-recording-continuation.zh-CN.md)。本轮没有运行原版 GUI，不把本地界面操作扩展为原版窗口整图一致性结论。

原有按时长导出另跑了三组真实 App 回归：无公式、原版布局公式、本地布局公式，均为 160×120、4 帧、1 秒，PNG 合成与 FFmpeg 解码通过，并完成取消与重试。

## 实现与验证记录

App 使用与作者文档对象绑定的隐式延续上下文，只在录制停止后启用它。普通隐式预览仍保留已有行为。播放、暂停、RAF 和生成请求采用同一个会话；编辑、时间跳转、替换文档和错误恢复明确结束它。时间线在延续状态下显示连续运行及相应说明。

录制复用 `ExportDialog`、`GenerationQueue` 和已有编码交付流程。独立观察的实际帧率仍传给源相机，预热与完成状态由 Worker 提供。隐式视频公式合成明确输出不透明 alpha。

实际运行记录在 `.cache/source-implicit-recording-ui-20261024/`：

- `verified/report.json`：六组 UI 操作、实际 Worker 请求、视频对照、性能采样和源码摘要。
- `verified/recording-dialog.png`、`verified/recording-saved.png`：录制窗口与保存后的截图。
- `verified/*.mp4`：实际视频；其中 `*-raw-reference.mp4` 是独立编码对照。
- `duration-regression/report.json`：三组按时长导出及取消重试。
- `tests-first.log`：5 个文件、77 项相关测试通过。
- `locales.log`：2 项翻译内容与占位符检查通过；另外 6 项未在本次定向运行中执行。
- `build.log`：`build:v2` 通过，包含 TypeScript 检查；仍有已有大 bundle 提示。

初次 UI 验收在编辑成功后仍试图向已改变名称的输入框发送 Enter，导致测试超时；删除多余操作后继续。第二次取样拦截了主预览网络并通过 `route.fetch` 代发，改变了取消请求的行为，触发一次 429 且测试回调未捕获异常。后续主预览走实际网络，不再代理其取消生命周期；仅对独立的录制像素取样，六组流程连续通过两次。终端检查未发现那次退出留下的浏览器或原生绘图进程。没有将失败运行计为通过，也没有因此改变产品的并发限制。

| 最终运行 | 墙钟 | 采样进程族 CPU | 峰值 RSS |
| --- | ---: | ---: | ---: |
| 六组录制 UI 验收 | 31.096 秒 | 72.640 秒 | 2531 MiB |
| 三组按时长导出回归 | 33.407 秒 | 59.030 秒 | 2778 MiB |

两项运行期间源码摘要稳定，无采样及清理错误，服务遗留进程均为 0。浏览器全程 headless，没有移动或聚焦用户窗口。CPU/RSS 是采样值，可能漏掉短命进程，且没有覆盖全部启动与清理；部分检查同时进行了构建，没有控制冷暖缓存，不作性能提升比较。GPU 与 agent token 成本未单独测量。

复验时需使用现有原生后端与 FFmpeg，并提供尚不存在的输出目录：

```sh
MATHART_SOURCE_RENDERER_BACKEND="$PWD/.cache/source-native-capture-20261023/backend.json" \
node scripts/verify-source-implicit-recording-ui.mjs \
  .cache/source-implicit-recording-ui-20261024/recheck
```
