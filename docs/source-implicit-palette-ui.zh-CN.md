# Implicit 调色界面与录制验收（2026-10-24）

基线为 `dae31571bfbed70be7dffec51c540e202b320225`。本批把源 Implicit CPU 网格的手动色板、Cosine、Curve 生成器接到上一批完成的冷配置／热色板运行控制。整体仍处于 M3；不是 2.0 发行完成，也不代表已安装的 1.0 应用更新。

## 使用行为

| 操作 | 结果 |
| --- | --- |
| 选择 Cosine 或 Curve、修改生成参数 | 生成离散颜色列表，作为热改色提交；当前时间与已应用的完整配置保留 |
| 返回 Manual | 恢复切换前的原始色板，保留已编辑的生成参数 |
| 应用为手动颜色 | 保留生成的颜色，结束生成模式并丢弃旧 Manual 快照 |
| 修改普通设置、参数或时间线 | 保留为草稿；画面仍使用已应用配置 |
| 应用场景／方程、应用初始相机 | 完整应用并回到起点；相同值也算一次明确操作 |
| 返回起点 | 恢复最后完整应用的冷配置，不把未应用的草稿带入 |
| 开始录制 | 从冷配置重置；停止后仍保留编辑器草稿 |
| 保存当前项目 | 保存原始颜色；当前打开项目的生成参数继续保留 |
| 关闭后重新打开保存文件 | 回到 Manual，生成参数恢复默认；不从导入来源记录重新激活旧参数 |

导入原版项目时，先读取原版生成参数，再按 Implicit 的原版分支清除生成模式开关；这与重新打开本地保存文件的边界不同。原版项目缺省七色，直接运行配置缺省六色，分别保留。

原始 ARGB、无效颜色文本、空列表、单色与长列表尾项由独立作者字段保存。冷 Apply 保留 ARGB；热改色按原版热解析器变为不透明。颜色选择器只把编辑项改为六位 RGB；其它项不变。首次打开外观面板会补齐空／单色色板，但不提交热修改，也不新增撤销记录。切换选项卡不会重复初始化。列表保真和当前打开项目的参数寿命是明确的本地编辑策略，不声称复刻原版全部控件副作用。

## 状态和失败

运行状态由独立会话与命令回执拥有，作者对象改变不会自动丢弃录制后的继续播放。Undo/Redo 和作品库切换保存冷配置与后续热命令；需要重建运行时会使用新会话。暂存编辑会重新请求持有配置的画面，以确认它与新作者文档的关联，但不会发出 Apply，也不意味着零 CPU 工作。

无效 Apply 保留上一幅完成图像和作者输入；修复后必须明确 Apply。取消或丢失 Worker 同样要求明确恢复，不能用旧回执猜测后台状态。命令／历史有累计表示容量准入，不把表示预算称为进程内存上限。

录制前的独立 PNG／按时长导出从运行检查点重建有效配置，避免把未应用草稿或原始 ARGB 错当当前热色板；它不是持有帧截图。录制后暂停 PNG 继续使用当前帧截图接口。

## 验证

最终相关回归为 29 个文件、572 项通过（主回归 571 项，最后新增截图回归并复跑相关 43 项，不重复计数）。TypeScript 与 2.0 构建通过；构建保留已有 chunk 大小提示。检查覆盖实际 Worker 协议、导入／保存边界、生成器、撤销计划、录制与暂停截图的生产链；单元测试中的绘图替身不作为 GPU 像素证据。

独立无头 Chrome 实际经过公开 App、真实 Worker、原生绘图服务和现有 FFmpeg，**320 项检查全部通过**：

- Manual／Cosine／Curve、数量与系数、曲线节点、回到 Manual、应用为手动颜色、同值热改色、完整 Apply 和重播。
- 首次打开 Appearance 前后的 Undo／Redo、切换面板不重复提交、暂存缩放和时间线不提前影响画面、非零固定时间拖动。
- 原始 32 色（含 ARGB 与尾项）、空列表和单色；项目导入保留原参数但关闭生成模式，保存期间保留编辑参数，重开回到 Manual 和默认参数。
- 无效方程通过公开 Apply 真正抵达 Worker 后保留旧图；修复后重新建立有效会话。
- 冷 A 与完整应用 B 两次录制共 **6 个原生帧（含 2 个 warmup）**，完整网格、法向、颜色、切片数组及 384×288 RGBA 与无控制协议的指定冷配置参考逐字节一致。
- 实际上传的 **4 张编码输入 PNG** 与原生帧按视频不透明 alpha 规则处理后的 RGBA 一致；两个实际 MP4 为 128×96、4 fps，分别 1 帧和 3 帧。解码后的每个 RGB 通道均与另外一次原始帧输入 FFmpeg 编码一致。这不表示有损视频等于未压缩输入；静态 wait 场景也不能证明复杂动态帧序。
- 两张 **256×192 暂停 PNG** 均来自录制停止后的实际继续播放／暂停帧。增强 Worker 收到的完整 RGBA 与原生截图一致，下载文件与该 Worker 完成的 PNG Blob 一致；没有把增强后图像误比为增强前像素。

578 个源码、脚本和原生二进制等依赖的前后摘要一致；浏览器未处理错误为 0。页面上下文、Chrome、Vite 和导出服务全部关闭，剩余 Worker 与服务子进程均为 0。过程中的截图、PNG、MP4 和详细可读结果见[实际 App 记录](../.cache/implicit-gradient-app-20261024-run-6/ACCEPTANCE.zh-CN.md)，便于复查的固定摘要见[证据索引](../tests/fixtures/source-implicit-controls/app-20261024.json)。

本次成功运行总耗时 **28.599 秒**；在 Vite／服务／浏览器准备完成后采样的流程耗时 **27.750 秒**，进程族 CPU **48.470 秒**，采样峰值 RSS **2,539,376 KiB（约 2.42 GiB）**。包括被动观察器、Chrome、Vite、原生服务与 FFmpeg；不是产品单进程内存。原生程序编译独立于该测量，编译耗时未测；文件和模块缓存已热；没有做等价改动前后的冷／热统计对比。Agent tokens、GPU 时间／显存、遗漏的短进程与瞬时峰值未测，不据此声称加速。

本轮关闭了两类集成缺陷：首次 Appearance 初始化原先进入用户历史，Undo 后会重复初始化并清空 Redo；改为不记历史的系统 metadata 更新。另一处是录制／截图把本地编辑器参数纳入运行身份比较，恢复编辑状态后可能误拒绝合法截图；输入、嵌套 Apply、录制交接和截图比较现在使用同一运行投影。新增真实 Worker 回归先复现“几何截图响应状态不匹配”，修复后保留正确能力与绘图失败恢复边界。

初次实际验收选中了旧原生绘图二进制，明确返回 Unknown frame version；随后用当前已固定源码和现有编译器在缓存目录构建匹配版本。后续脚本还校正了首帧时间、时间线面板展开造成的尺寸变化、录制自动续播与参考重绘的顺序，以及将原生帧请求误计为视频 PNG 上传的问题。早期失败报告全部保留，不将这些尝试计为完整通过。
