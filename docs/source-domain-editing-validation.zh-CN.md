# 域着色：保留动画状态的编辑操作

域着色的暂停平移、滚轮和通用参数数值修改已经贯通数值宿主、实时会话、Worker、Generator 和生成队列。CPU 与 WebGL 的实际后台绘制已验证。**主界面仍未切换到这条实时路径**；当前帧导出、录制和主界面接线继续推进，原版整窗一致性仍为 **0/11**。

## 修正的行为

暂停平移和滚轮直接修改当前对象，再绘制一次快照。队列位置、场景时间和更新序号保持不变。导航使用已完成主预览保留的逻辑尺寸，不从低质量预览的像素数倒推尺寸，也不接受手势事件伪造画布尺寸。

通用参数数值修改是一条独立操作：先写当前配置的参数图，再在同一对象上重新应用配置。它恢复配置中的中心／缩放、停止参数动画，同时保留队列、旋转、渐变、其他已经动画过的自定义参数和构建时的公式标注。修改本身不推进时间，也不自动绘制；随后拖动、重绘或恢复播放才产生新图像。

补上了上一轮数值接口尚未覆盖的常量刷新：原版 `applyConfig` 从当前参数 `a/b` 捕获 Float32 常量基值；普通参数动画不刷新它。现在手动修改参数会重捕获这对值，再交给现有公式解析拥有者处理文字常量覆盖。不会把公式推导后的结果反写成基础常量，也不会在每一帧重新捕获。

完整 Apply 仍使用作者明确提交的完整配置。手动参数修改和导航不会替换完整 Apply／录制重建的初始配置，未应用的公式草稿也不会混入当前绘制。

## 操作归属与验证

导航和参数操作必须提供当前已完成图像的有效身份。返回新导航画面后，旧画面不能继续控制会话；错误响应、被替换的更新序号或不确定的后台失败会使旧身份失效。

队列共用一套有序导航调度，保留逐次输入顺序和既有积压上限。参数操作只消费值编辑器明确提交的写入事件，不根据整个草稿的差异猜测热修改。批次在执行前验证全部输入，并共享一次宿主工作预算，不能通过拆成多个写入绕过预算。

真实浏览器验证使用生产 Worker 和 CPU／WebGL 渲染器，覆盖：

- 暂停平移／滚轮不推进数值队列；
- 修改 `a` 后实际像素改变，常量从旧基值刷新为新 Float32 基值；
- 参数修改恢复配置视口，但保留公式标注，不应用无效的公式草稿；
- 完整 Apply 恢复原提交配置，过期图像和损坏的参数批次被拒绝；
- 队列按顺序完成平移、滚轮，暂停参数提交不偷偷重绘；
- 现有实时播放、暂停、配置合并、失败恢复继续通过。

记录脚本为 `scripts/verify-source-domain-live.mjs`。一次开发验证过早在输出回调之后、队列完成通知之前发送手势，被正确拒绝；验证脚本已改为等待实际空闲通知，再检查可操作状态。未放宽产品的完成条件。

## 当前 PNG 的下一步

后续进展：[Retina 渲染修正及验收](source-domain-density-validation.zh-CN.md) 已完成下述逻辑／物理尺寸分离；当前状态 PNG 仍待接入。

固定 JAR 的共享保存路径已确认：当前数值实例绘制基础画布，叠加捕获的公式，再对整个图像增强、按 1／3／5 倍放大并编码。它不重建动画队列。Retina 密度与逻辑尺寸必须分开，例如请求 161×121、密度 2 时，原版基础画布是逻辑 81×61、实际 162×122。

Domain 的 CPU 路径先在逻辑尺寸生成 RGB 图像，再放到物理像素画布。现有本地路径直接按输出像素采样，这一差异必须修正后才能接入当前状态 PNG；不能通过强制密度 1 回避。GPU 的逻辑分辨率与物理 viewport／readback 也需分别归属。最终还需验证公式合成和回到主画布的行为。

原版证据为固定 MathArt 1.7.8 的字节码、调用关系和着色器，JAR SHA-256 为 `a6e1da3acfc05c347d2529c1d590657e2dd798e16d38c55df3dc61312be24018`。本轮没有新增原版 GUI／GL 像素对照，没有移动桌面窗口或替换已安装的 1.0 应用。
