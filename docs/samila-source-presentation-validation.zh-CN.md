# Samila 最终呈现验证

本轮处理 2.0 的 Samila 旋转取样、调色与最终合成。新导入文档保存独立 `samila-present-1.7.8` 呈现版本；已有本地作品，包括已有 `samila-splat-1.7.8` 作品，打开或保存时不会自动迁移。1.0 Apple Silicon 应用未重新打包或替换。

## 为什么之前颜色会不同

原版先计算颜色与透明度，再把结果画入已清空的目标。目标保存的 RGB 约为 `颜色 × alpha`，保存的 alpha 却是 `alpha²`。这不是通常的透明图层表示。正常窗口随后直接复制 RGB；本地之前又按透明度混合了一次，并采用不同的背景规则。

在普通有限输入下，源 RGBA8 目标先钳位 shader 颜色，再混合和量化；不能先乘 alpha 再钳位，也不能把 shader 颜色先量化为 8 位。独立原 shader 用例验证了这个差别。

## 实现与终点范围

| 边界 | 本轮行为 | 仍需区分 |
|---|---|---|
| 新导入 | 独立呈现版本与源绘制配对 | 旧作品原样保留；开发接口 `samilaPresentation:'legacy-v1'` 保留旧导入呈现 |
| 旋转 | 源浮点角差，不先取模；GPU 直接执行旋转与最近邻取样 | CPU 派生计算不能等同不同 GPU 的三角函数精度 |
| 调色 | 源 density、literal pow、形状参数下限及颜色分支 | 超出有限结果的输入明确报告，不能以本地稳定公式偷偷替代 |
| 正常预览 | 已合成目标 RGB 复制到不透明显示 | 原版 MSAA、系统窗口、显示器色彩管理仍需实机整窗验证 |
| 无公式 PNG | 直接编码目标完整 RGBA，保留透明像素中的 RGB | 本轮没有原版暂停保存的边缘抗锯齿、锐化、热实例或放大流程 |
| 视频传输 | 保留目标 RGB，显式设置 A=255 后编码中间 PNG | 本地 MP4 使用 yuv420p；源录制为带颜色标签的 yuv444p，不能声称原版视频一致 |
| 公式与 JPEG | 从不透明本地显示结果合成或编码 | 不属于原版目标 RGBA 原样保存 |

源的“录制预览”还有额外背景混合，与正常窗口及已经提交给编码器的帧不同。本轮选择普通窗口显示路径，不把三个终点混为一谈。导出仍是本地独立重放，不是捕获原版热实例。

## 证据与验证

固定应用 JAR SHA-256：`a6e1da3acfc05c347d2529c1d590657e2dd798e16d38c55df3dc61312be24018`。

固定 Processing core JAR SHA-256：`89410e2c4f59cb4b4aeb2a3baeaf6a4bc189d6e1c612920c3f8e0f58b62a769a`。

静态终点审计在本地 `.cache/v2-samila-present-audit.md`；manifest 绑定 15 份类／shader 提取结果。独立参照直接运行原包 vertex／fragment shader，只调整 GLSL 版本与精度声明，并采用源四顶点 TRIANGLE_STRIP。人工浮点累积输入与生产共享，不调用生产调色函数生成期望值。原 shader 输出、clear+blend 目标和额外合成分别记录。

第一轮小尺寸 GPU 对照曾有 106/106 组逐字节相同，但扩展到 513×517、旋转 .31 后发现两个像素取错相邻 texel。将原 shader 自己按相同虚拟视口分块也复现同样差异，定位到 viewport offset 改变插值舍入。不能把分块的原 shader 改成“正确参照”来消除失败；生产改为完整目标绘制，再分块读取与归约，并按实际目标计入资源预算。审计还确认原版是四顶点 TRIANGLE_STRIP，完整目标参照采用相同绘制几何。

第一次公开流程失败来自验证脚本在页面 reload 后没有重新安装呈现观察 hook，导致等待超时；页面及 Worker 没有错误。修复 hook 后，DPR 1／2 操作链通过。检查同时发现密度面板仍显示不再生效的透明背景控件，已按新版本隐藏，旧作品继续保留。

CPU 派生路径有 **16/122** 个差异或拒绝案例：4 个极端幂运算拒绝、8 个大角度三角函数差异、4 个宽图旋转最近邻取样差异。它们不计入一致性通过，也没有通过替换参照来掩盖。视频解码后 RGB 平均绝对误差为 1.547–1.620，最大单通道误差 11–15；这是本地有损编码测量，不是原版视频对照。

最终报告为 `.cache/source-samila-present-release/report.json` 与 `.cache/samila-source-present-public-final/report.json`；两份报告覆盖同一批 395 个生产源文件，运行前后哈希稳定，并与验收时文件一致。测试及构建日志分别在 `.cache/samila-present-tests-final.log`、`.cache/samila-present-build-final.log`。

完整目标新增 `20 × 宽 × 高` 字节：RGBA8 颜色占 4 字节／像素，RGBA32UI 检查事实占 16 字节／像素；还需已有缓冲和 4 字节／像素输出。768 MiB 工作预算在分配前检查，并检查设备纹理与 viewport 上限。尺寸变化先释放旧目标，旧模式不保留该目标。视频透明度修改复用逐行编码缓冲，不再复制整幅图像。这些是显式资源估算，不是操作系统进程内存测量。

独立 shader 对照耗时 10.62 秒，公开界面流程 30.56 秒，全套测试 46.99 秒，Vite 构建阶段 17.35 秒。部分验证并行执行；这些只是本次耗时，不用于性能提升或实时帧率声明。未测 CPU 时间、进程族峰值内存、GPU 驱动内存及任务 token 成本，也未完成同条件冷／热性能基准。

原版 JVM／JOGL 整窗一致性仍为 **0/11**。本轮窗口检查返回锁定，未获得原版截图。Chrome shader 与生产代码的相符，不能代替原版随机流、实时线程、热调整尺寸或完整窗口的对照。

## 复跑

在 `studio` 使用已有固定工具链、Chrome、FFmpeg 与本地固定原包：

```sh
node scripts/verify-source-samila-present.mjs .cache/source-samila-present-release
node scripts/verify-samila-source-math-public.mjs .cache/samila-source-present-public-final --splat
npm test
npm run build
```

所有浏览器验证使用无界面 Chrome，不操作用户前台窗口。完整输出保留在本地 `.cache/`，不提交图像、视频或二进制到 Git。
