# Symmetry 色板与 GPU 采样验证

2026-10-21。**已修复 Symmetry 项目默认色板、1024 格色表和 GPU 采样方式。170 组局部绘制对照通过；原版完整窗口验收仍为 0/11。** 本轮没有操作原生窗口，已有 1.0 Apple Silicon 应用未替换。

## 可见变化与原因

原版 Symmetry 项目的默认色板是七色：珊瑚红、橙、黄、深绿、浅绿、深蓝、紫。之前遗漏 palette 时会落入本地默认色板，现在使用原版 ProjectState 的实际输出。原版项目里的通用 `color` 字段不会进入 Symmetry 的渲染配置，因此不再把它误当作运行时余弦配色；原字段仍完整保留在来源记录中。

静态 RGB 与余弦色板现在由共享 PaletteRuntime 算法生成 1024 个 RGB Float32 样本，再使用 RGB32F、LINEAR、水平 REPEAT 纹理采样。偏移在生成色表时应用一次，不再在采样时重复应用；也不套用 Samila 的末端平滑。ROBUST 步长归一化改为原版浮点运算顺序。

用户已有的周期、HSV、非均匀色标位置及其他本地模式继续使用本地采样。输出记录明确区分 `source-rgb1024` 和 `local-rgba4097`。省略余弦系数的本地文档仍使用编辑器显示的本地默认系数；原版运行时默认系数在验证输入中显式指定，避免保存文件与编辑器含义不一致。

通用颜色字符串解析只保留一个实现，各场景提供各自默认值。GPU 由同一个纹理所有者切换两种格式；色板内容不变时复用已上传纹理，内容变化时更新，切回本地模式时恢复对应尺寸和过滤方式。

已查看本轮 Symmetry 预览截图。原版色表来自其随附 JVM；原版四个着色器来自固定 SHA-256 的 1.7.8 JAR，仅适配 GLSL 版本与精度声明后在 WebGL 中运行。参考与生产使用不同上下文，比较时只适配通道顺序和上下行方向。测试明确拒绝非有限样本。

## 仍然没有宣称完成的部分

这是原版算法与着色器的局部对照，不是原版 JOGL 窗口截图验收。后续已接通[源最终调色与物理画布归一化](source-symmetry-presentation-validation.zh-CN.md)，但梯度动画、完整混沌轨迹、实时帧节奏及原生完整合成仍需继续对齐，不能因色表一致就宣称整图一致。

本地导入要求项目名称，色表验证补充了不参与配色的名称；原版运行输入与补充后的本地输入分别保留。没有声称覆盖所有畸形 palette 字段或跨设备 GPU 行为。

## 复核与成本

原版输入、完整色表及 JAR/JVM/harness 摘要位于 `tests/fixtures/symmetry/palette-runtime.json`。可运行：

```sh
python3 scripts/verify-source-symmetry-palette.py <原版MathArt.app> <已有JNI头文件目录> <新输出目录>
node scripts/verify-source-symmetry-splat.mjs <新输出目录> <原版JAR路径>
node scripts/verify-captured-density-public.mjs <新输出目录>
```

原版执行脚本使用应用随附 JVM，不安装 Java、不启动应用窗口、不改应用状态。独立复跑 11 组约 1.17 秒。原包、运行二进制和截图只留在忽略目录 `.cache/source-symmetry-palette/`。

公开 App 流程脚本约 11.31 秒；外层进程族采样墙钟 11.93 秒、CPU 25.00 秒、峰值 RSS 约 2.16 GiB。上一轮同类流程约 11.49 秒、12.22 秒、24.87 秒和 2.16 GiB；两次不是受控冷/热配对，不据此宣称提速。

GPU 检查用新浏览器进程与上下文启动，脚本约 2.25 秒，外层 2.69 秒、CPU 6.49 秒、峰值 RSS 约 1.43 GiB；在同一所有者内执行的不变色板热帧约 2.2/2.1 毫秒，均未重复上传色板。指标与逐组 step 时间保存在 `gpu-isolated.metrics.json`、`gpu-verified/report.json`，不是操作系统冷缓存测量，也不是修改前后受控性能比较。250 ms 进程族采样可能漏掉峰值和短进程，共享页可能重复计数；token、GPU 内存及驱动缓存成本未测量。
