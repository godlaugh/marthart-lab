# MathArt Lab

本地数学艺术工作室，依据 MathArt Studio 的公开说明与用户提供的安装包静态证据独立实现。代码和工作区保存在本机，计算不需要云服务。

1.0 聚焦一个完整的螺旋图创作场景，以及作品管理、编辑、撤销重做、保存重开、动画、图片与视频导出。发行范围为现有 Apple Silicon 本地应用。其它尚未完成的创作场景及 Windows、Linux、Intel Mac 等平台发行延期至 2.0；已有其它类型作品和源码继续保留。当前验收结论见 [1.0 中文验收报告](docs/release-1.0-validation.zh-CN.md)。

## 启动

在 MathArt Lab 仓库根目录操作。使用 `.nvmrc` 固定的 Node.js 24.18.0，以及 `package.json#packageManager` 固定的 npm 11.16.0。已有 nvm 时可先运行 `nvm use`；项目不会安装或升级系统工具链。

首次获取源码后安装锁定依赖，再启动开发环境：

```sh
npm ci
npm run dev
```

浏览器访问 <http://127.0.0.1:5177>。需要视频编码或持久保存导出文件时，在另一个终端运行：

```sh
npm run server
```

导出服务仅监听 `127.0.0.1:5178`。它使用本机已有的 FFmpeg；不会安装系统软件。仅在需要重新安装项目依赖时运行 `npm ci`。

## 桌面应用

```sh

```

Apple Silicon 构建输出为 `dist-desktop/MathArt Lab-darwin-arm64/MathArt Lab.app`。桌面版自动启动和关闭本机服务，将工作区、备份和导出缓存在 `~/Library/Application Support/MathArt Lab/`。

## 创作与保存

- 1.0 新建与模板入口聚焦螺旋图，支持转子链、多图层及已有螺旋图示例。旧版本保存的其它类型项目仍可打开、保存和备份。
- 选中旋轮场景后先显示时间线结束时的效果；此时播放或录制会从头开始。手动拖动时间线后按所选位置播放，暂停后继续播放则接着当前位置。预览状态不写入作品文件。
- 编辑半径、转速、图层、配色、背景与项目尺寸；撤销和重做可恢复编辑前后的作品。
- 内置示例使用本地草稿。保存或收藏时生成独立作品；导出项目 JSON 可迁移到其他浏览器或桌面工作区。
- 我的作品支持嵌套文件夹、移动、复制、重命名、排序和可恢复的回收站；草稿列表可找回未保存的场景编辑。
- 可导入支持的 MathArt Studio JSON。保留原始内容和来源说明；未映射字段会明确列出，不会伪装成已应用。 项目文件最多 8 MiB 字符；保存默认保留缩进，只有缩进导致超限时改用紧凑 JSON。原始来源与数值记录完整保留，紧凑格式仍超限时明确报错。
- 时间线支持动作组合、参数动画与渐变。播放、暂停、跳转、反向查看与导出使用相同的确定性计算入口。
- 图片支持 PNG/JPEG；逐帧动画支持 MP4/WebM/GIF、自定义尺寸和 1–120 FPS。实时录制使用浏览器编码器，保留当前画布与公式标注；实际更新率取决于场景计算速度。

预览质量控制数学采样和画布像素；高质量使用导出级采样。计算中的像素、历史、迭代或内存预算会显示说明。高帧率视频导出通过逐帧编码完成，不代表同一场景能实时达到该帧率。

MathArt Lab 使用独立 Git 仓库，仓库根目录就是本 README 所在目录；外层 REA 仓库仍保持独立。开发与提交方法见 [Git 管理说明](docs/git-workflow.zh-CN.md)。

以下历史研究说明中的 `coverage/` 和 `.cache/` 链接指向原研究工作区的本地证据，新克隆不会包含这些文件。部分专项验证脚本，尤其 `scripts/check-coverage.mjs`，依赖原安装包分析、父目录证据或历史运行产物；它们不是新克隆默认检查的一部分。普通构建和源码测试使用仓库内的源码及 fixtures。

源视口默认中心 `(0,0)`、缩放 `2.5`，垂直半跨度为 `1 / max(1e-9, scale)`。虚轴向下，正角度使固定图案逆时针旋转。CPU 视口保留原版单精度归一坐标与双精度中心运算，GPU 视口使用单精度坐标规则；选择计算后端不会切换这套规则。源 CPU 视口暂用 CPU 采样。切换视口规则保留原始中心、缩放和角度，因此可能改变画面范围和纵轴方向；切回后恢复原有含义。缺少视口版本的已保存项目保持旧规则，包括之前导入的项目，不根据颜色版本或来源标记自动迁移。

源 GPU 视口按安装包中的四边形三角化顺序插值 UV，保持全图视口并裁剪每次绘制的区域。数值敏感像素交给 CPU 求值时，保留该 GPU 程序实际算出的坐标；因此，即使全部像素都需要 CPU 数学修复，坐标来源仍属于 GPU。直接选择 CPU 或 GPU 失败后的整图回退使用分阶段 float32 参考，无法逐位复现设备插值、三角函数和融合运算。两者的像素差异单独记录，不承诺统一的误差上限。源视口的超采样为本地扩展；原版 Processing/桌面驱动的最终像素尚未运行对照。

为保留全图插值，源 GPU 路径需要每像素 8 字节的两个图像附件（4K 约 63.3 MiB），另有最终 RGBA 输出和按块复用的读回、坐标缓冲。附件预算与共享图像输出上限关联，暂存表示上限为 8 MiB；设备容量不足时明确回退。这些是已知表示的分配估算，不是驱动实际显存测量。

逐帧时钟的帧 0 是初始状态，帧 1 开始更新；队列每帧最多推进一个片段，缓动、绘制、全局淡入淡出、旋转和完成判定共享同一回放状态。时间线显示由该状态得出的有效片段起止，保留原始长度供编辑。预览在队列结束后继续绘制，不使用循环或往返播放；若需要绝对时间线或本地额外动画类型，须先明确切回兼容时钟。模拟 FPS 与视频编码 FPS 独立，改变前者保留事件帧号并改变其对应秒数。

Newton/Nova 还可单独选择“MathArt 1.7.8 原版着色”，须同时使用原版数值规则和 WebGL2。内部与外部可分别选择 10 种算法、传递函数、密度、偏移、重复方式和固定颜色；原版色板独立保存，支持手动颜色、RGB/HSV 插值、伽马和余弦参数，生成 1024 色纹理。轨道与颜色在同一 GPU 片段内计算。算法“零索引”仍读取色板；传递函数“固定颜色”才使用区域固定颜色。颜色原文中的 alpha 保留，最终分形像素为不透明。

新导入的原版 Newton/Nova JSON 默认启用数值与着色两组原版规则；已有本地文档不自动迁移。首次手动启用原版着色使用独立默认值，不转换本地色板；切回本地时保留原版配置。需要恢复本地数值规则时，应先切回本地着色。原版着色只适用于 Newton/Nova；切到其他公式时会提示，并保留关闭该规则或恢复兼容公式的入口。

原版着色的偏移动画更新独立色板与区域偏移，运行时使用所选循环插值，停止后保留偏移并恢复普通采样。预览、跳转、重开和 PNG 导出共用本地确定性时间线，不代表原版实时帧时钟。

Magnet I/II 和 Binocular 可选择“收敛退出与残差着色”。收敛点使用外部着色，停止距离和颜色残差分别保留；Magnet I 按源着色器使用零颜色残差。选择此模式会同时启用独立内外着色，可用一次撤销恢复原模式。Magnet 的零收敛阈值关闭收敛，Binocular 的零阈值使用源运行下限。旧本地文档的兼容图像保持不变；原版 JSON 导入采用新模式，Magnet 只消费正式 parameter / perturbation 字段，缺省为零。Magnet I/II 与整数幂 Binocular 可用 WebGL2 双 float 轨道计算，数值不确定像素由 CPU 双精度修复；驱动检查失败、不支持的指数或表示范围会说明原因并回退。Newton/Nova 在本地数值规则下的 step 模式仍使用 CPU。三种公式的 720p／4K 完整任务已测；其中 Magnet II 的 4K 对照有 7 个像素相差一个 8 位色阶，分类和退出迭代相同。深缩与跨设备性能、原版 DS 运算及像素一致性未验证，见 [收敛验证](coverage/fractal-residual.json)和[残差 GPU 验证](coverage/fractal-residual-gpu.json)。

Perlin 纹理通过 512×512 分块生成原生输出，支持 4K 及最多 16,777,216 像素、每像素 1–128 步积分。分块限制中间 GPU 缓冲和取消等待时间；最终图像仍按完整尺寸保存。GPU 能力或精度检查失败时会说明原因并回退 CPU，复杂输出可能耗时更长。

流场会根据当前生效的计算参数识别预设，修改参数后显示“自定义”。“刷新噪声种子”只更换种子，支持撤销；保存种子后可重现同一后端的流场。

内置对称混沌模板的参数具有固定范围滑块，Samila 可编辑每个参数的范围和步长。范围用于滑块、随机参数和新建动画的默认值；直接输入、导入值及已有动画不会被限制或改写。超出范围时保留真实数值并显示提示。

原版 Symmetry JSON 的 `equation.glsl` 可导入并在持续批次 GPU 模式执行。参数按原版的标量 `uniform float name;` 匹配规则传入，缺失或无法表示为 float32 的值传入 0；原始参数值仍完整保存。公式最后一次写出的 `stepMetric` 独立决定步长配色，有限负值有效。`{N}` 与 `{N_MINUS_2}` 使用编译阶数；时间线中的同名参数只更新运行时 uniform。`equation.formula` 仅显示说明，不作为可执行公式。

自定义模式显示全部参数及绑定匹配状态，不套用内置系数的滑块范围、三位小数或删除限制。仍被启用动画引用的参数须先停用或修改动画才能删除。切换模板会保留参数、补齐缺失的内置系数，并停用自定义源码；可撤销恢复。若当前阶数或修正幂次不受内置模板支持，切换会被明确拒绝，源码保持不变。

当前自定义后端支持 GLSL ES 3.00 函数源码；宏、预处理指令、`discard` 和保留的 `rea_` 标识符有明确诊断。原始源码限 65,536 个 UTF-16 代码单元，每次 `calculate_next` 调用共享 4,096 次循环体预算（包括嵌套循环和辅助函数）。CPU、单次采样、GPU 不可用或编译失败会报错，不会改画内置公式。该阶段不宣称完整桌面 GLSL 410 兼容，循环预算也不是驱动编译或着色器墙钟时间保证。


实数公式支持 `arcsin`、`arccos`、`arctan` 别名，CPU 和 GPU 共用函数解析；反正弦和反余弦的越界输入会停止该条无效轨迹。原有同名参数仍可读取，新增参数会避免占用函数名。

同一作品的普通编辑保留当前计算会话的故障状态；“重试 GPU”取消并重建会话，再真实计算。“固定使用 CPU 整链”可保存并在重新加载后继续生效，“恢复所选规则”保留原有作者输入。CPU 回退色板可单独编辑，使用完整原产物色板，未保存时采用六色默认；不会从本地函数色板暗中转换。界面有效常量、视口导航和导出摘要消费实际完成帧的执行事实。预览和导出拥有独立计算会话，因此各自显示实际路径；多帧导出记录每条路径首次和最后出现的帧（最多显示 16 条不同详情），不承诺每帧采用相同路径。原应用、JVM 与原生驱动像素仍未执行对照。
