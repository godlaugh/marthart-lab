# MathArt Lab

本地数学艺术工作室，依据 MathArt Studio 的公开说明与用户提供的安装包静态证据独立实现。代码和工作区保存在本机，计算不需要云服务。

1.0 聚焦一个完整的螺旋图创作场景，以及作品管理、编辑、撤销重做、保存重开、动画、图片与视频导出。发行范围为现有 Apple Silicon 本地应用。其它尚未完成的创作场景及 Windows、Linux、Intel Mac 等平台发行延期至 2.0；已有其它类型作品和源码继续保留。当前验收结论见 [1.0 中文验收报告](docs/release-1.0-validation.zh-CN.md)。

## 启动

在 MathArt Lab 仓库根目录操作。使用 `.nvmrc` 固定的 Node.js 24.18.0，以及 `package.json#packageManager` 固定的 npm 11.16.0。已有 nvm 时可先运行 `nvm use`；项目不会安装或升级系统工具链。

首次获取源码后安装锁定依赖，再启动开发环境：

```sh
npm ci
npm run dev
```

浏览器访问 <http://127.0.0.1:5177>。需要视频编码或持久保存导出文件时，在另一个终端运行：

```sh
npm run server
```

导出服务仅监听 `127.0.0.1:5178`。它使用本机已有的 FFmpeg；不会安装系统软件。仅在需要重新安装项目依赖时运行 `npm ci`。

## 桌面应用

```sh
npm run desktop:dev
npm run desktop:build
```

Apple Silicon 构建输出为 `dist-desktop/MathArt Lab-darwin-arm64/MathArt Lab.app`。桌面版自动启动和关闭本机服务，将工作区、备份和导出缓存在 `~/Library/Application Support/MathArt Lab/`。

1.0 本地交付压缩包为 `dist-desktop/MathArt-Lab-1.0.0-mac-arm64.zip`；解压后双击 `MathArt Lab.app`。当前验收结果及未覆盖项见 [1.0 中文验收报告](docs/release-1.0-validation.zh-CN.md)；[原始机器记录](coverage/release-1.0-validation.json)供排查使用。

工作区设置支持选择输出目录和已有的 FFmpeg 可执行文件。输出目录立即生效；FFmpeg 选择在重启后生效。`MATHART_FFMPEG` 环境变量可显式覆盖该选择。开发浏览器版的下载目录由浏览器管理。

## 创作与保存

- 1.0 新建与模板入口聚焦螺旋图，支持转子链、多图层及已有螺旋图示例。旧版本保存的其它类型项目仍可打开、保存和备份。
- 选中旋轮场景后先显示时间线结束时的效果；此时播放或录制会从头开始。手动拖动时间线后按所选位置播放，暂停后继续播放则接着当前位置。预览状态不写入作品文件。
- 编辑半径、转速、图层、配色、背景与项目尺寸；撤销和重做可恢复编辑前后的作品。
- 内置示例使用本地草稿。保存或收藏时生成独立作品；导出项目 JSON 可迁移到其他浏览器或桌面工作区。
- 我的作品支持嵌套文件夹、移动、复制、重命名、排序和可恢复的回收站；草稿列表可找回未保存的场景编辑。
- 可导入支持的 MathArt Studio JSON。保留原始内容和来源说明；未映射字段会明确列出，不会伪装成已应用。 项目文件最多 8 MiB 字符；保存默认保留缩进，只有缩进导致超限时改用紧凑 JSON。原始来源与数值记录完整保留，紧凑格式仍超限时明确报错。
- 时间线支持动作组合、参数动画与渐变。播放、暂停、跳转、反向查看与导出使用相同的确定性计算入口。
- 图片支持 PNG/JPEG；逐帧动画支持 MP4/WebM/GIF、自定义尺寸和 1–120 FPS。实时录制使用浏览器编码器，保留当前画布与公式标注；实际更新率取决于场景计算速度。

预览质量控制数学采样和画布像素；高质量使用导出级采样。计算中的像素、历史、迭代或内存预算会显示说明。高帧率视频导出通过逐帧编码完成，不代表同一场景能实时达到该帧率。

## 保留实现与 2.0 开发说明

下列跨场景实现与历史验证供后续开发和既有项目读取使用，不构成 1.0 全部场景已验收的声明。

映射、对称混沌和 Samila 的持续批次模式保留粒子与密度历史，暂停不会重复累积；“从当前时间重新累积”会重置历史。计算后端以实际结果显示。GPU 使用 float32，与 CPU 的双精度混沌轨迹可能分离。

Samila 可选“限幅与参数补采”历史模型，旧文档仍使用原有累积。首帧采一批；时间线参数变化后清空历史并补采六批不同样本，直接编辑参数则从一批重新计算。每帧先衰减旧历史，再将旧像素密度限制到 300，最后加入新样本；300 不是帧数上限，新一帧的最终密度可以超过它。关闭新批次记录时仍处理清空与衰减，恢复后不会补做暂停期间的采样。冷启动、连续播放、跳转和导出共用固定采样时钟。

Samila 的归一调色使用已完成批次数、实际点半径和画布尺寸，可选色板均值或 YUV 均值；启用时同时选择新历史模型，切回原有累积会恢复白点调色，双方参数都保留。这里的采样时钟、随机序列、点形及半径换算是独立实现；直接编辑的重放也不同于原版交互热更新。小型 CPU/GPU 历史回归与单帧 4K 调色已验证，长期高批次补采性能、跨设备及原版像素一致性未验证。证据见 [历史合同](coverage/samila-history-v2-contract.json)、[历史回归](coverage/samila-history-v2.json)和[调色回归](coverage/samila-tone-v2.json)。

Samila 持续模式的 CPU 会话复用当前两条公式的编译结果，参数、时间、映射和旋转仍逐帧更新；重置或取消会释放缓存。61 帧、每批 64/4096 样本的改动前后对照具有相同像素和采样统计，完整任务耗时及内存观测见 [CPU 公式缓存回归](coverage/samila-cpu-compile-cache-final.json)。该报告绑定记录时的源码，三次本机重复不代表普遍性能提升；直接编辑参数仍按上述规则重新计算。

Samila 可启用“锚定 theta 相机”，同时切换为持续批次、限幅历史和 XY 投影。时间线支持 theta 数值动画、水平旋转、转至角度、对齐及持续旋转；旋转已有累积图像时不会额外采样。清空历史时重新捕获相机锚点，直接编辑起始角会重放历史。停用会保留参数。暂停时可拖动平移、滚轮缩放：修改临时几何视图，清空并从已呈现的时刻重新采样一批；关闭记录或尚未到设定起点时不采样。临时视图保留完整密度边界，覆盖本地几何动画；“重置临时视图”恢复配置与动画，手势支持撤销。图像导出复用临时视图，项目与工作区保存保留原配置，重新加载恢复原视图。适配仍未实现；已有不支持的相机字段保留并警告。旧本地文档不会自动迁移；原版 JSON 有明确 theta 或支持的 theta 动作时导入新模型。细节与实测范围见 [theta 相机验证](coverage/samila-camera.json)和[临时平移缩放验证](coverage/samila-navigation.json)。

映射和对称混沌的连续模式可启用归一化调色，以完成的批次数和保存的参考画布尺寸计算亮度。白点与归一化模式各自保留参数；切回单批次时使用白点参数。GPU 调色遇到精度敏感像素时会回退到 CPU，并在状态栏说明原因。5 百万粒子、原生 4K 已验证，但默认 gamma 的回退开销仍影响速度。

弹跳粒子的多边形边界支持拖动、键盘微调、逐点坐标编辑和添加或删除顶点。修改先保留为草稿，应用前检查自交、重叠和退化边；不合法的草稿不会覆盖已保存的边界。凹多边形使用 CPU，非零碰撞半径需要凸多边形。

连续吸引子可以选择 CPU 或 GPU。GPU 执行 Euler/RK4 积分并保留最多 200 万粒子的状态；历史拖尾使用 CPU，超过 CPU 预算时会明确报错并保留请求数量。200 万粒子的生成与绘制已验证，帧率取决于公式、积分步数和调色方式。 连续粒子模式的相机可按粒子索引跟踪，停止时保留该时刻的目标位置；死亡或越界索引会显示提示并保留此前有效的相机动作。预览和导出使用对应计算结果携带的相机状态。

隐式曲面支持每轴 4–200 个网格单元，单轴设置为 0 时沿用统一分辨率；会计算完整请求网格，超过内存或求值预算时明确停止。新增 Chmutov 八次曲面和 Klein 指南示例。GPU 格点分类会与 CPU 双精度核对，不一致时整次重放 CPU，因此选择 GPU 不保证加速。均匀网格仍可能遗漏薄于单元的结构或偶重根；极点、跳变和舍入平台也需要检查。环面 40³/80³ 测试中的舍入裂缝已修复，实际 Worker 和渲染验证通过闭合边、顶点邻域与 Euler 特征检查；这不保证任意公式的拓扑，也不代表已完成原版整图对照。

项目尺寸可以跟随视口，或保存为宽高各 64–8192 的固定项目尺寸。原版 JSON 顶层 `resolution.width/height` 按源整数规则读取，只有两维同时有效才启用；无效输入和数字原文仍保留在来源记录。项目尺寸适用于全部场景，画布按该比例居中适配窗口，现有预览质量继续控制计算像素；项目尺寸不是当前宿主画布的物理像素数。更改项目尺寸会从初始状态重新绘制，普通窗口缩放继续调整现有实例。保存和重开保留尺寸选择，旧作品省略该字段时保持原布局。

导出默认采用明确的项目尺寸，仍可单独修改。静态图片使用独立的画布维度和 128 MiB RGBA 表示预算，视频保留编码器的尺寸约束；有效的项目尺寸不会因此被悄悄缩小。浏览器 CSS 居中与实际测量是本地宿主适配，不声称与原 Compose/Swing/JOGL 的 DPI 舍入等价；原全局 anchored 模式的 300 ms 稳定后重建仍待接入。

复根图谱支持固定总量的渐进采样。播放会等待每批求根完成，计算较慢时数学时间相应放慢；导出显示实际已完成的多项式数量并可取消。总采样完成时间是时间轴上的位置，不是预计计算耗时。

复根渐进密度新增显式的 MathArt 1.7.8 度量着色规则：每个像素先累积原始根半径或固定采样参数 `t2` 的实部/虚部，再按平均度量读取 256 色纹理；亮度归一使用所有有限提交点，包括画布外的点。新原版 JSON 导入选择此规则，已有作品和预设保持本地 RGB 累积；单次根图不使用新规则。源色板、亮度、对比度、伽马、动态范围、饱和度和偏移独立保存，切换不会改写原本的丰富色板与通用调色值。源色板缺省用四个默认颜色，显式空色板使用白色，无法解析的颜色字符串原样保留并警告；“拷贝本地手动颜色一次”只复制保存的色标，不采样丰富色板。源模式的旧色板动画、通用调色和透明背景保留但不参与当前颜色。着色版本本身不选择求根器、随机序列、固定步调度、投影或点核；CPU Float64 与 GPU Float32 累积有精度差异，这一着色规则不代表原版求根与完整像素已等同。

复根数学另有独立的 `rootsMath` 配置。省略时保持原本的 MathJS 多项式、Durand–Kerner 与本地采样；`local-v1` 会保留但停用源配置。显式启用 `mathart-1.7.8-v1` 使用源系数表、七个系数函数、独立参数域、求解器设置和精确 64 位种子；首次启用采用源默认系数，不自动改写旧公式。新原版 JSON 导入选择此配置。系数和次数原文、显式最高零项、参数名称及倒序范围均独立保存；有效参数名与范围由源数学入口处理，通用参数和时间不隐式注入系数作用域。旧数学字段的数值或振荡轨道保留时长并显示未执行提示，切回本地模式后恢复；源色调、投影和本地回放设置仍可动画。无系数对象时采用源默认六项，显式空对象产生空根集合，数值系数会按源字符串字段要求拒绝。切换版本可恢复另一组输入，色彩与投影不会随数学切换升级。新导入的未知变量标签以显式 `sourceJson` 保留选中值的 JSON 原文，嵌套溢出数字不会在保存时变成 null；旧 `sourceValue` 标签仍兼容。

复根的“几何与参数 → 复根空间显示”提供显式的空间显示版本。点击“启用 MathArt 空间显示”会启用源数学、源配色和渐进采样；旧作品省略 `rootsPresentation` 时继续使用原本的平面显示。空间显示可选择密度图或三维点云，选择后点击“应用显示方式并重新采样”。面板支持 XYZ 变换、相机角度与中心、缩放、焦距、点尺寸和画面拖影；初始相机保留源默认方向，可直接调整角度后点击“重新开始空间采样”。

空间密度图的相机角度和调色修改保留已有墨迹；缩放、平移、空间变换及画布尺寸变化会清墨，后续新样本继续到达，不自动补画历史点。点云保留原始 XYZ 和到达时的颜色度量，并按当前相机重新绘制最近窗口。保存只保留文档参数，当前工作区内保存不会重启采样；重开作品或点击“重新开始空间采样”会建立新实例。“返回本地平面显示”保留休眠的空间参数。空间相机与变换暂不接入旧平面动画轨道。

新导入的原版复根 JSON 自动启用空间显示：`GPU_3D` 和 `GPU_DENSITY_3D` 为点云，其他模式按源构造规则采用密度。消费 `settings` 中的 `scale_x/y/z`、`offset_x/y/z`、`rotation`、`dot_size` 与 `camera.phi/theta/gamma` 的精确字段名；物体旋转为度，相机角为弧度，零与负缩放有效。数值按源表达式和 float32 规则转换；点径先夹取到源范围，其他非有限空间值明确报错。被消费的数字原文保存在来源记录，保存重载不会重新解释为旧平面缩放。已有本地作品省略空间配置时保持原行为。此入口依据直接运行配置构造规则；原版 UI 项目加载对相机中心、缩放和拖影开关的处理尚未确认，这些额外输入原样保留并列为未应用，不自动启用。`max_splat_points_per_frame` 也不会误作每帧多项式样本数。

新导入或新启用的空间显示使用 `roots-pending-ordinal-v1` 批次队列。`sampling.batch_size` 控制完整样本后的发布阈值，`settings.max_splat_points_per_frame` 控制密度基础绘制预算；积压较多时按源规则自适应增大消费量。原始点按 FIFO 保留，变换和清墨不会丢弃尚未绘制的点，点云不使用密度预算。队列满时保留未发布批次并暂停本地生产，终止标记实际取出后才算工作器结束。默认参考堆取打包配置的 4 GiB 上限，不声称等于运行时实际堆；真实表示仍受独立 768 MiB 本地准入限制。旧作品省略此配置时保留立即消费规则，可在空间显示面板明确升级；调整队列预算会重建本地实例。

带有 `timeline` 数组的新原版复根 JSON 启用完整源场景队列，支持等待、三轴环境旋转、停止旋转、缩放以及渐变启动/停止。同片段相机目标按源构造规则合并；渐变动作保留顺序，“先启动再停止”与“先停止再启动”有不同结果。渐变提供四种模式、四种相位曲线和以度/秒计的速度，停止后保留最终颜色偏移。旧 `roots-camera-sequence-v1` 作品继续只执行相机动作，可在面板显式升级；缺失配置的历史渐变标记需点击“设置渐变配置”，不会隐式套用默认值。片段开关有效，原版不读取动作级开关、绝对起点、重复次数和往返设置；界面用等待片段表示延迟。

相机回放按时间线帧率从第零帧执行固定 `dt` 更新，每帧最多推进一个片段；旋转使用整帧时间，即使动画队列仅消耗较短的剩余时间。密度清墨和点云拖影逐帧推进，每次请求最后只读取一次图像。重复请求同一帧不会继续推进相机或未修改点云的拖影。保存保留初始相机；编辑初始角度、初始缩放或时间线以及向后跳转会重建回放。完整队列按源顺序执行动作及 active/raw 两次渐变更新，图像使用每帧最终偏移；编辑初始颜色偏移也会重建完整队列回放。启用批次队列后，每帧先按本地样本时钟生产到整批发布阻塞，再按 active/raw 更新与显示入口分别排空；同帧不插入额外生产。此确定性顺序不模拟原实时首帧或工作线程竞速。

显式源队列的视频导出可选择“按源完成条件录制”：从新实例重放，真实渲染首帧作为预热，随后逐帧编码。存在动画片段时按队列结束停止，即使采样或渐变仍在运行；空队列等待本地有序采样和绘制提交完成。预热帧就结束的队列会报告零可编码帧，不创建编码会话。模拟帧率与编码帧率分别控制运动步长和视频播放速度。保留字节码显示原工具栏录制会先恢复并重建场景；此导出同样不复制预览历史墨迹。启用批次队列时，规划在 Worker 中执行真实求根及同一计数队列，求得全部数据和终止标记实际排空后的完成帧；有动画时仍优先按动画队列结束，不强制等待点积压清空。取消会停止后续上传；失败的会话清理在当前应用进程内保留重试，下一次导出先重试清理，已经完成的视频文件受到保护。

逐帧相机计算和布局受每次请求 200 万帧与队列折叠工作单位约束，空间显示受 10 亿像素与点访问预算约束；这些是本地同步工作预算，不是原版格式限制。大跨度跳转可能需要分段播放。布局和实际回放共用源时钟，不用总时长相加代替单精度逐帧结果。

空间 PNG 默认保存“当前暂停场景”，保留当前采样与热编辑历史，不推进动画或重新求根。先按基础尺寸绘制并做边缘抗锯齿、亮度锐化，再按 1×、3× 或 5× 输出；放大不改变采样量。PNG 直接编码 RGBA，保留透明像素通道。3×/5×采用明确的 OpenJDK 21 软件双三次插值规则，尚未证明原安装包在本机选择同一运行路径。

启用批次队列时，暂停截图会消费一次已有密度积压，随后主预览再消费一次；这两次绘制不生产新样本，也不推进动画时钟。暂停截图使用独立的离屏目标，随后刷新主预览。密度图共享累积墨迹，因此更换截图尺寸可能在截图和返回预览时清空墨迹；点云共享已有根点，但截图与主预览各自保留拖影。默认基础尺寸采用当前预览像素尺寸，需更换尺寸时可显式修改。容量检查拒绝截图后，可缩小尺寸直接重试；取消导出会放弃 PNG 交付，正在进行的场景绘制会完成并刷新预览。

“从初始状态重放”仍提供独立冷导出，支持 PNG/JPEG。固定采样时钟和样本序号到达顺序仍是本地规则，原版并发线程时序、项目加载 DPI 映射和完整像素一致性尚未验证。

原 JSON 的对象成员文本顺序和数字拼写由一次解析保留；源 HashMap 顺序、次数别名覆盖以及 Java 整数转换由共享模块解释。逻辑工作器使用独立随机流；原机器缺省工作器数依赖处理器数量，导入无法恢复时明确选择本地 1，可在界面修改。本地固定步预览与确定性提交顺序不代表原后台线程实时竞速。部分非字符串变量标签的 Java `toString` 文本仍明确标为未知，原值保留且不影响求根；手动编辑标签会替换该未知元数据。源数学采用顺序 Aberth–Ehrlich 求解与幂代换；达到迭代上限后仍逐根提交有限近似值，诊断不会将它们称为已通过残差验证。源次数不沿用旧模式的 48 次限制，但受明确的工作区和操作预算约束。源求解实现、工作区准入和验证范围由专项证据记录，未执行原应用或 JVM，也不宣称原版完整像素等价。

域着色支持 CPU 和 GPU 求值，精度与多步能力由公式执行规则决定。本地和旧兼容规则的分支切线、极点及精度风险点使用 CPU 修复，多步复数迭代使用 CPU；新增源 GPU 公式规则支持真实 GPU 多步，选择 CPU 时使用分阶段 float32 参考。界面显示实际计算后端，未保证 GPU 对所有公式更快。

域着色可以分别选择颜色规则、公式执行规则、视口坐标规则和计算后端。已有本地项目继续使用原有规则；新导入的原版 JSON 按原版 RuntimeConfig 的默认值与模式选择规则，采用 MathArt 1.7.8 的颜色、公式执行和视口方式。GPU 颜色规则使用最多前 16 色，CPU 颜色规则使用完整色板；空色板、单色、原始颜色顺序和透明度均可保存，绘图消费 RGB。切换颜色规则保留两套色板，并且不会激活原先停用的迭代公式。旧“MathArt 1.7.8”兼容公式规则继续保留，新增 CPU 与 GPU 公式规则分别执行安装包中的解析和算术方式。源 CPU 规则即使关闭多步迭代也会执行一次种子与迭代公式；源 GPU 规则关闭多步迭代时只执行一次主公式，忽略 next。留空 next 则使用 f(z)。原版 CPU 动态色板暂时使用 CPU 着色，界面会显示原因。

源视口默认中心 `(0,0)`、缩放 `2.5`，垂直半跨度为 `1 / max(1e-9, scale)`。虚轴向下，正角度使固定图案逆时针旋转。CPU 视口保留原版单精度归一坐标与双精度中心运算，GPU 视口使用单精度坐标规则；选择计算后端不会切换这套规则。源 CPU 视口暂用 CPU 采样。切换视口规则保留原始中心、缩放和角度，因此可能改变画面范围和纵轴方向；切回后恢复原有含义。缺少视口版本的已保存项目保持旧规则，包括之前导入的项目，不根据颜色版本或来源标记自动迁移。

源 GPU 视口按安装包中的四边形三角化顺序插值 UV，保持全图视口并裁剪每次绘制的区域。数值敏感像素交给 CPU 求值时，保留该 GPU 程序实际算出的坐标；因此，即使全部像素都需要 CPU 数学修复，坐标来源仍属于 GPU。直接选择 CPU 或 GPU 失败后的整图回退使用分阶段 float32 参考，无法逐位复现设备插值、三角函数和融合运算。两者的像素差异单独记录，不承诺统一的误差上限。源视口的超采样为本地扩展；原版 Processing/桌面驱动的最终像素尚未运行对照。

为保留全图插值，源 GPU 路径需要每像素 8 字节的两个图像附件（4K 约 63.3 MiB），另有最终 RGBA 输出和按块复用的读回、坐标缓冲。附件预算与共享图像输出上限关联，暂存表示上限为 8 MiB；设备容量不足时明确回退。这些是已知表示的分配估算，不是驱动实际显存测量。

新导入保留有限的原始缩放值，由视口计算统一应用下限；不再错误地转换为 `2 / scale`。原版运行配置不读取 `viewport.rotation`，该字段保留在来源中并提示，初始角度为 0。原版数值表达式的异常恢复和非有限值不照搬：不支持的表达式、错误类型及非有限值明确报错。源视口的旋转动作从当前转速过渡到目标转速，空参数按目标 0 导入；同片段最后一个启用的旋转动作生效。跳转使用确定性积分，与原版逐帧 float 累加并非逐位等价；本地重叠片段按后开始的动作接管，零时长按瞬时更新处理。

逐帧时钟的帧 0 是初始状态，帧 1 开始更新；队列每帧最多推进一个片段，缓动、绘制、全局淡入淡出、旋转和完成判定共享同一回放状态。时间线显示由该状态得出的有效片段起止，保留原始长度供编辑。预览在队列结束后继续绘制，不使用循环或往返播放；若需要绝对时间线或本地额外动画类型，须先明确切回兼容时钟。模拟 FPS 与视频编码 FPS 独立，改变前者保留事件帧号并改变其对应秒数。

新时钟将清除、重新开始、完成保存为 `spirographFrameEvents`，按钮修改当前已呈现的选中帧，最早在帧 1 更新前执行；同帧只执行最后一个命令，原事件列表继续保存。首次手动启用时，把仍保留的旧时间戳转录到不早于该时间的首帧；已被旧编辑器删除的历史无法恢复。显式空事件列表不会再读取休眠时间戳。切回本地规则会停用逐帧时钟，事件和 FPS 保留但不执行。

逐帧视频可从初始状态或当前已呈现状态的独立检查点开始；首次更新用于预热，不编码，之后按队列终点停止。若队列在预热内结束，会明确提示没有可编码帧。PNG 消费同一个已完成帧，不推进更新。此实现是保留源码算法的离线重放，未运行原应用或 JVM，不声称原实时调度、全部驱动浮点低位、Processing 抗锯齿或原生像素完全等价。

源视口在暂停后按实际显示帧的旋转角处理拖动和指针锚定缩放。尚未呈现的新编辑不会借用旧帧计算手势。如果时间线正在写入中心或缩放，界面会提示先停用对应轨道，避免手势修改被动画立即覆盖；仅旋转动画不影响这些手势。

这些规则依据安装包静态分析与独立数值检查实现。原版着色器的零复数输入涉及未定义的 atan(0,0)；本地明确采用零相位，可能与驱动给出的原版颜色不同。数值检查和本地浏览器运行不代表原版应用或所有设备的像素一致性。

新增公式规则保留原始文字，并独立显示语法恢复提示：主公式语法失败时使用 `z^3 - 1`，next 语法失败时不启用 next；容量限制不会被当成语法错误恢复。解析仅支持源函数名与语法，譬如 `1e3` 不是科学计数法、`sin (z)` 不是函数调用。参数键保留大小写及 Unicode，公式本身按源小写处理；保留符号优先于同名参数，普通缺失绑定为零。当前参数值必须是有限标量，导入数值表达式使用本地解析并对失败明确报错，尚未复现原版参数表达式的全部异常恢复。

新源公式规则在导入时从初始 `a` / `b` 捕获常量基值（默认 `1 + 0i`），之后参数动画不重新捕获。原始主公式文字还可能覆盖有效常量，例如 `z^3-2` 使用 `c = 2 + 0i`；界面显示有效值，原始参数和显式常量控件保持保存。直接编辑常量控件是本地扩展，仍遵守公式文字覆盖。原版运行配置不读取 `iteration.constant`，导入时保留该字段并提示。源 GPU 仅在主公式或启用的 next 引用 `c` 时上传常量；否则新程序读取零，即使选择常量种子也是如此，界面显示这一阶段的有效值。

源 GPU 公式在实际 GPU 上执行其单精度算术；主动选择 CPU 或设备不可用时使用分阶段 float32 参考，参考不保证与设备三角函数、融合运算或像素逐位一致。主公式引用 `w` 等无法生成原产物 GPU 程序的输入会明确使用源 CPU 公式语义回退，包括 CPU 的 next 行为；所选颜色与视口规则仍独立保留，这不同于原版整个显示链切换为 CPU。当前绑定遵循新场景与缺失值为零的确定性合同；原版保留 shader 时删除参数可能残留旧 uniform，其历史依赖尚未通过原版运行核验，本实现不会跨文档继承该值。上述实现使用保留字节码和着色器的静态证据；原版应用和 JVM 均未执行。

二维分形提供显式“距离估计规则”：新作品和原版 JSON 导入采用 `mathart-1.7.8-v1`，旧本地文档省略该字段时保持已有像素与错误行为。源模式保留内外区域的 Distance Estimator 选择和独立幂次；内部距离着色索引为 0；逃逸或收敛点不满足源能力条件时使用源 Smooth 回退，沿用距离算法的打包参数，不读取休眠的 Smooth 控件。切换规则会启用独立内外着色，可能改变外观；兼容选项仅移除新规则标记，不重写其他作者输入。原版 JSON 的 DE 参数对象省略或为空时默认幂次为 2，显式数值经 float32 转换、非有限归零后取最小值 2；原始输入保留在来源记录，各算法的显式空值或非对象参数容器会报错。该实现依据静态包内合同，未运行原版应用或 JVM，不承诺跨驱动或原版像素一致性。

二维分形的渐变动画可选择“内部与外部偏移”，分别控制两个区域，支持余弦和曲线色板。该模式的速度单位为度/秒；已有色板动画仍按原来的色标与速度设置执行。

域着色的渐变偏移也支持启动、停止和重新启动。偏移模式启动完成后进入全速，停止完成后保持最终颜色，包括终点返回零的缓动曲线。跳转和重载通过数值与浏览器回归验证；分形 GPU 在不同上下文间仍可能有一个 8 位色阶的差异。

Newton/Nova 在本地数值规则下的“迭代步长与残差着色”模式区分收敛退出与迭代耗尽，Smooth 根据最后一步的残差着色，Nova 的阈值随缩放和请求分辨率变化。这套本地模式使用 CPU 或整数幂 DoubleDouble；已有文档保持原先保存的模式。

Newton/Nova 可显式选择“MathArt 1.7.8 数值规则”：使用 WebGL2 双 float 运算，符合条件时启用源参考轨道和有理扰动；扰动失效时继续普通 GPU 迭代，设备不可用或选择 CPU 时明确报错。精度支持 low、medium、high 三档，调节扰动判定，不切换为 CPU 双精度。新原版 JSON 导入默认采用此规则，缺省精度为 medium；已有本地文档（包括先前导入的项目）不自动迁移。源着色器最多执行 2048 步，作者保存的迭代数继续保留。

切换数值规则保留作者参数；源 Newton 固定使用参数平面，Nova 使用所选变体。源视口的跨度和纵轴方向不同，切换后可能改变画面。Nova 的收敛阈值使用缩放和逻辑画布尺寸：预览取实际画布逻辑尺寸，导出取请求输出尺寸。未选择原版着色规则时，配色继续使用本地实现。多遍预览、猜测和时间线调度仍沿用本地实现；未验证原版应用帧缓冲、DPI 或跨驱动逐像素等同。

Newton/Nova 还可单独选择“MathArt 1.7.8 原版着色”，须同时使用原版数值规则和 WebGL2。内部与外部可分别选择 10 种算法、传递函数、密度、偏移、重复方式和固定颜色；原版色板独立保存，支持手动颜色、RGB/HSV 插值、伽马和余弦参数，生成 1024 色纹理。轨道与颜色在同一 GPU 片段内计算。算法“零索引”仍读取色板；传递函数“固定颜色”才使用区域固定颜色。颜色原文中的 alpha 保留，最终分形像素为不透明。

新导入的原版 Newton/Nova JSON 默认启用数值与着色两组原版规则；已有本地文档不自动迁移。首次手动启用原版着色使用独立默认值，不转换本地色板；切回本地时保留原版配置。需要恢复本地数值规则时，应先切回本地着色。原版着色只适用于 Newton/Nova；切到其他公式时会提示，并保留关闭该规则或恢复兼容公式的入口。

原版着色的偏移动画更新独立色板与区域偏移，运行时使用所选循环插值，停止后保留偏移并恢复普通采样。预览、跳转、重开和 PNG 导出共用本地确定性时间线，不代表原版实时帧时钟。

Magnet I/II 和 Binocular 可选择“收敛退出与残差着色”。收敛点使用外部着色，停止距离和颜色残差分别保留；Magnet I 按源着色器使用零颜色残差。选择此模式会同时启用独立内外着色，可用一次撤销恢复原模式。Magnet 的零收敛阈值关闭收敛，Binocular 的零阈值使用源运行下限。旧本地文档的兼容图像保持不变；原版 JSON 导入采用新模式，Magnet 只消费正式 parameter / perturbation 字段，缺省为零。Magnet I/II 与整数幂 Binocular 可用 WebGL2 双 float 轨道计算，数值不确定像素由 CPU 双精度修复；驱动检查失败、不支持的指数或表示范围会说明原因并回退。Newton/Nova 在本地数值规则下的 step 模式仍使用 CPU。三种公式的 720p／4K 完整任务已测；其中 Magnet II 的 4K 对照有 7 个像素相差一个 8 位色阶，分类和退出迭代相同。深缩与跨设备性能、原版 DS 运算及像素一致性未验证，见 [收敛验证](coverage/fractal-residual.json)和[残差 GPU 验证](coverage/fractal-residual-gpu.json)。

Perlin 纹理通过 512×512 分块生成原生输出，支持 4K 及最多 16,777,216 像素、每像素 1–128 步积分。分块限制中间 GPU 缓冲和取消等待时间；最终图像仍按完整尺寸保存。GPU 能力或精度检查失败时会说明原因并回退 CPU，复杂输出可能耗时更长。

流场会根据当前生效的计算参数识别预设，修改参数后显示“自定义”。“刷新噪声种子”只更换种子，支持撤销；保存种子后可重现同一后端的流场。

内置对称混沌模板的参数具有固定范围滑块，Samila 可编辑每个参数的范围和步长。范围用于滑块、随机参数和新建动画的默认值；直接输入、导入值及已有动画不会被限制或改写。超出范围时保留真实数值并显示提示。

原版 Symmetry JSON 的 `equation.glsl` 可导入并在持续批次 GPU 模式执行。参数按原版的标量 `uniform float name;` 匹配规则传入，缺失或无法表示为 float32 的值传入 0；原始参数值仍完整保存。公式最后一次写出的 `stepMetric` 独立决定步长配色，有限负值有效。`{N}` 与 `{N_MINUS_2}` 使用编译阶数；时间线中的同名参数只更新运行时 uniform。`equation.formula` 仅显示说明，不作为可执行公式。

自定义模式显示全部参数及绑定匹配状态，不套用内置系数的滑块范围、三位小数或删除限制。仍被启用动画引用的参数须先停用或修改动画才能删除。切换模板会保留参数、补齐缺失的内置系数，并停用自定义源码；可撤销恢复。若当前阶数或修正幂次不受内置模板支持，切换会被明确拒绝，源码保持不变。

当前自定义后端支持 GLSL ES 3.00 函数源码；宏、预处理指令、`discard` 和保留的 `rea_` 标识符有明确诊断。原始源码限 65,536 个 UTF-16 代码单元，每次 `calculate_next` 调用共享 4,096 次循环体预算（包括嵌套循环和辅助函数）。CPU、单次采样、GPU 不可用或编译失败会报错，不会改画内置公式。该阶段不宣称完整桌面 GLSL 410 兼容，循环预算也不是驱动编译或着色器墙钟时间保证。


实数公式支持 `arcsin`、`arccos`、`arctan` 别名，CPU 和 GPU 共用函数解析；反正弦和反余弦的越界输入会停止该条无效轨迹。原有同名参数仍可读取，新增参数会避免占用函数名。

域着色的“渲染恢复规则”与三项作者规则分开保存。缺省策略保留 1723 之前保存作品的行为；新导入的 GPU 原版 JSON 显式采用“GPU 故障后使用 CPU 整链”。设备、编译或绘制等已分类 GPU 故障发生后，同一已求值时间帧按原产物 CPU 公式、CPU 视口和 CPU 着色重新完成整图，不改写保存的三项选择、原始公式或色板。显式选择 CPU 后端仍按所选规则计算；数值保护、成功的 GPU 终值加 CPU 着色、输入错误、本地资源准入限制和取消不冒充 GPU 故障；实际设备能力查询或分配失败由 GPU 边界另行分类。

同一作品的普通编辑保留当前计算会话的故障状态；“重试 GPU”取消并重建会话，再真实计算。“固定使用 CPU 整链”可保存并在重新加载后继续生效，“恢复所选规则”保留原有作者输入。CPU 回退色板可单独编辑，使用完整原产物色板，未保存时采用六色默认；不会从本地函数色板暗中转换。界面有效常量、视口导航和导出摘要消费实际完成帧的执行事实。预览和导出拥有独立计算会话，因此各自显示实际路径；多帧导出记录每条路径首次和最后出现的帧（最多显示 16 条不同详情），不承诺每帧采用相同路径。原应用、JVM 与原生驱动像素仍未执行对照。
